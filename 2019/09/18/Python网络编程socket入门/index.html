Python 网络编程 socket 入门

本文属于《Python 学习路线》第 16/29 篇
上一篇系列目录下一篇

网络编程离业务很远，但 Web 服务最终都要把字节写进内核套接字缓冲区。本文从 socket 接口讲起，依次完成 TCP 服务端与客户端、消息分帧、UDP、超时处理和 selectors 单线程服务器。读者只需掌握 Python 基础语法，读完后应能写出可用的长连接服务，并知道常见故障该往哪里查。示例基于 Python 3.7，3.8 即将在 10 月发布，但文中不依赖新语法。

分层、地址与字节序

TCP/IP 分为链路、网络、传输与应用四层。IP 把数据包送到主机，TCP 与 UDP 把数据交给进程，socket 是内核暴露给应用的一组接口，位于传输层与应用层之间。调用 socket() 得到的是一个文件描述符，读写它和读写文件有相似的直觉。

flowchart LR
    A[应用进程] --> B[socket 接口]
    B --> C[TCP 或 UDP]
    C --> D[IP 层]
    D --> E[网卡]

TCP 面向连接、可靠，把数据看成连续字节流；UDP 无连接、保留消息边界、不保证送达。端口是进程在传输层的地址，0 到 1023 是特权端口，服务端通常监听 1024 以上。地址用主机加端口的二元组表示，绑定 0.0.0.0 表示所有网卡，绑定 127.0.0.1 则只允许本机访问。网络传输中，协议头里的多字节整数通常用大端字节序，struct 的 ! 前缀即声明大端，解析协议头时不要依赖本机字节序，否则换一台机器就可能读出错位的长度。

TCP 服务端的最小实现

一个回声服务端只需十几个调用。下面的例子监听 9000 端口，把收到的内容原样发回，直到客户端关闭。

AF_INET 表示 IPv4，SOCK_STREAM 表示 TCP。bind 占用地址与端口，listen 把主动套接字变成被动套接字，参数是内核等待队列长度。accept 返回新套接字，专门服务这个客户端，原来的 server 继续接收新连接。recv(1024) 中的数字是单次最多读取的字节数，不是要求读满。send 可能只写出一部分，业务代码应当使用 sendall。

SO_REUSEADDR 值得单独说明。服务端主动关闭连接后，端口会在一段时间内处于 TIME_WAIT，此时直接重启会报地址已被占用。该选项在 Linux 上让新的监听套接字可以复用这个端口，但不会让两个进程同时监听同一地址。这个例子一次只服务一个客户端。

TCP 客户端与连接状态

客户端更简单：解析地址、建立连接、收发数据。create_connection 会完成域名解析，并在多个地址间依次尝试，适合大多数场景。

timeout=3 同时约束连接建立和后续阻塞操作，超时抛出 socket.timeout。recv 返回空字节 b"" 只有一个含义：对端已经有序关闭发送方向。它不表示“暂时没有数据”，后者在阻塞模式下继续等，非阻塞模式下抛出 BlockingIOError。把空字节当成“再试一次”，是新手常见的死循环来源。

调用 shutdown(socket.SHUT_WR) 会发送 FIN，告诉对端“我没有更多数据要发了”，本地仍可继续读取。HTTP/1.0 的请求结束、某些“发完请求再等结果”的协议都依赖它。close 则同时关闭读写两个方向并释放描述符。客户端还应处理 ConnectionRefusedError，它表示目标端口没有进程监听，通常意味着服务没起来或地址写错。

字节、编码与消息边界

socket 只认识 bytes，发送前编码，接收后解码。UTF-8 是变长编码，一个汉字通常占 3 个字节，协议长度必须按字节数算。不要把半个汉字拿去 decode，那会得到乱码或 UnicodeDecodeError。

关键在于：TCP 是字节流，不保留消息边界。发送端两次 sendall，接收端可能一次读到两段内容，也可能只读到前半截，这就是粘包与拆包。这不是缺陷，而是流式协议的正常行为，应用层必须定义消息的结束位置。

常见方案有三种。长度前缀先发固定字节数的长度，再发正文，解析简单，二进制协议常用。分隔符方案例如每行一个 JSON，便于用 nc 和日志观察，但正文出现分隔符要转义，且要限制单行长度。定长帧每条消息大小固定，不足补零，适合遥测小包，但浪费带宽。选择取决于可读性与实现复杂度。

用长度前缀封装帧

recv 不保证一次读满，需要循环直到凑够长度头或正文。这个函数是几乎所有自定义 TCP 协议的基础件。

recv_exact 每次只请求还缺的字节数，避免多读下一帧。长度检查必须在分配内存之前，MAX_FRAME 是协议的一部分，双方要约定一致。send_frame 把头部和正文拼成一个 bytes 再 sendall，小帧最省事；多线程共享 socket 时发送必须加锁，否则字节流会被交叉写入。接收方按“读头、读体”的节奏前进即可，代价是发送方必须知道正文长度，流式内容要先缓冲或改用分块协议。

UDP：无连接的另一条路径

UDP 的模型更短，没有 listen 和 accept，每个数据报自带地址，收发围绕 sendto 与 recvfrom。

SOCK_DGRAM 表示 UDP，recvfrom 返回数据与来源地址，sendto 每次都要给出目标地址。UDP 保留消息边界，不存在粘包，但不保证送达与顺序，也可能重复。单个数据报受 MTU 限制，IPv4 下应用数据最好控制在 1472 字节以内，超过可能被分片，分片会显著提高丢失概率。

UDP 适合“丢了也比等着强”的场景：DNS 查询、日志采集、指标上报、实时音视频、游戏状态同步，不适合文件传输和支付指令。在 UDP 上实现确认、重传与拥塞控制，要处理序列号、时延估计、去重和拥塞窗口，做对非常困难，QUIC 就是例子。需要可靠传输就用 TCP，能容忍少量丢失就用 UDP。UDP 也可以 connect，但它不发报文，只在本地记录默认对端并过滤来源，双方没有握手。

超时、错误与重试

阻塞 socket 默认会一直等。服务端等不说话的客户端，客户端等不回包的服务端，都会拖住线程。settimeout 是最低成本的防护。

socket.timeout 是 OSError 子类，超时后套接字不一定还能用。ConnectionResetError 表示收到 RST，常见于进程崩溃、中间设备重置，或对端还有未读数据时直接关闭。BrokenPipeError 出现在对端已关闭、本地仍继续发送时，ConnectionRefusedError 则发生在连接阶段。它们语义不同，混成一个 except 会让排障失去线索。

重试只对可能瞬时恢复的错误有意义，且要求操作幂等。查询可以重试，扣款不能盲目重试，除非服务端用请求号去重。退避要有上限并加随机抖动，避免客户端同时冲击服务端。最糟糕的是在循环里 except Exception: pass，它会把编码错误、参数错误和网络故障一起吞掉。至少记录异常类型、对端地址和重试次数。服务端也要超时，否则慢客户端会耗尽资源。

并发模型：线程、线程池与事件循环

最直观的扩展是每连接一线程：主线程 accept 后启动线程。

这个模型最轻松，每个连接内部可以随意阻塞，读数据库、调外部接口都不用改写。上限来自线程：每个线程要预留栈空间，切换也有成本，连接上千后开销明显。Python 有 GIL，但 socket 读写和多数数据库驱动等待时会释放 GIL，所以线程模型对 I/O 密集型服务仍可用。

线程池是约束版：固定数量工作线程从队列取任务，超过处理能力时排队或拒绝。它避免线程无限增长，却可能让长连接长期占住线程，因此必须配合超时。事件循环是单线程加非阻塞 socket，用 select 等待就绪的描述符，连接数上限取决于内存和文件描述符，可支撑上万连接。代价是任何阻塞调用都会卡住循环，代码必须拆成状态机。

模型 适合连接数 主要优点 主要代价
一连接一线程 数百到两千 编程简单 线程开销大
线程池 数百 资源可控 长连接占满线程
selectors 数千到数万 连接密度高 全链路非阻塞

选择时先看连接是否长期空闲。短连接、请求平稳的内部服务，线程池足够；大量长连接、消息推送、网关服务，事件循环更合适。容量取决于消息速率和业务耗时，而不只是连接数。

selectors 实战：单线程 echo 服务器

selectors 把 epoll、kqueue 等机制统一成一套接口，DefaultSelector 会自动挑选平台最优实现。下面的骨架接受连接、回显数据，并处理部分读写。

sel.select() 返回 (key, mask) 列表，key.fileobj 是注册对象，key.data 是附带数据，这里用来区分监听套接字和客户端，并存放回调。mask 是位标志，可能同时包含可读与可写。监听套接字非阻塞后，accept 没有新连接会抛 BlockingIOError，所以用内层循环把积压连接全部取出。

客户端 socket 同样非阻塞。recv 没有数据时抛 BlockingIOError，不能当成错误退出。send 只写出内核缓冲区能容纳的部分，剩余数据要留在本地缓冲，等下一次可写事件。只注册可读事件时，对端不收数据会让发送缓冲区堆满；缓冲区非空时应同时注册 EVENT_WRITE，清空后再降回只读。骨架省略了异常处理、空闲连接清理和协议解析，生产代码还要处理 ConnectionResetError，为每个连接维护读缓冲，并用帧函数切分消息。

关闭、资源与调试

在 Unix 上，socket 是文件描述符，每条路径都要释放。最简单的是 with，它等价于在 finally 里调用 close，抛异常也不会漏掉。

close 减少描述符引用，真正终止连接还要看是否有其他引用，例如 makefile。shutdown 直接作用于连接：SHUT_WR 发送 FIN，SHUT_RD 关闭读方向，SHUT_RDWR 两个方向一起关。要把“不再发送”与“释放描述符”分开，先 shutdown 再 close。只 close 而不读走剩余数据，某些系统会发 RST，对端看到的是连接重置而非正常结束。

主动关闭的一方会进入 TIME_WAIT，持续 2 倍报文最大生存时间，Linux 上约 60 秒，作用是让迟到报文消亡、保证最后一个 ACK 能重传。高并发短连接若由服务端主动关闭，会积累大量 TIME_WAIT，占用四元组。SO_REUSEADDR 只能缓解监听端口无法重新绑定，更根本的办法是长连接、连接池，或让客户端先关闭。描述符泄漏更常见：忘记关闭 accept 返回的连接、异常路径提前 return、把 socket 存进全局字典却不删。用 ulimit -n 看上限，用 lsof -p <pid> 或 ss -tnp 观察，报 Too many open files 时先找泄漏点。

排查网络问题，先看连接状态，再抓包。ss 比 netstat 更快，参数接近。

tcpdump 的 -A 会把载荷按 ASCII 打印，调试自定义协议方便，但也意味着有权限的人都能看到明文，只应在测试环境使用。nc 适合验证连通性和手工发几个字节，不能替代压测。线上抓包前要确认授权，抓包文件往往含敏感信息。

安全边界与框架的关系

socket 不提供加密和认证。公网明文 TCP 传口令、令牌或个人信息，等同于把内容写在明信片上。需要保护时，用 ssl.SSLContext 包装套接字并校验服务端证书，不要关掉校验。Python 3.7 中应通过 SSLContext.wrap_socket 建立 TLS，不要再用 ssl.wrap_socket。

绑定地址决定暴露面。本机管理接口就绑 127.0.0.1，不要图省事绑 0.0.0.0；必须对外时，用防火墙只放行需要的来源与端口。接收数据前先限制长度，长度头超限立即断开，避免对端用巨大数字让服务端预分配内存。读取要有上限和超时，防止慢速发送占住连接。不要用 pickle 反序列化不可信数据，它能构造任意对象，风险远高于 JSON。

最后是它与 Web 框架的关系。WSGI 服务器（例如 Gunicorn 的同步 worker）和 ASGI 服务器（例如 Uvicorn）底层都在做本文讲的事：监听端口、接受连接、读取字节、解析 HTTP、调用应用、写回响应。框架封装了连接管理、超时、并发和协议，业务代码不应重写。学习 socket 的价值在排障：知道 ConnectionResetError 从哪来，知道 worker 为什么只处理一个请求，知道长连接为什么占住线程，才能在框架出问题时选对参数。

小结

socket 是应用与内核网络栈的接口，TCP 提供可靠字节流，UDP 提供保留边界但不可靠的数据报。使用 TCP 必须自己定义消息边界，长度前缀最稳妥，任何一次 recv 都不能假设收到完整消息。超时、半关闭、错误分类和资源释放要一开始就设计好。连接少时一连接一线程足够，连接多时用 selectors 集中等待，但要接受非阻塞的复杂度。明文、暴露的地址和无长度上限的读取都是真实风险，框架不能替我们做安全决策。
