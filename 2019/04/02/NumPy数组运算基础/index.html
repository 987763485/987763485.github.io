NumPy 数组运算基础

本文属于《Python 学习路线》第 26/29 篇
上一篇系列目录下一篇

如果把 Python 的 list 想象成一排贴着标签的抽屉，那么 NumPy 的 ndarray 更像一整块切割整齐的巧克力：每格等宽、紧密相连，取哪一格都能用坐标直接算出来。本文面向已经会写 Python、但还没系统使用过 NumPy 的读者，从内存布局讲起，依次梳理数组的创建、变形、索引、广播、聚合与线性代数，最后落在几个高频的坑上。读完之后，你应当能独立写出可复现的数组代码，并大致判断哪些工作应该交给 pandas。

为什么用 ndarray

Python 的 list 很灵活，代价是每个元素都是一个独立的 Python 对象。列表本身只保存指向这些对象的指针，对象分散在堆内存里，读取一个元素往往要先解引用，再做类型检查；用 for 循环对一百万个元素做一次加法，解释器要执行一百万次循环体。NumPy 把这部分工作交给了 C：ndarray 在一块连续内存中存放同一种 dtype 的数据，元素之间没有额外的对象头，地址可以由起始位置和步长直接计算。所谓向量化，并不是语法上的魔法，而是把循环从 Python 层下沉到编译好的循环里，顺带获得更好的缓存局部性。

同构的 dtype 还带来两个直接好处。其一，内存占用可预测，一个 float64 元素固定占 8 字节，形状确定后总字节数就确定了；其二，数组可以把“数据、形状、步长”分开描述，于是同一块内存能有多种解读方式，切片和 reshape 因此可以做到几乎零成本。

上面的 arr * 2 + 1 会生成两个临时数组，先乘后加；如果数据量很大，可以改用 ufunc 的 out 参数或就地运算来减少分配，这一点在后文还会提到。需要强调的是，本文不讨论具体快多少倍，因为倍数取决于数据规模、dtype、内存带宽和解释器版本，脱离场景谈倍数没有意义；真正稳定的结论是：元素越多、循环越简单，向量化的相对收益越明显。

创建数组

最直接的方式是从 Python 序列构造。np.array 会复制数据并推断 dtype，嵌套列表会得到二维数组；推断规则在整数与浮点数混排时偏向更宽的类型，但跨平台时默认整数宽度可能不同，涉及存储或接口时最好显式写出 dtype。

zeros、ones、full 用于按形状填充已知值；empty 只分配内存、不初始化，里面的内容是内存残留，不要假设它是 0。需要占位再逐块赋值时，empty 可以省掉一次清零，但读取未赋值的部分，结果不可预测。

等差序列有两个常用函数，选择取决于你要的是“步长”还是“个数”。arange 按步长生成，默认不包含终点；linspace 按个数生成，默认包含终点，更适合画图和需要固定采样点数的场合。浮点步长的 arange 还可能积累误差，例如 np.arange(0, 1, 0.1) 的长度和末值都不宜依赖，这类场景应改用 linspace。

随机数在 NumPy 1.16 中仍以 np.random 模块为主。做示例、写测试或需要复现实验时，先调用 np.random.seed 固定全局种子；它影响后续所有基于全局状态的随机函数，因此适合在脚本开头一次性设置。rand 生成 [0, 1) 的均匀分布，randn 生成标准正态分布，randint 生成指定区间内的整数。

如果不希望污染全局状态，可以创建独立的 RandomState 实例，把它传给需要随机性的函数。对于单机脚本，固定种子已经足够；在并行任务里，每个进程最好使用不同的种子，否则会得到相同的“随机”序列。

形状、维度与重排

shape 是描述各维长度的元组，ndim 是元组的长度，size 是所有维度长度的乘积。三者关系简单，但排查广播错误时几乎都要回到 shape 上：绝大多数“维度不匹配”都是尾维对不上。

reshape 按行优先（C 顺序）重新解读元素，返回的是原数组的视图（只要内存布局允许），不复制数据。-1 表示“这一维由其余维度推出来”，一次只能出现一个；b.reshape(2, -1) 之所以得到 6，是因为 12 除以 2 等于 6。若元素总数不能被整除，会直接抛出 ValueError，不要靠试错去猜。

转置用于交换维度。二维数组的 .T 就是行列互换；高维数组的 .T 会反转所有轴，若只想交换其中两轴，应使用 transpose 并显式给出轴顺序。转置同样返回视图，底层数据没有搬动，只是步长变了，因此对转置结果赋值会写回原数组。

ravel 和 flatten 都能把多维拉平成一维，区别在复制策略：ravel 尽可能返回视图，flatten 总是返回副本。需要保证后续修改不影响原数组时用 flatten，只是临时遍历时用 ravel 更省内存。另一个常用技巧是用 np.newaxis（也就是 None）插入长度为 1 的维度，把一维数组变成列向量，为后面的广播做准备。

索引与切片

一维数组的索引与 list 类似，支持负索引和 start:stop:step 切片，区别是切片不复制，且可以一次跨多步。二维数组用逗号分隔各维，a[1, 2] 是第 2 行第 3 列，a[0:2, 1:] 取前两行的后几列；只写一个下标时取的是整行，得到的是一维视图。省略号 ... 可以代替若干连续的冒号，在维度较多时比较方便。

布尔索引用一个同形状的布尔数组筛选元素，表达式通常直接写成比较式。多个条件组合时要用 &、|、~，不能用 and、or、not，因为后三者会对整个数组求真假而不是逐元素运算；同时每个比较式都要加括号，否则运算符优先级会让结果出乎意料。布尔索引返回的是副本，常用来做条件赋值。

花式索引用整数数组或列表指定位置，可以重复、可以乱序。二维情况下若行、列各给一个数组，得到的是成对的元素而不是子矩阵；想要行列的笛卡尔积，需要借助 np.ix_ 或分两步索引。花式索引总是返回副本，这一点与基本切片不同。

视图与副本

基本切片返回视图，视图与原数组共享同一块数据。修改视图会立刻反映到原数组，这一点在处理大数组时既能省内存，也容易引发难以追踪的 bug。判断两个数组是否共享内存可以用 np.shares_memory；想彻底断开关系，就显式调用 copy()。

逐元素运算与广播

形状相同的两个数组做 +、-、*、/、//、** 时，运算逐个元素进行，结果形状不变；这些运算符背后是 ufunc，也可以直接调用 np.add、np.multiply 等函数。np.sqrt、np.exp、np.log 等数学函数同样按元素作用，不需要写循环。要特别注意 * 是逐元素乘法，矩阵乘法另有运算符，两者不能混用。

广播让形状不同的数组也能逐元素运算，规则可以概括为三步：先把两个形状从尾部对齐，短的一方在左侧补 1；再逐维比较，相等或其中一个是 1 就兼容；最后结果在该维取较大值。维度不满足“相等或为 1”时直接报错，错误信息通常包含 could not be broadcast together，此时先打印两个 shape，往往一眼就能看出问题。

广播最常见的实用场景是标准化：每列减去该列均值，再除以标准差。均值形状是 (m,)，与 (n, m) 的数据相减时会自动扩展成每一行，不必手动平铺。若统计量本想按行计算，却得到 (n,) 这样的一维形状，它与 (n, m) 相减会因尾维不匹配而报错，这时用 keepdims 或 newaxis 变成 (n, 1) 即可。

比较运算返回布尔数组，逻辑运算则用 np.logical_and、np.logical_or、np.logical_not 或对应的 &、|、~。np.where 是三目运算的向量化版本：给定条件、真值、假值，逐元素选择；只传条件时返回满足条件的下标元组。把负数截断为零、按阈值分段，都可以用它一行写完。

聚合与轴

sum、mean、std、min、max 既可作为数组方法调用，也可作为 NumPy 函数调用。不传 axis 时把数组展平后聚合，返回一个标量；传 axis 时沿指定轴归约，返回的维度少一维。理解 axis 的关键不是“行还是列”，而是“被消掉的那一维”：axis=0 消掉行，二维数组会得到每一列的结果；axis=1 消掉列，得到每一行的结果。

keepdims=True 保留被归约的那一维，长度变为 1。它的价值在于让结果可以直接参与广播，例如用每行均值做中心化时，a - a.mean(axis=1, keepdims=True) 不需要再手动加轴。默认情况下 std 的 ddof=0，计算的是总体标准差；做样本统计时若需要无偏估计，应显式传入 ddof=1，这个差异在样本量小时不能忽略。

argmax 和 argmin 返回最值的下标而不是最值本身。二维数组不传 axis 时，下标是按行优先展平后的位置；传 axis 后，返回沿该轴的最值位置，常用于从概率矩阵中取类别。若存在多个并列最值，返回的是第一个出现的位置。

线性代数初步

矩阵乘法用 @ 运算符或 np.dot。二维数组相乘时，左矩阵的列数必须等于右矩阵的行数，(2, 3) @ (3, 4) 得到 (2, 4)；两个一维数组做 dot 时按点积处理，结果是标量。矩阵乘法不满足交换律，顺序写反要么形状不兼容，要么得到形状相同但数值完全不同的结果。

解线性方程组优先用 linalg.solve，不要先求逆再相乘：求逆既慢，又会放大数值误差。linalg.inv 适合确实需要逆矩阵本身的教学或推导场景，生产代码里应谨慎。det 用来判断矩阵是否接近奇异，norm 计算向量或矩阵的范数，默认是二范数，对矩阵而言就是 Frobenius 范数。做数值比较时用 np.allclose 判断两个结果是否在容差内，而不是逐元素写等号。

拼接与拆分

把多个数组拼在一起时，concatenate 沿已有轴连接，要求除拼接轴外其余维度一致；stack 则新增一个轴，适合把一组同形数组合成批量数据。vstack 和 hstack 是常用方向的快捷方式，前者按行叠，后者按列接。拆分用 split，它要求能等分，除不尽时会报错；允许不等分的是 array_split。

缺失值、类型与浮点比较

NaN 是浮点世界的“未知值”，它不等于任何值，也不等于自己。因此判断缺失不能用 ==，要用 np.isnan；含有 NaN 的数组直接求和会得到 NaN，需要时改用 nanmean、nansum 等忽略缺失的函数，或者先用布尔掩码把有效值挑出来。

整数没有 NaN，也就没有“缺失”的表示，这一点常被忽略。此外，定宽整数会溢出：int8 的范围是 -128 到 127，127 再加 1 会回绕成 -128，且不一定有醒目提示。整数与浮点混合运算时结果会提升为更宽的类型，整数除法 / 也总是得到浮点数；需要整除时用 //。需要主动改变类型时用 astype，它默认返回副本；把浮点转成整数会截断小数，转换前要确认目标类型能容纳原值。浮点数则不要用 == 比较，应使用 np.isclose 或 np.allclose，并理解它们带有默认容差。

与 pandas 的分工

NumPy 负责同构的数值数组和数学运算，pandas 负责带标签、可能混合类型的表格。需要按列名筛选、对齐索引、分组聚合或处理时间序列时，用 pandas 更合适；拿到一列干净的数值后，再转成 ndarray 做矩阵运算。DataFrame 的清洗与变形属于另一个话题，本文不展开。两者之间通常用 .values 转换，注意它可能返回视图，修改前先确认是否需要 copy。

常见坑

最后把容易重复踩的坑集中列一下。切片是视图，改切片会改原数组；广播只在“维度相等或为 1”时成立，报错先看尾维；axis 是归约掉的那一维，不是行的方向；含 nan 的数据直接聚合会污染结果；对视图做 += 等原地运算会修改共享数据，需要独立结果时先 copy()。把这五条记牢，大多数“结果不对”都能快速定位。

小结

NumPy 的核心是“同构数据、形状描述、向量化运算”。创建时明确 dtype，变形时留意视图与副本，索引时区分基本切片和花式索引，运算前先核对形状是否满足广播，聚合时想清楚 axis 消掉的是哪一维。把这些基础打牢，再进入 pandas 或更复杂的数值计算，就不会被底层的共享内存和类型规则绊住。
