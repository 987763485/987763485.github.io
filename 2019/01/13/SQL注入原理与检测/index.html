SQL 注入原理与检测

SQL 注入并不神秘，它只是“把用户输入当成 SQL 代码”这一习惯动作的必然结果。本文从两条最常见的查询语句出发，说明注入为什么成立，再梳理常见类型与手工检测思路，最后落到参数化查询与纵深防御。读者应具备基本的 SQL 知识，以及一种后端语言的读写经验。文中所有示例仅用于解释原理，测试请在授权范围内进行。

一、边界消失：注入的本质

1.1 拼接把数据放进了语法位置

任何一门语言都要区分“代码”与“数据”，编译器靠引号、括号、关键字把这些边界划出来。SQL 的特殊之处在于：文本在应用层被拼接，解析却发生在数据库服务端，两者之间没有任何隔离机制。

二、常见类型与判定特征

分类的意义不在于记住名字，而在于每一类对应一种回显通道：结果直接返回、报错信息返回、只有真假可辨、只有时间可辨。检测时先确定通道，再选择手法，比背 payload 有用得多。

2.1 字符型与数字型

字符型靠引号扰动判定：在参数后加一个单引号，观察是否出现语法错误；再加一个单引号，若错误消失，说明闭合成功。数字型靠算术判定：把 1 改成 2-1，若返回结果与 1 相同，说明该位置被当作表达式而非字符串常量。

括号是常被忽略的一层。WHERE id IN (1)、WHERE (name = 'x') 这类写法需要先补齐括号才能闭合，因此检测顺序通常是：单引号、双引号、括号、注释符，逐层试探。

2.2 联合查询

UNION SELECT 的思路是把第二条查询的结果拼到第一条结果集之后。判定特征有三：列数必须一致、对应列的类型需兼容、页面会多出原本不存在的行。检测时先用 ORDER BY 递增确定列数，再用只含常量的联合查询试探回显位置。这类只在页面直接渲染结果时可用，属于“有回显”的场景。

2.3 报错注入

当页面屏蔽了结果、却没有屏蔽错误，数据库的报错文本就成了通道。MySQL 中 EXTRACTVALUE、UPDATEXML 等函数在参数非法时，会把表达式内容带进错误消息。判定特征是：请求后返回 500 或统一错误页，且错误详情里出现函数名或 SQL 片段。检测阶段只需确认“是否因注入而报错”，看到函数名被回显，就说明输入已进入语法层。

2.4 布尔盲注

页面既不回显数据也不回显错误，但“有结果”与“无结果”两种状态在界面上可区分，例如列表长度、提示文案、HTTP 状态码。此时可把条件写成真假表达式，逐位推断。判定特征是：同一请求在 AND 1=1 与 AND 1=2 下页面表现稳定不同，且这种差异可重复。盲注请求量大、结论慢，确认“真假可分”即可停止。

2.5 时间盲注

连真假都不可辨时，只能依靠响应时间。SLEEP()、BENCHMARK() 是 MySQL 中常用的手段。判定方法是成对比较：同一参数分别注入“立即返回”与“延迟数秒”的表达式，若延迟稳定复现且与网络抖动无关，才可判定。误判常来自缓存、限流与代理重试，至少要重复三次并换用不同延迟值交叉验证。

2.6 堆叠查询

部分驱动允许一次执行多条以分号分隔的语句。判定特征是：注入后出现与第一条查询无关的副作用，例如表中多出一行、连接被意外断开、事务被提交。MySQL 5.7 的 JDBC 默认不允许批量执行，需显式开启多语句选项，因此这一类在实际环境中比想象中少见；但一旦成立，危害最高，因为它把“读”扩展成了“写”。本文不展开具体语句。

三、手工检测：从输入点到判定

3.1 容易漏掉的输入点

多数人只盯着地址栏里的查询参数，实际上凡是进入 SQL 的位置都算输入点。做检测时可以先列一张清单，逐项确认：

  • URL 查询串中的每一个参数，包括看似只做展示的 sort、page、size；
  • 表单与 JSON 请求体中的字段，注意嵌套结构与数组形式的批量 id；
  • 路径片段，例如 /user/123 中的 123，很多框架会把它直接拼进查询；
  • 请求头中的 User-Agent、Referer、X-Forwarded-For，它们常被写入日志表或风控表；
  • Cookie 中的会话标识、偏好设置、租户编号；
  • 排序字段与排序方向，这类值往往不在参数化之列；
  • 分页的偏移量与每页条数，尤其是拼接进 LIMIT 的那些。

清单的价值在于避免“测了首页就收工”。只用于排序的参数看似无害，却进入 ORDER BY 之后的位置，恰恰是占位符覆盖不到的地方。

3.2 扰动、类型与对比

确定输入点后，按由轻到重的顺序做扰动。第一步是单引号与双引号，观察是否出现数据库错误或页面结构变化；第二步是补括号，处理 IN (...)、(... AND ...) 这类嵌套；第三步是加注释符，确认尾部残余能否被吞掉。

接着做类型层面的验证。对数字参数传入 2-1、1+0，若结果与直接传 1 一致，说明它被当作表达式求值；对字符参数传入长度突变的字符串，观察是否触发截断或类型转换告警。'1abc' 在 MySQL 中可能被转成 1 而不报错，这种隐式宽容容易让人误以为参数已被正确处理。

最后是对比法。布尔对比看页面差异，延迟对比看响应时间，两者都要成对出现、可重复。错误信息观察要区分三种情况：完整报错、统一错误页、静默返回空结果。检测记录应写清输入、现象与重复次数，否则复测时无法复现。

3.3 授权是前提

上述操作都会在目标数据库留下痕迹，可能触发告警、写入错误日志，甚至因延迟语句拖慢生产查询。因此检测必须满足三个条件：有书面授权与明确的域名、IP 范围；避开业务高峰并控制请求频率；不使用会修改数据的语句。授权测试中可用自动化工具辅助验证，但工具的输出仍需人工确认，误报在注入检测里并不罕见。

四、代码层的根因

4.1 字符串拼接

最直接的根因就是把变量拼进 SQL 文本，前面几节的例子都属于这一类。变体很多：用 String.format、模板字符串、+ 连接，或先拼再交给 createStatement。判断标准只有一条：SQL 文本进入驱动之前是否已是最终形态。若是，任何转义函数都只是补丁。

4.2 ORM 的 raw 与 order by

用了 ORM 不等于安全。ORM 的常规查询接口会生成占位符，但几乎都提供了“原样执行”的入口：Django 的 extra 与 RawSQL、SQLAlchemy 的 text()、GORM 的 Where 传入字符串片段。这些入口接上用户输入，ORM 的保护就完全失效。排序更是重灾区，order_by(request.GET['sort']) 把列名直接交给框架，而列名无法用占位符绑定。

4.3 动态表名与列名

多租户、分表、报表导出等场景常需要动态表名，例如按月份查 orders_201901。表名与列名属于标识符，不是值，参数化查询对它们无效。开发者往往因此退回拼接，并顺手把用户可控的字段名也拼进去。解法是白名单映射，下一节展开。

4.4 LIKE 与 IN 的拼接

LIKE '%" + kw + "%' 极为常见，因为参数化后通配符不好拼。正确做法是把通配符放进参数值，而不是放进 SQL 文本。IN 列表则相反：不少人用循环拼出 ?,?,?，这本身是安全的，但若拼的是值而非占位符，就回到了老路。另有一种隐蔽写法是用 FIND_IN_SET 接收逗号串，此时用户输入直接进入函数参数，同样需要参数化。

五、修复：让值始终是值

参数化的核心是把语句结构先交给数据库编译，再把值单独送达。值在编译之后才出现，无论它包含引号、注释符还是关键字，都只能停留在“值”的位置。

5.1 Java JDBC

占位符只能替代值。表名、列名、排序方向都不能用 ?，硬套会直接报语法错误。

5.2 Python DB-API

不要写成 sql % name 或 sql.format(name=name)，那等于在 Python 层完成拼接，驱动只会收到一条成品语句。

5.3 Go database/sql

Query、QueryRow、Exec 的额外参数就是绑定值，驱动会走服务端预处理或安全转义。注意 MySQL 驱动的占位符是 ?，PostgreSQL 是 $1，不要混用。

5.4 动态标识符用白名单

用户只能选择映射表中的键，无法把内容写进语句。表名、导出字段同理，映射表要写成常量；示例中的 LIMIT 仍走占位符绑定，不要拼进语句。

六、纵深防御

数据库账号按最小权限授予：应用只需要目标库表的增删改查，就不给 DROP、FILE、SUPER，更不要用 root 连接。生产环境关闭详细错误回显，对外返回统一错误码，堆栈与 SQL 片段只写服务端日志。WAF 能争取时间，但规则可被编码、注释、大小写变化绕过，只能作补充。输入校验能缩小入口，却覆盖不了所有语法位置，正则黑名单尤其脆弱。使用 ORM 的团队应定期搜索 raw、extra、order_by，确认没有把参数直接交给它们。

七、检测与响应

日志里值得留意的信号包括：查询文本中出现注释符、恒真比较、SLEEP 或 BENCHMARK、以及异常长的参数；同一来源短时间大量 500 与慢查询同时抬头；应用账号访问了本不该访问的库表。发现疑似注入后，先限流或封禁来源、必要时下线接口，保留原始日志与请求样本，再按数据敏感度评估影响范围并转入应急流程。取证与定级属于应急响应的完整流程，注入只算其中一类入口；命令执行、信息收集与整体渗透流程各有专文，本文不越界展开。

小结

SQL 注入的根因只有一个：数据被放进了语法位置。字符型、数字型、联合、报错、布尔、时间、堆叠，这些分类只是回显通道不同，判定思路都是扰动、对比、确认可重复。检测要先列全输入点，逐层试探引号、括号与注释，守住授权边界。修复以参数化查询为主，动态标识符走白名单；最小权限、关闭报错、WAF 与输入校验都只是补充，不能替代前者。
