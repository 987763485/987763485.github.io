Matplotlib 数据可视化入门

本文属于《Python 学习路线》第 29/29 篇
上一篇系列目录下一篇

很多人的第一张图，是在 Jupyter 里用一行 plt.plot(x, y) 画出来的；可一旦图里要放三条线、两个子图、中文标题和一处箭头注释，这一行就不够用了。本文面向刚学会用 pandas 读表、还没系统用过 Matplotlib 的读者，从两种绘图接口讲起，依次覆盖常用图形、图形组成、多图布局、中文字体、刻度与保存，最后落到与 pandas 的分工和几个高频的坑。读完之后，你应该能独立写出一个可复现、能交给同事的绘图脚本，而不是在 Notebook 里反复试错。

pyplot 是一套“状态机”式接口：它在内部维护“当前图形”和“当前子图”的隐式状态，plt.plot 画到当前子图上，plt.title 改的也是当前子图的标题。写一次性脚本、做快速探索时，它足够短。

问题在于“当前”是隐式的。一旦在函数里嵌套调用，或在循环里连续画图，你很难确认 plt.xlabel 作用在哪张图上。更稳妥的是面向对象接口：先显式创建 Figure 和 Axes，之后所有操作都挂在具体对象上。

两种写法画出的图一样，区别在可维护性。OO 接口有三个好处：作用域明确，ax 属于哪张图的哪个格子一目了然；便于封装，把绘图逻辑写成接收 ax 参数的函数，既能用于单图，也能塞进网格；方便画完再改，fig 和 ax 都是普通对象。所以后文统一使用 OO 接口。

基础图形：先看数据关系，再选图

选图的第一原则不是“哪个好看”，而是“数据之间是什么关系”。连续自变量上的变化用折线，两个连续变量的关系用散点，离散类别的比较用柱状，单个变量的分布用直方图或箱线图，占比才轮到饼图。下面每一类给一个最小示例，示例共用同一组固定种子的随机数据。

折线图适合连续自变量上的趋势，横轴通常是时间或序号。纵轴不必从 0 开始，折线表达的是变化率而非面积，归零反而压扁波动；这也意味着截断纵轴能放大差异，读图时要先看刻度范围。

散点图看两个连续变量是否相关、有无离群点。点一多就糊成一团，alpha 设成 0.3 到 0.6 能让重叠处颜色更深，看出密度；s 控制点的大小，别用默认值应付几百个点。

柱状图比较离散类别的数量，纵轴应从 0 开始，否则柱子高度比例会骗人。类别名较长时改用 barh，标签就不用旋转。看构成可用 stacked=True，但堆叠超过三四段就很难比较中间的分段。

直方图看单个变量的分布形状，bins 对观感影响很大：太少看不出双峰，太多全是锯齿。经验是先按数据量的平方根取值再调整；多组对比时用 hist(..., alpha=0.5) 叠放，或用 density=True 归一化后比较形状。

饼图要少用。人眼比较角度的精度远低于比较长度，超过五六类或占比接近时几乎读不出差别，不如换成排序后的条形图。非用不可时，把扇区按大小排序并标上百分比，也不要并排两个饼图让人对照。

箱线图用五数概括描述分布，还能直接标出离群点，适合十几组数据并排比较。它的短板是隐藏了样本量和分布形状，几十个点以内的小样本，散点或条带图反而更诚实。

六种基础图形的最小用法齐了。实际更常见的是“一张主图加两三个辅助小图”，下一节先把一张图的组成部分拆开。

一张图由什么组成

初学时常把 plt.title 和 ax.set_title 混着用，根子在于没有分清几个对象的层级。Matplotlib 的图形是一棵树，最外面是 Figure，里面装着一个或多个 Axes，每个 Axes 又挂着坐标轴、标题、图例和一堆数据图元。

flowchart TD
    F[Figure 整张画布] --> A1[Axes 子图]
    F --> A2[Axes 子图]
    A1 --> AX[Axis 坐标轴]
    A1 --> T[Title 标题]
    A1 --> L[Legend 图例]
    A1 --> AR[数据图元 Line2D 等]
    AX --> TK[Tick 刻度与标签]

Figure 是画布，管尺寸、分辨率、背景色和保存，它本身不画数据。Axes 是真正绘图的矩形区域，俗称子图，一个 Figure 可以并排好几个；plot、scatter、set_xlim、legend 这些方法绝大多数属于 Axes。Axis 是坐标轴对象，管刻度的位置、刻度文本、轴标签和尺度（线性或对数），它和 Axes 只差一个字母，含义却完全不同，读文档时要看清。

再往下是装饰性元素：Title 分为单图的 ax.set_title 和整张画布的 fig.suptitle；Legend 由带 label 的图元自动汇总，ax.legend() 才生成；Tick 是刻度，位置由 Locator 决定，文本由 Formatter 决定；Annotation 是带箭头的标注，用 ax.annotate 添加。它们都继承自 Artist，也就是所有可见元素的基类。理解了这一层，看报错信息里的 Axes、Axis、Line2D 就不会一头雾水。

摆好之后，标签重叠几乎必然发生。fig.tight_layout() 会根据文本占用的空间重新计算边距，多数情况下一行就够；它要和 suptitle 共存时，给 tight_layout(rect=[0, 0, 1, 0.95]) 留出顶部。若布局由 GridSpec 精细控制、不希望被自动改写，就用 fig.subplots_adjust(left=0.1, right=0.95, top=0.9, bottom=0.15) 手工留白。2.2 之后还提供了实验性的 constrained_layout，思路类似但会考虑更多元素；入门阶段掌握 tight_layout 即可。

样式、中文显示与可读性

样式决定图能不能被读懂。颜色可用单字母缩写（'r'、'b'、'k'）、十六进制（'#2b6cb0'）或颜色名（'steelblue'），透明度用 alpha。默认颜色循环在三条线以内还算清楚，到六七条时相邻颜色开始接近，此时应主动指定明度递进的颜色。如果图会被黑白打印，或读者中有色觉障碍者，就不要只靠红绿区分：给每条线配上不同线型（'-'、'--'、'-.'、':'）和标记（'o'、's'、'^'），让颜色只作辅助。标记太密会连成一片，用 markevery=5 每隔几个点画一个。

字号要成体系。可以在开头统一设 plt.rcParams['font.size'] = 10，标题 12 到 13，刻度与注释 8 到 9。字号是绝对磅值，不随画布缩放：为宽屏准备的 12 号字，缩到双栏宽度后往往看不清，定稿前要按最终尺寸预览。网格线只在需要读数时打开，ax.grid(True, linestyle=':', linewidth=0.6, alpha=0.7) 比默认实线轻得多；只关心纵轴数值时，用 axis='y' 只画横向网格。图例位置也有讲究，loc='best' 单图看着聪明，多图并排却忽左忽右，正式出图建议固定 loc='upper right'，或用 bbox_to_anchor=(1.02, 1) 放到绘图区外侧，再用 ncol=2 横排。

中文显示是中文用户遇到的第一个硬钉子。Matplotlib 的默认字体 DejaVu Sans 不含汉字，必须在 rcParams 里指定一个系统里真实存在的字体：

sans-serif 是候选列表，Matplotlib 按顺序找第一个能用的字体，把三个平台的名字都写进去，脚本换机器时就不用改。各系统的字体名并不通用：macOS 常见苹方和黑体，Windows 是微软雅黑和黑体，而精简安装的 Linux 服务器上往往一个中文字体都没有。这种情况最易被忽略：本地正常，部署后才发现全是方框。

找不到字体时，表现很固定：终端打印 findfont: Font family ['SimHei'] not found. Falling back to DejaVu Sans，图里的汉字变成空心方框，负号也可能变方框。排查分两步：先用 matplotlib.font_manager.findfont('SimHei') 看返回的是不是回退字体，再遍历 font_manager.fontManager.ttflist 的 name 字段，确认系统里有哪些中文字体名。确认缺失后，Linux 上装 fonts-noto-cjk 或文泉驿，把字体放进用户目录，再删掉 matplotlib.get_cachedir() 下的字体缓存并重启内核。若只有某张图要用特殊字体，可改用 FontProperties。

坐标轴、刻度与日期

坐标轴是读者读数的尺子，默认值经常不合适。ax.set_xlim(0, 24)、ax.set_ylim(0, 200) 明确范围，比让 Matplotlib 自己留白更可控；纵轴表示排名或深度时，用 ax.invert_yaxis() 翻转。刻度不必逐个手写，MultipleLocator(2) 每两个单位一个刻度，MaxNLocator(5) 最多放五个，避免标签挤在一起。给刻度加单位或百分比时，用 FuncFormatter 传一个转文本的函数，如 lambda v, pos: '{:.0%}'.format(v)。旋转标签用 ax.tick_params(axis='x', rotation=45, labelsize=9)，比逐个设 set_xticklabels 省事。

时间轴是最常见的麻烦。把 datetime 对象交给 plot，Matplotlib 会按日期处理，但默认格式往往过长，此时用 mdates 指定定位器与格式化器：

横轴必须传日期对象，传 '2019-01-01' 这样的字符串会被当成类别，跨月时就错位。MonthLocator、DayLocator、HourLocator 用法一致，按时间跨度选粒度。数据跨几个数量级时，用 ax.set_yscale('log') 换成对数轴，趋势和数量级差异会同时可读；对数轴不能含 0 或负值，含 0 的序列要先确认业务含义再决定是否过滤，或改用 symlog。

保存图片与服务器环境

出图最后一步是 fig.savefig('latency.png', dpi=300, bbox_inches='tight')。dpi 决定位图分辨率，屏幕预览 100 到 150 足够，印刷或投稿用 300；对 svg、pdf 这类矢量格式，dpi 只影响内嵌位图，文字和线条不受影响。bbox_inches='tight' 按实际内容裁剪白边，专治图例、轴标签被切掉一半，代价是尺寸随内容浮动，多张图需要严格等宽对齐时应改用 subplots_adjust 固定边距。

格式按用途选：png 体积小、兼容好，适合网页和文档；svg 是矢量，放大不糊，也方便继续编辑；pdf 同样矢量且能嵌入字体，适合打印和论文排版。savefig 按扩展名推断格式，也可显式写 format='svg'。保存要放在 show() 之前，并坚持用 fig.savefig 而非 plt.savefig，后者保存“当前图形”，多图时容易存错。

服务器上要让流程脱离显示器：脚本开头设 Agg 后端，结尾不调用 show()，直接保存。批量出图时每张用完就 plt.close(fig)，否则图形对象一直挂在 pyplot 的全局状态里，内存只涨不降。

几个高频的坑

第一是 show() 阻塞。脚本执行到 plt.show() 会停下等窗口关闭，放进定时任务或 Web 请求里就是挂起；服务端应只保存不显示。第二是在循环里 plt.figure() 却不关闭，几百张图后内存明显上涨，应复用画布加 ax.cla()，或每轮结束 plt.close(fig)。

第三是中文变方框，原因无非字体没装、字体名写错、缓存没刷新。第四是图例被裁，多半是 bbox_to_anchor 把图例放到画布外又没配合 bbox_inches='tight'。第五是混用 plt.xxx 和 ax.xxx，在多个子图间切换时画到错误的格子。最后是颜色，默认色环在灰度打印和色觉障碍下区分度有限，类别多时还会循环复用，重要图表应固定配色，并用线型和标记做冗余编码。

小结

Matplotlib 的难点在对象层级，而非 API 数量：Figure 是画布、Axes 是画板、Axis 是尺子，绝大多数方法调用在 Axes 上，复杂图就写 OO 接口。选图先看数据关系，布局优先用 subplots 加 tight_layout，中文显示靠 rcParams 指定真实存在的字体。保存用 fig.savefig，按用途选位图或矢量格式，服务端切到 Agg。把这些固定成模板函数，以后每张图从模板出发即可。
