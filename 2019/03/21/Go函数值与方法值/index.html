Go 函数值与方法值

本文属于《Go 语言与工程》第 47/78 篇
上一篇系列目录下一篇

在 Go 里，函数不只是可以调用的代码块，它和整数、字符串一样是一种值：可以赋给变量、作为参数、作为返回值，也可以存进 map 与结构体。方法则多了一层接收者，当我们写 obj.Method 而不加括号时，得到的同样是一个函数值，只是接收者已经被绑定进去。本文从函数值出发，依次讲清闭包捕获、方法值与方法表达式、接收者拷贝以及 nil 函数值这几个容易混淆的点，最后给出回调、选项模式、中间件与策略表的落地写法。示例基于 Go 1.12，读者只需熟悉基本的函数与方法语法。

一、函数是一等值

在 Go 里，函数不是语法上的特殊公民，而是一种普通的、可以传递的值。所谓“一等值”，意思是函数可以出现在其他值能出现的任何位置：赋给变量、作为参数传入、作为返回值传出、放进切片或 map、存进结构体字段。理解这一点，是理解后面所有内容的前提。

函数的类型只由参数和返回值决定，函数名不参与。参数的个数、顺序、类型，返回值的个数、顺序、类型，任何一项不同，都是不同的类型，赋值时编译器会直接拒绝。反过来，只要签名一致，普通函数、匿名函数、方法值就可以互相替换，它们的底层类型相同，差别只在于有没有名字、有没有绑定上下文。

上例中，IntOp 是具名函数类型，底层类型是 func(int) int。addOne 的类型是未具名的 func(int) int，可以直接赋给 IntOp 变量。这不是隐式转换，而是 Go 的可赋值性规则：当两个类型底层相同、且至少有一个不是具名类型时，可以直接赋值。若把 addOne 的参数改成 int64，哪怕函数体完全一样，也无法通过编译。签名不同，类型就不同。

函数作为返回值时，既可以返回已有的函数，也可以返回当场写出的匿名函数。上例的 pick 两种都演示了。返回函数值让“延迟决定行为”成为可能：调用方先拿到一个符合约定的函数，等到合适的时机再执行。标准库里的 http.HandlerFunc、sort.Slice 的 less 参数、filepath.Walk 的回调，都是这个思路的不同变体。

还有一点必须提前说明：函数值只能和 nil 比较，不能相互比较。f == g 这样的写法无法通过编译，因为两个闭包可能捕获了不同的环境，语言没有为“函数相等”定义有意义的语义。判断一个函数值是否为空，唯一合法的比较对象是 nil。

二、函数值与闭包

匿名函数写起来像普通函数，只是省掉了名字。一旦匿名函数引用了外层的局部变量，它就不再是“一段孤立的代码”，而是携带了环境的闭包。实现上，被捕获的变量通常会被分配到堆上，函数值内部保存指向这些变量的指针；因此闭包看到的是变量本身，而不是创建闭包那一刻的副本。

两次 inc 调用共享同一个 n，reset 也能改到它，说明这些函数值指向同一份环境。即使把 n 换成结构体字段或指针，结论也一样：捕获的是变量，读写的也是变量。闭包因此适合封装带状态的小对象。

三、方法值：把接收者绑定进去

方法的调用形式 c.Inc() 大家很熟，去掉括号写成 c.Inc，得到的是一个函数值，称为方法值（method value）。它的类型是方法签名去掉接收者后的样子：Inc 没有参数也没有返回值，所以 c.Inc 的类型是 func()。绑定的时机是表达式求值的那一刻，而不是调用的时候；值接收者在这一刻复制，指针接收者则记下地址。

inc 是指针接收者的方法值，保存的是 &c，两次调用改的是同一个对象；val 是值接收者的方法值，绑定时 c.n 为 2，副本从此固定，之后 c 再涨也影响不到它。同一个对象上，两种接收者的方法值表现出完全不同的“视角”。

方法值也受可寻址性约束。c.Inc 只是 (&c).Inc 的简写，编译器需要取得 c 的地址，因此 c 必须可寻址。Counter{}.Inc 不能编译，因为临时值没有地址；写成 (&Counter{}).Inc 才可以。map 的元素不可寻址，m["a"].Inc() 同样会报错，常见做法是先取到局部变量，改完再放回，或者让 map 直接存指针。

方法值最适合传给那些只接受无接收者函数的地方。例如把 strings.Builder 的写入方法存起来复用：

四、方法表达式

方法表达式（method expression）把接收者从“隐式绑定”改成“显式参数”。写法是 T.Method 或 (*T).Method，得到的是普通函数，第一个参数就是接收者。

值接收者的方法两种写法都合法：Greeter.Hello 直接收值，(*Greeter).Hello 收指针，调用时自动解引用。指针接收者的方法就只有指针形式，Counter.Inc 会报编译错误，必须写成 (*Counter).Inc。接收者声明成指针，方法表达式也得用指针类型。

方法表达式适合接收者到调用时才确定的场景：方法值把接收者固定了，它则把选择权留给调用者。例如一组校验规则，每次调用可以使用不同的校验器实例：

五、接收者拷贝：值接收者与指针接收者的分野

值接收者方法体里的接收者是副本，这和方法值绑定时的复制是同一件事，只是发生的时间点不同：普通调用在每次调用时复制，方法值在绑定时复制一次，后续调用复用同一份副本。指针接收者复制的只是一个地址，方法体通过地址读写原对象。

DepositWrong 无论调用多少次，acct.Balance 都停在 100；old 更说明问题：它绑定的是余额为 100 时的副本，之后把原对象改成 1000，再调用 old 也只会改那份旧副本。deposit 则捕获了 acct 的地址，加 50 直接落到原对象上。值接收者方法值经常被误认为“引用着原对象”，实际恰好相反。

不过，值接收者并不等于绝对隔离。结构体里如果有切片、map 或指针字段，复制的是这些描述符，底层数据仍然共享：

切片头包含指针、长度和容量，复制后两者指向同一个底层数组。容量足够时，append 会把元素写进共享数组，但原对象的长度仍是 0，所以从原对象看不到新元素；一旦触发扩容，新数组与原对象就彻底无关了。如果值接收者方法直接改 b.items[0]，原对象能看到，因为改的是共享数组里的元素。map 字段类似，增删键会影响原对象，给字段重新赋值则不会。值接收者是否产生副作用，要看字段是不是描述符。

选择接收者时可以遵循几条朴素规则：需要修改状态、结构体较大、或包含 sync.Mutex 之类不可复制的字段，用指针接收者；只是读取的小结构体，用值接收者更安全；同一个类型的方法尽量统一接收者形式，避免调用者猜测哪些方法会改动原值。

六、nil 函数值：最容易被忽略的零值

函数类型的零值是 nil。声明了却没有赋值的函数变量可以传递、可以比较、可以存进结构体，但一旦调用就会 panic，运行时报的是空指针解引用。错误往往在回调路径上才暴露，因此可选函数字段要判空。

if fn != nil 是最直接的防御。对于结构体里的可选钩子，还可以在构造函数里填一个空实现作为默认值，让调用方不需要判空。选哪种取决于钩子是必须提供还是可以提供：前者让构造函数返回错误，后者判空后跳过。

更隐蔽的坑在接口里。把一个 nil 函数值装进空接口，接口本身并不等于 nil：

接口值由“动态类型 + 动态值”两部分组成。这里动态类型是 func() error，动态值是 nil，类型部分非空，所以接口与 nil 比较为 false。若某个函数接收 interface{} 参数后只判断 arg == nil，就会把“装着 nil 函数的接口”当成有效值继续往下走，直到调用时才 panic。正确的做法是先做类型断言，再判断断言出来的函数是否为 nil；或者干脆让参数类型就是具体的函数类型，把问题挡在编译期。

方法值在 nil 接收者上还有一点微妙差异。指针接收者的方法值可以从 nil 指针上取得，调用时是否安全取决于方法体有没有解引用；值接收者的方法值在绑定阶段就要解引用，nil 指针会立刻 panic：

七、实际用法

函数值的用武之地，多半集中在下面四种模式里。

回调

回调把“做什么”交给调用方，排序是最朴素的例子。

选项模式

选项模式用一组 Option 函数修改配置，默认值集中在构造函数里，调用方只写关心的项。它在社区里很常见，但不是语言规定的标准写法。

中间件

中间件就是 func(http.Handler) http.Handler，每层包住下一层，顺序由组装函数决定。

策略表

策略表把分支换成查表，增加策略时只加一个键值对。

八、性能与语义

方法值会捕获接收者：值接收者把结构体复制进闭包，越大越贵；指针接收者只存地址，却会让对象存活到函数值不可达。循环里反复绑定并存进切片，等于留下许多份接收者。闭包还会让变量逃逸到堆上，可用 go build -gcflags=-m 观察；经由函数值的调用难以内联，热路径上提前绑定、循环内复用更划算。但可读性优先，不必为了“优雅”给每段逻辑都套一层闭包。

小结

函数值让行为可以像数据一样传递，前提是签名匹配；闭包捕获变量而非值，循环中要用遮蔽或参数固定当轮变量。方法值在求值时绑定接收者，值接收者复制、指针接收者共享；方法表达式把接收者变成第一个参数。nil 函数值不能调用，装进接口后也不等于 nil。把这些语义用熟，回调、选项、中间件与策略表才不会写成谜题。
