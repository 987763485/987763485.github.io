SVG 图标系统实践

图标字体用了两年，直到设计给出一套双色图标，我才承认这套方案到了该换的时候。本文记录我们从一个字体图标项目迁到 SVG 图标系统的过程：最小结构怎么搭，viewBox 和 currentColor 怎么配合，外部雪碧图在 IE 11 下怎么兜底，以及 Gulp 构建和交接规矩。适合正在维护图标字体、准备迁移的前端同学。

事故是从三个方向同时来的

第一个事故出在活动页。设计给了一套双色图标，主色跟随品牌，辅色是固定的浅灰。图标字体只能有一种颜色，color 一改，整个字形一起变。我们试过用两个字体文件叠在一起，位置差半个像素，缩放后缝隙肉眼可见。那套图标最后被切成 PNG，活动页在视网膜屏上糊成一片。

第二个事故出在缩放。列表页的图标用 font-size: 16px 控制，设计稿画在 24×24 的网格上。字体图标不是按图形边界排布的，它带着字体的上伸部和下伸部，line-height 一紧，图标就被裁掉一点。用户把页面放大到 150%，文字清楚，图标边缘却发虚——浏览器把字形当文字做亚像素渲染，路径并没有按新尺寸重新计算。我们把 -webkit-font-smoothing 翻来覆去地调，只能改善，不能根治。

第三个事故出在读屏。运营同事用 VoiceOver 检查活动页，焦点落到一个只有图标的按钮上，读出来的是一串没有意义的音节。那个字符在字体里没有语义，屏幕阅读器要么跳过，要么按字符名硬读。我们给按钮补了 aria-label，但字体图标本身仍然是一段文字，选中、复制、翻译插件都会把它当内容处理。

三个问题叠在一起，说明这不是调样式能解决的。字体方案把图形塞进了文字的模型里，彩色、几何精度和无障碍三件事，它天生就有一件做不好。

为什么最后选了 SVG

SVG 是矢量格式，图形由路径描述，缩放时由浏览器重新计算，不存在放大发虚的问题。它的颜色由 fill 和 stroke 控制，一个图标可以有多条路径、多种颜色，currentColor 还能让它跟着父级文字颜色走。作为 DOM 的一部分，它可以被 aria-hidden 隐藏，也可以带上标题和角色，读屏能正确理解。它也不依赖字体文件加载，不会再出现字体没下来时满屏方框的窗口期。

代价也有：每个图标都是一段标记，页面里用得多，HTML 会变长；外部引用在 IE 下不工作，需要垫片；设计稿里的图标如果不按统一网格画，合并后大小不一。这些问题都能在工程侧解决，比改字体的字形要现实得多。

图标字体怎么制作、怎么引入，另有专文，这里不再展开。本文只讨论换成 SVG 之后，我们怎么把结构、构建和兼容性搭起来。

最小结构：一个 symbol，一个 use

所有图标都定义在一个隐藏的 <svg> 里，每个图标是一个 <symbol>。symbol 不会直接渲染，只提供图形模板，id 是引用名。页面里要显示图标的地方，再放一个小的 <svg>，用 <use> 指向那个 id。

xlink 命名空间在当年还得写。不加前缀的 href 在新浏览器里能用，但 IE 11 只认 xlink:href，团队统一写带前缀的版本，省得在一堆页面里找差异。HTML5 解析器能识别 xlink，把它写在 <svg> 根节点上就够了，不必每个 use 重复声明。

隐藏定义块用 display: none，它不占布局，也不会被读屏读到。定义块里只放 symbol，不要混入需要直接显示的图形。定义块放在 <body> 开头，页面里的引用在其后解析，不会出现先引用、后定义造成的闪烁。

viewBox 与尺寸：CSS 说了算

viewBox="0 0 24 24" 定义了图标内部的坐标系：原点在左上，宽高各 24 个单位。它和渲染尺寸是两件事，width 和 height 决定 <svg> 在页面上占多大，viewBox 决定图形怎么映射进这个尺寸。没有 viewBox 时，<svg> 不会自动缩放，CSS 把宽高改成 32px，图形还是按原始单位画，超出的部分被裁掉。这也是合并图标时最容易丢的属性，构建时必须明确保留。

preserveAspectRatio 控制映射规则，默认值是 xMidYMid meet：等比缩放，图形完整放进视口，多余空间平均分在两侧。改成 none 就会横向和纵向各自拉伸，图标会被压扁，只有确实需要填满非等比容器时才用。我们希望图标保持形状，所以全部使用默认值，不写这一行。

24×24 网格的好处是对齐。设计在 24 的坐标里画，整数坐标落在像素边界上，2px 描边放在 10 到 12 之间，缩小到 16px 时按比例映射，边缘不至于糊。图标的视觉重心也要照顾：同样的外框，圆形看起来会比方形小，设计通常会把圆放大半格。我们在验收时把图标排成一行，在 16、24、32 三个尺寸下看，不齐的退回重画。

图标与文字并排时，<svg> 默认按基线对齐，底部会沉下去一点。给 .icon 加 vertical-align: -0.125em，让它略微下移，和文字的中线对齐。这个值不是固定的，字号变化时要跟着看，但比 vertical-align: middle 稳定。

currentColor 与多色图标

单色图标最省事的写法，是在 symbol 的路径上写 fill="currentColor"。它取当前元素的 color 值，图标放在按钮里就跟随按钮文字色，放在导航里跟随链接色，悬停时只要改 color，图标自动变。这比给每种颜色写一个类省事，也让图标天然适应主题。

双色图标要拆成两条路径，分别控制。2016 年可用的是类名和 CSS 变量两条路。前者兼容性最好：给路径加 icon-primary 和 icon-secondary 两个类，在样式表里按图标或按业务覆盖 fill。

CSS 变量在当年的 Chrome 和 Safari 上已经能用，写法更灵活：fill: var(--icon-primary, #1f8ceb)，换主题时只改变量。但 IE 11 完全不支持自定义属性，var() 会让整条声明失效，所以变量方案必须留一份类名回退，不能只写变量。我们最终没在图标层用变量，原因就是回退代码比省下的重复更多。

IE 11 还有一个细节：外部样式表里的 fill 能作用到内联 <use> 的图形上，但作用不到外部文件里的内容，外部引用要靠垫片内联之后才生效。currentColor 本身在 IE 11 的内联 SVG 里是正常的，这条可以放心。

单色图标直接在路径上写 fill="currentColor"，双色图标在路径上写各自的类名。这样即使 CSS 加载失败，图标至少还是黑的，不会整块消失。

用 Gulp 把图标合并起来

构建顺序是关键：先清理，再合并，最后落到模板目录。我们用 Gulp 3.9 配 gulp-svgo 和 gulp-svgstore，跑在 Node 6 上。源文件按业务放在 src/icons/ 下，文件名就是图标名，构建时统一加前缀。

removeDimensions 删掉根节点的 width 和 height，让 CSS 决定尺寸；removeViewBox: false 必须显式写，否则优化器会把 viewBox 当冗余删掉，图标再也缩放不了。prefix 统一加前缀，inlineSvg: true 去掉 XML 声明，产物可以直接嵌进模板。

合并前还要过一道检查：每个文件必须有 viewBox，不能带位图 <image>，id 不能冲突。我们写了一个几十行的小任务，读文件名和 viewBox 生成清单，缺属性就让构建失败。产物不进版本库，CI 里生成一次，部署包带上即可。

命名、目录和交接规矩

图标 ID 用 icon- 加业务名，比如 icon-search、icon-order-detail，全小写，单词之间用连字符。目录按业务分组：src/icons/common/、src/icons/trade/、src/icons/user/，构建时递归读取。分组只影响源文件管理，合并后的 ID 仍然全局唯一，所以文件名要带业务含义，不能让三个目录里都放一个 edit.svg。

重复图标是体积失控的主要原因。同一个“关闭”，三个业务各画一版，角度和线宽都不一样，合并后就是三份路径。我们每月导一次清单，按图形哈希和人工目测两条线查重，能合并的合并，不能合并的注明差异。清单里还有一列“使用位置”，写清楚哪个页面在用，删除前先搜代码。

最重要的规矩是：设计师不要直接把文件丢进 src/icons/。听起来不近人情，但这是被坑出来的。设计导出的 SVG 常带 Sketch 的图层名、id、内联样式和隐藏图层，viewBox 可能是 0 0 100 100，描边被转成了填充，直接合并会让整套图标的网格乱掉。我们的流程是设计把图标放进共享目录并附上名称和用途，前端按 24×24 网格检查、清理、改名，再提交合并请求。交接文档里有一张对应表，产品和设计都能查：

可访问性：先判断图标是不是装饰

SVG 进了 DOM，读屏就会把它当内容。第一步不是加属性，而是判断这个图标有没有独立语义。绝大多数图标是装饰：搜索按钮旁的放大镜、菜单项前的小图标、状态标签旁的圆点，文字已经说清楚了，这时给 <svg> 加 aria-hidden="true"，让辅助技术跳过。IE 11 里 SVG 默认可聚焦，还要补 focusable="false"，否则 Tab 会停在图标上。

有语义的图标是另一类：没有文字的关闭按钮、只有图标的社交链接。图标本身就是内容，不能隐藏。做法是给可聚焦的父元素一个可读名称，比如 <button aria-label="关闭">，图标仍然 aria-hidden。如果图标独立展示，比如状态图例，就给 <svg> 加 role="img" 和 aria-labelledby，指向内部的 <title>。

<title> 放在 symbol 里会被所有引用共享，读屏可能重复朗读，所以我们把它放在使用处，按场景写不同文案。还有一条底线：不要用图标替代按钮文字。图标含义依赖约定，新用户猜不出，读屏用户更是如此。能用“文字 + 图标”的地方，不要只留图标。

加载策略与最后的选型

首屏内联，其余延后

我们把图标分成两批。首屏用到的十几个，构建时直接内联进页面模板，随 HTML 一起到达，不额外发请求，也不会出现图标晚一步才出现的跳动。剩下的图标合并成一个 icons.svg，由浏览器按需缓存；页面里通过外部 use 引用，IE 下交给垫片。两批图标用两份源文件清单维护，构建任务分别输出内联版和外部版。

版本号只做一件事：文件内容变了就换查询串或文件名，让缓存失效，缓存头的细节不在本文范围。
