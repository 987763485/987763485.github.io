Photoshop 切图与标注协作流程

接过设计稿、切完图、还原好页面，被设计一句”这阴影没了””这块比稿子大一圈”打回来重切——这个循环我前一年走得太多，把返工原因一条条记下来才发现，真正吃时间的不是 Photoshop 里那几下鼠标，而是切图和标注从头到尾没有规矩。这篇写我这两年和一个视觉同学反复磨出来的一套协作流程，给那种已经会拉切片、却每次交接都要来回问十几遍”这个字号多少”的前端。

先把矛盾摆清楚

协作不顺的根子在一个绕不开的事实：设计稿是像素，页面是流体。设计师给的是画布上一块固定、边到边的像素，我们的页面却要在宽度不同的屏幕上被拉来拽去，这个错位不会因为谁更努力就消失，只能靠规矩管理。最怕把它当成”你多担待点”的人情问题——你问一句”这个圆角几像素”，对方正赶另一张稿，隔两小时回你一个模糊的数，你照着改、改错还得再来一轮。一次交接攒二三十条这种小问题，一个下午就没了，损耗还是双份：你的实现时间，加上对方被打断后重新进入状态的时间。

所以我对标注的定位很明确：它不为好看、不走形式，唯一目的是减少返工。合格的标注该让前端不用发问就能落地——尺寸、字号、行高、字色、透明度、内外边距、圆角、阴影参数一旦写死在交付物里，来回问就没必要；凡是让前端”看着办”的地方，都是下一次返工的种子。还有一点：别指望设计替你想还原的事，他给的默认是给”人看”的一张图，不是给”机器用”的一组资源，切图命名、格式、倍图、清单表都得前端反过来推动设计，因为只有我们知道部署时 Linux 大小写敏感、JPEG 在渐变上会出带状伪影。

Photoshop CC 2015 的几条出图路径

CC 2015 这一代（含 2015.5）出图大致三条路，选错后面全乱。

第一条”文件 > 导出 > 导出为…”，一次性把选中几层导成指定格式，界面里选 PNG-8／PNG-24／JPEG、给倍率、看预览；缺点是不保留”这是一组切片”的概念，改版得重新选层重导，没有增量，零散图标走它没问题。

第二条是切片：选中普通图层走”图层 > 新建基于图层的切片”，图层多大切片就多大；建好后选中它，用”存储为 Web 所用格式（旧版）”导出——这个”旧版”是 Photoshop 自己的叫法，2015 年它仍是控制单切片格式、质量、透明最稳的路。切片的好处是把”这块要出图”固化进了 PSD，改版时切片还在原位，重导便宜。

第三条我最推荐：”生成 > 图像资源”，先在”生成”菜单勾上，之后完全靠图层命名驱动出图：图层名写成 png home-banner.png 就直接导成对应 png，名字前加 #（如 #icon-close）基于该层生成切片，带 @2x 的额外产出两倍图。资源随画布改动实时刷新，命名即产物，前端拿到的就是一个自动长出来的文件夹。

有个坑提前说：智能对象放大导出会糊。它存的是原始内容，放到超过原始分辨率再导就是拉大原图、不是矢量重绘。会被放大用的，让设计在源里给够像素，或栅格化到目标尺寸再切。

命名规范：省的是部署时的命

命名最容易埋雷，雷还往往炸在生产环境。规矩先写死：切图文件名只用小写字母、数字和连字符，禁止中文、禁止空格。中文和空格进 URL 会被转义成一长串 %，日志难读；真正狠的是大小写——本地 Windows 或 Mac 不分大小写，Banner.png 和 banner.png 是同一个文件，页面跑得好好的，一部署到 Linux 引用写成小写就 404，还常只在某条懒加载路径上炸。统一小写加连字符，等于把这类只在服务器上现形的 bug 提前掐死。

结构上用”模块名-用途-状态”三段：首页播放按钮悬停态叫 home-banner-play-hover，默认态 home-banner-play。从文件名就知道属于哪个模块、状态靠后缀区分，不用翻 PSD 猜用途。反例是有人图省事叫 btn1.png、btn2.png，接手的人分不清哪个是哪个状态，最后还是回头问设计——命名没起作用等于没命名。

改版时最容易漏的是切图版本号与替换流程。旧图不能靠”覆盖同名文件”处理，浏览器有缓存，同名覆盖后测试环境还是一片旧图，你会误以为没生效。做法是引用后面挂 ?v=日期，改版时往前推；大改版让设计重新导出、我们核对清单表逐个替换，旧图不留在目录里，免得和 1x／@2x 混出歧义。

交付物清单：一次交接要给全的东西

我不接受”发我个 PSD 我自己看着切”这种交接。一次合格交付要一次给全四样，缺一我都先退回补齐再动工。

第一样是切图清单表，把所有要出的图列成可核对的表，每行一个产物：

文件名 尺寸 格式 用途 是否可拉伸 是否九宫格
home-banner-play 48x48 PNG-24 播放按钮默认态 否 否
common-card-bg 自适应 PNG-8 卡片底 是 是

其中”是否可拉伸””是否九宫格”两列最关键，它告诉我这张图能不能靠 CSS 拉、还是得走九宫格，免得我拿一张带圆角阴影的图硬 background-size 拉变形、四角全糊。第二样是标注表，逐元素给死值：宽高、字号、行高、字色（十六进制）、透明度、内外边距、圆角、阴影参数，有了它就不用再问任何数。第三样是 1x 和 @2x 两个目录分开摆，同名同路径只靠目录区分倍率。第四样是色板和常用渐变：色板存成 .aco 我能导进 Photoshop 直接取色，渐变给源参数而不是导出图，因为渐变我倾向用 CSS 复现。

格式怎么选：讲原理不给口诀

那种”图标用 PNG、照片用 JPG”的口诀太粗，切错照样翻车，我按原理给几条判断线。

带透明的 logo 和图标走 PNG-8 或 PNG-24，都保 alpha。纯色或有限色用 PNG-8 更小，但 PNG-8 的透明在早年实现里有半透明边缘的兼容毛病，凡边缘带羽化我一律退回 PNG-24，宁大也要干净。照片走 JPEG，让设计在”存储为 Web 所用格式”里盯两件事：一是品质滑条，不是越高越好，往下拉是拿可见的块状失真换体积，位置得边看边定；二是有没有去掉无损元数据，PSD 导出的 JPEG 常带版权、GPS，白占体积还泄露设计机信息。

渐变和带噪点的图最容易在 JPEG 上出带状伪影，一圈圈色带在平滑渐变上格外扎眼，高级底图切完像劣化了，所以渐变优先给 PNG，或直接”这块用 CSS 复现、根本不出图”。至于尺寸很小、纯色或简单图形的小图（一组箭头、几个状态点），要不要单独出得算账：HTTP/1.1 下一个域名并发连接有限，几十张小图就是几十次请求。要么内联 base64，要么合进雪碧图。之前那篇讲雪碧图收益的文章我不重复推导，只补切图侧怎么配合：设计一次给来的全是零碎小图时优先合并而不是内联，因为 base64 让体积比原图胖约三分之一又没法单独缓存；雪碧图横排还是纵排由我前端定，设计只要保证子图不重叠、留够间距就行。

适配与还原：1x、2x 与九宫格

2015 到 2016 这一年移动端主流还是靠 DPR 选倍图，CSS 用 -webkit-device-pixel-ratio 分别命中 1x、2x、3x：

这里 background-size 一定按逻辑像素写死，别跟图的实际像素走，否则 @2x 会被撑成两倍大。也有团队用 JS 读 devicePixelRatio 运行时换 src，适合首屏大图按需加载，但要防它在无 JS 或慢设备上退回默认图。一个真实的坑是 Android 4.x 那档 WebView 对 DPR 取整不一致：物理是 2.x 倍，报出来却在 1 和 2 之间乱跳，选图就错，所以关键大图我会加一层兜底。至于 srcset，规范当时已有但浏览器支持还不齐，我不敢当唯一手段。

桌面端可拉伸的底图用九宫格，两条路：border-image 省事，一张图切九块靠 CSS 铺，但渲染细节早年各引擎参差、边角偶尔差一像素；三段式（切成上中下、中间可拉伸）多几行 CSS，可维护性反而更好，出问题一眼能定位。我的偏好是简单容器用三段式、形状复杂再上 border-image，并在清单表里把这张图标成”九宫格”，让设计按安全区出图，别把内容画到会拉伸的区域。

标注到底怎么落

2016 年初在线协作标注平台还很新，很多团队——包括我们——还在用最土也最稳的方式：设计把标注导出成图片，或从 Photoshop 存一个带尺寸线的 HTML 页面，连着 PSD、切图文件夹打包发给前端；前端拿到后把标注表的值拷进项目 wiki 对应页面，实现对 wiki 落地而不是每次翻那个大 PSD。这么做丑，但标注进了 wiki 就成团队公共事实，产品和测试走查看同一份。纪律是数值只抄一份、以标注表为准，wiki 不重复写像素，改稿先改源头再同步，免得文档和实际各说各话。

走查环节：把返工压到一次

还原完不等于完事，得走一次设计走查，它组织得好不好直接决定返工是一次还是三五次。走查前前端先备好两样：一个可访问的测试地址（设计和产品点得开，不是截图糊弄），一份按页面组织的改动说明（每页动了什么、哪几块切图重出、哪几块纯 CSS 复现）。

走查记录我固定几个字段，不散在聊天记录里：

模块 设计稿版本 差异描述 是否需切图重出
首页轮播 v2 0108 指示点间距偏大 2px 否
商品卡片 v2 0108 右下角阴影缺失 是

最后那列”是否需切图重出”把问题分成”改 CSS 就行”和”得回设计重新导出”两类，前者我当场消化，后者才惊动设计。二次返工的判定看归因：差异根因若是我没按标注表落地，那是我一次还原没做到位，不该再占设计时间；只有标注表缺值、或设计稿走查时改了参数，才算需要设计参与的二次返工，并回写进标注表补上那个当初没给的数。

两次让我改规范的事故

规范是被事故逼出来的。

一次是导出后阴影被裁：稿里卡片投影明明在，切出来贴页面上四周少一圈。查下去是 PSD 里投影加在一个带”效果”的图层上、这层没栅格化，走”基于图层切片”时切片框按图层自身像素边界取，而效果是渲染期才扩散出去的，根本没把阴影圈进来。修法是导出这类带效果的图前先栅格化，或把切片框外扩到覆盖阴影。规范因此加了一条：挂投影、外发光这类效果的切图，导出前必须确认切片覆盖到效果范围。

一次更隐蔽：”切图尺寸明明对、页面里看着偏大”。每张图宽高和标注表一字不差，整体就是一圈大。根因在画法：设计按 720px 宽画稿，我们实现按 360 逻辑像素走，同一张 @2x 图我以为二倍按一半放，它其实被当成等比，于是一路偏大。这不是谁粗心，是”稿子基准宽度”从没约定过。为它钉死一条：设计稿一律按逻辑像素尺寸出，需要高分辨率靠图层名的 @2x 前缀解决。这条加进去后，尺寸类返工基本归零。

前端-设计交接 checklist

最后把这套流程压成一张能打勾的单子，交接前对着核一遍，缺项不进实现。

  • 切图走”生成 > 图像资源”，图层命名按小写加连字符、模块-用途-状态三段
  • 切图清单表齐全，可拉伸与九宫格两列已标注
  • 标注表覆盖全部元素，字号、行高、字色、透明度、边距、圆角、阴影参数无空缺
  • 智能对象已确认不会被放大导出，必要处已栅格化
  • 带投影、发光效果的切图已确认切片覆盖到效果范围
  • 格式按原理选过：透明图标走 PNG、照片走 JPEG 且已去无损元数据、渐变不出 JPEG
  • 小图合并策略已定，雪碧图排布方向由前端确认
  • 1x 与 @2x 目录分开，同路径同名，倍图替换有规律
  • 设计稿基准宽度约定为逻辑像素，高分辨率靠 @2x 前缀
  • 色板 .aco 与渐变源参数一并交付
