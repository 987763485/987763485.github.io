可视化图表库 ECharts 入门

十二张图，后十张是白的

八月中旬，运营数据看板从四张图扩到十二张，按业务线分成三个页签。上线当天下午，运营反馈”后面两个页签打开是白的”，第一个页签一切正常。

我们本地打开，切页签，果然：第二、第三个页签里的图表容器有高度，图却画不出来；控制台里一行警告，大意是拿不到容器的宽高。原因不复杂：页签用的是 display: none 切换，图表在页面初始化时就全部 init 了，隐藏容器的宽度是 0，画布被初始化成 0×0，之后即使容器显示出来，画布也不会自己长回去。

修法有两种。一种是把 init 推迟到页签第一次显示时；另一种是初始化时给死宽高，显示后再 resize。我们选了前者，因为它顺带解决了另一个问题：十二张图里，用户可能只看其中两张，没必要一进页面就全画出来。

第一版修法其实不是这个。我们图快，在切页签之后 setTimeout 两百毫秒再 resize，本地测试全绿。上线后偶发仍然白屏，因为网慢的时候两百毫秒不够图表库完成初始化，resize 调在了一个还不存在的实例上。定时器猜时间这件事，在本地永远猜得准，在线上永远猜不准。

pending 这个名字起得不好，它装的其实是已经建好的实例，不是待办。但那段代码我们用了一年多没改，因为改名的收益实在比不上风险。

最小的一张折线图

ECharts 3.x 的用法就三步：准备一个有宽高的容器，init，setOption。没有构建工具也能跑，一个 script 标签引进来即可。

几个参数值得先认识。tooltip.trigger: 'axis' 让鼠标在横轴附近移动时同时显示这一列的所有系列，比逐点悬停好用；legend.data 要和系列名对上，对不上就不显示图例；grid 控制绘图区四周留白，不设的话默认值在窄屏上会把轴标签挤掉。

容器高度必须给死。给百分比高度时，父元素也得有确定高度，否则一路算下来还是 0。这是图表”有数据但看不见”最常见的原因，和页签那个坑是同一个根。

数据是异步来的

真实看板的数据不会写在页面里，都是请求回来的。这里有一个很容易省错的地方：请求发出到数据回来之间，图表区域是空的，用户分不清”还在加载”和”本来就是零”。

失败分支比成功分支重要。空图配一个零值的坐标轴，传达的信息是”这段时间没有订单”，不是”没加载出来”。这两件事在运营眼里差别巨大，我们因为一张空图被问过一次”昨天是不是系统坏了”。后来所有图表都改成：成功才画，失败就显示一行文字和重试按钮。

option 的三个层级

刚开始我们总在 series 里找坐标轴配置，找不到就以为版本不支持。其实 option 分三层：

  • 顶层：tooltip、legend、grid、color、animation，管整张图。
  • 坐标轴层：xAxis、yAxis，管刻度和网格线。它们可以是对象，也可以是数组；双 Y 轴就要写数组。
  • 系列层：series 里的每一项，管一种图形和它自己的数据。

颜色也有优先级：系列里写 itemStyle.color 会盖掉顶层的 color 数组。我们有一次给每个系列单独设了颜色，后来换主题，顶层怎么改都不生效，查了半天才发现是系列里写死了。

两个细节。yAxis 写成数组之后，系列默认还是用第 0 根轴，转化率那根线必须显式写 yAxisIndex: 1，漏了就会出现”线怎么贴着底”的假象。第二根轴建议设 max: 100，否则 ECharts 会按数据自动缩放，百分之五的波动被放大成半屏，看着像出了大事。

setOption 是合并，不是替换

第二个坑比页签那个隐蔽。看板支持在”按天”和”按小时”之间切换，我们图省事，每次都 setOption 一份新配置，以为旧的自然会被替换。结果切回”按天”时，图上多出一条按小时的线，图例里却没有它的名字。

原因是 setOption 默认按合并处理：同名属性覆盖，没提到的属性保留，series 数组按索引合并。新配置只有两个系列，旧配置的第三个系列就留在了数组里。

resize 不会自己发生

窗口大小变了，图表不会跟着变，得手动调 chart.resize()。这个话题在讲图表库时经常被一句带过，实际用起来，漏掉的后果比想象中严重：容器变窄，画布还是旧宽度，右侧的内容被裁掉，用户以为数据少了。

150 毫秒是自己拍的。拖拽窗口时 resize 触发得非常密，不防抖会把主线程占满，图表一顿一顿。页签切换也要 resize，那次页签空白的问题修好之后，我们又漏了这一步：图表是在隐藏时按 0 宽初始化的场景没有了，但从窄容器切到宽容器，还是得手动调一次。

销毁这件事，页面上看不出来

单页应用里图表最容易漏的是销毁。每次进入报表页都 init 一次，离开时不处理，DOM 被移除了，ECharts 实例还挂在内存里，里面存着数据、事件和画布。来回切十几次，内存曲线就上去了。

dispose 会解绑事件、释放画布，之后这个实例不能再用；clear 只是清掉内容，实例还在。这两个方法名字像，用途完全不同，我们混用过一次，页面切回来图表是空的，因为实例被 dispose 了却还拿着旧引用。

还有一个更常见的重复初始化问题：同一个容器 init 两次，第二个实例会覆盖第一个，第一个就泄漏了。ECharts 3 提供了 getInstanceByDom，可以先把已有的拿回来：

时间轴别直接塞字符串

折线图的横轴用 category 时，数据点按顺序排，标签写什么就显示什么，间隔均匀。这在”周一到周五”这种场景够用，但换成真实时间就会骗人：周五到周一之间隔了两天，图上还是一格。

饼图超过八块就别画了

运营很喜欢饼图，因为它看起来像”占比”。可十二个业务线塞进一个饼，标签互相压，颜色分不清，图例排了三行。我们做过一版，运营自己都说不清哪块是哪个。

处理顺序是这样的：

  1. 先按数值排序，只画前七块，剩下的合并成”其他”。
  2. 标签只显示百分比，名字交给图例；或者反过来，别两头都写。
  3. 打开 avoidLabelOverlap，让库自己挪一挪。

饼图的适用范围本来就很窄：它适合展示”几块加起来是一百”的构成，不适合比较相近的数值，也不适合看趋势。两块差不多大的扇形，人的眼睛分不出谁大。要比较，用横向条形图；要看变化，用折线。我们把这条写进了图表选型规范，运营提需求时先按目的选图，不再默认”画个饼”。

数据一多，先关动画和点

订单趋势图接了半年的数据，两万多个点，第一版打开要卡两三秒，鼠标移动时 tooltip 跟不上。处理顺序是这样的：

  1. 关掉数据点标记：showSymbol: false。两万个圆点画出来既慢又没有意义。
  2. 关掉初始动画：animation: false。入场动画对趋势图没有信息量，反而拖慢首屏。
  3. 降低数据密度。这一步不在 ECharts 里做，是让后端按小时聚合；前端拿到两千个点，图看起来一样，渲染快一个数量级。

animation 要放在顶层也行，写在系列里只影响这个系列。我们的看板统一在顶层关，因为十二张图没有一张需要入场动画。

图再准，也没法同时展示半年的走势和某一天的尖峰。dataZoom 把缩放交给用户，比自己加一排”最近七天/三十天”的按钮省事：

inside 管滚轮和触控板的缩放，slider 给一根可以拖的条，两个都开，用户各取所需。dataView 会弹出一个只读的数据面板，正好补上前面说的”图表之外的通路”；它不能替代页面里的数据表，但临时查一个数够用。saveAsImage 在移动端会把图导出成图片，运营做周报时很爱用，唯一要注意的是导出的是当前画布，缩放过的话只导出可见的那一段。

图表是画出来的，读屏读不到

ECharts 3 默认用 canvas 画图，画布里的文字对读屏软件是不存在的。这不是 ECharts 的缺陷，是 canvas 的共性。运营团队里有一位同事用读屏，第一版看板对他等于空白。

能做的补救不多：容器上加 aria-label 说明这是什么图，旁边提供一个”查看数据表”的开关，点开渲染一张普通 HTML 表格。我们只给最常用的两张图做了表格视图，剩下的在图下面用一句话概括结论，比如”本周订单量比上周上升 12%”。

这件事让我改了一个习惯：图表不是数据的唯一出口，任何时候都得有一条文字或表格的通路，给读屏、给截图、给打印。

移动端还有一点：tooltip 在触屏上是点按触发，手指会挡住数据点本身。我们的做法是把 tooltip.position 固定在图上方，或者干脆在移动端关掉 tooltip，直接在柱子上标数值。看板在手机上只有一个场景——运营在外面看一眼有没有异常，不需要精确读数，少一层交互反而清楚。

什么时候不用图表库

不是所有数据都值得画图。一个数字能说清的事，写成大字号文本比画一圈仪表盘清楚；三五个数的对比，用 HTML 的条形块就够，不必引入几百 KB 的库。

我们的判断很简单：需要坐标轴、需要缩放、需要多种图形叠在一起，才用 ECharts；只是”这个月比上月多”这种结论，用一个数字加一句同比就够了。库是工具，不是页面上的装饰。

现象 先查哪里
容器有高度，图是白的 初始化时容器是否隐藏、宽高是否为 0
切数据后旧系列还在 setOption 合并语义，考虑第二个参数 true
窗口变小，图被裁 有没有调 resize
切页签回来图变空 实例是否被 dispose、有没有重复 init
时间点间距不对 xAxis 是否该用 type: ‘time’
两万个点卡顿 showSymbol、animation、数据聚合
读屏读不出图 加 aria-label 与数据表兜底
图例不显示 legend.data 与系列 name 是否一致

图表库能省掉坐标换算、图例交互、tooltip 定位这些细活，但省不掉对容器、生命周期和数据形态的负责。那十二张图后来稳定跑了很久，真正修过的 bug 里，没有一个是图表类型选错了，全是容器、合并、销毁这些外围的事。
