动态规划入门：背包问题

本文属于《算法与数据结构》第 12/13 篇
上一篇系列目录下一篇

这个月的双十二，笔者帮朋友凑了一张满减券，又在给测试组选开发机时卡了一次预算。两件事看起来毫不相干，背后却是同一个模型：容量有限，每件东西只能拿一次，怎样组合才最划算。本文从这两个生活场景出发，讲清 0-1 背包的状态定义、填表过程和一维优化，再顺带把完全背包、方案计数和路径还原串起来。读者只需要会写基本的 JavaScript 循环，不需要动态规划基础。

从一张预算表说起

先看选机器。测试组要添置几台开发机，总预算三万元，候选有四种配置：甲单价一万二，跑压测的综合评分 70；乙单价一万，评分 62；丙单价八千，评分 48；丁单价六千，评分 33。按”每块钱买多少分”排序，甲最划算，先买两台甲、再买一台丁，花掉三万，总分 173；改成一甲一乙一丙，同样花三万，总分 180。

凑单也是同样的结构。优惠券要求满 300 元，购物车里每件商品的价格和”想要程度”都不同，我们既不想为了凑单买没用的东西，又不想浪费已经看中的商品。凭直觉先放最想要的那件，往往会把预算占掉一大块，剩下的小件塞不进去，最后总额差几十块，券用不上。

两件事都有固定容量、一组带重量和价值的物品，且每件最多选一次。抽象成 0-1 背包：n 件物品、容量 W，求总重不超 W 的最大价值。”0-1”指每件只能选零次或一次。

用状态把问题说清楚

动态规划的第一步不是写循环，而是定义一张表。设 dp[i][j] 表示”只考虑前 i 件物品、容量为 j 时能取得的最大价值”。这句话里有两个细节需要抠清楚。

第一，”前 i 件”是一个前缀范围，不是”恰好选了第 i 件”。也就是说，dp[i][j] 的最优方案里，第 i 件物品可能在，也可能不在。把范围限定成前缀，是为了让问题可以按物品一件一件地扩张，后面的状态只依赖前面的状态。

第二，j 是”可用容量的上限”，不是”必须用掉的容量”。容量为 j 时，允许实际用量小于 j。这一点在初始化时会带来一个很容易踩的坑，后文单独讲。

有了定义，考虑第 i 件物品时只有两种决策。不选它，问题退化成”前 i-1 件物品、容量 j”，价值是 dp[i-1][j]。选它，就要先确认它的重量 w[i] 不超过 j，然后把它占用的重量从容量里扣掉，剩下的容量留给前 i-1 件物品，价值是 dp[i-1][j - w[i]] + v[i]。两者取较大值，就是状态转移方程：

选第 i 件后用 i-1，是因为它只有一件，不能重复选；容量减去 w[i]，是因为重量会占用后续空间；外层取 max，是因为两种决策覆盖了全部情况。

边界 dp[0][j] = 0，答案是 dp[n][W]。下标写反成 dp[W][n] 会越界。

为什么贪心不行

回到预算表的例子，再看一个更小的反例。容量是 10，有三件物品：甲重 6、价值 12，乙重 5、价值 9，丙重 5、价值 9。按单位价值排序，甲是 2，乙和丙都是 1.8，贪心先拿甲，容量只剩 4，乙和丙都塞不进去，总价值 12。而最优解是乙加丙，总价值 18，重量正好 10。

问题出在贪心只看当下性价比，没给后面留余地。甲的单位价值最高，却占掉六成容量，把能拼起来的乙丙挤掉。选不选甲会改变后续空间，这种耦合无法靠一次排序解决。用动态规划的说法，贪心只走一条路径，状态转移把所有分支都保留下来，最后在完整的表里取最大值。

若物品可切分，按单位价值排序确实最优，那是分数背包；整件选择的 0-1 背包没有这个性质。也正因如此，0-1 背包没有多项式时间的精确解法，后面的 O(nW) 只是把容量当作数值规模来看的伪多项式算法。

一维滚动数组：为什么容量要逆序

二维表虽然直观，但空间是 O(nW)。观察转移方程会发现，第 i 行只用到第 i-1 行，更早的行不会再被读取，所以完全可以把两行压成一行。设 dp[j] 表示”当前处理到的物品范围内，容量 j 的最大价值”，在开始处理第 i 件物品之前，这个数组里存的其实是上一行的结果。

关键在于内层为什么必须逆序。假设只有一件物品，重量 2、价值 3，容量 4，初始 dp 全是 0。如果正序遍历，容量 2 时把 dp[2] 更新成 3，等到容量 4 时读 dp[2]，读到的已经是本件物品刚写进去的 3，于是 dp[4] 变成 6。这相当于同一件物品被拿了两次，0-1 背包悄悄变成了完全背包。

容量 j 正序更新后的 dp[j] 逆序更新后的 dp[j]
0 0 0
1 0 0
2 3 3
3 3 3
4 6 3

逆序时，容量 4 先算，读到的 dp[2] 还是初始的 0，更新成 3；之后容量 2 才算，不会反过来影响容量 4。每一步用到的 dp[j - w] 都位于左侧，逆序遍历保证左侧还没被本轮修改，读到的一定是上一行的值。

滚动数组把空间降到 O(W)，但也丢掉了每一行的历史，只能得到最大价值，无法直接还原选了哪些物品。

完全背包：把逆序改成正序

完全背包允许每件物品拿任意多次，现实中的例子是硬币凑数、原料切割、可重复购买的授权。二维状态仍然可以写成 dp[i][j]，表示前 i 种物品、容量 j 的最大价值，但转移方程里选第 i 件之后，剩余问题仍然可以使用第 i 件：

注意第二项的下标是 i 而不是 i-1。这是两种背包在方程层面唯一的差别，却决定了它们完全不同的遍历方式。在一维数组里，完全背包的内层容量要从小到大正序遍历，因为我们在更新 dp[j] 时，恰恰希望 dp[j - w] 已经包含了本件物品的若干次选择。前面演示过，正序会让一件物品被重复拿，那正是完全背包想要的效果。

循环的嵌套顺序在完全背包里还有一层容易被忽略的含义。物品在外层、容量在内层，得到的是组合数：顺序不同的拿法被视为同一种。容量在外层、物品在内层，得到的是排列数。以面额 1 和 2 凑出 3 为例，前者只数出 1+1+1 和 1+2 两种，后者会把 2+1 也算一种，共三种。求最大值时两种顺序结果相同，求方案数时就必须先想清楚”1+2 和 2+1 算不算同一种”，再决定谁在外面。

初始化语义：恰好装满与至多容量

前面一直默认 dp 全初始化为 0，这对应的是”总重量不超过容量”的语义：容量用不完没关系，空着的部分不算违反约束。如果把题意改成”必须恰好装满”，初始化就要换一套写法：dp[0] = 0，其余容量全部设为 -Infinity。

道理不复杂。没有物品时，只有容量 0 能被”恰好装满”，方案价值是 0；容量大于 0 的状态根本不存在，用负无穷标记成不可达。转移时负无穷加上任何价值仍是负无穷，不会污染最大值，最后 dp[capacity] 如果还是负无穷，就说明无解。二维写法同理，第 0 行只有 dp[0][0] 是 0。

这是最高频的错误：题目要求恰好装满，代码却全初始化为 0，等于把”没装满”当成了合法方案，答案偏大而且隐蔽。判断方法很简单：容量没用完算不算合法？算，就全 0；不算，就负无穷。

计数：方案数与”前 i 件”的前缀语义

把状态里的”最大价值”换成”方案数”，转移方程里的 max 就要换成加法。dp[i][j] 表示从前 i 件物品中选、总重量满足容量约束的装法数量，那么不选第 i 件的方案有 dp[i-1][j] 种，选第 i 件的方案有 dp[i-1][j-w] 种，两类互不重叠，直接相加：

初始化的含义也跟着变。求”至多容量”的方案数时，dp[0][j] 全部为 1，因为一件不选也是一种装法；求”恰好装满”时，只有 dp[0][0] 为 1，其余为 0。一维写法仍然是 0-1 背包逆序、完全背包正序，这一点不因 max 换成加法而改变。

“前 i 件”依然是前缀，每件物品都要明确分到”选”或”不选”其中一边，方案才不重不漏；若定义成”以第 i 件结尾”，会漏掉大量组合。方案数增长很快，超过 2^53 后 Number 不能精确表示整数，题目通常要求每步取模。

路径还原：从答案倒推选择

只求最大价值时，一维数组就够了；一旦要输出具体选了哪些物品，就得把决策信息找回来。最直接的做法是保留二维表，从 dp[n][W] 出发倒推：如果 dp[i][j] 与 dp[i-1][j] 相等，说明第 i 件没有被选；否则它一定被选了，把容量减去它的重量，继续看前一行。

这个写法省事，但相等时一律判为”没选”。若某件物品选与不选价值相同，倒推只能给出其中一种合法方案；要严格记录，就在填表时另开布尔数组存选择。

二维表加倒推最好懂，代价是 O(nW) 内存；一维数组省空间，但历史被覆盖，除非额外维护父指针，否则无法还原。

复杂度与数据范围

二维实现的时间复杂度是 O(nW)，空间也是 O(nW)；滚动数组把空间降到 O(W)，时间不变。这里的 W 是容量的数值大小，不是它的二进制位数，所以这个复杂度被称为伪多项式。容量一万、物品一千，一千万次状态转移在现代机器上很快；容量十亿，哪怕只有十件物品也跑不完。

容量特别大时，通常有几种方向。若价值总和远小于容量，可以把”价值”当成状态维度，求达到某个价值所需的最小重量，复杂度变成 O(n × 总价值)。物品数量很小（比如不超过四十件）时，可以用折半搜索，把物品分成两半分别枚举再合并。再不然就只能接受近似解，用贪心加调整换一个可接受的误差。具体选哪条路，要看题目给出的数据范围，而不是看哪个算法名字更高级。

常见错误清单

  • 状态下标从 1 开始，取物品时忘了 weights[i - 1]，导致整体错位一位。
  • 容量为 0 的循环没有跑，或者 dp[0] 没有初始化，边界答案变成 undefined。
  • 物品重量大于容量时没有跳过，j - w 变成负数，读到 undefined 后参与加法得到 NaN。
  • 一维写法内层正序，0-1 背包退化成完全背包。
  • 题目要求恰好装满，初始化却全填 0。
  • 计数题用 max 而不是求和，或者忘记在每一步取模。
  • 二维表每行忘记重新申请数组，多行指向同一个引用，改一行污染所有行。

小结

背包问题的骨架只有三步：定义”前 i 件、容量 j”的状态，写出选与不选的转移，确定初始化和遍历方向。0-1 背包的内层容量逆序，完全背包正序；最大值用 max，方案数用加法；至多容量全初始化为 0，恰好装满用负无穷标记不可达。把这几个开关记住，大多数变体都能在原有方程上改出来。

问题变体 状态定义 遍历方向 初始化
0-1 背包，至多容量 前 i 件、容量 j 的最大价值 容量逆序 全部为 0
0-1 背包，恰好装满 前 i 件、恰好占用 j 的最大价值 容量逆序 dp[0] = 0，其余负无穷
完全背包 前 i 种、容量 j 的最大价值 容量正序 全部为 0
0-1 方案数 前 i 件、容量 j 的装法数 容量逆序 至多填 1，恰好只有 dp[0][0] 为 1

遇到新题时，先判断它是 0-1 还是完全，再判断问的是价值还是方案数，最后确认容量是至多还是恰好。这三问定下来，代码基本就成形了。
