Fullscreen 全屏 API 实践

九月底给客户交付数据大屏，演示前十分钟才发现，他们一直用 F11 当”全屏”。地址栏还在，鼠标往上一推就弹出工具栏，误触一下整个画面退回窗口。这篇记录我用 Fullscreen API 重做全屏的过程：前缀怎么写、为什么必须发生在点击回调里、状态与事件怎么维护、退出和 iframe 有哪些坑。示例是 ES5，按 2016 年 Chrome、Firefox、IE 11 的实际表现整理。

事故：F11 不算真全屏

项目本身不复杂：一个 1920×1080 的监控页，左边是设备列表，中间一张实时曲线，右边滚动展示告警。客户把笔记本接到会议室电视上，按 F11 让浏览器进入全屏，看起来一切正常。真正演示时问题一个接一个。

第一，F11 是全屏浏览器窗口，不是全屏页面。地址栏、标签页、书签栏都还在，页面可视高度比设计稿矮了一截，底部的告警条被裁掉一半。第二，鼠标只要移到屏幕顶端，浏览器工具栏就会浮出来盖住图表；客户拿激光笔讲解时手一抖，画面直接退出全屏，投影上露出桌面。第三，他们用双屏扩展模式，F11 只占当前屏，拖到另一块屏还得再按一次。

这三点都不是 CSS 能解决的。F11 的状态页面拿不到，浏览器 UI 的显隐也管不了。合适的做法是 Fullscreen API：让某个 DOM 元素独占屏幕，此时没有地址栏，Esc 才退出，页面还能收到进入与退出的通知。代价是 2016 年它仍要写前缀，而且必须由用户手势触发。

标准方法与各浏览器前缀

按规范，进入全屏是元素上的方法：element.requestFullscreen()，退出是文档上的方法：document.exitFullscreen()。听上去很干净，但 2016 年没有哪个浏览器能只写这一句就跑通。Chrome 与 Safari 走 webkit 前缀，方法名全小写；Firefox 走 moz 前缀，而且方法名是 mozRequestFullScreen，Screen 的 S 是大写，这一点最容易抄错；IE 11 与当时的 Edge 走 ms 前缀，方法名 msRequestFullscreen，又是一个小写。三种拼写，三种大小写习惯，靠记忆一定会出错，所以第一步是写一个探测函数。

这里有两个当年必须注意的细节。一是方法要从元素上取，再 call 回去，直接 var fn = el.webkitRequestFullscreen; fn() 会丢 this，Chrome 报 Illegal invocation。二是不要指望返回值。规范草案里 requestFullscreen 返回 Promise，但 2016 年各家的实现并不一致，IE 与老版 Safari 压根没有 Promise 这一层，写了 .then 只会在部分浏览器里报错。判断成功与否只能靠 fullscreenchange 事件，失败靠 fullscreenerror，这一点后面单独讲。

同理，能力检测也要带前缀：document.fullscreenEnabled、document.webkitFullscreenEnabled、document.mozFullScreenEnabled、document.msFullscreenEnabled。其中 IE 的 msFullscreenEnabled 在 iframe 场景下恒为 false，这个坑后面讲 iframe 时还会遇到。

必须由用户手势触发

第一版我把进入全屏写在了路由初始化里：页面加载完成，读到大屏模式，自动全屏。本地调试看着没问题，因为我是手动在控制台敲的命令，控制台执行算作用户操作。上线后客户打开页面，什么也没发生，控制台一行红字：Failed to execute 'requestFullscreen' on 'Element': API can only be initiated by a user gesture.

这是规范里写死的约束，不是实现缺陷。全屏会把浏览器的地址栏、标签页一起藏起来，如果不限制触发来源，任何广告脚本都能劫持整个屏幕，用户连关都关不掉。所以浏览器只认”用户手势”这一种上下文：点击、触摸、按键的回调里直接调用可以，一旦跨出这个调用栈就不行。

我踩过的三种失效写法，都是同一个原因：

连 setTimeout(fn, 0) 都不行，直觉上它和同步调用只差一个 tick。Chrome 与 IE 11 直接拒绝，Firefox 某些版本会放行，但不可依赖。唯一的正路是把调用放进真实事件的回调第一层，不要包在 Promise、定时器或动画帧里。确实需要”加载完再全屏”，就加一个开始页，让用户点一下”开始演示”，用这次点击同时完成全屏和初始化。键盘触发要绑在 keydown 上，keypress 在部分浏览器里不算手势。

元素全屏与视频全屏不是一回事

Fullscreen API 作用在元素上，任何 <div>、<canvas>、<img> 都能全屏，全屏后它仍是页面的一部分，CSS 与 JS 照常生效，图表可以继续重绘。视频全屏是另一条路径：浏览器接管绘制，铺满屏幕、保持宽高比、自带原生控制条，页面拿不到它的布局信息。两者桌面端都可用，移动端差别很大。

iOS Safari 是硬限制。iPhone 与 iPad 上的 Safari 只允许 <video> 元素全屏，而且不是走 webkitRequestFullscreen，是视频元素自己的 video.webkitEnterFullscreen()。普通元素全屏的 API 在 iOS 上根本不存在，document.documentElement.webkitRequestFullscreen 是 undefined，能力检测直接为假。这意味着 iOS 上做”整页全屏”没有正路，只能引导用户”添加到主屏幕”，用 apple-mobile-web-app-capable 让页面以独立窗口打开，看着接近全屏，实际还是普通窗口。这条路的门槛太高，最后只给 iOS 加了横屏提示。

Android 与桌面 Chrome 的差异在边角上。桌面 Chrome 全屏后鼠标移到顶部不会呼出工具栏，必须按 Esc 或 F11 才退；Android Chrome 全屏后会隐藏状态栏，但系统返回键和手势会直接退出全屏，页面收不到”用户想退出”的确认机会，只能靠 fullscreenchange 事后补救。Android WebView 更麻烦：元素全屏能用，视频全屏要原生层配合，WebChromeClient 不实现 onShowCustomView 就是一片空白，只能提前和客户端对齐。

状态判断与事件

只信 document.fullscreenElement

我最初维护一个 isFullscreen 变量：点按钮置 true，再点置 false。测试没问题，交给客户十分钟就出笑话——他们按 Esc 退出，我的变量还是 true，再点”进入全屏”，代码判断”已在全屏”于是执行退出，屏幕闪一下又回来。

退出全屏的入口不止我的按钮。Esc、F11、Android 返回键、浏览器策略都能改变状态，这些动作不会调用我的代码，自然不会更新变量。唯一的真相在 document 上：document.fullscreenElement 返回当前全屏的元素，没有全屏时返回 null。这个属性同样有前缀版本，大小写也不统一，取值函数要写成这样：

还有两个时序细节。第一，全屏是异步的，requestFullscreen() 返回时状态还没变，紧接着读 fullscreenElement 仍是 null，必须等事件。第二，不要用比较窗口尺寸的方式猜状态，多屏和缩放都会让 innerHeight 与 screen.height 对不上。业务代码统一走取值函数，别在十个地方各写一遍前缀。

进入、退出与失败事件

全屏相关的事件只有两个：fullscreenchange 和 fullscreenerror。前者在状态切换后触发，不告诉你方向，得自己读 fullscreenElement 判断是进入还是退出；后者在请求被拒绝时触发，但当年浏览器给的信息极少，事件的 target 是 document，没有错误码，只有一个”失败了”的事实。

前缀版本连大小写都不一致：webkitfullscreenchange、mozfullscreenchange、MSFullscreenChange。IE 那两个大写字母坑过我一次，监听写成 msFullscreenChange 就永远不触发，代码看起来完全正常。稳妥的写法是全部绑一遍，各浏览器只会派发自己那一个：

进入时要做的事：记录 window.scrollY，给 body 加类锁住滚动，隐藏悬浮控制条，通知图表重算尺寸。退出时反向操作并还原滚动位置，否则用户会落在页面中部。用户按 Esc 退出时不要弹”确定退出吗”，拦不住，弹窗只会让人困惑，直接把按钮文案改回”进入全屏”即可。

fullscreenerror 的排查顺序我总结成四条：一，调用是否在用户手势里，setTimeout、异步回调都算违规；二，document.fullscreenEnabled 是否为 false，企业策略和 iframe 权限都会让它为假；三，元素是否还在文档中，display: none 或者在 DocumentFragment 里的元素请求会失败；四，是不是 iframe 且没写 allowfullscreen。这四条覆盖了我遇到的全部失败案例。

全屏态的 CSS

全屏元素会被浏览器塞进一个特殊层，样式表里能用伪类选中它。标准写法是 :fullscreen，但 2016 年真正生效的是带前缀的三个：:-webkit-full-screen、:-moz-full-screen、:-ms-fullscreen。注意前缀伪类里是 full-screen 带连字符，方法名里却是 Fullscreen 连写，两套拼法不通用，写错就整条规则失效，而且不会有任何报错。

最容易被忽略的是背景色。全屏元素的默认背景由浏览器给，多数是黑色，如果页面本来是白底，四周和内容区之间会突然出现黑边，看起来像布局坏了。其次是尺寸：不要用 100vw/100vh，移动端地址栏收起时的 vh 计算在当年并不稳定，直接 width: 100%; height: 100% 配合 box-sizing: border-box 更可靠。

层级问题更隐蔽。全屏元素被提升到独立层，页面里的 z-index: 9999 对它无效，不在它内部的东西都会被压住。我们最初把工具栏放在 body 下、与全屏容器平级，点”全屏”后工具栏直接消失，客户以为功能坏了。正确做法是把控制条移进全屏容器内部，再用全屏态淡出，鼠标移动时唤回，顺带解决了控制条挡图表的问题。

退出、Esc 与清理

退出方法是文档级的，同样四套：document.exitFullscreen()、document.webkitExitFullscreen()、document.mozCancelFullScreen()、document.msExitFullscreen()。Firefox 那个名字最不讲道理，是 Cancel 而不是 Exit，中间的 FullScreen 还是两个大写。封装和进入时一样，先探测再 call。

Esc 是浏览器提供的退出通道，不可拦截。全屏状态下 Chrome 不会把 Esc 的 keydown 派发给页面，preventDefault 自然也谈不上。想阻止用户退出只有一个办法：在 fullscreenchange 里发现退出了就立刻重新请求全屏，但重新请求又需要用户手势，所以这条路走不通。接受它，把退出当成正常流程处理。

清理要覆盖两个入口。一是组件销毁或路由切换：先判断 isFullscreen()，是就退出并移除监听，否则单页应用切走后全屏还挂着，下一个页面直接以全屏出现。二是 beforeunload：浏览器会自己退出全屏，但定时器和播放器还开着，顺手停掉。元素被 removeChild 时通常也会退出，但事件不一定按时到达，别把清理押在它上面。

iframe 里的全屏

大屏项目里嵌了一个第三方地图，地图自己带”全屏”按钮，点了没反应。原因在 iframe 标签上：默认情况下框架内的文档没有全屏权限，必须显式声明 allowfullscreen。这个属性是布尔属性，写上就行，老版本还要补 webkitallowfullscreen 和 mozallowfullscreen，否则 Safari 与 Firefox 不认。

跨域时权限和事件分属两边。父页面拿不到子文档，没法替它请求，只能把 <iframe> 元素整块全屏，子页面内部的布局变化父页面一无所知。请求由子文档发起时，fullscreenchange 先在子文档触发，父文档随后也会收到一次，实测父页面的 fullscreenElement 指向那个 iframe。反过来，父页面调 exitFullscreen() 也能收掉子页面的全屏，做统一退出按钮时很有用。

IE 还有个坑：iframe 场景下 document.msFullscreenEnabled 恒为 false，能力检测会误判成不支持，实际调用 msRequestFullscreen 又能成功。所以能力检测只决定要不要显示按钮，结果仍以事件为准。

全屏后的布局时序

全屏切换会改变视口尺寸，resize 事件一定会来，但它和 fullscreenchange 谁先谁后不由我们决定。Chrome 通常是先 change 后 resize，Firefox 在某些版本里相反。如果在 fullscreenchange 里立刻读 offsetWidth，很可能拿到的还是旧尺寸，图表按旧宽高重绘，屏幕右侧留一条白边，或者被拉伸变形。

Canvas 还要多一步：按容器尺寸乘以 devicePixelRatio 重设画布的 width/height，再缩放上下文，否则全屏后线条会糊。这部分属于高清屏适配，另有专文，这里只提醒它必须挂在重排之后。

小结与场景对照

这套东西写完，大屏的全屏才算稳定：进入靠点击手势，状态只信 document.fullscreenElement，进出都走事件，退出不拦 Esc，布局延后一帧再算。API 本身不难，难的是 2016 年的前缀分裂、手势限制和移动端残缺。鼠标锁定是 Pointer Lock，另一套 API，和全屏没有依赖。

场景 使用的 API / 前缀 限制
桌面整页全屏 requestFullscreen 及 webkit/moz/ms 前缀 必须用户手势，Esc 退出不可拦
视频全屏（桌面） 元素全屏或播放器自带按钮 原生控制条由浏览器绘制
iOS Safari 仅 video.webkitEnterFullscreen() 普通元素全屏不可用
Android Chrome webkitRequestFullscreen 返回键直接退出，无确认
跨域 iframe iframe 加 allowfullscreen 父页面无法代子页面请求
退出与状态 exitFullscreen 系列 + fullscreenElement 前缀命名不一致，需封装
