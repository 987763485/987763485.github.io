HTML5 progress 与 meter 进度展示

本文属于《HTML 与 CSS》第 12/62 篇
上一篇系列目录下一篇

进度条是后台系统、上传弹窗、仪表盘里最常见的控件之一。很多团队要么一水儿用 div 加内联宽度自己拼，要么误以为 <progress> 和 <meter> 是一回事、随便挑一个。本文想解决的是后者：先把这两个原生元素的语义边界讲清楚，再逐一摊开它们在 WebKit、Blink、Firefox、IE 上截然不同的样式覆盖能力，最后给一套”特性探测 + 双套渲染”的 ES5 降级架构，把它接到真实的 XMLHttpRequest 上传进度上。适合正在做上传、任务进度、用量展示，又被 IE 和老安卓兼容折磨的前端同学。读完你会拿到一份能直接抄的完整 CSS、一个可运行的 ProgressBar 构造函数，以及一条清晰的降级判断链。控件皮肤重置、动画节流、上传前压缩这些能力旧文已经写过，本文只在需要处一句话带过，主线始终是这两个元素本身。

语义边界：progress 与 meter 不是一回事

这是全文所有取舍的前提，先把它钉死。<progress> 表达的是”某个任务的完成度”，它的时间维度隐含”还会继续往前走”；<meter> 表达的是”一个已知标量范围内的测量值”，它是静态的、此刻的读数，没有”完成”这个概念。磁盘占用、评分、配额用量该用 meter，文件上传、页面加载、任务处理该用 progress。二者混用不只是”不好看”，而是把语义喂给了屏幕阅读器和以后接手代码的人，喂错了。

维度 <progress> <meter>
表达的东西 任务完成度，随时间推进 范围内的标量测量值，静态读数
value 可省略，省略即不确定进度 必填，代表当前测量值
min / max 只有 max（默认 1），无 min min、max 都可设（默认 0、1）
low / high / optimum 无这些属性 三者齐全，决定颜色档位
参与表单提交 否 否
典型场景 上传、加载、批处理进度 磁盘占用、评分、流量配额、电量

两个高频误用点值得单拎出来。第一，用 meter 显示”下载进度”——下载是个会走到底的任务，进度归零到满有明确的”完成”语义，这正是 progress 的领地，meter 只会把它读成一个”此刻的采样值”。第二，用 progress 显示”磁盘占用”——占用率是个静态测量，没有”任务在推进”的含义，用 progress 会让人误以为正在往满格涨。至于”能不能用于表单提交”这一列，答案是两者都不能：progress 和 meter 既不是 listed 元素也不是 submittable 元素，FormData 从表单里收不到它们，若确实要把数值发给后端，另配一个 input type="hidden" 携带，别指望元素本身。

meter 的最小写法要看懂它的颜色档位规则。low、high 把 min 到 max 的区间切成三段，optimum 指定哪一段是”最好”：

不带 optimum 时，中间段 [low, high] 视为最佳（绿色），两侧 [min, low) 与 (high, max] 都是”更差”（红色）——也就是说没有 optimum 就没有橙色。一旦 optimum 落在某一段里，那一段变绿，相邻段变橙，最远的段变红。这套机制决定了 meter 天生适合表达”用量超没超阈值”这类有健康区间含义的读数，而不是单纯的一根填充条。

兼容性现实：IE 是绕不开的洞

把支持面如实摊开，别自作多情。progress 在 Chrome、Firefox（4 起）、Opera、Safari 5.1 起、IE10 起都能原生渲染，但 IE9 和 Android 2.3 的原生浏览器不支持——它们只是把 progress 当未知行内元素，前面写的内容兜底会在这里救场。meter 的支持面更窄：IE 全系都不支持（连 IE10、IE11 也不，IE 把它整个当不存在），Chrome、Firefox、Safari 桌面端支持，Android 2.x 不支持。

这里要和旧文划清界线：header、footer 这类结构性标签在不认识它的老 IE 里可以靠 html5shiv 补出 DOM 节点，但那套迁移清单管的是”块级语义容器”，progress 与 meter 是”带特殊渲染行为的元素”，html5shiv 救不了它们——它能让 CSS 命中节点，却变不出进度条的绘制逻辑。所以这两个元素的老浏览器问题，只能用本文后面的 JS 降级架构来解，别指望垫片。

样式定制：各内核能力天差地别

这是本文实操的重头。原生进度条各浏览器画得不一样，统一外观是刚需，但覆盖能力完全不统一，得分内核写。先给一段覆盖全内核的完整 CSS，再逐条解释。

逐条说清代价。第 1 段是保底层：IE10 支持 progress 但只能用整块的 background + color 粗改——background 是轨道、color 是填充，border 能改外壳，除此以外没有更细的钩子，而且 ::-ms- 这种形式的伪元素根本不存在，别去查。想彻底重置原生外观靠 appearance: none，可惜 appearance 在 IE 全系都无效，这条能力边界在旧文《CSS3 用户界面属性与外观定制》里已经讲透，本文不重复。第 2 段的 WebKit 三件套是覆盖最彻底的：::-webkit-progress-bar 管轨道、::-webkit-progress-value 管填充，填充宽度是内核按 value/max 算的，你只能给它上色不能给它设宽。第 3 段 Firefox 只有一个 ::-moz-progress-bar，对应填充部分，轨道只能靠基线的 background。

indeterminate 状态有个必须诚实面对的现实：在 Chrome 和 Firefox 里那个来回游动的动画是内核自带的，你无法通过 -value / -moz-progress-bar 给它改颜色——因为它压根不画”值”，没有值区可上。想要不依赖内核、颜色可控的”忙碌”效果，只能自己用 @keyframes 加 -webkit- 前缀做条纹滚动动画，就像第 4 段那样。而这条路在 IE9 上没有 CSS 动画可用（IE 到 10 才支持 @keyframes 且无 animation 前缀），所以第 4 段的动画只对 WebKit 系和 IE10+ 生效，IE9 用户仍回到内容兜底文字，这是当年真实的天花板。

meter 的样式另一套钩子：WebKit 用 ::-webkit-meter-bar（轨道）加 ::-webkit-meter-optimum-value / -suboptimum-value / -even-less-good-value 三个按档位上色的填充；Firefox 用状态伪类 meter:-moz-meter-optimum、meter:-moz-meter-sub-optimum、meter:-moz-meter-sub-sub-optimum（当时可用）配合 ::-moz-meter-bar 给条上色。记住 meter 在 IE 全无，所以它的外观定制天然只在 WebKit/Firefox 里有意义，IE 用户看到的就是内容兜底文本。

刷新频率与性能：别在回调里读写布局

upload.onprogress 触发极其频繁，大文件上传时一秒能来几十上百次，每次回调里既改 DOM 又读几何属性，就是在给自己制造强制重排。原则两条：回调里只做”记录最新百分比”这一件事，把真正的 DOM 写入合并到下一帧；且只在整数百分比变化时才动 DOM。

这里只用了 rAF 做”合并写入”，动画节流、polyfill 前缀探测那套细节旧文《DOM 动画与 requestAnimationFrame》已经讲透，本文不再抄一遍。另一个易忽视的点：value 变化时只改这一个属性，绝不 innerHTML 重建整个 progress 节点——重建会打断内核动画、丢掉焦点、还平白触发一次 DOM 结构变更。上面的 ProgressBar 从头到尾复用同一个节点，只动 value、width 和文本，就是这个道理。

无障碍与可用性

原生 progress 在各家屏幕阅读器上的支持当时并不齐——有的读初始值不读变化，有的干脆静默。务实策略是把它当”自己负责播报”的控件：用 aria-valuenow 随进度手动更新（前面 _paint 里已经在做），再包一层 aria-live="polite" 的容器播报阶段性的百分比，避免每 1% 都打断用户。

aria-live="polite" + aria-atomic="true" 让读屏在用户空闲时朗读整块最新内容，而不是被高频进度事件淹没。文案上，进度条旁边把”正在上传 report.pdf”这类文字和百分比数字同时给出，别只画一根没有标注的条。meter 有个更隐蔽的可用性问题：它的绿橙红颜色在很多环境不代表状态、只是装饰，色盲用户和黑白打印下完全丢失信息——所以凡用 meter 表达”超标”这种关键含义，必须配文字（”磁盘已用 82%，接近上限”）或图标补足，颜色只作锦上添花。

小结

回到判断链。什么时候能直接用原生元素：progress 在目标用户以 Chrome/Firefox/Safari/IE10+/较新安卓为主时可放心用，写好内容兜底文本和 role/aria-valuenow 标注即可，样式走 WebKit 三件套加 Firefox 的 -moz-progress-bar，IE10 退到 background+color。什么时候必须自己写组件：需要兼容 IE9 与 Android 2.3（progress 原生不支持）、需要兼容任何 IE（meter 全无）、需要 indeterminate 颜色可控而内核动画改不动、或需要在进度条上做复杂自定义视觉时——这时上本文的 ProgressBar 双套渲染，用 div+span 把控制权全拿回来。语义这条红线任何时候都不松：任务完成度用 progress，范围内测量值用 meter，别拿 meter 装下载进度、别拿 progress 装磁盘占用。拿到真实 loaded/total 就用真实进度，拿不到（IE9、老安卓）就诚实降级成 indeterminate 动画加完成态，这比让进度条一直停在 0% 体面得多。
