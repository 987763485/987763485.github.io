jQuery 自定义动画 animate 实战

很多人把 animate() 用成一个”带插值的 .css()“，会写 {width: 200} 就止步了。但它其实是 jQuery 里最值得拆开看的一个函数：一套定时器驱动的数值插值引擎，而且留了扩展口，让你能把”任意一个数字”变成可动画的属性。本文基于 jQuery 1.11 讲清 animate() 内部的计算机制，用 $.fx.step 给动画加自定义属性，注册自己的缓动曲线，最后串三个实战例子和一份坑清单。适合已经吃透 show/hide/fade 系列、想把动画再往前推一步的同学。

动手之前：animate 到底在做什么

调用一次 $(el).animate(props, duration)，jQuery 会把 props 里的每个属性拆成一条数值补间任务：起始值从元素当前的计算样式里读出来并统一折算成数值，结束值来自你传的参数——可以是纯数字、带单位的字符串、"+=120" 这样的相对值，也可以是 show、hide、toggle 这类内置关键字。随后这组任务交给一个全局唯一的定时器 $.fx.timer 驱动，每隔 $.fx.interval（默认约 13 毫秒）做一次 tick。每个 tick 上发生的事情可以压缩成一行：

percent 是已经过去的时间比例，easing 是所选缓动函数，算出来的 now 再经 $.fx.step[prop] 这一步写回元素。整个 animate 就是这三件事的无限循环，直到 percent 走到 1。

两个常被忽略的细节藏在这段流程里。其一，13 毫秒不是拍脑袋定的：它略快于 60 Hz 屏幕的一帧（约 16.7 毫秒），保证每一帧渲染前都至少算过一次新值，同时又不至于快到一个 tick 挤不进同一帧。其二，$.fx.timer 是全局共享的——页面上同时在跑三十条动画和三条动画，走的是同一个定时器回调，这既省掉了三十个 setInterval 的调度开销，也意味着任何一个元素的补间算得慢，都会拖到别人头上，这是后文性能一节所有结论的根源。

flowchart TD
    A["调用 animate 传入属性对象"] --> B["逐属性建补间任务：读起始值、解析结束值与单位"]
    B --> C["排进该元素的 fx 队列并交给全局 $.fx.timer"]
    C --> D["每 13ms 一次 tick：算出时间比例 percent"]
    D --> E["easing(percent) 得到数值比例"]
    E --> F["now = start + (end - start) * 数值比例"]
    F --> G["$.fx.step[prop] 写回元素"]
    G --> H{"percent 是否到 1"}
    H -->|否| D
    H -->|是| I["写入精确终值并执行 complete，继续走队列"]

从这个机制直接推出两条结论。第一，插值只对”数”有意义，所以能直接补间的属性都是”一个数字加一个单位”能完整表达的：left、top、width、height、opacity、margin、padding、fontSize、scrollTop 等。颜色本质是三个数、background-position 是两个数、transform 是一串矩阵文本，jQuery 核心没有为它们内置拆分与合成的解析器，不额外做处理就只能整字符串地跳变。第二，逐帧写内联样式，几何属性每帧都会让浏览器重算布局——这笔账《减少重排与重绘的实践清单》里已经量过，本文不再重复。

哪些属性交给 animate，哪些交不了

把边界整理成一张表，写动画之前先对一遍：

属性 能否直接补间 说明
left、top、width、height、opacity、margin、padding、fontSize 能 缺省单位是 px，opacity 无单位
scrollTop、scrollLeft 能 内部有专门的读写钩子，替我们抹平了 document 与窗口差异
backgroundPosition 有条件 必须写驼峰，目标值给成两个 px 数字；百分比写法在老内核与老解析里不可靠
color、backgroundColor 不能 核心不拆颜色，需要 jQuery UI 或 jQuery Color 插件
transform 不能 1.11 不认识这个属性，字符串无法插值，只会整段跳变
display 不能 关键字没有插值含义，只能在动画起止时刻切换

duration 除了毫秒数，还接受 "fast"（200）与 "slow"（600）两个字符串；第三个参数或选项里的 complete 回调只在动画完整跑到终点时执行一次，这一点后面坑里会用到。

transform 那行值得多说两句。2014 年写动画不能不考虑 IE9，而 IE9 对 transform 的支持是残缺的，即便 jQuery 能补间它也占不到便宜；jQuery 自己也不会在 style 里逐帧拼一条合法的 transform 串。所以当年的现实路线只有两条：位移继续用 left/top 补间，或者干脆把这组动画让给 CSS transition 去做。两条路线的帧率账我在《CSS动画与JS动画的性能取舍》里实测过，这里一句带过。

$.fx.step：给 animate 增加一个能动画的属性

$.fx.step[prop] 就是上面公式里”写回”这一环。默认实现把 now 写进 elem.style[prop]；而一旦我们定义了 $.fx.step.myProp，这个属性的写回流程就整个归我们接管，now 从此可以不碰样式、直接进 DOM 文本或任意状态。往属性上还可以挂 create 与 start 两个一次性钩子，三阶段职责如下：

  • create(hook)：建补间任务时调用一次。自定义属性在样式表里读不到起始值，所以在这里把 start、end 规范成纯数字、清空 unit——不清的话默认逻辑会给我们的数字硬拼上 px。
  • start(hook)：动画正式开始（第一次 tick 之前）调用一次。用来给元素铺初始状态，避免第一帧闪旧值。
  • run（即 step 函数本体）：每个 tick 调用一次。挂在我们身上的参数就是那条补间实例：anim.elem 是元素，anim.pos 是经缓动映射后的比例，anim.now 是插值出来的当前值；create 阶段挂在实例上的自定义字段，这里可以直接取回。

写完之后，num 就和 width 一样是一个”可动画属性”了，任何元素、任何时长、任何缓动都能用。另外两种等价姿势要分清：$({p: 0}).animate({p: 1}, {step: fn}) 这种挂在选项里的 step 回调是一次性的，适合临时插值；$.fx.step 是属性级复用，写组件和插件用它。市面上有 jQuery Number 等官方插件做同样的事，值得找来读一遍源码，但不要为一个二十行的需求背一份插件。

第二个例子：scrollTop 补间与”缓动到位”。 animate({scrollTop: dest}) 的起始值在动画开始时读自 elem.scrollTop，终值就是我们算好的 dest。注意最后一个 tick 上 percent 被钳成恰好 1，而任何正经缓动函数都满足 easing(1) = 1，于是 now = start + (end - start) * 1 = end 精确落位——不存在浮点漂移导致”差 0.3 像素没滚到位”的问题。这对”滚动到某行并高亮”这类要求终点像素精确的场景很关键：

缓动函数：往 $.easing 注册自己的曲线

jQuery 1.11 内置的缓动只有两个：linear 与 swing（后者是默认值）。面试常被问到的 easeInQuad 那一整族并不在核心里，它们来自 jQuery UI 的 effects 模块或第三方 easeings 插件。所有曲线都存在 $.easing 这张注册表上，随时可以自己加。1.x 里缓动函数会被传五个参数：时间比例、已走的毫秒数、常量 0、常量 1、总时长——但值域映射 jQuery 自己会做，我们只需要用第一个参数，把”时间过了几成”翻译成”值该走几成”：

swing 的内部实现是 0.5 - Math.cos(percent * Math.PI) / 2，即一条正弦缓入缓出；和 linear 的差别在观感上就是”有没有起步与刹车”。注册完成后，曲线名在任何一次 animate 的选项里随取随用。

例三：平滑滚动到锚点

为什么选择器要写 "html, body" 两个元素：2014 年”页面滚动条挂在谁身上”仍不统一，标准模式的现代内核挂在 documentElement（也就是 html）上，IE8 在怪异模式下挂在 body 上。把它们都选中做一次 animate，jQuery 会逐帧给两者写 scrollTop，其中只有一个在当前内核里真正生效，另一个的写入无害；只写一个则必有一类内核失灵。hash 要放进 complete 里再改，否则浏览器先执行原生跳转，动画起点当场作废。

几个咬过人的坑

动画中途读 offset()。 动画每帧都在写几何样式，此时调 offset()、position() 都会强制一次同步布局，拿到的还是中间帧的值——用这个值再算新终点，布局会跟着抖。起点终点都应在动画开始前量好、存进闭包。

width/height 动画撞上 padding 与 box-sizing。 content-box 下补间的只是内容宽，视觉上元素比数值”胖一圈”；全局 border-box 重置后反过来，width 收不到比左右 padding 更小的值，从 0 起步的动画第一帧就会跳到 padding 宽度（盒模型的账《CSS3 box-sizing 与全局重置样式》里有）。解法：动画外层 overflow: hidden 的容器，把 padding 留给内层。

元素被移除后 complete 不再执行。 上一周那篇讲过 .stop() 打断不触发回调；补一个动画场景特有的入口：带飞行、退场动画的元素常在终点前被业务代码 remove()，挂在 complete 里的锁和状态就永远悬着。给锁加一个按标称时长兜底的超时：

动画期间用户还能操作。 补间跑 600 毫秒，用户连点三次，open 标志跟着翻转，动画和状态就错位了。轻量方案是动画期间禁用触发按钮，终点再放开；配合”状态跟着点击意图当场更新、不塞进回调”的原则（旧文讲过），基本不会再出鬼畜画面。

动画留下的内联样式会盖死样式表。 animate 写回的是 inline style，优先级高于一切选择器：抽屉收拢后残留的 width: 0px、飞行结束后残留的 top，都会让后来想用 CSS 改版的人怎么改类都不生效。凡是”动画结束即终态”的属性，收尾时用 .css("width", "") 清掉内联值、把控制权还给样式表；只有你确定还要用它当起点时才保留。

性能：三个可调的旋钮

每个 tick 的工作量约等于”在跑的补间实例数 × 每实例属性数”，而写回的样式量决定了布局代价。所以旋钮有三个：少动画几个属性、少同时几个实例、放慢 tick 频率。多元素联动时，与其给每个元素建一次 animate，不如用一个 animate 驱动全部：

用 Chrome 35 的 Timeline 录”Scripting 加 Layout”的单帧耗时自测（口径自己机器自己认，不必引用别人的数字）：桌面端十几个实例以内两种写法几乎无差；实例涨到几十个，写法一的启动读值和全局定时器里的逐条计算会明显抬高单帧成本，掉到三十几帧；写法二每帧只增加 N 次写回，脚本段平缓得多。但要清醒：写回样式引发的布局两种写法同样要付，卡在布局上时合并驱动救不了场——出路是交回 CSS，见性能取舍那篇。另外把 $.fx.interval 调大到 30 甚至 60，可以用帧率换 CPU，给低端机续命；$.fx.off = true 则是一键关死所有补间的降级总闸。

小结：animate 还是 CSS，一眼判断

需求 推荐方案
起止值写代码时已知、无需中途打断 CSS transition / animation
目标值要运行时测量或按数据计算 jQuery animate
需要中途打断、反向、动态改终点 jQuery animate
动画对象是 DOM 文本、JS 数值状态而非样式 $.fx.step 自定义属性
想用 transform 走合成器加速 CSS；老内核兜底才退回 left/top
同时动画的元素以几十计 CSS，或单条 animate 合并驱动

animate() 的全部内容其实就是一句话：13 毫秒一次的定时器里，对每个属性执行 start + (end - start) * easing(percent)，再按 $.fx.step 写回。看懂这一行，它就不再是黑盒——凡能折算成数字的量都能动画，$.fx.step 与 $.easing 两个注册表把引擎的油门和方向盘都留在了我们手里。剩下的唯一代价是每写一帧样式都要付布局的钱，什么时候值得付、什么时候让给 CSS，按上面的表选就行。
