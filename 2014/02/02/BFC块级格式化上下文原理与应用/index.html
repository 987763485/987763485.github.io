BFC 块级格式化上下文原理与应用

本文属于《HTML 与 CSS》第 27/62 篇
上一篇系列目录下一篇

BFC（Block Formatting Context，块级格式化上下文）是 CSS 布局里最容易被含糊带过的概念。很多人知道”加个 overflow: hidden 能清浮动”，但说不清为什么。本文从进阶角度把 BFC 的定义、触发条件、三条特性和典型应用讲透，并说明 overflow: hidden 方案的副作用。结论先给出：BFC 是一个独立的渲染区域，它的价值在于隔绝 margin 折叠与浮动重叠，代价是可能引入裁切和滚动条。

什么是 BFC

BFC 是页面渲染时的一块独立布局区域。区域内部的盒子按自己的规则排列，不受外部元素影响，也不影响外部元素。这个”隔离”是理解全部应用场景的钥匙。

规范给出的定义是：浮动元素、绝对定位元素、非块级盒子的子盒子，以及具有 overflow 非 visible 的块级盒子，都会与它们的块级容器一起建立新的格式化上下文。用更直白的话说：一个元素成为 BFC 之后，它把自己和内部内容包成了一个布局上的”独立王国”。

要理解它的意义，先看不建立 BFC 时会发生什么。普通块级容器里，块级子盒子垂直排列，相邻盒子的上下 margin 会折叠；如果容器里有浮动元素，浮动元素会脱离文档流，容器可能”罩不住”它，高度塌陷。

BFC 的三条特性

记住这三条，应用场景就能自己推导出来。

特性一：内部的块级盒子垂直排列。 这不是 BFC 特有的，普通块级容器也这样。真正的含义是：BFC 内部的垂直排列规则独立计算，margin 折叠只发生在 BFC 内部，不会跨过 BFC 边界。

特性二：属于同一个 BFC 的相邻块级盒子，上下 margin 会折叠；不同 BFC 之间不折叠。 这一条是”防止 margin 折叠”的理论依据。

margin 折叠的规则本身值得单独说清：相邻兄弟盒子的上下 margin 折叠取两者较大值；空盒子的上下 margin 会自身折叠；父子元素之间，如果父元素没有 border、padding、overflow 非 visible 或未建立 BFC，子元素的 margin-top 会”穿透”到父元素外面。

特性三：BFC 的区域不会与浮动元素重叠。 这一条解释了自适应两列布局，也是 overflow: hidden 能清浮动的根本原因。

普通块级盒子在计算宽度时会忽略浮动元素（它的盒子会延伸到浮动元素下方，但内容文字会环绕避开）。而 BFC 的盒子会主动避开浮动区域，宽度收缩到浮动元素之外。这就实现了”定宽侧栏加自适应主区”的两列布局，主区不需要写宽度。

这个方案在 2013 年前后非常流行，因为它比 float 加负 margin 的写法简单，也不需要 clearfix。它有个副作用：主区不能有元素溢出（会被裁切），下面会讲。

overflow: hidden 的副作用

overflow: hidden 是最简便的 BFC 触发方式，但副作用必须清楚。

裁切。 子元素超出容器的部分被切掉。下拉菜单、tooltip、负 margin 拉出的装饰元素，都会在这个容器里消失。

滚动条。 overflow: auto 在内容溢出时出现滚动条，可能造成布局抖动（出现滚动条后可用宽度变化）。overflow: scroll 则恒定显示滚动条，浪费空间。

position: fixed 失效。 如果祖先元素建立了 BFC 且带有 transform 或 filter，fixed 定位的包含块会变成那个祖先。这一点与 BFC 没有直接关系，但常在同一批样式里出现，容易混淆。真正与 BFC 相关的是：overflow 非 visible 会成为 absolute 定位元素的包含块。

这个行为在没预料到时会产生”绝对定位元素跑偏”的 bug。

无法与负 margin 布局配合。 靠负 margin 把元素拉出容器做视觉效果的写法，在 overflow: hidden 下全部失效。

选型建议很直接：能接受裁切时用 overflow: hidden，不能接受时用 clearfix。页面级容器、文章正文容器通常可以裁切；带下拉菜单、弹出层的导航容器必须用 clearfix。2013 年的主流做法是两者并存，按模块性质选。

2013 年的实践建议

第一，优先用语义化方案避免问题。统一 margin 方向避免折叠，flexbox 做等高布局，能不上 BFC 就不上。BFC 是”理解之后能用好”的技术，不是”到处都用”的技术。

第二，记住每个触发条件的副作用。overflow 带裁切、float 脱离文档流、position: absolute 同理、table-cell 丢 margin、inline-block 有基线间隙。选条件就是选副作用。

第三，调试时善用计算样式。Chrome DevTools 里看元素的 overflow、float、position、display，就能判断它是否建立了 BFC。当年没有专门的可视化工具，靠这几个属性反推。

第四，flexbox 已可用但需前缀。2013 年写 flex 容器要带 -webkit- 和 -ms- 前缀，IE10 支持，IE9 及以下不支持。flex 容器本身建立 BFC，所以 flex 布局天然享有 BFC 的隔离特性，这是它比 float 布局更稳的原因之一。

小结

BFC 是页面中一块独立的布局区域，核心价值是隔离：内部 margin 折叠不外溢，区域整体避开浮动元素。触发条件包括 float 非 none、position 为 absolute 或 fixed、overflow 非 visible、以及 display 为 inline-block、table-cell、table-caption、flex 等值；display: flow-root 在 2014 年初还不存在。三条特性——内部垂直排列、相邻 margin 折叠只发生在同一 BFC 内、区域不与浮动重叠——直接派生了清浮动、防 margin 折叠和两列自适应三大应用。overflow: hidden 最简便但有裁切、包含块改变、无法配负 margin 三方面副作用，不能裁切的场景用 clearfix。工程上的最优解仍然是提前设计好 margin 方向与布局方案，把 BFC 当作兜底手段而非首选。
