Swiper 轮播图组件实战

首页轮播这个需求，我们从 jQuery 自写动画一路换到 Swiper 2.x，中间踩了八个坑，其中三个是上线后被运营在群里 at 才发现的。本文不是配置项手册，只写两件事：一套能直接抄走的接入写法，以及每个坑的现象、原因和最后的解法。适合正在给移动页面接轮播、或者打算把祖传 jQuery 轮播换掉的同学。全文基于 Swiper 2.7.6，代码都是 ES5。

选型背景：一句话交代清楚

2014 年做移动端轮播，主流路线就一条：用 touch 事件读手指位移，把内容层用 transform 搬走，松手后自己算惯性。这条路线的成本模型和四种滚动方案的对比，笔者在《移动端滚动方案优化》里已经推过一遍，这里不重复。

当时项目里其实试过 iScroll 做轮播，很快就排除了：它搬动的是整块 scroller，slide 里塞满大图时合成层内存吃不消，而轮播本身在它的体系里属于外挂玩法而不是核心能力，细节都在《iScroll 实现移动端滚动》里记过。Zepto 也不解决这件事——它只给事件、数据动画这些模块，压根不带轮播组件，模块拼法见《Zepto 移动端库实战》。同类方案里还看过几个零散的小插件，最后落到 Swiper：MIT 协议，原生实现不依赖 jQuery（虽然当时我们项目里 jQuery 和 Zepto 都还活着，混用是常态，但接它确实可以只引两个文件），DOM 约定简单，loop、分页圆点、自动播放这些轮播必需的能力都是内置选项。

八个坑，逐个复盘

坑一：动态插入 slide 之后滑不动

现象：接口回来的 banner 拼成 HTML 插进 wrapper，圆点数量对了，但怎么划画面都不动，或者一次直接跳到最后一片。

原因：slide 的宽度和可停靠位置（内部那份 snap 数组）在初始化时算完就缓存了，你后来追加的 DOM 它一无所知，边界还是旧的。

解法：任何改变内容数量或尺寸的操作之后，手动调 update()。

需要 update() 的时机我列过一张便签：appendSlide / prependSlide 之后；改过 slide 或图片的 CSS 尺寸之后；图片 load 完把容器撑高之后（所以上面把 onLazyImageReady 直接接给了 update）；父容器宽度从 0 变成有值之后。2.7 里还有 updateOnWindowResize 与 resizeReInit 这类开关，但它们只管窗口尺寸变化，管不了”tab 刚显示”这种容器自己变宽的情况。

坑二：loop 模式下 activeIndex 的数字对不上

现象：埋点上报的曝光序号一片混乱，第一片和最后一片反复重复上报，中间那片反而没数据。

原因：loop: true 时库会在头尾各复制若干片 slide，复制出来的那些带 swiper-slide-duplicate 类。activeIndex 数的是 DOM 里的位置，包含复制片，所以它和数据下标不是一回事；realIndex 才是去掉复制片之后的真实序号。

字段口径沿用《移动端 H5 页面分享与埋点》里定好的那套 banner 曝光规范，这里不重讲打点链路。另外 s.slides.length 也是含复制片的，凡是用它做取模或遍历的地方都要当回事。

坑三：在 display: none 的面板里初始化，布局全错

现象：轮播放在首页 tab 的面板里，默认隐藏。切到首页时画面挤成一条、只能看到半片，或者怎么划都在原地。

原因：初始化那一刻容器的 clientWidth 是 0，slide 宽度算出来也是 0，所有可停靠位置退化成同一个值。库不会报错，它只是安静地按 0 布局。

解法一（推荐）：延迟到面板真的显示之后再 init，且只 init 一次。

解法二：已经初始化过、只是后来被隐藏又显示出来的实例，用 reInit() 把配置和尺寸一起重来。它比 update() 重，会把事件与内部结构重建，别在每个 tab 切换上都调。

这里补一条当年吃了两天亏的细节：Swiper 在 touchstart 里会调 preventDefault，为的是干掉系统橡皮筋和页面滚动，代价是浏览器原生 click 的生成、文本选中、以及输入框聚焦会被一起压掉——轮播里有 input 时点它弹不出键盘。把输入框所在那块标成 swiper-no-swiping，让库在起手阶段就放弃这次手势，默认行为就还回来了；仍然不行的话，只能把热区彻底交给 swipeHandler，让输入区完全落在热区之外。

坑五：iOS 上循环到最后一页白屏或闪烁

现象：前三片循环得好好的，划到最后一片闪一下白，或者停住不动，回划一次又正常了。

原因：图片解码时机加上层数。每片 slide 都带 -webkit-transform，等于各自是一张纹理；loop 又在头尾复制，实际层数比视觉上多。纹理申请失败或图片还没解完码，就是一片白。

解法是一套组合，不是单个开关：图片宽高写死（HTML 的 width/height 与 CSS 高度都给准，后端出图比例固定），preloadImages: true 让图片在初始化前解完，slide 数量克制在 8 片以内。首屏之外的图片如果要省流量，就用坑前那套”第一张硬编码 + 其余 lazyLoadingInPrevNext 提前一片”的组合，别裸开懒加载。

必须诚实说一句：这个问题在 iOS 6 与 iOS 7 上表现不一样，iOS 6 那批机器更容易白，同一份代码在模拟器里看不出来，在真机上划五下就能复现。我们最后的结论只有一个——轮播白屏类问题必须以真机清单为准，任何”改了个 CSS 就好了”的提层偏方都不值得抄。

坑六：用户滑一次之后就不再自动播

现象：进页面自动播得好，运营在手机上手划一下，之后这个页面就再也没自己换过片。

原因：autoplayDisableOnInteraction 默认是 true，即用户一交互就停掉自动播放，而且是停掉不是暂停。这不是 bug，是当时没人注意的默认值。

如果产品要的是”用户动过之后先歇一会再续播”，就保留默认 true，自己在 onTouchEnd 里安排一次重启。注意 startStop() 是开关语义，连调两次等于没调，必须自己记状态：

现象：竖屏正常，横过来之后每片都偏移半屏，最后一片露出一角，划到那里就划不回来了。

坑八：回调的参数是实例，不是当前那片 DOM

现象：想在 onSlideChangeStart 里给当前 slide 的标题条换文案，直觉写了 function (slide) { slide.style... }，报 undefined。

原因：2.x 的所有回调，第一个参数传进来的是 swiper 实例本身，this 也指向同一个实例。参数压根不是事件目标。绑定规则本身《this 指向的四种绑定规则》里讲透了，这里只提醒一句：组件库回调属于最普通的函数调用那一档，别指望 this 是 DOM。

坑就在 wrapper.children[...] 的下标：loop 在头尾插了复制片，所以这个下标是含复制片的 DOM 位置，不能拿去索引业务数据数组。两个索引各用各的，序号一律走 realIndex。

一次改造的复盘：换掉 jQuery 自写轮播

原来的首页轮播是组里一位同学自写的：jQuery 的 animate 改 left 做位移，setInterval 切页，手指拖动根本没实现，只支持点圆点。业务代码加上配套 CSS 差不多四百多行，改需求时要同时动定时器和动画队列，stop(true, true) 漏一处就会看到画面在中间抖。换成 Swiper 之后，同一个需求剩下的是上面这段配置加一层 DOM，一百来行，拖动、惯性、圆点这些不用自己写。

掉帧方面的改善是明显的，但我说的是主观口径：手上那台 iPhone 5 和红米一档的机器上，自写版本改 left 时每帧都要重新布局，松手那段动画肉眼能看出不跟手、一顿一顿；换成库的 -webkit-transform 位移后跟手了，白屏只剩坑五那一种场景。当时的判断办法就是人眼加 console.time，没有可靠的帧率采集工具，所以这里只能给量级不能给数字，别当成基准测试结论。

有两类需求我们试过，确实不适合拿它做。一是 slide 内要放可上下滚的长列表：两套 touch 监听抢同一根手指，怎么配都不干净。务实解法是内外分层——内层老老实实用原生 overflow: auto 配 -webkit-overflow-scrolling: touch，外层用 swipeHandler 把拖动热区限定在顶部图片区，列表区完全不参与轮播手势，这样各滚各的互不打扰。二是需要复杂手势组合（双指缩放叠着旋转再叠拖动），Swiper 只负责横滑这一条通道，硬凑不如直接上专门的手势库，我们那种场景最后是拿 Hammer.js 自己拼的，思路在《Hammer.js 手势库入门》里。

无障碍与自动播放的取舍

paginationClickable: true 只让圆点能被点，但它们是 div，不能聚焦、读屏也念不出来。当年我们的处理是给分页容器补一个 role 和 aria-label，再把当前状态同步到文案上——paginationType: 'fraction'（”3/8”这种）在这里比圆点友好，因为它天然是一段可读文本。

键盘翻页是不能指望库的：2014 年我们用的这个版本没有可用的键盘支持，桌面浏览器上想看轮播只能用鼠标划。补一段原生绑定不难，注意只在本页可见时接管按键：

slideNext / slidePrev / slideTo 都是现成方法；要精确到某片并按自己的时长跳，用 swipeTo(index, speed, runCallbacks)，第三个参数决定是否触发回调——埋点要不要跟着这次跳转上报，就在这里控制。

自动播放本身是有争议的：文案还没读完就跳走了，无障碍指南里也一向不建议无人控制的轮播自动动。我们的取舍是不争论、直接给控制：右下角一个”暂停轮播”的小按钮，点下去走 startStop() 并把文案换成”继续轮播”，同时记住这个状态（写进 localStorage），下次进这个页面就不自动播。成本三十行不到，换来的是客服工单里少一类”我看不清活动规则”的投诉。

小结：接入 Swiper 的检查清单

  1. 版本写死。swiper-2.7.6.min.js 与 swiper-2.7.6.min.css 必须同版本、路径带版本号；换版本时先翻一遍那份源码里的参数表，别照着旧教程抄键名。
  2. update() 与 reInit() 的时机要背下来：追加 slide、改尺寸、图片撑高、容器从隐藏变显示、横竖屏切换之后。前者轻、后者重，能用前者别用后者。
  3. 只要开了 loop，一切与业务数据下标有关的地方都用 realIndex；activeIndex 和 slides.length 都含复制片，只能用来取 DOM。
  4. 事件冲突提前设计：用 swipeHandler 与 onlyExternal 圈定热区，用 noSwipingClass 把输入框、按钮、内层滚动区标出去，内层滚动交给原生。
  5. 真机清单不能省：iOS 6 与 iOS 7 各一台、Android 2.3 与 4.x 各一台、自家 App 的 WebView、微信内置浏览器（2014 年下半年开始，它已经是独立的坑源）。白屏、闪烁、聚焦失效这几类问题，模拟器一律看不出来。

库帮省掉的是手势与位移那一整段最难写的代码，省不掉的是”什么时候要重算、哪个索引是真、哪块区域归谁管”这三件事。把这三件事记牢，换个轮播库也不至于再踩一遍。
