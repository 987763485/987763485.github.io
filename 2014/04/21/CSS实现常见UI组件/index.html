CSS 实现常见 UI 组件

本文属于《HTML 与 CSS》第 38/62 篇
上一篇系列目录下一篇

标签页、面包屑、分页器、进度条、开关、星级评分、工具提示、徽章、加载中，这些是后台系统和活动页里每天都要重复造一遍的东西。2014 年的现状是很多团队直接引 Bootstrap 3（2013 年 8 月发布）的现成组件，改一套配色要覆盖十几个 class，需求一旦超出它的范围就没人敢动。本文面向工作一两年、正被”把这个组件做出来”支配的同学，从 DOM 结构开始，每个组件都给一份可以直接粘贴运行的 HTML 与 CSS，并写清兼容性口径。箭头三角、居中、圆角阴影这几件事我已经单独写过，本文只用一句话引用，不再重复推导。

写组件之前的四条纪律

第一，DOM 结构能少一层就少一层。 一个元素能表达完外观，就不要拆成两个。徽章只需要一个 span，不需要”外容器 + 内数字”两层；工具提示的气泡和箭头可以用 ::before 与 ::after 两个伪元素解决，也不必往 HTML 里塞两个 div。层数少了，样式的继承链短了，出问题时排查的路径也短了。反过来，确实需要两层的地方别硬凑：进度条必须是”轨道 + 数值”两个元素，因为轨道负责边框和背景、数值负责宽度百分比，这是两个职责。

第二，语义与可访问性优先，不要用 div 假装按钮。 理由很实际：div 不能通过 Tab 聚焦，按回车不会触发点击，读屏软件不会播报它的角色，键盘用户直接丧失操作能力。用 <button type="button">（type 必须显式写，否则放进表单里默认是 submit，一点就提交），用 <a> 做标签页和分页的链接（这样禁用 JavaScript 之后它还能退化成一个普通跳转），用 <ol> 做面包屑（它本来就是有序列表），用真实的 input[type=checkbox] 和 input[type=radio] 做开关与评分。role="tablist"、aria-current 这类 ARIA 属性在 2014 年的浏览器和读屏软件里支持还很参差，可以加，但不要指望它救回一个语义错误的结构。老 IE 里 <button> 有点麻烦：IE6/7 会强加一个内建边框、宽度不好控制、字体大小不继承，当年的通用补丁是显式写 font-size 并用 *overflow: visible 触发重算。

第三，class 命名按”组件名-元素名”来。 我们团队 2013 年底开始统一这套写法：组件根节点用组件名（.tabs），内部元素用组件名加连字符（.tabs-nav、.tabs-item、.tabs-panel），状态用 is- 前缀（is-active、is-disabled）。它的好处是全局搜索一个组件名就能拿到全部相关样式，样式表里也天然按组件分块。俄罗斯人 Yandex 公开的那套 BEM 写法和它大同小异，2013 年后在 becss 上讨论得很多，国内团队更多是把它和 SMACSS 的分类思路混着用。不必纠结流派，重要的是别写出 .red-box、.left20 这种把颜色和尺寸当组件名的类。

第四，能用 background 与 border 解决的就不加图片。 圆角、渐变、阴影、描边、箭头都可以纯 CSS 画（三角与气泡的做法见我那篇箭头文，圆角和阴影的参数细节在圆角阴影那篇）。图片只留给两类东西：真正复杂的插画，以及需要精确控制的品牌图标。少一张图就少一次请求、少一套 @2x 出图、少一次”设计师改了 1px 颜色前端要重新切图”的扯皮。

尺寸单位上，2014 年我仍然建议组件内部一律用 px，行高写无单位数值（line-height: 1.5）。rem 现在能用，但 IE8 及以下不支持，把组件的可维护性押在根字号换算上，等于给自己多加一层兼容工作。

标签页 Tabs：:target 的纯 CSS 与 jQuery 类切换

先看结构。导航用 <a>，面板用 <div>，两者的对应关系靠 href="#tab-2" 与面板 id 建立，这样没有 JavaScript 时链接依然可用。

:target 的匹配语义是”当前 URL 的片段标识符指向的那个元素”，所以原理就是：点链接改变 hash，命中面板，面板显示。要让首屏（无 hash）也有内容，需要一个小机关——把默认可见的那个面板放在 DOM 最后，用 :last-child 让它显示；一旦有任何 :target 出现，:target ~ .tabs-panel:last-child 就把这个默认面板藏起来。注意 ~ 只能往后选兄弟，所以当被点击的恰好是最后那个面板时，这条规则不会命中它自己，逻辑正好自洽。面板用绝对定位叠在一起，DOM 顺序就不影响观感，#tab-1 写在中间也无妨。

局限也很明确。第一，min-height 得靠人工给定，因为绝对定位的面板撑不起父容器，面板内容长度不一时更容易露馅。第二，导航项的”当前态”高亮做不到——:target 只能作用在被指向的面板上，CSS 没有反向选择父级或对应链接的能力，只能靠后端在渲染时给链接补一个 is-active。第三，也是最实际的一条：点一下就在 URL 后面挂一个 hash，还会往浏览器的历史栈里塞一条记录，用户按后退键会先在 hash 之间来回跳。要做真正的无刷新路由，得用 History API，我在那篇 History API 的实践文里写过取舍。

面包屑与分页器

面包屑：分隔符交给伪元素

结构上用 <nav> 包一个有序列表，最后一项是当前页，不该是可点链接，直接输出文本。

关于兼容，IE8 是支持 :before/:after 与字符串 content 的，坑在别处：生成内容在老 WebKit 与 IE8 里对 margin 的处理不一致，所以显式声明 display: inline-block 再配 line-height: 1 是最省事的写法，别指望只靠 content 就精确对齐。真正的断点是 :last-child，它要 IE9 才支持。稳妥办法是让后端在最后一项输出 is-current，然后用 .crumb-item.is-current:after { content: ""; } 覆盖，IE8 及以下就都正常了；IE6/7 连生成内容都不支持，只能把分隔符当真实文本写进 HTML，或者接受它消失。顺便一提，IE 私有扩展 expression() 能在 CSS 里跑脚本，当年也有人拿它给伪元素补内容，这条路收益极低、性能极差，不要写。

分页器：inline-block 的空白间隙

inline-block 会把标签之间的换行和空格当成一个真实空格渲染，于是每个页码之间凭空多出 3 到 4 像素，margin 怎么调都不对。font-size: 0 是最常用的一招：父容器字号归零，空白符就没有宽度了，子元素再写回 12px。它有两个副作用要留意：老 IE 在 font-size: 0 时会给容器留下一个非零的最小内容宽度，导致整组偏移，上面用 min-width: 0 加 zoom: 1 兜底；中文 Chrome 有最小字号限制，如果哪天发现某个浏览器里 font-size: 0 被忽略，就换 letter-spacing: -4px 配合子元素 letter-spacing: normal，或者干脆从输出上消灭换行。font-size: 0 还有个连带问题：如果忘了在子元素恢复字号，整块内容就直接隐形了，所以这个容器里的规则要写在一处、别散开。顺带说一句，2014 年想用 Flexbox 一行排开也不是不行，但 IE10 只支持当年那套混合语法、IE9 及以下完全不支持，为了这么一排页码不值得。

当前态用 <span> 而不是 <a>，因为它没有可跳转的目标；省略号同理，并且要靠 cursor: default 和透明边框明确告诉用户”这不可点”。

进度条、徽章与加载中 spinner

进度条：transition 让数值变化有过程

外层负责轨道（边框、内边距、圆角），内层负责数值（宽度百分比），这就是前面说的”该两层就两层”。宽度由服务端渲染或 JS 写进 style，transition: width 让每次 AJAX 轮询更新数值时都自动有补间动画，不用写一行 JS 动画。渐变与条纹的完整语法我在那篇渐变实战文里写过，这里只强调顺序：先写 background-color 再写 background-image，不支持渐变的浏览器才会保留纯色而不是白底。IE9 及以下既没有 linear-gradient 也没有 border-radius，降级方案是纯色加一张 45 度斜纹的平铺 PNG——如果条纹本身是装饰，直接给它加个 is-stripes 类让老 IE 只看到纯色底，是最省成本的口径。

徽章：一个 span 足够

两层结构的”外容器 + 数字”完全没有必要，min-width 加上 line-height 就能让 1 位数是圆形、2 到 3 位数是胶囊形。有一个 CSS 无能为力的点：数字为 0 时不能只靠样式隐藏，因为 CSS 读不到文本内容，必须让服务端或 JS 不输出这个 span。另外 box-shadow 描边在 IE9 以下会整圈消失，底色较深时改用真实 border 更稳。

加载中 spinner：border 加旋转

最小示例就是这样：四条边框同色、只给一条上色，再让它无限旋转。animation 在 IE10 及以上和所有现代浏览器可用，IE9 及以下不会转，只剩一个静态的带色缺口方框——这种地方就是 2014 年仍然要留一张 GIF 的典型理由，别硬用 CSS 补。移动端要注意 Android 2.3 上的 CSS 动画支持不完整，列表里的加载指示建议直接用图片。

开关与星级评分：让表单元素自己说话

纯 CSS 开关

关键点在于隐藏 checkbox 的方式。用 display: none 会把它从可聚焦列表里彻底摘掉，键盘用户就再也切不动了；正确做法是 opacity: 0 让它透明但依然可聚焦、依然保留原生交互——按空格键切换选中、for 关联让点击轨道也能切换、读屏软件能念出 label 文案。这些全是白捡的，是”不要用 div 假装按钮”最直接的收益证明。:focus 那条规则务必保留，否则键盘用户完全不知道自己在哪。兼容口径：:checked 需要 IE9 及以上，Android 2.3 的部分机型上表现不稳；IE6 到 IE8 就退回 class 切换，用 jQuery 在 change 事件里给 .switch 加一个 is-on，样式复制一份即可。

星级评分与 float: right 反序

为什么必须 float: right？因为 CSS 的组合器只能往后选：A:hover ~ B 里的 B 必须在 DOM 中位于 A 之后。我们希望”悬停第 3 颗星时，1、2、3 都亮”，也就是让分值更低的星跟着亮，那么这些星必须在 DOM 里排在被悬停元素的后面——于是标记顺序要写成 5、4、3、2、1。而 DOM 顺序反过来之后，靠 float: right 把视觉顺序再翻回来：浮动元素是按 DOM 顺序从右往左排的，所以最后写的 1 分星落在最左边，正好是 1 到 5 从左到右。等价的另一种做法是给容器加 direction: rtl，但浮动更通用。选中态用 .rate-input:checked ~ .rate-star，因为 input 与后面所有 label 是兄弟关系，能一次点亮它和它左边的星。键盘方面，同 name 的一组 radio 可以用 Tab 进入、方向键切换，value 由表单正常提交，这些是 span 假星给不了的。兼容口径：~ 在 IE7 及以上可用，IE6 只支持 +，所以 IE6 下悬停预亮做不到，降级为”只有后端加过 class 的那颗星亮”；content 里的 Unicode 星号 \2605 在 IE8 也能用，真要统一字形可以换成雪碧图背景。

工具提示 tooltip

文案放在 data-tip 里，靠 attr() 把它喂给 content，好处是文案与样式彻底分离，后端填一个属性就行，不用为每种提示写一个 class。两个坑必须提前知道。第一个是兼容：IE8 及以下不支持在 content 里用 attr()（连字符串 content 在 IE6/7 也不支持），降级办法是把同一句文案同时写进 title 属性，浏览器原生的提示会兜住大部分用户；如果要求所有浏览器一致，就让后端再输出一个 .tip-text 的 span 默认隐藏，靠 :hover 或 JS 显示。第二个是被裁掉：绝对定位的气泡并不会跳出祖先的 overflow: hidden，只要它外面有一层带裁切的容器（表格滚动区、轮播、带 overflow: hidden 的卡片）就会被切一半。遇到这种情况，先确认能否去掉那层 overflow，不能去就改用 position: fixed 或者干脆用 JS 把气泡挂到 body 下——2014 年所有 tooltip 库几乎都是这么做的，这不是 CSS 的失败，是层叠上下文的物理限制。与之相关的是 z-index：只要祖先里有任何一个建立了层叠上下文（position 加 z-index、后来的 opacity 小于 1 也算），气泡的 z-index: 10 就只在这个上下文内部有效，跳出去照样被盖。排查顺序应该是”谁创建了层叠上下文”，而不是无脑把数值加到 9999。移动端另说，:hover 在触屏上不可靠，第一次点击常常只是把提示显示出来，这类交互在触屏上应该改用点击展开或者 title。

读这张表的正确方式不是找”全都支持”的那一列，而是确定你的最低支持线，然后为每条依赖准备一个不炸的退化结果。我一般的口径是这样：结构、语义、可点可提交这些属于基础层，必须从 IE6 起就正确；圆角、阴影、渐变属于观感层，IE8 及以下是直角纯色，可以接受；transition 与 animation 属于动效层，IE9 以下直接没有，但状态切换不能依赖动画——上面每个组件的状态都靠 visibility、background-color 或 class 决定，动画只是让它好看一点。只有 spinner 是例外，它不转就等于没有，所以那个位置在老 IE 上必须换 GIF。前缀方面 2014 年仍不能省：-webkit- 覆盖 Chrome、Safari 与 Android，-moz- 给 Firefox，-o- 给 Opera 12，IE10 的 animation 与 transition 不需要前缀。把这些写全有点笨拙，但比在浏览器里逐个试要便宜。

小结

九个组件写下来，能提炼的共同点其实比代码多。第一，结构决定样式的可能性：:target、:checked、~ 这些能力全都建立在”元素之间必须是兄弟或自身可被伪类命中”上，DOM 多塞一层，选择器就断了，所以少写一层不是洁癖而是给未来留余地。第二，用真实语义元素几乎总能白捡交互能力，开关的空格键、评分的方向键与表单提交、标签页在无 JS 时的降级跳转，都是 div 假装不出来的。第三，兼容性问题不要正面对抗，准备一个不炸的退化结果更划算——圆角阴影渐变交给观感层，状态切换永远靠得着的属性来。第四，Bootstrap 3 之类的组件库该用，但要用得明白：知道它的条纹进度条为什么在 IE9 上只剩纯色，才知道能不能向业务方承诺那个效果。把原理掌握住，抄谁的代码都不心虚。
