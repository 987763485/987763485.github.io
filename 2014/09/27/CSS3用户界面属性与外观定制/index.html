CSS3 用户界面属性与外观定制

本文属于《HTML 与 CSS》第 44/62 篇
上一篇系列目录下一篇

CSS3 里有一批 Basic User Interface 属性，不参与布局也不负责动效，干的是一件更琐碎的事：把浏览器给控件画的默认外观改掉，再把点击、选中、拖拽这些交互行为微调一遍。工程上最常见的用途就两类——给表单做皮肤，以及移动端交互的修补。本文按“先重置、再重建、最后兜底”的顺序，把这批属性在 2014 年 9 月的真实支持情况，以及一套集中管理的组织方式过一遍。

本文的边界与这批属性的定位

这批属性大多来自 CSS3 Basic User Interface Module Level 3，截至本文写作时该规范仍是草案，离 Recommendation 还有距离。所以标准属性走得快、实现跟得慢：box-sizing 与 text-overflow 已经可以当基线能力使用，user-select 还是三个前缀必须写全的局面，而 appearance 干脆找不到 IE 的支持。定位清楚这一点再动手：先查支持率，再决定一个属性写进基线层还是增强层，这是全文所有方案共同的前提。

范围上本文只讲“外观与交互行为”这层。盒模型两套定义与全局 reset 的取舍，《CSS3 box-sizing 与全局重置样式》已经讲透，本文只引用结论；表单取值与校验逻辑在《表单元素操作与表单验证实战》里；长按与选择控制的完整处理在《移动端长按与复制粘贴处理》里。本文的主线是这些属性本身的用法、兼容代价与工程约定。

appearance：重置原生外观的第一步

表单控件自带一整套浏览器画的渲染层——select 的下拉箭头、checkbox 的方框与勾、button 的渐变，这些都不是普通盒模型，光靠 box-sizing 和 border 只能改外壳改不了内核。appearance 的作用就是声明“这个控件不要原生外观，我自己来”。它的取值有 textfield、button、menulist-button、none 等，工程上九成场景只用 none：设了之后控件退化成普通盒子，border、padding、background 全部生效，这是做皮肤重建的入场券。

代价也必须讲清楚。抹掉原生外观的同时，你抹掉的是系统免费帮你画的下拉面板：展开与键盘导航还在，但选项高亮、弹出动画的视觉反馈全变成你自己的事。iOS 上还有个怪脾气——桌面调好的箭头位置，换个 font-size 在 iPhone 上就错位，每次调字号都要重新实测背景定位。

老 IE 是这套方案绕不开的洞：IE 全系不支持 appearance，原生箭头删不掉。务实做法是分层兜底——基线层接受原生外观，只改 border 和背景色，保证完整可用；增强层再用上面这套删箭头自绘。历史上还有一种更彻底的补丁：在 select 右侧绝对定位一张箭头图盖住原生箭头，老 IE 里用 filter: progid 一族渲染图片，属于能用但不体面的方案，这里只留一句。

移动端交互三兄弟：高亮、callout 与选中

移动端 WebKit 有一族带前缀的属性，管的不是外观而是交互反馈。

第一个是 -webkit-tap-highlight-color。iOS Safari 与 Android WebKit 在点击可点元素时会糊上一层半透明灰块，很多团队第一反应是抹掉：

这个属性只吃颜色值，transparent 可以、none 不行。但完全抹掉是有代价的：灰块是页面响应之前触摸屏上唯一的即时反馈，抹掉之后弱网环境下用户分不清“没点到”还是“没反应”。正确姿势是先替代再抹除——给按钮补 :active 的深色背景，保住即时反馈，再关掉系统灰块。

第二个是 -webkit-touch-callout，管 iOS 长按链接与图片弹出的系统菜单。要关就在目标元素上加 -webkit-touch-callout: none，至于关掉之后自定义长按菜单怎么实现、和系统能力的取舍边界，《移动端长按与复制粘贴处理》一文已经讲全，本文不重复。

焦点样式：outline 不是垃圾

全局重置里顺手把 outline 一起清掉，是旧文批评过的老问题，这里正面讲怎么重建焦点样式。outline 的价值在不占布局尺寸，而它通常是键盘用户找到焦点的唯一视觉线索，outline: none 不该是无脑操作。要用自定义效果替换原生焦点框，替换样式必须同时到位：

resize 与 textarea 的实用样式

resize 决定用户能否拖拽元素右下角改尺寸，取值有 none、both、horizontal、vertical。它有个反直觉的生效条件：元素 overflow 必须不是 visible，否则整个属性被忽略——而 textarea 的默认 overflow 恰恰是 visible，所以实战永远成对写：

max-width: 100% 是交过学费的：Safari 的 textarea 有数百像素的默认宽度，移动端布局经常因为它多出横向滚动。resize: none 的适用场景主要是两类——外观伪装成展示区的控件，以及高度由 JS 托管的编辑器，这两种都不该让用户手动拖。resize 从 IE9 起支持，老浏览器忽略它维持原行为，无伤害。

滚动条定制：WebKit 独占的角落

::-webkit-scrollbar 一族伪元素可以把滚动条的粗细、轨道与滑块全部换掉：

::-webkit-scrollbar 的 width 与 height 各管一个方向，需要时还能用 :horizontal、:vertical 伪类把两个方向分开定义。坑集中在 -webkit-scrollbar-button 上：很多教程教人 display: none 隐藏滚动条两端按钮，但部分内核隐藏后滚轮就滚不动、或点击轨道跳位失真，安全的做法要么不动它，要么把它的尺寸压成零。

更大的事实是：这族伪元素只有 WebKit 内核认，Firefox 与 IE 没有对应属性，连“退化到默认”都不算，就是无效果。工程约束随之而来——滚动条可以变好看，但绝不能用它的颜色、粗细传达关键状态，一半用户的浏览器不会配合。触屏设备上滚动条多是覆盖式细条，定制也基本只在桌面 Chrome、Safari 里有意义。

工程约定：ui.css 分组与兼容汇总

这批属性适合集中而不是散写。笔者的做法是把它们收进一个 ui.css（Stylus 项目里是 ui.styl），按四段组织，顺序固定：第一段是重置基线，放 appearance 与 box-sizing 的衔接和控件尺寸基准；第二段是文本，放 text-overflow 三件套、-webkit-line-clamp 与 JS 截字函数的约定；第三段是交互，放移动端三兄弟、user-select 区域类、cursor 与焦点替换样式；第四段是装饰，放 resize 与滚动条伪元素——整段允许在任何浏览器上失效。业务样式只许引用这里定义的语义类名，不许就地重写带前缀的属性，这样补前缀、砍兜底只改一个文件。

小结

三条实践建议收尾。第一，每个抹掉原生外观的属性都要配套分层方案：“支持的是更好看的版本，不支持的是完整可用的版本”；appearance 在老 IE 用原生渲染兜底，:focus 的 box-shadow 用 border-color 兜底，一层都不能省。第二，交互类属性集中写进 ui.css 并按区域给类名，-webkit-tap-highlight-color、-webkit-touch-callout、user-select 三个经常要同时动，散写必然漏掉输入框这类例外；抹除点击高亮之前，先确认页面已经提供了自定义的即时反馈。第三，装饰性的能力止步于增强：多行省略、滚动条皮肤、cursor 新值都属于“一半浏览器不支持”的类别，关键信息与关键操作绝不能依赖它们。CSS3 UI 规范此刻还是草案，但工程策略现在就能定：把支持度写进表格、把兜底写进基线层，草案转正的那天，你只需要删代码。
