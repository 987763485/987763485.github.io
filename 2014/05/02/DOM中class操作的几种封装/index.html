DOM 中 class 操作的几种封装

上一篇《jQuery 操作 class 与样式的方法》讲的是 jQuery 提供的那套 API 怎么用。本文换个角度：把”操作 class”看成一项需要自己封装、需要写规范、需要能被代码审查卡住的底层能力。在只做 PC 站点、页面里只有几十个节点的时候，随手写一句字符串拼接看不出问题；一旦遇上 SVG 图标、旧版 Android 浏览器、几百个列表项的批量状态切换，这些随手写的代码就会变成线上故障。本文给出一套 ES5 的完整实现、与 jQuery 共存时的适配层写法，以及一份可以直接抄进团队规范的检查清单。读完你应该能回答三个问题：class 到底存在哪、怎么改才不出错、改完之后要连带做什么。

底层事实：className 是字符串，classList 是 DOMTokenList

一个元素的类名，在 DOM 层面只有两个入口。

第一个是 className 属性，它就是一个空格分隔的字符串，读写都是整串替换：

第二个是 classList，它是一个 DOMTokenList 活集合，提供 add、remove、toggle、contains、item、length，改动会立刻反映到 className 上。看起来这是最理想的入口，但 2014 年的现实是支持并不整齐，必须心里有数：

环境 classList 状况 实践结论
IE 9 及以下 完全没有 只能走字符串实现
IE 10 / IE 11 HTML 元素完整；IE 10 的 SVG 元素没有 需要按元素类型降级
旧版 WebKit（Chrome 24 之前、iOS 5 / 6） 只有单参数形态可靠 别一次传多个类名
Android 4.0 自带浏览器 基本没有 必须走 polyfill

所以当时能写进规范的用法只有一条：一次只传一个 token，且不依赖强制参数。

原生 toggle 当时也只有单参数形态，传第二个布尔参数在部分浏览器上是无效甚至报错的，需要”用布尔值表达状态”的时候只能自己判断或者交给封装层。另外 classList 是活集合但不是数组，别指望它能用数组的方法遍历，也不要缓存它的引用后又去整串改 className（集合会跟着变，但你在循环里持有的索引语义就乱了）。

还有一个坑是写 SVG 图标时踩到的：SVG 元素上的 className 不是字符串，而是 SVGAnimatedString 对象。

这就是我们自己动手实现的第一条设计约束：读用 getAttribute('class')，写用 setAttribute('class')，让 HTML 与 SVG 走同一条路。

自研 tiny 实现：四个函数加一次特性检测

下面是我们在用的那一份，单文件、无依赖、UMD 形式。它刻意只用 for 循环和 split，不调 filter、map、indexOf、trim，这样在 IE 8 上也不需要额外补丁。

几个实现上的取舍值得说明。

第一，去重与空格归一化都靠 splitNames 加一次 join 完成，所以 add 一个已经存在的类不会让 className 变长，多次调用也不产生垃圾空格。

第二，polyfill 路径先算数组、最后一次性赋值。如果写成 current.forEach(function (n) { el.className = el.className + ' ' + n; })，每个类名都会让 DOM 属性失效一次，浏览器要重复做多次样式标记；连续多次写中间还夹着一次读布局的操作，就直接变成多次重排。原生路径因为要遵守”一次一个 token”，确实会有多次 DOM 写，但它的出错率远低于字符串方案，这点代价是值得付的。

第三，changed 标记的作用不只是省一次赋值，更重要的是避免”无意义的 DOM 变动”触发 MutationObserver 或者第三方埋点的重渲染。

第四，toggle 的强制状态由我们自己的参数提供，这样上层代码不用关心当前浏览器支不支持那个尚未统一的第二参数。

与 jQuery 共存：一条混用规范和一层适配

项目里已经有 jQuery，为什么还要自己写？反过来问更清楚：为什么一个页面里一半用 $().addClass、一半用原生字符串操作会出事？真正会出事的不是 class 本身——两边读写的都是同一份 DOM 属性，值总是同步的。出事的是围绕 class 的那两份”状态缓存”。

一个是 data() 的缓存。上一篇旧文里提过，jQuery 会把首次读到的 data-* 值缓存进内部对象，之后你直接改 HTML 属性它是感知不到的。于是当脚本 A 用 $panel.data('expanded', true)、脚本 B 用 el.setAttribute('data-expanded', 'false')，同一个面板在两份代码里就是两个状态，谁对谁错全看加载顺序。

另一个是事件命名空间。.on('click.panel') 注册的东西只有 $off('.panel') 能摘干净；用原生 removeChild 把节点拔掉，jQuery 的数据还留在缓存里，节点重建后旧的处理函数很容易被重新挂上一遍，出现”点一次触发两次”。

所以规范可以定成一句话：同一个模块内只允许一种 class 写法。有 jQuery 的模块一律走 $()；需要同时伺候 SVG 图标、旧 Android 浏览器、或者被别的非 jQuery 脚本复用的工具层，一律走 domClass。跨界的时候只通过适配层。

状态类名的设计约定

工具解决了”怎么改”，命名解决的是”改完之后别人能不能看懂”。我们沿用的前缀约定很简单：

前缀 语义 例子 约束
is- 元素自身的状态 is-open is-loading is-disabled 同一组内互斥
has- 持有某种修饰或子内容 has-error has-dropdown 可与 is- 共存
js- 只给脚本做选择器 js-toggle 样式表禁止依赖
no- 显式否定，用来盖住默认 no-transition 优先级最高

js- 前缀的价值在于把”结构钩子”和”视觉表现”解耦：设计师改样式时可以随便换类名，只要 js-toggle 还在，脚本就不会瞎。反过来，样式表里出现 .js-toggle { color: red; } 应该在 CR 里直接打回。

互斥比叠加更重要。一个面板的展开收起，应该写成 is-open 与 is-closed 只存在其一，而不是”有 is-open 是开、没 is-open 也可能是开但还在动画中”这种要靠推断的状态。互斥状态用一组类名穷举，配合一个设置状态的函数，可以让”删旧加新”这件事只有一处实现：

兜底定时器不能省。元素被 display: none 隐藏、或者页面切到后台时，transitionend 根本不会派发，只监听事件的话回调永远不执行，动画类就永久残留下来，这类”偶发一次再也复现不了”的 bug 最难查。超时时间取 CSS 里的 duration + delay 再加几十毫秒裕量。

性能：改一次 class 的代价花在哪

改 className 不会立刻重排。浏览器把元素标记成失效，真正的样式重算、布局、绘制要么在下一帧统一做，要么被一次读布局属性的操作提前拽出来。所以讨论 class 的性能，要讨论的是这三件事。

第一是命中的规则数量。一个状态类在样式表里带出多少条规则、这些规则覆盖多少个节点，决定了样式重算的量。.is-active 只改 background-color 是重绘，改 padding 或 font-size 就会连带重排它自己和它的后续兄弟；如果它在文档里被写在 .list .item 这种高复用选择器上，一次切换要更新的盒子可能上百。

第二是选择器匹配的代价。当时主流引擎的后代选择器是从右往左匹配的，.modal .panel .list .item.is-active .title span 这种链条，最右侧 span 的候选节点最多，每一层向上回溯都可能失败。把状态类挪到靠近实际要改属性的元素上、把链条缩短，比加 !important 或者在脚本里写内联样式健康得多。

可访问性：class 切换必须同步 ARIA

只改 class 是不够的。屏幕阅读器看到的不是你的样式表，而是可访问性树里的角色和属性。展开收起这类交互，视觉上的”收起来了”和语义上的”收起来了”是两件事：用 height: 0 加 overflow: hidden 藏住内容，DOM 还在、还在可访问树里，读屏用户依然会读到一整段”看不见”的文字。

WAI-ARIA 1.0 规范当时还在候选推荐阶段（2013 年 9 月发过 Last Call 工作草案），但 aria-expanded、aria-hidden、aria-controls 这几个属性主流读屏软件已经支持得不错。写进规范里不难，难的是别忘了写：

这套实现值得配一组小单测，成本很低，覆盖的都是真实出错过的场景。断言直接用 throw，跑在任何页面的控制台里就行。

代码审查这一侧，把规矩写成可以直接对照的表格比写三段说明有用。下面是我们现在逐项打勾的版本：

检查项 结论 说明
用 className.indexOf 判断类名 禁止 子串误匹配，见第二节的线上故障
用 className += 或 replace 增删类名 禁止 空格失控，还会切断别的词
手写正则匹配类名 禁止 连字符会被 \b 误判成边界
classList.add('a', 'b') 传多个 token 禁止 旧 WebKit 只加第一个
依赖原生 toggle 的第二参数 禁止 当时行为不统一，交给 domClass.toggle
对 SVG 元素读写 className 禁止 它是 SVGAnimatedString，走属性
一个元素同一组状态叠加多个类 禁止 用互斥的 is- 类穷举
动画类没有摘除逻辑 必须补 用 playOnce，并带兜底超时
class 切换未同步 ARIA 属性 必须补 aria-expanded 与 aria-hidden 同一处写完
循环里交替读写布局 必须改 先读完算成数组，再统一写 DOM

小结

class 操作看起来只有一行代码，但它底下压着三个容易忽略的事实：className 是整串替换的空格分隔字符串，classList 在当时还不完整且对 SVG 元素不可靠，状态类名同时牵着样式、脚本逻辑和无障碍语义。工程上的对策也就这三条：把所有增删判断收进一份可靠的实现（能走原生就走原生，走不通就 split 成数组去重后一次写回），在一个模块内只允许一种写法并用适配层守住 jQuery 的链式习惯，再给状态类名定下前缀与互斥约定。动画类必须配合 transitionend 加兜底超时摘干净，可访问性属性必须和视觉状态在同一次调用里写完。最后，这些约束只有进 CR 清单和单测才算真的落地——grep 一下 className.indexOf，十分钟就能把一个历史项目扫干净。
