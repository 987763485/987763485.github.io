CSS 打印样式表 print 实践

本文属于《HTML 与 CSS》第 60/62 篇
上一篇系列目录下一篇

后台系统的验收会上，产品提了两条需求：”订单明细要能直接打印成 A4 交给仓库”，以及”月度报表要能导出 PDF 存档盖章”。看着都是”把网页变成纸”，做完才发现是两件事：前者给人看一眼就扔，后者要进档案柜、要能被别人打开、要防止篡改。本文把 CSS 打印样式表这条路的写法、关键属性、浏览器坑和验收方法完整走一遍，再和”服务端生成 PDF”做个选型对比，最后给出我们落地的混合方案。适合做过屏幕样式但对 print 媒体一无所知的前端，读完你应该能独立写出一份能交付的打印样式。

两个需求其实不是一回事

先把两个概念拆开。

打印（print）的目标是纸。读者是仓库里的大哥，纸用完就进抽屉，内容正确、别把表格行拦腰截断就行。它的实现成本极低：屏幕页面已经渲染好了，浏览器按 Ctrl+P 就能出纸，前端只要补一份 @media print 的样式，把屏幕上不该出现在纸上的东西干掉，把分页控住。服务端一行代码不用改。

导出 PDF 的目标是文件。它要落盘、要发邮件附件、要进归档系统、要能被 Adobe Reader 打开、可能要加公司抬头和水印、甚至要盖章扫描回来做双向核对。这种需求下，”用户在打印对话框里选 Adobe PDF 打印机”是一种妥协而不是方案——你没法保证他选对，也没法保证文件名和内容排版每次一致。

混在一起做的后果我们吃过一次：产品说”加个导出 PDF”，前端偷懒绑了个 window.print()，两个月后财务归档时发现存下来的一半是用户随手选的”另存为网页”快照，页边距、页码、抬头全都不统一。从那以后我们的判据是：输出物是不是一个需要被第三方消费的持久文件，是就走服务端，不是就走 CSS。

媒体查询与四种落地写法

打印样式的挂载方式有四种，各自的取舍如下（表格里的”额外请求”指是否多一次 HTTP）：

写法 额外请求 是否阻塞屏幕渲染 可维护性 适用场景
<link rel="stylesheet" href="print.css" media="print"> 是（一次） 否，print 媒体不参与屏幕布局 好，独立文件 打印样式超过一屏、多人协作
<style media="print"> 内联 否 否 差，混在主 HTML 里 单页应用、临时给某一页打补丁
@import url("print.css") print; 是，且串行 是，@import 会拖慢首屏 一般 老项目复用现成样式入口，新项目不推荐
JS 切 body 上的 class 否 否 最差，状态在 JS 里 需要配合 beforeprint 做数据重渲染

外链一份独立文件是我们最终选的方式，理由不是性能而是边界：打印样式改坏了不该影响屏幕，物理隔离比约定”这段别动”可靠。

真正让这条路便宜的是共享同一份 DOM。屏幕页面已经把数据渲染成表格了，打印样式只是换一套皮肤：不用重复请求接口、不用维护两套模板、不用在服务端再造一套表格结构，字段改了只要改一处。相对地，服务端生成 PDF 要么把同一份 HTML 交给一个独立的渲染引擎再解析一遍（等于两套模板），要么用 Java 手写一遍表格（等于三套）。这个成本差是选型时最实在的砝码。

打印样式的核心属性

下面是我们 print.css 的主体，逐段解释。

页面尺寸与页边距

size 的合法值是 A4、A3、letter 这类关键字，或者两个长度（先宽后高）。注意 @page 里能写的属性非常少，规范给了 size、margin、marks、bleed、page 这几样，此外基本都是无效的——别指望在这里放 padding 或 background。其中 marks（裁切标记）与 bleed（出血）是给印厂用的，page 用来给页面命名以便分别设置样式，这三样在 2014 年没有任何浏览器实现，只有 size 与 margin 值得写进生产代码。

分页控制

这是打印样式里性价比最高的一段，纯粹在解决”表格行被切成半行”这个最难看的毛病。

page-break-inside: avoid 是必写的，加在 tr 上能解决 90% 的投诉。但要清楚它是建议而非强制：一行内容比一页还高时浏览器只能切断。orphans/widows 只对块级文本生效，对表格无效，别浪费时间去查为什么不生效。

背景色默认不打印

浏览器出于省墨的默认策略，打印时不会输出 background。所以屏幕上一张漂亮的表头底色，纸上是一片白。两条出路：

  1. 让用户在打印对话框勾选”背景颜色和图像”（Chrome 的”选项”里、IE 的”颜色”选项卡里名字各不相同）——这是用户操作，前端控制不了，得写在操作手册里。
  2. WebKit 系（Chrome、Safari，含 Windows 版 Safari）支持一条私有属性，只有带前缀的写法生效：

2014 年这个时间点，Firefox 和 IE 都不认这条私有属性，去掉前缀的写法也不存在任何实现。所以我们的做法是：纸上必须出现的色块一律用边框和字符表达，底色只当锦上添花。比如状态列除了色底，再加一个”【加急】”文字前缀，保证黑白打印也读得懂。

删掉屏幕元素、补回链接地址

content: attr(href) 这一招是纸面可读性的关键，Bootstrap 3 自带的打印样式表里就有同款规则，可以拿来抄。要提醒的是长 URL 会把行撑破，必要时配合 word-wrap: break-word。

为什么正文一般给 10.5pt 或 12pt？因为 12pt 换算成屏幕是 16px，正好是我们习惯的正文大小，而印刷可读的下限大约在 9pt（12px）——再小仓库里的人戴上老花镜也看不清。屏幕上习惯写 px，打印样式里请改成 pt，或者直接用 mm，物理单位在纸上是可预期的。

现实约束与几个绕不过去的坑

理想很规整，现实里浏览器各自有主意。

@page 的支持差异

我们的实测结论（截至 2014 年 5 月，Chrome 33 / Safari 6 / Firefox 28 / IE 8-10）：

  • size 基本别指望。Chrome 与 Safari 会忽略 @page 的 size，纸张以打印对话框选的类型为准；Firefox 同样不支持；只有 IE 8 以上认一部分。所以纸张必须由用户或者打印机驱动决定，不要假设纸上就是 A4。
  • margin 的表现是”各家都不稳”：Firefox 与 IE 会用它，Chrome 长期以对话框里的页边距设置为准。所以正文的留白要靠 body/容器的 padding 自己兜住，@page 的 margin 当作可选优化。
  • 页眉页脚（页码、文档标题、日期）没有任何浏览器提供页面可控的入口。CSS Paged Media Level 3 草案里的 margin box（@top-center 这类）和 running element（position: running(header)）写得很漂亮，但当时没有一个浏览器实现，规范状态也还是草案，不要往生产代码里写。浏览器打印时加的页脚（”第 1 页，共 3 页”和标题、URL）只能引导用户去对话框里勾选或取消，位置和字号你控制不了。
  • 老代码里流传一种只针对 IE 的土办法：在页面上放 id="header"、id="footer" 的块，配合 IE 私有的 CSS 表达式（expression(...)）与负定位把它顶进页边距区。IE 的表达式在 IE 5 到 IE 9 有效、IE 10 标准模式已禁用，其它浏览器一律忽略，属于厂商私有扩展。我们现在不建议再写这种代码，维护成本远高于收益，真要精确的页眉页脚就走服务端。

分页媒体里 thead 会在每一页顶部自动重复，tfoot 在最后一页底部重复，这是免费送的。但前提是别用 CSS 破坏表格结构：

移动端几乎没有打印入口

iOS Safari 的分享面板里没有直接打印，只能”发给自带 App”（邮件、AirPrint 打印机）；Android 自带浏览器 4.4 时代没有打印菜单，Chrome for Android 到 2014 年也还没上打印能力。也就是说移动端的”打印”按钮点了没反应。现场最常见的处理是发给电脑再打——和之前《移动端调试工具与实践》里”很多问题只能在真机上复现、再回桌面处理”是同一个思路：移动端只负责查看和转发，输出交给桌面浏览器。所以打印按钮在移动端应该直接隐藏，或者降级为”分享到邮件”。

验收：怎么知道打印样式做对了

打印预览能做到所见即所得，但它不等于纸。预览的字体渲染、边距和真实打印有系统偏差，尤其：

  • 预览按屏幕字体（微软雅黑）度量，纸上的换行点可能不同；打印机驱动可能用内置点阵字体，字距变化更大。
  • 页边距受驱动的物理不可打印区限制。多数激光打印机四周各有 4-5mm 打不出去，紧贴边缘的边框线会缺一角。
  • 分页点受内容高度影响，同一份页面在 A4 与 letter 上分页位置完全不同。

量可打印区域有个简单办法：临时放一个占位块，宽度和高度都撑满一页，打出来用尺子量。

从 height: 842pt 开始试，只要溢出就会多打一张空白页；缩到刚好一页不打空页时，那个高度减去已知的 @page/对话框边距，就是你真正可用的内容高度。我们的经验值是 A4 加 20mm 边距时可打印区约 482pt x 729pt，一页正文大约能放 40 行表格（每行 16pt）。

纸张也不只有 A4。餐饮后厨与物流分拣用的是热敏小票机，常见纸宽 80mm 与 58mm，纸是连续卷纸、没有固定页高：

小票场景三个额外注意：不要背景色（热敏打不出底色，只能打粗体）、不要细线（0.5pt 边框会断）、每行字符数比字号更要命——80mm 纸用等宽 10.5pt 一行大约 48 个半角字符，超出就自动折行错位。至于 A5（421pt x 595pt），最常见的用法是快递面和笔记本内页，直接按同样公式换算即可；关键是代码里不要出现任何”按 A4 硬算”的魔法数字，把一页高度写成变量或者干脆用 100% 加 page-break-inside 控制。

和”服务端生成 PDF”怎么选

两条路的成本和能达到的控制力对比：

维度 客户端 window.print + CSS Flash/Flex 打印 服务端 HTML 转 PDF 服务端手写模板（iText 等）
服务端成本 零 零 中（要装依赖、起进程） 高
排版还原度 与屏幕一致 与 SWF 一致 取决于转换引擎 完全可控
页眉页脚/页码 不可控 可控 可控 完全可控
精确分页 只能 avoid，不能强制 可 可 可
批量 / 定时 / 邮件 做不到 勉强 天然支持 天然支持
归档一致性 弱（用户选什么打印机都行） 中 强 强
部署风险 无 客户端要装插件 引擎是独立进程，要考虑内存与并发 开发量大

几个具体选项在 2014 年的状态：

  • wkhtmltopdf：把网页喂给一套打过补丁的 WebKit 渲染再输出 PDF，命令行 wkhtmltopdf --page-size A4 --margin-top 20mm url out.pdf。好处是能复用 HTML，坑在于它的 WebKit 版本落后于浏览器、老版本在服务器上还需要虚拟 X（xvfb-run），中文要自己塞字体，复杂 CSS（表格浮动、绝对定位）会走样。适合”能看就行”的存档。
  • Prince：对 CSS 分页媒体支持最好的商业实现，@page 的 margin box、页码计数器都真能用。可惜按页收费，报价对我们这种内部系统是天文数字，只有对排版要求极高的出版物场景值得。
  • pdflatex / LaTeX：排版质量顶级，但要先把 HTML 转成 LaTeX 源，前端和后端谁都不愿意维护这套东西，成本完全不成比例，pass。
  • Java iText：在代码里一个单元格一个单元格地画表格。像素级可控、体积可控、页眉页脚随便写，代价是和屏幕样式彻底脱节——改一个字段两边各改一遍。财务凭证、发票类必须精确的东西才值得。
  • Flash/Flex 打印（FlexPrintJob）：还有一批 2010 年前后的系统在跑，打印排版能力确实比 CSS 强，但依赖客户端插件，新系统我们不再选。
  • 导出为图片：html2canvas 从 2012 年起就有了，思路是在 canvas 里重绘 DOM 再 toDataURL。听着适合”报表截图发群里”，但它对 CSS 的支持非常有限——背景渐变、iframe、部分字体、transform 都还原不了，产出的是一张长图，分页语义全无，且体积大、打印时清晰度取决于导出倍率。当”分享快照”用可以，当”打印方案”用不行。顺带说明：pdf.js 是把 PDF 渲染到 canvas 的阅读器，方向反了，不能拿来生成 PDF。

我们的判据最终固化成三句话：

  1. 只给人看、看完即扔 → CSS 打印。零服务端成本，改样式不用发版。
  2. 要归档、要盖章、要批量、要邮件发送 → 服务端 PDF。输出物是文件就必须由服务端保证一致性。
  3. 要严格分页、页眉页脚、页码、水印 → 服务端模板（Prince 或 iText），别在浏览器上硬凑。

我们最终落地的混合方案

结论是两套并行，各管一段。屏幕页面维护一份 @media print / print.css，覆盖仓库日常打印订单明细这类需求；月度报表与凭证走服务端。为了让”打印”这一步可控，我们在页头加了一个打印预览按钮：先用接口返回的数据把静态视图渲染到独立容器里，确认无误后再调 window.print()。

配套的样式在 print.css：屏幕上 #printArea 藏在预览弹层里，打印时只留它。

小结

打印样式最容易被忽略的价值在于它复用屏幕的 DOM，几乎零成本，适合”给人看一眼就扔”的场景；一旦输出物要归档、盖章、批量或邮件投递，就必须交给服务端 PDF，判据是”文件是否要被第三方消费”。技术上，@page 的 size 与 margin 在浏览器里都不可靠，留白要用 body 的 padding 兜底；page-break-inside: avoid 加在 tr 上收益最大；thead 会自动重复但要求 CSS 不破坏表格的 display；背景色默认不打印，-webkit-print-color-adjust 只有 WebKit 认；页眉页脚在浏览器侧无解。单位改用 pt 或 mm，正文 10.5pt 到 12pt，A4 内容区约 482pt x 729pt。验收一定要真机打一次，用整页占位块量出可打印区，别忘了热敏小票这类非 A4 纸张；移动端普遍没有打印入口，按钮该隐藏就隐藏。
