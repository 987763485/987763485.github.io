HTML5 文档大纲与标题层级的正确用法

本文属于《HTML 与 CSS》第 4/62 篇
上一篇系列目录下一篇

HTML5 引入了 sectioning content，理论上改变了标题层级的计算规则——每个 section 内部的 h1 都重新开始一级。这个设计在规范里写得很漂亮，但 2014 年初的现实是：没有任何浏览器实现了它。本文从入门角度，讲清 HTML4 与 HTML5 大纲规则的差异、为什么不能真的按新规则写，以及当年务实的标题层级实践。结论先给出：继续按 h1 到 h6 逐级递减排，不要跳级，把 section 当作分组容器而不是层级计数器。

HTML4 的标题层级规则

HTML4 时代规则简单粗暴：h1 到 h6 直接表达文档层级，数字越小层级越高，不跳级是硬约定。

这套规则的优点是直观、工具支持好。屏幕阅读器、大纲工具、爬虫都按这个层级理解页面结构。缺点是表达力弱：嵌套结构一旦深了，标题数字会被迫变大（层级越深数字越大），而视觉上我们往往希望深层的标题字号也还过得去。更重要的是，一个页面里只能有一个 h1 成了不成文的规矩，而实际页面常常有多个平等的顶级区块。

HTML5 的 sectioning content 与大调整

HTML5 新增了四个 sectioning content 元素：section、article、aside、nav。规范里，这些元素会创建新的”大纲节点”，节点内部的标题层级被重新计算。

规则大致是这样：从文档根开始，遇到一个 sectioning content 元素就压栈一层，里面出现的第一个标题元素（不管它是 h1 还是 h6）就成为这一层的标题。所以下面两个结构在规范下是等价的：

这个设计的出发点很好：让标题的”语义级别”与”视觉样式”解耦。CSS 想怎么控制字号都行，结构层级由嵌套决定。它还顺带解决了 syndication 问题——一篇文章被 RSS 抓走或者被嵌入别的页面时，它的 h1 依然是 h1，不需要因为宿主页面已有 h1 而改写。

大纲算法并未被实现

关键事实：HTML5 的大纲算法（outline algorithm）在 2014 年初没有任何浏览器实现。这不是”实现有差异”，而是”根本没实现”。浏览器生成的可访问性树里，标题的层级就是它的标签名，h1 就是一级，h2 就是二级，嵌套的 section 不会让里面的 h1 降级。

这意味着写法二在真实世界的后果是：一个页面里出现五六个 h1，屏幕阅读器会把它们全部报成一级标题，用户听到的是一串平级的标题，完全失去结构。

因此当年的实践共识是：把 HTML5 大纲规则当作提案看待，代码按 HTML4 的层级规则写。W3C 的规范文档自己也没有采用”全部用 h1“的写法，这个信号已经足够明显。

正确的标题层级实践

结合现实，下面几条是 2014 年初可以直接落地的规则。

一个页面一个 h1。 它应该是页面的主题——文章标题、产品名、站点名。多个 h1 在未实现大纲算法的浏览器里就是多个一级标题，没有好处。

不跳级。 h2 后面直接跟 h4 是错的，中间应该补 h3。跳级会让依赖标题导航的用户（屏幕阅读器用户、用阅读模式的用户）丢失层级线索。

独立文章可以用 h1。 一篇博客文章的主体，页面上最显眼的标题就是文章标题，用 h1 合理。站点名称可以放在 header 里用 p 加样式而不是 h1，避免与文章标题争夺一级位置——这是博客类站点最常见的争议点。

header 与 footer 不产生大纲节点。 这是 HTML5 与 HTML4 的一个实质差别。header 只是”区块的头部容器”，无论它出现在页面级还是 article 内部，都不会创建新的层级。所以 header 里的标题依然按全局层级计算：

反过来，footer 也一样。页脚里的版权信息不需要标题，如果非要有，层级依然从属于所在区块。

section 要有标题。 规范里 section 是主题性分组，隐含它应该有自己的标题。如果一个块只是想包起来加样式，用 div。滥用 section 会让结构看起来有层级、实际语义上说不通。

用工具验证大纲

2013 年验证大纲的可靠手段不是浏览器，而是第三方 outliner 工具。W3C 的 validator 带大纲输出，一些浏览器扩展和在线工具也提供这个功能。它们的共同点是按规范实现大纲算法，所以你既能看到”规范认为的结构”，也要记得浏览器实际不是这么读的。

用法很直接：把线上页面的 HTML 存下来，贴到工具里，看生成的大纲树。检查点有几个：

  • 顶层是否只有一个节点（h1）。
  • 层级是否连续，有没有跳级。
  • 每个 section 是否都有对应标题，否则是滥用了 section。
  • 大纲树的形状是否与视觉结构一致。

一个常见发现是：侧栏的推荐文章用了 h2，而正文的小节也用 h2，两者在大纲里平级，但语义上一个是从属内容一个是主干。这种问题靠肉眼看页面发现不了，大纲工具一跑就暴露。

SEO 角度的建议

从搜索引擎的角度，标题层级的影响在 2014 年已经相当温和。真正决定排名的是内容质量、外链、页面性能，标题标签只是众多信号里较弱的一个。但有几点仍然值得做：

  • 标题文本要有信息量。<h2>更多</h2> 不如 <h2>更多性能优化文章</h2>，爬虫和用户都受益。
  • 关键词自然地出现在 h1 和靠前的 h2 里，不要堆砌。
  • 标题层级清晰有助于爬虫理解页面结构，对长文尤其明显。
  • 图片的 alt 与所在区块的标题语义一致，别让 alt 与标题各说各话。

不要为 SEO 制造假结构：把一个 h1 藏在页面顶部只为了塞关键词，或者把页脚堆满 h2。这类做法对排名帮助有限，且会严重伤害使用屏幕阅读器的真实用户。

小结

HTML5 的 sectioning content 在规范层面重新定义了大纲计算，section 内的 h1 会重新成为该层级的标题，标题的语义级别与视觉样式因此解耦。但 2014 年初没有任何浏览器实现大纲算法，标题层级实际上仍由标签名决定，所以务实的做法是按 HTML4 规则逐级递减排标题、一个页面一个 h1、不跳级。header 和 footer 不产生大纲节点，其中的标题仍按全局层级计算。独立文章主体用 h1 合理，站点名可退化为样式化文本以免争夺一级位置。验证大纲用 W3C validator 或第三方 outliner 工具，重点检查顶层唯一性、层级连续性和 section 是否都有标题。SEO 上标题层级只是弱信号，清晰的层级结构和有信息量的标题文本比堆砌关键词更有价值。
