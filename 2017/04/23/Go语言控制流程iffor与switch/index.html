Go 语言控制流程：if、for 与 switch

本文属于《Go 语言与工程》第 3/78 篇
上一篇系列目录下一篇

从 Java 或 JavaScript 转写 Go，最先卡住的往往不是类型系统，而是控制流程的写法：没有 while，switch 不用写 break，if 的条件不带括号。这些差异单独看都很小，合在一起却会改变代码的组织方式。本文按关键字逐个梳理 if、for、range、switch、类型 switch 与标签跳转，说明它们与旧习惯的差别在哪里、坑通常出在什么地方，适合已有其他语言基础、刚开始写 Go 的读者。

从 Java 和 JS 转过来的三处意外

笔者最早用 Go 是在一个日志收集服务上。需求很简单：从队列取消息，失败就退避重试，最多五次。这段逻辑在 Java 里写过很多遍，于是顺手敲下 while (retry < 5) { ... }，编译器给出的第一句话就是语法错误：Go 没有 while。改成 for retry < 5 { ... } 之后才通过。

第二个意外来自 switch。在 Java 和 JavaScript 里，漏写 break 会一路穿透到下一个分支，是新手最常见的 bug 之一；而在 Go 里，每个 case 执行完自动结束，不需要 break，写了反而显得多余。第一次写的时候下意识补上 break，编辑器不报错，但读起来别扭，因为整个语言的心智模型和过去相反。

第三处是 if 后面的括号。if (err != nil) 在 Go 里能编译，只是括号被当成普通的分组表达式，习惯上省略；条件本身也不再接受”非零即真”，必须是 bool 类型。这三处差异看起来只是形式，实际会影响代码的组织方式，下面按关键字逐个拆开。

if：括号没了，多了初始化语句

Go 的 if 只有一种形式：if 初始化语句; 条件 { ... }，初始化语句可选，条件必填，且必须是布尔表达式。花括号不能省略，else 必须和右花括号写在同一行。后者不是风格偏好，而是语法要求：Go 会在行尾自动插入分号，如果把 else 换到下一行，它就成了一个孤立的语句，编译直接失败。

条件必须显式比较。C 与 JavaScript 里 if (ptr)、if (len)、if (name) 这类写法在 Go 中一律编译不过，if err 也不行，必须写 if err != nil。初看啰嗦，但它消灭了”空字符串算假、空数组算真”这种语言之间的隐式约定，读代码时不需要回忆类型。

range：统一了所有容器的遍历

手写三段式在 Go 里并不常见，遍历容器基本都用 range。它支持数组、数组指针、切片、字符串、map 和 channel，是这门语言里唯一的 foreach 形式。两个返回值分别是索引（map 里是键）和元素：

这也是结构体较大时的推荐写法：for _, v := range 每次迭代都要复制一遍，字段多、体积大时开销可观。只要下标就写 for i := range s，只关心次数就写 for range s，这两种写法都不会产生元素拷贝。

range 后面的表达式只求值一次。切片被复制的是切片头，也就是指针、长度和容量，循环次数在开始时就定了。因此在循环体里 append 不会让循环多跑几轮；如果追加触发了扩容，底层数组换了新地址，循环看到的仍然是旧数组，改动是否可见取决于是否共享底层数组。这个细节在批量过滤时最容易踩到：一边 range 一边往新切片里追加是安全的，一边 range 一边往原切片里删元素则不成立。

字符串：按 rune 而不是字节

字符串是 range 里最特殊的一个。Go 的字符串本质是只读字节序列，通常按 UTF-8 编码，而 range 会先解码再返回，所以拿到的是字符（rune，即 int32），索引则是该字符首字节的位置：

索引从 3 直接跳到 6，因为一个汉字占三个字节。这与 len(s) 的口径一致：len 返回字节数而不是字符数，上例中 len(s) 是 9。想要字符数得用 unicode/utf8 包的 utf8.RuneCountInString(s)，要取第 n 个字符也不能写 s[n]，只能转成 []rune 或者用 range 数过去。

如果按字节下标遍历，s[i] 的类型是 byte，遇到多字节字符时只能拿到半个字符，拼出来就是乱码。反过来说，判断前缀、查找 ASCII 分隔符这类操作按字节处理更快，不必强行转成 rune。

switch：默认不穿透，穿透要显式

switch 的第一条规则就是和 C 系语言相反的那条：每个 case 执行完自动结束，不会落到下一个分支。break 在这里是多余的，写了不报错，但会让读过 Java 的人误以为下面还有逻辑。真正需要穿透时必须写 fallthrough，而且它只能出现在 case 块的最后一行，不能带条件，也不能用在最后一个 case 上。

分支超过三个、条件又都在比较同一个变量时，这种写法比嵌套 if 更容易扫读。它同样支持初始化语句，switch v := f(); { 是合法写法，变量作用域限于整个 switch。default 的位置可以随意放，但只在所有 case 都不匹配时执行；习惯上仍然写在最后，别让读者多找一遍。

switch 内部的 break 只跳出 switch 本身；外面还套着 for 时，要让循环一起停下，只能用下一节的标签。

类型 switch：让接口值落地

switch v := x.(type) 是类型断言的分支版本，用来根据接口值的动态类型分派逻辑。它只能写在 switch 里，且 x 必须是接口类型，对具体类型使用会编译失败。

每个 case 里 x 的静态类型取决于该分支列了几个类型。只列一个时，x 就是那个具体类型，可以直接调用它的方法；列了两个及以上，x 退回原来的接口类型，想用具体方法得再做一次断言。case nil 匹配的是接口本身为 nil 的情况，和”接口里装了一个 nil 指针”不是一回事，后者会落到指针所属的具体类型分支。

类型 switch 常用来处理 interface{} 形态的配置值和 JSON 解码结果。它的可读性比连续写 if _, ok := x.(T); ok 好得多，也比反射安全：漏掉的分支会走 default，不会在运行时突然 panic。至于 default 里要不要直接报错，取决于这个接口的封闭程度，后文会再提。

标签、break 与 goto

嵌套循环里想一次跳出两层，Go 没有”带层数的 break”，用的是标签。标签写在 for、switch 或 select 的前一行，以冒号结尾，break 和 continue 后面跟上标签名就能指定目标：

break outer 直接结束最外层循环，中间那层不会再多跑一轮。把 break 换成 continue outer，效果是跳过外层当前这一轮、继续下一轮，内层剩下的元素也不再处理。这两种写法在解析二维结构、按条件提前收工时非常直接，比引入标志变量干净。

标签必须紧贴在循环或分支语句之前，中间不能插入别的语句。

goto 同样依赖标签，但限制更多：只能在同一个函数内跳转，不能跳过变量声明，也不能跳进另一个块。它在标准库里有少量用例，比如统一跳到函数末尾做清理，但在业务代码里通常被视为坏味道。一个 goto 往往意味着这段逻辑该拆成独立函数，用 return 和 defer 表达退出路径。

作用域与变量遮蔽

if 和 for 支持初始化语句，:= 又会在当前作用域创建新变量，两者相遇就容易出现遮蔽：内层变量和外层同名，内层赋值成功，外层却一直是旧值。

发现手段有限。go vet 的 shadow 检查在当时的版本里还需要单独开启，编辑器与 gometalinter 一类工具会提示一部分，但漏报不少，最终还是靠读代码时留意 := 左边的变量名。规避办法有两个：需要复用外层变量时提前声明，用 = 赋值；或者把这段逻辑抽成小函数，让返回值成为唯一的出口。遮蔽本身不是错误，短作用域能减少变量污染，问题只出在”以为改的是外层”这种误判上。

常见错误与收敛写法

循环变量捕获是最隐蔽的一类。for _, v := range items 里的 v 自始至终是同一个变量，每次迭代只重新赋值，闭包或 goroutine 捕获的是它本身：

惯用解法是在循环体内写 v := v 复制一份，或把值作为参数传给闭包，团队内统一一种即可。

switch 要不要 default，取决于分支集合是否封闭。处理 HTTP 方法这类有限集合时，default 直接返回错误，能挡住以后新增的值；分支会持续增加时，default 反而成了每次都要改的负担。笔者的取舍是：外部输入兜底，内部枚举不写。

前文提到的几处坑有共同点：range 改副本无效、map 顺序随机、switch 里的 break 跳不出外层循环。它们都是”看起来像别的语言”的地方。

控制流程的长度则靠早返回和表驱动压缩。参数校验、错误分支放在函数开头直接 return，成功路径就能平铺；分支多且动作相似时，用 map[string]func 替掉长 switch，新增类型只加一行注册，也更好测试。

小结：与其他语言的对照

Go 的控制流程语法点更少，规则却更统一：if 与 for 共享初始化语句，switch 默认不穿透，range 包办了容器遍历。迁移时真正要适应的是”显式”：条件显式布尔，穿透显式声明，跳出多层显式标签。下表可逐行对照。

场景 其他语言 Go 写法 注意点
条件循环 while (c) for c {} 没有 while，条件必须是 bool
无限循环 for (;;) for {} 靠 break 或 return 退出
至少执行一次 do {} while (c) for { ...; if !c { break } } 判断放在循环体末尾
分支穿透 默认穿透 fallthrough 显式穿透 只能放 case 末尾
多条件分支 嵌套 if-else 无表达式 switch 可带初始化语句
遍历容器 for (x : xs) for i, v := range xs v 是副本，改它无效
遍历字符串 for...of for _, r := range s 索引是字节偏移
跳出多层 标签加 break break Label 标签紧贴循环
类型分派 instanceof 加强转 switch v := x.(type) 多类型 case 中 v 是接口
