Go 结构体与方法集

本文属于《Go 语言与工程》第 5/78 篇
上一篇系列目录下一篇

把结构体放进接口切片，前面加个 & 就能编译，去掉就报 does not implement，这大概是 Go 新手最容易被绊一下的地方。本文从这个小现象出发，把结构体定义、值接收者与指针接收者、方法集规则、嵌入与组合、值语义这几件事串起来讲清楚。文中的代码基于 Go 1.7 与刚发布的 1.8，沿用的是 GOPATH 下的写法，没有 modules，也没有泛型。读完你应该能一眼判断某个类型能不能赋给某个接口，以及为什么。

结构体的基本写法

结构体是字段的集合，定义时把字段名和类型写在花括号里即可。Go 没有类，也没有构造函数，创建实例就是用字面量或 new。

零值这件事值得单独说一句。声明了但没赋值的结构体变量，每个字段都是该字段类型的零值：数值是 0，字符串是空串，布尔是 false，指针与接口是 nil，字段本身又是结构体就继续递归。所以 Go 里很少见到构造函数，一个零值的结构体通常可以直接用，只有当零值没有意义时才需要写 NewXxx。这与 Java 里 new 出来一片默认值的思路不一样。

字面量有带字段名和位置式两种写法，两者不能混着用。位置式要求字段全部写出，顺序也必须与定义一致。字段少时它还算清爽，但一旦给结构体加了字段，所有位置式字面量都会编译失败；新字段若插在中间，甚至可能出现类型恰好兼容、语义却错了的情况。工程上更推荐带字段名的写法。另外，跨包使用位置式还有一个限制：访问不到未导出字段，所以对外暴露的结构体基本只能用带字段名的写法。

方法：值接收者与指针接收者

方法是带接收者的函数，接收者写在 func 关键字和函数名之间。接收者只能是一个在当前包里定义的类型，或者它的指针，不能是别的包里的类型，也不能是接口。

两次调用看起来一模一样，结果却只加了一次，原因在下一节细说。这里先看调用的形式：c.Inc() 的接收者是一个值，而 Inc 要的是指针，编译器发现 c 是一个可寻址的变量，就悄悄改写成 (&c).Inc()；反过来，用指针调用值方法时，编译器会自动解引用成 (*p).IncByValue()。这层自动转换只对可寻址的值生效，所以 map 里的元素、函数调用的返回值、复合字面量都不能直接调用指针方法，这是后面要说的坑之一。

什么时候必须用指针接收者？大致有四条判断：

第一，方法要修改接收者。想让 c.Inc() 真的加上去，接收者必须是指针，值接收者拿到的是一份拷贝。

第二，结构体比较大。每次调用都复制整个结构体，字段多、数组大时开销很实在，指针只传一个字。

第三，结构体里含有不该被复制的字段。sync.Mutex、sync.WaitGroup 这类类型一旦被复制就失去意义，go vet 的 copylocks 检查会直接报错。这类结构体连赋值都要小心，方法自然只能用指针接收者。

第四，保持一致性。一个类型只要有一个方法用了指针接收者，其余方法最好也统一用指针，否则方法集被劈成两半，接口赋值时会莫名其妙地失败。标准库里的 bytes.Buffer、http.Request 都是这个风格。

方法集规则

把上一节的现象抽象出来，就是方法集的定义。Go 语言规范里的说法很短：类型 T 的方法集由所有接收者为 T 的方法组成；类型 *T 的方法集由所有接收者为 T 或 *T 的方法组成。

换成表格更直观：

方法声明 在 T 的方法集中 在 *T 的方法集中
func (t T) M() 是 是
func (t *T) M() 否 是

也就是说，指针类型的方法集是值类型方法集的超集，多出来的正好是那些指针接收者方法。接口赋值只检查方法集，于是就有了开头那一幕：Rect 的 Area 用指针接收者声明，Rect 的方法集里没有 Area，不满足 Shape；*Rect 的方法集里有 Area，满足 Shape。

这条规则可以用一句话记住：值类型的方法集只含值接收者方法，指针类型的方法集两者都含。反过来推论也成立：如果一个接口的所有方法都是值接收者实现的，那么值和指针都能赋给它；只要接口里有一个方法是指针接收者实现的，就只有指针能赋给它。

这里有个容易忽略的对称问题：接口变量存进去是什么类型，取出来就还是什么类型。var s Shape = &r 之后，s.(Rect) 断言会失败，因为动态类型是 *Rect，必须写 s.(*Rect)。很多人第一次遇到断言失败，以为是值相等的问题，其实是动态类型不匹配。

值语义：拷贝、比较与成本

值接收者改不了字段，原因朴素得近乎无聊：接收者是拷贝。调用 c.IncByValue() 时，c 被整个复制到栈上的一块新空间，方法里 c.n++ 改的是那块临时空间，方法一返回就丢了。指针接收者传的是地址，c.n++ 通过地址写回原对象，所以能留下痕迹。

初学者常有一个反例式的困惑：结构体里放一个切片字段，值接收者里改元素，居然改成功了。这不是方法集的漏洞，而是切片的语义造成的。切片变量本身只是个描述符，里面是底层数组指针、长度和容量（细节见《Go 指针与内存布局理解》）。结构体被拷贝时描述符被复制，指向的底层数组还是同一个，所以 s.Tags[0] = "x" 会改到共享数据。一旦方法里 append 触发扩容，新的描述符指向新数组，原结构体就完全感知不到了。map 字段能改也是同理，它本身就是引用语义。

比较也是同一套值语义。结构体可以参与 == 和 !=，也可以当 map 的键，前提是所有字段都可比较：数值、字符串、布尔、指针、接口、数组，以及由这些组成的结构体都行；只要有一个字段是切片、map 或函数，整个结构体就不可比较，写 == 直接编译失败。数组可比较的前提是元素可比较，所以 [3]int 可以，[]int 不行。

最后是成本。结构体按值传递时，每次赋值、传参、装进接口都会复制一份，字段越多、内嵌数组越大，代价越高。把超过几十字节的结构体用指针传递是常见做法，但也不必教条：小结构体传值反而对缓存友好，也省了 nil 判断。标准是热点路径上是否出现大量复制，而不是结构体看起来大不大。

嵌入：方法提升与组合优于继承

Go 没有继承，但有一个语法很像继承的东西：匿名字段。把一个类型不带字段名地放进结构体，它的字段和方法就被“提升”到外层，可以直接访问。

u.ID 和 u.Hello() 都是编译器帮忙转发的，等价于 u.Base.ID 与 u.Base.Hello()。字段名冲突时按“浅层优先”处理：外层自己定义了 ID 或 Hello，内层就被遮蔽；同一层有两个嵌入字段都带 ID，访问 u.ID 就是歧义，编译报错，必须写 u.Base.ID 或 u.Other.ID 说清楚。歧义只在真正用到时才报错，所以藏一段时间才暴露是常事。

嵌入指针要单独提醒。把 *Logger 嵌进去，外层零值时这个字段是 nil，调用被提升的方法就会在方法内部解引用 nil 而 panic，值嵌入则会得到零值对象，安全得多。但嵌入指针有个很实用的副作用：方法集。嵌入 T 时外层值类型只获得 T 的值方法；嵌入 *T 时外层值类型直接获得 *T 的整个方法集。想让一个值就满足某个接口，嵌入指针是常用手法。

至于组合优于继承，落到 Go 里就是两句话。第一，嵌入是组合加转发，不是 is-a 关系：User 嵌了 Base，但 User 不是 Base 的子类型，不能把 User 赋给 Base 类型的变量，也没有向上转型。第二，遮蔽不是覆写。Java 里父类方法调用另一个方法会动态分派到子类实现，Go 没有虚函数表，Base.Hello 内部调用 b.Other() 永远调到 Base 自己的版本，外层的同名方法不参与。所以复用字段与方法靠嵌入，多态靠接口，两条线分开，比 Java 的单继承加覆写清楚得多，也少了很多“父类调子类”的隐式耦合。

方法表达式与方法值

方法有两种“取出来当函数用”的方式，区别在绑定时机。方法值 v.M 把接收者一起绑定，得到一个普通函数；方法表达式 T.M 或 (*T).M 不绑定接收者，第一个参数留出来给调用者填。

这个差异很容易咬人：值接收者的方法值一旦取出，接收者就被冻结成一份快照，后面改原对象不再有效；指针接收者的方法值绑定的是地址，改动会实时反映。方法表达式适合做泛化的调用，比如需要一个 func(*Counter) 的回调时，直接写 (*Counter).Inc 比包一层匿名函数省事。

几个常见的坑

map 的元素不可寻址，这条规则和结构体一起用时最容易翻车。m["a"].X = 1 直接编译失败，因为 map 扩容时元素会被搬走，指针随时可能失效。正确做法是取出、修改、放回，或者干脆让 map 存 *Item。复合字面量同样不可寻址，Rect{1, 2}.Area() 在 Area 为指针接收者时报错，先赋给变量即可。值接收者里 append 也一样：s.Items = append(s.Items, x) 只改了副本的长度，调用方看不到新元素，必须换成指针接收者。嵌入引发的歧义和 nil 指针接收者的问题前面已经提过，前者要写全路径消歧，后者要在方法开头判断 if r == nil 再决定行为。

小结

结构体承载数据，方法集决定行为，接口只认方法集。把三种声明摆在一起看，结论一目了然：

声明方式 T 的方法集 *T 的方法集 值能赋给接口 指针能赋给接口
func (t T) M() 含 M 含 M 能 能
func (t *T) M() 不含 含 M 不能 能
外层结构体嵌入 *T 含 *T 全部方法 同左 能 能

写 Go 的这两年，笔者最深的体会是：不要跟编译器较劲，它报 does not implement 时，先看方法接收者，再看嵌入的是值还是指针。需要修改状态、结构体较大、含不可复制字段，就用指针接收者，并且一个类型保持统一。剩下的交给接口，别用嵌入去模拟继承。
