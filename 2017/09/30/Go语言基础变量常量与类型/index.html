Go 语言基础：变量、常量与类型

本文属于《Go 语言与工程》第 2/78 篇
上一篇系列目录下一篇

从别的语言转到 Go 的人，往往在第一天就被两件事绊住：一是短变量声明 := 到处都是，二是几乎看不到类型转换的隐式写法。这两点其实是同一个设计取向的两面——Go 希望读者用最少的上下文推断出“这个值是什么类型、活在哪里”。

本文面向刚接触 Go 的读者，用 Go 1.9 的工具链，把变量、常量与类型这三块地基逐层拆开。读完你应该能看懂一段普通的 Go 代码里每个标识符的来历，也能避开零值、整数溢出、变量遮蔽这些新手高频坑。

从最小程序看 Go 的骨架

先看一个能跑起来的最小例子。把它保存为 main.go，放在 $GOPATH/src/hello 目录下，执行 go run main.go 即可看到输出。

这段代码里只有三个关键字值得记住：package、import、func。Go 用包来组织代码，一个目录就是一个包，同一目录下的文件必须声明同一个包名。main 包被编译器特殊对待，它必须提供一个 func main()，链接器会把它作为入口。其他包名（比如 utils）编译出来是库，不能被直接执行。

几个容易忽略的约束：

  • 导入的包必须被使用，否则编译报错 imported and not used。这不是风格建议，而是编译错误，Go 用这种方式逼你保持依赖干净。
  • 左花括号 { 必须与 func、if、for 写在同一行。Go 在词法分析阶段会自动插入分号，换行写会直接导致语法错误。
  • gofmt 是官方格式化工具，缩进用制表符。团队里不必争论风格，提交前跑一次即可。

理解了这层骨架，后面的变量与类型才有落脚点：它们要么写在函数体里，随函数调用而生灭；要么写在包级别，随程序启动而初始化。

变量：var、短声明与作用域

var 是最完整的声明形式，语法是 var 名字 类型 = 表达式。类型和表达式可以只留一个，编译器会从另一边补齐。

包级变量的初始化顺序按依赖关系决定，而不是按书写顺序，所以不必担心“先用后定义”。但包级变量不宜过多：它们是隐式的全局状态，测试时难以隔离。

函数体内更常用的是短变量声明 :=，它把类型完全交给编译器：

:= 有三条硬规则。第一，只能出现在函数内部，包级作用域不允许。第二，左边至少要有一个新变量，否则编译报错 no new variables on left side of :=；这条规则让 a, err := f() 这种写法可以复用已存在的 a。第三，:= 会为每个新变量声明类型，之后不能再赋别的类型。

两者的取舍很简单：需要显式控制类型（比如 var n int64，避免 := 推断成 int）或需要零值初始化时用 var；其余场合用 :=，代码更短，读起来也更贴近“值在前、名字在后”的自然语序。

关于作用域，Go 只有三个层级值得记：包级（整个包内可见，首字母大写还能导出到包外）、函数级、以及由 {} 划出的块级。if、for、switch 的初始化语句里用 := 声明的变量，作用域被限制在对应的块内，出了块就消失。这种设计让临时变量不会污染外层，也埋下了下一节会讲的遮蔽问题。

变量的生命周期比作用域更宽松：编译器发现某个局部变量的地址被返回或被闭包引用时，会把它分配到堆上，函数返回后依然有效。初学者只需记住直觉——Go 不会出现“函数返回后指针失效”的悬垂引用，写代码时不必手动管理这块内存。

零值：Go 为什么没有“未初始化变量”

在 C 里忘写初始化，变量里是什么取决于栈上残留的字节；在 Go 里这件事不存在。任何变量被声明后立刻拥有一个确定的零值：

  • 布尔类型为 false；所有数值类型为 0；字符串为 ""（空串，不是 nil）。
  • 指针、接口、切片、映射、通道、函数类型的零值统一是 nil。
  • 数组的零值是长度固定的全零数组；结构体的零值是每个字段各自取零值。

这个设计不是语法糖，而是内存模型的承诺：Go 的变量在分配时就被清零，所以“读到垃圾数据”这类问题从语言层面消失了。它带来的直接好处是，类型的零值应该尽量是可用状态。标准库里 bytes.Buffer、sync.Mutex 都是“声明即可用”，不需要构造函数，这条经验值得在自己写的类型里模仿。

nil 的零值需要区分场景。var s []int 得到的 nil 切片可以直接 len、range、append，行为与空切片一致；var m map[string]int 得到的 nil 映射可以读、可以 range，但写入会直接 panic，必须先 make。这是新手最常见的运行时错误之一，遇到 assignment to entry in nil map 时，先检查 map 是不是只声明没初始化。

常量与 iota

常量用 const 声明，值必须在编译期确定，因此右侧只能是字面量、其他常量或能在编译期求值的表达式，不能调用普通函数。

无类型常量是 Go 一个很有意思的设计。Pi 本身没有确定类型，它会在被使用时按上下文取类型：赋给 float64 就是 float64，参与 float32 运算就是 float32。这让同一个常量可以适配不同精度的场景，也让常量表达式能保持很高的精度，直到最后一刻才被截断。有类型常量则被固定住，赋值给别的类型必须显式转换。

批量声明配合 iota 可以写出枚举。iota 是常量组内的行号计数器，从 0 开始，每换一行加一；如果某行省略表达式，就沿用上一行的表达式。

用下划线占位跳过某个值，用位移表达式生成进位单位，是标准库里很常见的两种写法。需要提醒的是，iota 只认行号，中间插入空行或注释不影响计数，但插入一行新的常量就会让后面所有值整体后移。如果这些值会被序列化到磁盘或发送给外部系统，最好显式写出数字，别让枚举顺序成为隐式契约。

Go 的常量没有枚举类型约束，Sunday 之外的值依然可以赋给 Weekday 变量，编译器不会检查范围。想获得更强的约束，只能在运行时自己校验，或者靠代码评审。

基础类型全景

Go 的类型数量克制，一张表就能列完，但每类都有需要留意的细节。

布尔类型 bool 只有 true 与 false，且不与整数互通。其他语言里习以为常的 if 1 {} 在 Go 里是编译错误，条件必须是真正的布尔表达式。这一条看似啰嗦，却消除了“0 是假、非 0 是真”带来的歧义。

整数家族按位宽分四档：int8/16/32/64 与对应的 uint8/16/32/64，另有平台相关的 int、uint 和用于存放指针值的 uintptr。int 在 32 位平台上是 4 字节，在 64 位平台上是 8 字节。所以凡是涉及文件格式、网络协议、二进制序列化的字段，一律用定长类型；只做计数、循环、内存内索引时，用 int 最省心。

浮点有 float32 与 float64，浮点字面量默认推断为 float64。浮点数不要用 == 比较，两个看似相同的计算结果在末位可能有差异，需要比较时判断差值是否小于一个容差。

整数运算还有一处易错：5 / 2 的结果是 2 而非 2.5，整数相除会直接丢弃小数部分；负数取模的结果符号跟随被除数。写分页、哈希取余这类逻辑时，单位换算要放在乘法一侧，避免整数除法先把精度吃掉。

复数类型 complex64 与 complex128 在实践中很少出现，主要服务于信号处理、数值计算类库。byte 与 rune 则是两个别名：byte 就是 uint8，用来强调“这是一个字节”；rune 就是 int32，用来强调“这是一个 Unicode 码点”。类型相同、语义不同，读代码时这层区分很有价值。

最后是 string，它是只读的字节序列，默认按 UTF-8 存储。这一句里藏了两个坑：只读意味着不能原地改字符，UTF-8 意味着长度不等于字符数。下一节展开。

自定义类型、类型别名与遮蔽陷阱

type MyInt int 定义的是一个全新类型：底层表示仍是 int，但与 int 不兼容，不能直接赋值或混合运算，必须转换；好处是它可以拥有自己的方法。方法只能定义在同一个包内的具名类型上，所以 int 本身无法扩展，MyInt 可以。方法集不会从底层类型继承，这一点与“嵌入字段”不同，等读到接口那篇时会更清楚。

type MyInt = int 中间多一个等号，语义完全不同：这是类型别名，两者是同一个类型的两个名字，可以直接互换赋值。别名在 Go 1.9 才进入语言，最初的动机是支持大规模重构——把某个类型从 A 包搬到 B 包时，先在旧位置留一个别名，调用方无需改动。byte 与 rune 就是标准库里最著名的两个别名。

数组、切片与映射：先会用

这三者是日常代码里出现频率最高的复合类型，这里只讲声明与基本操作，底层结构与扩容留待专文。

数组是值类型，赋值或传参时整体复制，长度固定，实践中直接用得不多。切片是对底层数组的视图，长度可变，len 是当前元素数，cap 是还能容纳多少；append 在容量不够时会另辟空间，所以别假设两个切片一定共享数据。映射的读取永远安全，键不存在时返回零值，配合 comma ok 形式区分“值是零”与“键不存在”；写入前必须用 make 或字面量初始化。遍历映射的顺序是随机的，这一点在 Go 里被刻意保留，不要写出依赖顺序的代码。

小结

Go 的类型系统在入门阶段显得啰嗦，核心却只有几条：变量声明即有零值，不存在“未初始化”；类型转换必须显式，编译器不为你做隐式提升；常量可以是无类型的，在上下文中才定型。理解 := 与 var 的分工、type 与 type = 的差别，以及短声明在 if 里造成的遮蔽，能避开新手期最费时间的一批 bug。把基础类型、string 的字节与字符之分、切片与映射的基本用法吃透，再去读并发与接口，会顺很多。
