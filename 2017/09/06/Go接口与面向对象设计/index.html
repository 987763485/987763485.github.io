Go 接口与面向对象设计

本文属于《Go 语言与工程》第 8/78 篇
上一篇系列目录下一篇

从 Java 或 C++ 转过来的开发者，第一次写 Go 时最常问的两个问题是：没有 class 怎么写面向对象，没有 implements 又怎么知道谁实现了接口。本文从这两个疑问出发，先把接口的语法与语义讲清楚，包括方法集、隐式实现、空接口、类型断言与嵌入，再讨论几个容易踩坑的细节，最后用一个存储层的例子说明接口在解耦与测试中的作用。读完之后，你应该能判断一段代码该不该抽接口，以及抽出来的接口该长什么样。

没有 class 的语言，怎么表达抽象

Go 有类型系统，也有方法，但没有类、构造函数和继承关键字。我们能用的材料只有三样：结构体承载数据，方法把行为绑到类型上，接口描述一组行为。三者拼起来，足以表达大多数面向对象的设计。

值接收者与指针接收者：谁实现了接口

方法可以绑在值上，也可以绑在指针上，这两种选择直接决定了“谁拥有这个方法”，进而决定谁能满足接口。规则只有一句话：类型 T 的方法集只包含值接收者方法，类型 *T 的方法集包含值接收者与指针接收者的全部方法。换句话说，指针类型的方法集是值类型方法集的超集。

最后一行报错，不是 Inc 不能作用于值，而是接口赋值只检查方法集，不做取地址的自动转换。日常调用 c.Inc() 能通过，是因为 c 可寻址，编译器自动改写成 (&c).Inc()；而装进接口的是一份没有固定地址的副本，编译器不会替它取地址。

这条规则有两个实践推论。第一，有指针接收者方法时，就统一用指针接收者，避免“值能调一部分方法、不能调另一部分”的割裂。第二，把值放进接口后，方法里改的是副本，原值不受影响：

若方法需要修改接收者状态，或结构体较大、复制成本高，就应用 *T 接收者，并让接口变量装 *T。判断标准不是面向对象的习惯，而是方法需不需要改到原对象。

空接口：能装一切，也丢了一切

interface{} 的方法集为空，因此任何类型都满足它。它是 Go 表达“任意类型”的主要手段，标准库中随处可见：fmt.Printf 的变参、container/list 的元素类型、encoding/json 解码到未知结构时的目标类型。

便利的代价是类型信息在编译期消失。函数内部拿到的是接口值，想使用具体类型的字段或方法，必须先做类型断言；传错类型只会在运行时暴露。更隐蔽的问题是签名失去信息量：func Process(data interface{}) 让调用者无法判断该传什么，维护者也要读完函数体才知道支持哪些类型。

空接口适合两类场景：通用容器与格式化输出，以及与外部世界交互的边界，比如解析未知结构的 JSON。业务代码里，若类型集合有限且可知，用具体类型或小接口更清晰。另外，[]interface{} 与 []string 是两种类型，不能相互赋值，需要逐元素转换。

接口可以嵌入其他接口，效果是把被嵌入接口的方法集合并进来。标准库的组合方式非常直白：

嵌入是纯合并，没有继承层次，也没有方法覆写。ReadWriteCloser 要求实现者同时具备三个方法，缺一不可；反过来，实现了这三个方法的类型，可以自由赋给 Reader、Writer 或 ReadWriteCloser 变量。同一份实现、多种视图，正是接口组合最实用的地方：函数按最小视图声明参数，调用方传同一个对象即可。

接口嵌入与结构体嵌入容易混淆，两者形似而语义不同：接口嵌入合并方法签名，产物仍是接口；结构体嵌入把被嵌入类型的字段与方法一起提升到外层，产物是具体的结构体。

User 可以直接访问 u.ID、调用 u.Describe()，字段与方法都被提升了。如果 User 自己定义了 Describe，外层会遮蔽内层，但内层仍可通过 u.Base.Describe() 调用，这是 Go 里最接近“覆写”的写法。这种遮蔽不是多态：把 User 赋给接口后调用的是 User 的方法，通过 Base 变量调用则永远是 Base 的版本。

结构体里也可以嵌入接口，常见于两种场合：只想实现接口的一部分方法，其余留给具体类型补上；或在测试里用嵌入接口的结构体占位，只覆写关心的方法。后者很方便，但未被覆写的方法在运行时调用会因接口为 nil 而 panic，只适合测试。

面向行为的设计

把语法串起来，Go 的面向对象只有两条主线：用组合搭建结构，用接口描述行为。结构体嵌入复用字段与方法，接口让调用方只看见需要的那部分能力。两者都不产生继承链，改一个类型不会波及整棵树。

接口应当从调用方长出来。先写使用方需要的那几行，再抽出真正被依赖的方法，接口自然就小；先设计全能接口，几乎一定多出用不到的方法。同样重要的是克制：只有一个实现、也没有替换需求的类型，直接用具体类型就好，接口这层间接同样有阅读成本。

小结

Go 用结构体、方法和接口替代了类与继承：接口是方法集，实现是隐式的，满足即可赋值。值接收者与指针接收者的方法集差异决定了接口赋值能否成立，而 nil 接口与装着 nil 指针的接口是两回事。小接口让复用与测试更轻，嵌入则把它们拼成更大的契约。设计时先想行为、再想类型，让接口跟着调用方走，通常比先画类图更有效。
