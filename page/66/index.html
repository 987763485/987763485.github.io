前端安全之 XSS 攻击与防护

把用户输入原样拼进页面，是前端最古老也最顽固的错误。XSS（Cross-Site Scripting，跨站脚本）并不依赖某个框架漏洞，它利用的是浏览器对 HTML 与 JavaScript 的解析规则：只要不可信数据落在了本该写代码的位置，浏览器就会把它当代码执行。本文从 XSS 的本质讲起，依次梳理三类攻击的数据流、几种常见上下文的编码方式，以及富文本、框架转义和 Cookie 属性的边界，最后给出一份可以照着做的排查清单。读者不需要安全背景，但需要写过表单回显和 DOM 操作。

HTTP 安全响应头配置

很多团队把 HTTPS 证书装好就认为传输层已经安全了，但浏览器还有一半的防线藏在响应头里：能不能降级到 HTTP、能不能被别的站点用 iframe 套住、脚本能从哪些源加载、Referer 会不会把内网地址带出去，全都由几个几十字节的头部决定。本文按“先讲语义、再给配置、最后排顺序”的方式，把 2018 年主流浏览器已经支持的安全响应头过一遍，重点是它们之间的组合关系与 Nginx 上的落法。

前端安全之点击劫持与防护

点击劫持（clickjacking）是一种不需要注入脚本、也不需要拿到密码的攻击：攻击者只用一个透明 iframe，就能让用户在毫不知情的情况下按下某个按钮。本文从攻击原理讲起，先用两个本地 HTML 文件复现一次完整的点击劫持，再逐一介绍 X-Frame-Options 与 CSP 的 frame-ancestors 两种防护手段，包括它们的优先级、兼容性与配置写法，最后给出测试方法和几个常见的坑。读完之后，你应该能为站点选出合适的防嵌套策略，并清楚它何时会失效。

Redux 状态管理入门与实战

组件之间共享数据，是每个 React 项目绕不过去的一道坎。当页面从几个组件长到几十个组件，props 一层层往下传的写法很快就会失控：改一个购物车数量，要沿着三层组件链把回调函数传下去；两个互不相邻的模块要同步一份筛选条件，只能靠父组件当中转站。本文从这些问题出发，讲清楚 Redux 的三个原则、action 与 reducer 的分工、store 的用法，以及如何用 react-redux 把 store 接到组件树上，最后给出异步请求、中间件和常见坑的处理办法。读完之后，你应该能在一个中等规模的 React 项目里独立搭起一套可维护的状态层。
