PostgreSQL 索引类型与查询优化

索引是 PostgreSQL 性能调优里投入产出比最高的一环，但“建了索引”并不等于“查询变快”：选错访问方法、排错列顺序，或者让统计信息过期，都可能让一条本该毫秒返回的 SQL 退化成全表扫描。本文以 PostgreSQL 12 为基准，先梳理各类索引的适用边界，再按查询形态给出选型建议，然后讲清楚规划器的成本模型与执行计划的读法，最后用一个订单表的例子把单列索引、复合索引和部分索引放在一起对比。读完本文，你应该能判断一条 SQL 该建什么索引，以及规划器为什么有时偏偏不用它。
