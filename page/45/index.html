Prometheus 告警规则设计

告警规则是把指标翻译成行动的最后一公里：表达式写错、阈值拍错、通知发错人，前面的采集与存储都白费。本文从告警价值观、指标与标签、PromQL 表达式、阈值与 for、规则组织、延迟与 SLO 燃烧率，一直讲到 Alertmanager 的分组、抑制与路由，并给出可以直接落地的规则与测试样例。读者应已了解 Prometheus 的基本抓取模型与 PromQL 语法，读完后能为一个真实服务设计出噪声可控、责任清晰、可被测试的告警体系。

Redis 缓存穿透、击穿与雪崩

缓存是大多数系统抵御数据库压力的第一道堤坝，穿透、击穿、雪崩是这道堤坝最常见的三种溃口。三者都表现为数据库流量陡增，但触发条件、影响范围与处置手段不同。本文沿 cache-aside 读取路径拆解三种故障，给出防御手段与取舍，并用一段 Go 代码把空值缓存、互斥重建与 TTL 打散组装起来。读者应已用 Redis 做过业务缓存，希望把“能挡住”变成“知道为什么能挡住”。

MySQL 主从复制与读写分离

单机 MySQL 迟早会遇到读请求压满 CPU、备份把磁盘 IO 打满、主库维护只能停服这几类问题，主从复制是最常见的第一层解法。本文从复制到底解决了什么讲起，依次拆解 binlog 格式、GTID、半同步与延迟成因，再落到读写分离的几种实现与读一致性的补偿手段。读完你应该能独立搭起一主两从，并清楚哪些问题复制本身答不了。

MySQL InnoDB 索引与 B+ 树

很多开发者能背出“B+ 树、聚簇索引、最左前缀”这些词，却说不清一次查询究竟读了几次页、页里到底长什么样。本文从 InnoDB 的 16 KB 页和行记录格式讲起，逐层拆开聚簇索引、二级索引、页分裂、缓冲池与统计信息，并用一张订单表把一次查询的完整路径走一遍。读者应已会写基本 SQL，读完后能根据数据分布和写入模式判断索引为何这样设计、又为何在某些场景下失效。

连接池参数调优实践
