内网渗透与横向移动

内网渗透中最容易被低估的一环，是“拿到第一台机器之后”发生的事：许多团队把预算堆在边界防护上，却在内部默认“自己人可信”，于是一次终端失陷就可能演变为域控失守。本文从授权红队演练与防御建设的双重视角，梳理横向移动在攻击链中的位置、信任关系被滥用的原理、检测思路与加固路径，并说明演练的边界与整改闭环。

本文面向有一定网络与系统基础的安全工程师、运维负责人和研发骨干，读完后你应当能为自建内网画出“信任关系图”，判断哪些通道最可能被复用。全文不提供任何可直接执行的攻击操作，所有细节都停留在原理与风险面。

一、横向移动在攻击链中的位置

一次完整的入侵通常遵循“初始访问—执行—持久化—权限提升—内部发现—横向移动—收集—外传”的顺序。初始访问决定第一个落脚点，横向移动决定这个落脚点能被放大成多大的面。前者依赖入口漏洞或一次成功的社工，后者依赖企业长期积累的信任关系。这解释了一个常见现象：边界设备越来越难打，但一旦被打穿，内网往往在数小时内连续失守。

横向移动的特殊性在于它几乎不产生新的漏洞：协议、账号、工具都是日常运维在用的，流量在语法上完全合法。防守方要在大量合法行为中识别出目的不同的那一小部分，这正是检测难度的来源，也决定了防护重点不在补丁，而在权限结构、网络结构与身份治理。

1.1 杠杆效应与横向阻力

攻击者每跳一次，就多一份凭据、多一个可用的管理通道、多一层对业务的理解。一台掌握域内查询权限的主机，可以让攻击者在一夜之间得到完整的资产清单；一台运行配置管理客户端的主机，可能同时拥有对数百台服务器的下发能力。因此评估内网风险时，“有多少台主机存在高危漏洞”意义有限，更有意义的是“从任意一台普通办公终端出发，到达核心资产最少需要几跳”。这个跳数就是内网的横向阻力，由账号权限、网络可达性和管理通道共同决定；后文的加固建议，本质上都是在提高这个跳数。

1.2 ATT&CK 中的战术归类

MITRE ATT&CK 把攻击行为按战术和技术两层组织，横向移动对应战术 TA0008。这个分类把具体手法抽象成可比较、可检测的行为类别，便于防守方建立覆盖矩阵，而不是追逐工具的名字。

与横向移动紧密耦合的还有四个战术：凭据访问（TA0006）提供可复用的身份材料；内部发现（TA0007）通过查询账号、主机、共享与域信任关系绘制内网地图；远程服务利用借助系统自带或已部署的远程管理能力在目标上执行动作；权限提升（TA0004）在目标主机或域内取得更高层级控制权。防御规避（TA0005）常与之伴随，表现为尽量使用自带工具、减少落地文件。

本文只做类别级描述。具体到哪一种协议、哪一个参数、哪一款工具的组合，属于授权演练中的执行细节，不在公开讨论范围。防守方仅凭类别级信息也可以完成检测设计与加固规划，因为攻击者无论换什么工具，最终都要落在“身份”“通道”“目标”三个要素上。

二、企业内网为什么容易被横向移动

横向移动在多数企业里“好使”，不是因为攻击者手段高明，而是因为内网在设计之初就把可用性放在了安全性之前。“边界之内皆可信”的假设支撑了文件共享、域认证、集中管理，也留下了持续至今的结构性问题。下面五类问题往往同时存在、相互放大。

2.1 共享凭据与口令复用

最常见的问题是本地管理员口令全网统一。为了运维方便，很多组织用同一套镜像批量装机，或通过组策略统一设置本地管理员密码。任何一台主机上的本地管理员凭据被取得，等价于取得全网主机的本地管理员权限。攻击者不需要漏洞，只需要一个账号。

与之并存的是服务账号的口令复用：数据库连接串、定时任务、监控采集、备份代理各自使用账号，其中相当一部分在多个系统间共用同一口令，且长期不轮换。这类账号通常被排除在口令复杂度与过期策略之外，因为“改了会挂业务”。它们的凭据散落在配置文件、脚本、注册表和部署流水线中，暴露面远超普通用户账号。

2.2 过度授权与管理员日常化

第二个结构性问题是权限向上集中。域管理员、云平台管理员、虚拟化管理员的权限极大，却在日常工作中被当作普通账号使用：收邮件、上网、登录办公终端。一旦这台终端被控，攻击者得到的不只是一个账号，而是整个目录服务的控制权。

更隐蔽的形式是：业务账号被加入本不需要的安全组，历史项目权限从未回收，外包人员离场后账号仍启用，服务账号被授予交互式登录权限。这些权限在目录里看得见，却少有人复核，而攻击者对内网的理解往往就从这些多余的授权开始，因为它们是通往下一跳最短的路径。

2.3 扁平网络与缺失的东西向控制

多数企业内网在二层或三层上扁平可达：办公网、测试网、生产网之间只靠几条访问控制列表隔离，甚至完全互通。办公终端可以直接访问服务器的管理端口，服务器之间也可以任意互访。这种结构便于故障排查，却让攻击者的每一次成功都具备“全网可达”的收益。

分段缺失的后果是检测盲区：边界设备上的精细策略在内网没有对应物，东西向流量往往不采集或只做抽样，攻击者在内部移动几个小时，安全设备上只留下几条不起眼的登录记录。

2.4 老旧协议与不安全的名称解析

为了兼容旧系统，不少内网仍启用 SMBv1、NTLM 认证、Telnet 管理与未签名的 SMB 通信。这些协议诞生于信任环境，缺少完整性保护与双向认证，在今天的威胁模型下应被视为“明文传输的凭据通道”。

名称解析同样是被忽视的面。LLMNR 与 NBT-NS 这类广播式解析机制在找不到目标时向本地网段询问，任何主机都可以应答。攻击者据此冒充目标主机，诱导客户端把认证材料发到自己手里。根因不是某个漏洞，而是协议设计年代过早，企业又缺少关闭它们的决心。

2.5 补丁滞后与资产盲区

对外暴露的系统有变更窗口和责任人，内网系统却常常“能跑就不动”。一台三年未重启的跳板机、一套无人认领的测试环境、一批停止维护的旧版中间件，构成了资产盲区。攻击者一旦在其中任何一台取得执行能力，就可以利用同网段内其他未修补主机继续扩散。

补丁管理的难点往往不是打补丁，而是“不知道有多少台”。台账偏差会让风险评估建立在错误的基数上，因此应把“可管理资产占比”与“补丁合规率”分开统计，两者的差距通常就是风险最集中的地方。这五点很少单独出现：共享口令、管理员日常化、网段互通、旧协议未关、补丁缺失叠加在一起，从一台终端到核心数据库可能只需要两三次身份复用。因此单点加固收效有限，有效的做法是同时压缩“身份”“通道”“可达性”三个维度。

三、信任关系被滥用的原理

横向移动的手法看起来五花八门，抽象之后只有一句话：把系统为运维设计的信任关系，用在设计者没有预期的方向上。这类行为不依赖漏洞，因此不会出现在漏洞扫描报告里；它依赖授权本身，因此也很难被传统入侵检测规则命中。下面按通道类型说明原理与风险面，只讨论“为什么可行”。

3.1 远程管理协议：合法通道的用途漂移

远程桌面、文件共享、远程命令执行、远程 shell 都是系统自带的管理设施，它们对攻击者有三个价值：使用自带组件、流量可加密、行为与运维在协议层无法区分。当攻击者掌握合法凭据，这些通道就变成移动工具，安全设备看到的只是一次成功的、加密的内网登录。

风险面集中在暴露方式：管理端口对办公网开放；管理通道只做单因素认证；会话不做录制与命令审计；同一套管理员账号跨网段通用。任一点成立，远程管理协议就会成为最短路径。

3.2 共享目录：凭据与脚本的集散地

文件共享承担了大量“隐式分发”的职责：登录脚本、部署包、应用配置、数据交换目录。风险不在协议本身，而在内容与权限的长期失管：对所有登录用户可读的共享可能存放着含明文口令的脚本、连接配置和资产清单；可写的共享则可能让他人以“正常更新”替换他人在用的脚本。检测难点在于读共享极为常见，有效的观察点是上下文：某账号在非工作时段遍历了与业务无关的共享，或某台终端首次访问管理类目录。

3.3 身份票据：不需要口令的复用

在域认证环境中，用户登录后取得的是票据而非口令。票据在有效期内可以被重复使用，服务端校验的是“票据是否合法、是否在有效期内”，而不是“出示票据的人是否就是当初申请的人”。因此攻击者只要取得可用票据，就不需要知道明文口令，也不需要破解哈希，即可在有效期内以该身份访问对应服务。

放大风险的因素包括：票据生命周期过长；服务账号使用弱口令且绑定了服务主体名称，使口令可被离线尝试；委派配置过宽，使某台主机能够代表用户访问其他服务；SMB 签名与通道绑定未启用，使认证材料可被中间人截获并转发。防御重点因此落在缩短票据价值窗口与提高获取难度上，而不是禁止票据机制本身。

3.4 配置管理与运维编排：批量能力即批量风险

配置管理、补丁分发、终端管理、监控采集、备份代理，共同的设计目标是“以高权限在大量主机上执行动作”。控制台的一次合法操作可以在几分钟内覆盖上千台主机；控制台凭据一旦泄露，攻击者不需要逐台突破，只需要下发一条作业。

风险面有四层：控制台暴露在办公网或可被 VPN 直接访问；作业定义与变量库中硬编码高权限口令；被管理端与控制端的通信未做双向认证；审计日志只记录“谁提交了作业”，不记录“作业实际做了什么”。演练中经常出现的情况是，攻击路径完全绕开服务器漏洞，沿运维系统的授权关系走到底。

3.5 供应链与第三方跳板：信任链的上游

当企业把运维外包、把构建发布交给流水线、把监控交给第三方平台，信任关系就延伸到了边界之外。这类通道的特点是“下游主动连接上游”，入站策略再严格也无法阻断。虚拟化管理平台则具备对全部虚拟机的控制、快照与克隆能力，一旦管理面失守，影响面是整片集群。

这一层的风险包括：第三方账号没有明确到期时间与访问范围；更新通道缺少签名校验；构建节点同时具备代码读取与生产部署权限；外包人员的跳板机与内部管理员处于同一网段。防守方需要把第三方当作内部资产治理。五类通道的共同点是授权过宽、缺少二次验证与行为审计，封禁协议并不可行，可行的方向是收敛授权范围、增加使用时的验证、把操作过程变成可读的证据。

四、检测思路

检测的基本前提是：防守方无法穷举攻击者的工具，但可以描述“正常是什么样”。所有检测逻辑最终都归结为偏离基线的行为。本节给出四个层次，它们的数据源不同、成本不同，组合起来才能形成有效覆盖；文中的阈值均为示意值，实际部署必须按自身业务量重新标定。

4.1 身份异常与登录基线

身份是横向移动的燃料，身份侧日志的优先级最高。值得关注的行为包括：同一账号短时间内在多台主机上发生网络登录；账号首次访问从未触达的资产；特权账号在非维护窗口登录；服务账号出现交互式登录；账号被加入特权组后立即跨主机访问；认证失败在多个目标上呈扫描式分布。

基线的建立应按“账号 × 主机 × 时段 × 登录类型”统计历史分布，再对首次出现或频率突变的事件打分。单纯统计失败次数超阈值误报极高，因为运维脚本、监控探针、老旧应用都会产生大量失败；把失败与随后的成功关联起来才更接近真实意图，先在多台主机上失败、再在少数主机上成功，几乎是横向尝试的典型形状。

4.2 东西向流量与连接矩阵

南北向设备看不到内网的横向路径，因此需要在服务器区与办公区之间的关键节点采集流量，或利用主机侧的网络连接日志。分析重点不是单个连接，而是“谁和谁在通信”的矩阵：某台办公终端第一次与数据库服务器建立管理端口连接；一台应用服务器在深夜向数十台主机发起同一端口的连接；内网出现明显的单源多目标探测。矩阵中的未知对端往往就是台账里缺失的主机。

4.3 端点遥测与行为链

端点侧能看到动作的结果，而不只是连接的发生。值得采集的信号包括：办公软件、浏览器、文档处理器派生出命令行解释器；服务被创建或修改；计划任务被新增；命名管道出现异常名称；管理工具的子进程行为与其正常用途不符；对系统凭据存储区域的异常访问。单看任何一条信号都可能是运维行为，因此端点检测要做链式关联：同一进程链上同时出现异常派生、权限提升与服务创建，才构成高置信度告警，而网络侧更适合发现已经扩散。

4.4 蜜罐与欺骗防御

蜜罐把误报这个难题转化成了几乎不可能误报。常见形式包括：在服务器网段部署低交互诱饵主机，模拟常见管理端口；在共享目录放置带唯一标识的诱饵文件，任何读取都会触发告警；创建没有业务用途的诱饵账号，并赋予其看似有价值的权限。

关键是诱饵要可信：诱饵账号要出现在通讯录或资产系统中，诱饵主机要有正常的名称与开放端口。诱饵被触发意味着攻击者已在内网活动，属于高优先级事件，不与普通扫描告警同队列。

下面给出一条示意规则，说明如何把“账号在多台主机上连续网络登录”表达成可执行的逻辑，字段与阈值仅作示范。

这条规则的误报主要来自运维脚本，上线前应把已知的批量作业账号加入白名单，并对其余账号单独标定阈值。规则只是起点，真正的价值在于它迫使团队回答“哪些账号本来就会在多台主机上登录”，答案本身往往就暴露了过度授权。

五、加固路径

加固的目标不是让攻击者无法进入，而是让他进来之后走不远。工作可以分成四组：收敛身份权限、收紧网络可达性、清理协议与补丁债务、把过程变成证据。

5.1 最小权限与分层网络

权限侧先做分层：按资产价值把身份划分为目录与虚拟化管理层、服务器管理层、终端用户层，层级之间不得混用，高层级账号只能从受控的管理工作站登录。再消除共享凭据：本地管理员口令逐机随机化并集中保管，而不是全网统一；对特权组、服务账号与历史遗留授权做季度复核，把没人说得清为什么有的权限回收。

网络侧遵循默认拒绝、按需放行：办公网与服务器区之间只保留必要的应用端口，管理端口不直接暴露；服务器之间按业务调用关系建立白名单。分段不必一步到位，可以先从核心数据库、域控与虚拟化管理面做起。

5.2 特权访问管理

特权访问管理的核心是把拥有权限和使用权限分开。日常办公使用普通账号，需要特权时通过统一入口申请，获得有时限的授权，操作过程被完整记录。管理流量走独立网段，管理终端不用于上网与收邮件。

比工具更重要的是流程：谁能审批、授权多久、哪些操作必须双人确认、会话记录保存多久、离场人员如何即时回收。演练中反复出现的失败模式是平台建好了，但管理员仍保留一条绕过平台的直连通道，因此加固后应清点通道，确认除平台入口外不存在其他可达管理面的路径。

5.3 服务账号与协议基线

服务账号应当有清单、有责任人、有用途说明。能用托管服务账号的，优先采用由目录统一管理口令的形式；不能用的，至少做到口令定期轮换、禁止交互式登录、权限限定在最小范围。散落在脚本与配置文件中的口令，应迁移到统一的凭据管理设施，而不是继续以明文随代码流转。

协议与补丁方面，关闭 SMBv1 与广播式名称解析，启用 SMB 签名与通道绑定，对 NTLM 采取先审计后限制的策略，淘汰明文管理协议。补丁管理的前提是资产可见性，应把台账、补丁合规率与不可管理资产占比纳入月度指标。基线可参照通用加固基准，但必须做例外登记，否则半年内就会形同虚设。

5.4 日志留存与持续验证

检测能力依赖数据。域控的认证日志、端点的进程与服务变更日志、关键网络节点的连接日志，应当统一采集、统一时间源、集中留存，留存周期按合规要求与调查需要取较长者。等保 2.0 在入侵防范与访问控制方向上对身份鉴别、访问授权与入侵行为记录提出要求，落地时可以把这些方向转成具体的日志项与告警项，而不是停留在制度文本。加固是否有效同样需要验证：把第四节的检测逻辑做成可回归的用例集，用授权演练定期检验最少跳数是否下降，比统计完成了多少项加固更有意义。

六、演练的范围、授权与停止条件

横向移动的验证要在真实内网中复用真实凭据，因此授权必须先于技术。书面授权至少写明目标与资产清单、时间窗口、发起演练的源地址、明确禁止的动作（不得破坏业务数据、不得留存持久化机制、不得横向到范围外资产）、数据处理方式与中止方式。演练应分级推进：先做桌面推演，在不接触真实系统的前提下讨论“如果这台终端失陷会怎样”；再做紫队演练，重点验证检测规则是否有效；最后才是严格约束下的红队演练。

数据保护是红线。演练中不导出真实业务数据，取得的凭据材料只用于验证路径，完成后销毁并留存记录；不在生产环境留存账号、计划任务或服务。停止条件应提前量化：业务中断或性能明显劣化、误触范围外资产、发现真实的外部攻击者、触发约定的高危告警，任一条件成立即暂停，由双方负责人确认后再决定是否继续。

七、报告与整改闭环

一份可用的报告应包含三条主线：攻击路径图，按时间顺序还原每一次身份复用与通道切换；ATT&CK 映射，把观察到的行为归入对应战术，便于与检测覆盖矩阵对照；根因分析，指出问题出在权限结构、网络结构还是流程缺失。

风险评级应同时考虑可能性与影响，并把修复成本单独列出，避免所有问题都被标成高危。整改通常分三档：短期阻断，如关闭不必要的管理端口、回收多余的授权；中期改造，如本地管理员口令随机化、管理面独立组网；长期治理，如服务账号体系重构与权限复核机制化。每项都要有责任人与时限，并在复测中验证。

闭环的最后一步是沉淀：把有效的检测思路转成正式规则并入监控平台，把失败的检测点补进用例库，把新增的资产与信任关系更新到台账。衡量成效可以看平均发现时间、平均处置时间、特权账号数量与可直达核心资产的主机占比，这些指标连续几个季度下降，才说明内网真的变厚了。

小结

横向移动的本质是信任关系被复用，利用的不是漏洞，而是为运维便利设计的授权结构。防守方应从身份、通道、可达性三个维度同时收敛，让任意一次凭据泄露都不足以直达核心资产。检测以基线为核心，把身份日志、东西向流量、端点遥测与欺骗防御组合使用；加固优先解决共享凭据、过度授权与扁平网络，再清理协议与补丁债务。演练要有书面授权、数据保护与明确的停止条件，报告要落到根因与可复测的指标。
