DOM 查询与遍历的性能优化

查询与遍历是脚本碰 DOM 的两个最基本动作，也是最容易藏进热路径的两个：一次按键触发几百次全表扫描、一段递归把调用栈吃穿，事故现场往往就出在这两件“看起来不花钱”的事上。《DOM 查询缓存与批量操作》和《DOM 节点类型与节点关系梳理》已经把“查询结果要缓存”“活集合边删边遍历会漏”讲过，本文不重复这些结论，而是把主线换成成本模型与集合语义：一次查询的开销由哪几段构成、live 与静态集合在规范层面差在哪、老 IE 缺失的 Element 系列怎么补、深树遍历在调用栈与显式栈之间怎么选，最后用一张后台表格页的热路径重构把全部方法走一遍。适合维护列表、表格、树类页面的同学，也适合被“IE6-8 到底缺了什么 API”困扰、准备手写兼容层的读者。文中所有数字都按同一把手工计时口径测得，只给相对量级，不编权威数据。
