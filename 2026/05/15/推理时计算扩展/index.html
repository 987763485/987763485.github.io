推理时计算扩展

推理时计算扩展说的是件很朴素的事：模型权重不动，把更多算力花在回答这一次问题上。它常被说成”多试几次”或”再想想”，但要让收益稳定，就得把这两句口号拆成可测量的东西——预算口径、搜索结构、验证器质量、采样多样性、延迟形态与配额治理。本文按这条线展开，给出可复用的伪码骨架、一张预算决策表和一份实验记录表模板，并明确说明它在哪些任务形态上不如检索、不如路由、不如直接换模型。

两种扩展：并行与串行

训练阶段的算力只花一次，却服务于此后每一次请求；推理时计算扩展反过来，权重不动，把算力加在单次请求上。它的基本杠杆只有三个：让一次采样生成更长的中间步骤、同一次问题多采样几条独立轨迹再收口、以及让轨迹与外部世界交互之后再回来。前两个分别对应并行扩展与串行扩展，第三个通常作为前两者的支撑条件出现，本身不构成独立方向。

并行扩展（parallel scaling）指对同一问题跑 N 条相互独立的轨迹，再用某种选择器收敛到单一答案——选择器可以是多数投票、验证分数，也可以是一次执行结果。它的成本对 N 近似线性，延迟可以通过批处理与并发摊平，因此工程上最容易先落地。它的收益曲线之所以呈凹形，核心原因通常不是”模型想不出来”，而是错误之间不独立：同一个底座、同一批训练数据、同一条提示，会把 10 条轨迹推向同一类误解。错误高度相关时，N 从 1 提到 2 有可见收益，提到 8 只是把同一份偏见复制了 8 份，账面成本却翻了 8 倍。

串行扩展（sequential scaling）指把单条轨迹拉长：分阶段推理、递归分解、拿到中间结果后复核再进入下一阶段。它的成本随序列长度上升得更快，因为注意力计算与缓存占用同时增长（具体机制属于推理服务层的讨论，此处不复述）；它的延迟无法靠并发摊薄，而且早期步骤的错误会沿上下文累积——模型相当擅长把上一步的错误”圆”成顺理成章的下一步。作为回报，串行扩展可以在步骤之间插入检查点，让校验发生在结论成型之前，这是并行扩展结构上做不到的事。

两条价格曲线不同，选择规则因此相当直接：存在可靠验证器时优先并行，因为生成便宜、挑选可靠、失败可归因；任务能自然分解且中间产物可检查时优先串行；两者都不满足时，多花算力基本等于多花钱。这条规则会在第六节的决策表里细化成可操作口径，但要先把一个前提说清楚：验证器的可靠性不是”打分准不准”，而是它的误差方向会不会被选择压力持续逼近。

预算的三种口径

“多想一会儿”要变成可控变量，第一步是选一个既能被系统强制执行、又能被实验复现的口径。常见三种口径各有失真方式。

token 预算。给单次请求的输出与中间推理 token 设上限，由服务层截断。优点是单位明确、能在网关强制执行、与资源占用直接挂钩。失真是 token 数与”想清楚”并不等价：同一个上限，模型可能用来铺陈冗长解释，也可能提前收束；上限压得过紧时，被截掉的往往恰好是最后那段汇总与自检，于是错误率上升却看不出原因。

步骤预算。以可数的中间动作为单位：一次候选生成算一步，一次工具调用算一步，一次校验算一步。优点是可观测性最好，天然适配 agent 循环，方便做”用了多少步、还剩多少步”的界面与配额。失真是步骤边界必须由执行框架事先定义，否则模型会把”读了 5 个文件”表述成 1 步，预算被语义滑动吃掉。把计数写死在 harness 层（每次工具调用固定计数一次，与模型自述无关）是唯一稳妥的做法。

时间预算。给请求一个绝对 deadline。优点是与用户侧 SLA 对齐，熔断语义清晰。失真最大：同一 deadline 在不同负载、不同批量、不同模型规模下完成的步数不同，可复现性最差；扩缩容或容量紧张期间它还会悄悄改变答案质量，而监控上看不到任何异常。结论是时间预算适合做熔断与保护，不适合做实验档位。

分配策略上，总预算要拆成三段而不是全给首轮生成：首轮生成、扩展分支、校验复核。校验段应留固定比例（示意值为首轮 40%、扩展 35%、复核 25%；团队可重新约定，但必须在实验开始前写死）。关键在于这个预留由调度器强制执行，而不是靠提示词请求模型”记得检查一下”——后者在预算紧张时最先被牺牲。

还有一类容易被忽略的现象：预算边界处的行为突变。当剩余预算落在模型在训练分布里习得的”典型解答长度”附近或以下时，输出会出现三种退化。其一是伪收敛：提前给出结论，并把不确定性用肯定语气抹平。其二是反思压缩：原本该逐条核对的自检被缩成一句”以上推理是合理的”。其三是硬截断：预算在句子中间用完，下游解析器拿到结构不完整的输出，进而触发重试放大。三者都有可观测特征——结论出现在预算使用率的很高位置、自检段落长度骤降、结束原因为长度上限。工程对策不是”再多给一点点预算”卡在临界点上，而是把预算给到舒适区，同时显式要求预算不足时输出部分答案并标注哪些部分未经验证。宁可要一份带标注的不完整答案，也不要一份语气完整的错误答案。

树搜索与验证器打分

把”多想”组织成搜索，就绕不开四件事：候选生成、价值评估、剪枝、回溯。搜索树的宽度与深度直接和预算挂钩，成本形态接近 b 的 d 次方，所以真正的工程问题从来不是”用哪种搜索算法”，而是”评估函数的质量能不能支撑这个分支因子”。候选生成要有区分度，同分布重复采样只增成本；价值评估可以是终局打分，也可以是中间步骤打分，两者的可靠性来源完全不同；剪枝要有可解释依据，例如低于阈值、被支配解替代、命中硬约束，否则事后无法归因；回溯意味着要保留部分中间结果并重用，实现上依赖推理服务层的缓存能力，机制细节另文已述，本文只关心它对预算回收的影响。

验证器从哪里来，按可靠性从高到低排：

  • 能执行的：跑单元测试、跑解释器、跑校验器。返回码、断言失败信息、编译错误列表是最硬的信号，因为它们不依赖模型判断。
  • 能形式化的：schema 校验、类型检查、单位与量纲核对、静态规则、命名与格式规范、合规清单。它们覆盖面窄但结果可复现。
  • 能对证据的：要求打分方引用具体行号、原文片段、日志摘要或执行输出，第三方可复核。没有证据字段的打分，本质上仍是猜测。
  • 判别模型或另一条轨迹的打分：最弱的一档，且与生成器共享盲区。

验证器噪声如何把搜索带回幻觉，这条机制值得写透。best-of-N 的动作是对验证分数取 argmax，这在数学上等价于沿着验证器的误差方向做优化：N 越大，越容易选中恰好落在验证器误判区里的那一条。也就是说，把答案带偏的不是生成器变差，而是选择压力专门去挖验证器的盲区。分数分布通常是重尾的，少数高分候选对均值的贡献远大于多数候选，于是”平均分在涨”和”质量在涨”可以长期背离。账面表现也很典型：通过率上升、置信度上升，人工抽审却发现自信的错误变多了。

缓解手段要与机制一一对应：

  • 把验证器当过滤器而不是排序器。先用硬约束淘汰不可接受的候选，剩下的按原文顺序或随机取，避免持续逼近误差边界。
  • 双验证器一致性。来源不同的两个验证器都通过才算通过；两者的一致率本身就是可观测指标，一致率下降往往先于质量下降。
  • 保留 top-k 而不是 top-1。多条并列时把候选集交给下一段流程——更多检查、换一种提问方式、或转人工——而不是强行造一个全序。
  • 要求证据字段。无证据的高分降级为待复核，而不是直接采信。
  • 定期做校准核对。在有可执行验证的真值切片上，用执行结果作为基准，检查学习型打分器的排序相关性是否退化。

过程奖励与结果奖励的取舍也落在这里。结果奖励只判终局，信号稀疏，容易被投机——凑出正确答案的形状而过程完全错误。过程奖励判中间步骤，能直接指导搜索方向，但依赖步骤级标注，而且很容易被”看起来规范的中间步骤”骗过：步骤写得工整不等于步骤正确。折中做法是能用可执行检查点的地方就不要用学习型过程奖励；确实需要学习信号时，把它限制在”提示搜索往哪里走”，不让它单独决定最终答案。

生成与验证分离是另一个结构性决定。把生成器与验证器拆成两次调用甚至两个模型，价值在于切断误差相关性：同一个模型做自我批改，倾向于在它自己犯错的地方同样犯错。代价也要写清：要维护两套提示、两套评测、两套版本与两套故障模式，而且验证器必须能看到证据而不只是结论，否则所谓分离只是换了个口吻的自评。

并行采样、投票与多样性控制

并行扩展有两种收口方式，混用会让归因失效，先分清楚。

自洽性（self-consistency）指生成多条独立推理轨迹，把最终答案规范成可判等的形式后取多数。它能奏效有两个前提：答案可规范（数值、选项、可字符串判等的短串），以及错误足够分散。投票能消掉随机错，消不掉共同偏——所有轨迹共享的误解会以一致同意的形式通过。它不需要验证器，这是它受欢迎的全部理由；它也处理不了开放式文本，因为两段方案之间不存在”相等”关系，多数表决无从定义。

最优选择（best-of-N）指用验证器或打分器挑一条。它把可达质量的上限抬到 N 条里最好的那条，但下限由验证器决定。两者的差别可以这样记：自洽性的收益受限于错误相关性，best-of-N 的收益受限于验证器噪声，而两者的成本结构几乎一样，所以选哪个取决于你手上更缺”分散的错误”还是更缺”可靠的裁判”。

多样性有四个杠杆，各自带副作用：

  • 温度与核采样参数。最直接，但随机性提高通常先破坏格式稳定性与算术可靠性，换来的是一堆低质候选，而不是候选空间的真正扩张。
  • 种子。便于复现与回放，固定种子集合适合做 A/B，但它不改变错误结构——同一提示同一种子换批次，看到的仍是同一类误解。
  • 提示扰动。换分解方式、换表示（代数与几何、列表与表格）、换单位制、换提问语言。收益最大，风险也最隐蔽：扰动会悄悄改掉题目条件，于是 N 条轨迹在回答 N 个不同问题。控制原则是扰动只作用于”怎么解”，不作用于”解什么”，并保留一份原始表述用于最终比对。
  • 异构生成器。不同规模或不同族，误差相关性最低，但运维成本与评测口径成本同时上升，且不同模型的截断行为与格式倾向不一致，过滤逻辑要按来源分支。

自我校验与反思的成本

反思的收益集中在”不需要新信息就能查出来”的部分：单位与量纲核对、边界样例、把答案代回原约束、schema 一致性、算术复算、以及把结论与题目原文逐条对齐。这类自查不依赖外部知识，所以自反思确实能拿到真收益，而且成本极低。

它的失败同样成模式，常见四类：

  • 确认式反思。第二次生成以第一次输出为条件上下文，先验本身就偏向维持原结论，于是反思文本长成”承认可能存在一些小瑕疵，随后原样重申”。
  • 局部修补掩盖结构错误。改掉最显眼的一处措辞或一个数值，结构性问题原样保留，输出看起来”处理过意见”，实际变更只发生在表面。
  • 反思挤占预算。自检段落变长意味着候选数或答案长度变少，同一份预算下并行与串行互相抢占，最后两边都做 half。
  • 虚假信任外溢。把没有外部验证支撑的反思文本直接展示给用户，用户读到的确定性比模型实际掌握的更强，这是产品层面的伤害而不只是质量问题。

“越反思越自信”是上述机制的合力结果，而且可测：对同一批样本记录反思轮次与结论翻转次数，如果轮次增加而翻转次数接近零、同时置信表述显著上升，就已经拿到信号，不需要等到线上出问题再回头查。

替换关系上，凡是能用外部信号的地方就不要用自评：

  • 用执行代替”再想一遍”：测试通过与否、解释器返回、校验器错误列表。
  • 用规则代替判断：schema、类型、单位、许可证、命名与格式规范。
  • 用检索代替回忆：把结论与可引用来源对齐，未命中来源的句子一律标记为待确认。
  • 用交叉异议代替自我批改：让来源不同的另一方只被要求指出可能的错误位置与理由，不给出正确答案；只有”指出了可复核位置”的异议才计入统计。
  • 用位置可核对性作为采信门槛：说不出具体位置的自查视为复述，不计入通过条件。

一句划界：把失败样例沉淀成可检索条目属于规划实践的范围，本文只讨论校验信号本身该从哪里来。

预算决策表：什么时候不该用它

先明确三种”不是它该解决的”情形。知识缺失：答案缺的是事实、接口约束或版本差异，多想不会补上信息，检索与工具调用的收益更直接，而且可归因。能力上限：底座在该任务形态上不具备所需能力，扩大预算只会放大同一类错误，此时该动的变量是模型规模、任务表述或交互方式。已经稳定正确：在接近饱和的切片上加预算，带来的是成本、延迟和格式风险，质量曲线早就平了。

把判定条件按列读，比按行读更可靠：先看有没有可靠验证器，再看延迟约束，最后才看预算上限。当”可靠验证器”这一列是弱或无时，任何形式的并行择优都应降级为过滤或转人工。

    L -- 不能 --> Y

延迟、成本与流式的配合

并行扩展对尾延迟的影响是结构性的。它是典型的 scatter-gather：响应时间由最慢的那条分支决定。当分支时长近似独立时，收齐 N 条的时间等于 N 个样本的最大值，分布整体右移且随 N 增长，P99 的上升幅度比均值更大；再叠加排队与批处理抖动，长尾会更陡。所以”预算多花一倍、延迟只多一点”这种直觉在 P50 上大致成立，在 P99 上不成立，而 SLA 恰恰是拿 P99 谈的。

对应的手段按机制来配：

  • 分支独立超时加早停。一旦有候选通过过滤且证据可核对就收敛，主动取消其余分支，把”等齐再答”改成”等到第一个满足条件的”。
  • 分层预算。先跑 1 条并设接受阈值，不满足才扩到 N；扩档请求携带剩余 deadline，避免扩展后必然超时。
  • 绝对等待上限。投票与复核阶段有硬 deadline，超时返回带未验证标记的答案，而不是无限等待一条迟迟不通过的分支。
  • 流式结构化事件先行。先输出”第 k 条完成””测试通过 n 比 m””剩余预算档位”这类事件，再输出最终答案正文；未通过校验的候选内容不进入用户可见文本流，避免出现”错误答案已经打完了”的既成事实。
  • 若产品要展示过程，展示可核对的检查结果（执行输出、命中的规则），不展示模型自述的确定性。
  • 取消必须传播。客户端断连要传播到分支池，否则用户早已离开而 N 条分支继续跑满；网关侧要携带剩余 deadline，服务层据此推导分支超时与是否停止扩展。
  • 重试要区分性质。预算尚未消耗的排队失败可以重试；已经消耗预算的部分失败不该重试放大，改为降级返回，因为重试只是把同一份预算花两遍。

串行扩展的延迟形态不同：它不是把尾巴拉开，而是把持有时间拉长，因此对排队系统施加的是周转压力而不是峰值压力。两种形态需要不同的容量策略，这也是为什么预算档位要与部署形态一起声明。成本口径上本文不谈单价，只看资源占用形态：并行的形态是”同一时刻多份并发加短时峰值”，容量规划要按峰值预留；串行的形态是”少量并发加长时间持有”，压力体现在并发槽位周转与排队长度上。同一个标称预算在两套系统里并不等价。配额则应该按租户与用户建账户，而不是按请求限流——否则单个用户用并行采样就能占满一整个批处理窗口，把别人的延迟拖进同一个长尾。

怎么证明多想有效

先声明立场：本节只给实验设计与记录模板，不给结论数字。推理时扩展的收益高度依赖任务切片、底座与验证器质量，任何跨环境搬过来的”提升幅度”都不成立。

七条设计约束：

  • 预算档位固定且实验前声明。用离散档（示意值 1、2、4、8），不要事后补档再挑好看的；每个档位要与执行层一致的口径定义，说清是 token、步骤还是时间。
  • 并发档位与预算档位分离。同一预算档跑不同并发，才能把排队与尾延迟效应从”多算”效应里剥出来；否则容量变化会被读成收益变化。
  • 预热与限额。正式计数前跑预热批次，排除冷启动、缓存填充与配额抖动；预热样本一律不入统计。
  • 配对样本。同一提示、同一底座、同一验证器版本，只变预算一个因素；否则模型差异会被读成预算收益，这是这类实验最常见的自欺。
  • 随机性入记录。温度、种子集合、重复轮次全部写进实验表，跨轮次给区间而不是报单点最好成绩。
  • 任务分层。按”是否有可执行验证器””可分解程度””答案长度”切片汇报；总均值几乎不携带信息，收益通常集中在少数切片上。
  • 抽审做盲评。人工标签的抽样规则事先固定，且抽审时不展示预算档位与候选条数，避免”看起来更用心”的暗示。

一句划界：样本集建设、评审偏差的系统性校正、发布卡点这些属于评测体系的范围，本文只处理预算实验特有的变量控制。

记录表模板给到字段级别，值留空，落地时它就是埋点 schema：

字段 含义 记录要点
run_id 批次标识 与配置快照绑定，可重放
generator_version 生成器版本 记构建号，不记”最新”
verifier_version 验证器版本 含规则集与打分器标识
budget_kind 预算口径 token、步骤或时间
budget_tier 预算档位 离散档编号
concurrency_tier 并发档位 与预算档位分开记
temperature / seed_set 随机性设置 种子集合需可重放
n_generated 实际生成条数 通常小于申请条数
n_truncated 长度截断条数 预算边界退化的直接信号
n_timeout_cancelled 分支超时取消数 早停是否真的生效
n_hard_pass 硬约束通过数 过滤口径下的幸存者
n_pass_with_evidence 通过且有可核对证据 首选主指标
n_multi_survivor 多条并列的比例 验证器分辨力的代理指标
human_audit_label 人工抽审标签 抽样规则事先固定
p50 / p99_latency 端到端延迟 按并发档分列
peak_slots 峰值并发槽位 容量规划输入

两个字段值得盯得比质量分更紧：n_pass_with_evidence 与 human_audit_label 的背离，是验证器正在被逼近误差边界的早期信号；n_multi_survivor 上升，意味着过滤条件已经区分不了候选，继续加 N 只是加成本。

调度、配额与可观测

推理时预算一旦被当成产品变量，它就变成一种资源，需要按资源来管。

预算账户。按租户与用户建立推理时计算额度，粒度是”这一段时间内可支配的扩展量”，而不是”每秒多少请求”。账户要能区分口径（token 与步骤不可互相抵扣），并在超额时给出明确降级路径：降到 1 条直出、只保留格式校验，而不是排队等待。

优先级与抢占。首轮生成属于交互路径，不该被抢占；扩展分支属于可选路径，可以在容量紧张时被丢弃；复核与投票介于两者之间。把这条差别写进队列，容量事件的表现就从”所有人变慢”变成”扩展档位自动降下来”。

观测面板最少要有：各预算档位的到达率与转化率（从申请 N 到实际生成几条）、过滤通过率分布及其随时间的漂移、截断率、并列率、取消传播成功率、验证器服务自身的错误率与延迟。缺少”通过率漂移”这一项时，验证器退化通常以质量投诉的形式第一次被注意到。

典型故障模式有四类：配额泄漏（分支已取消但预留未释放，账户被幽灵消耗填满）；扩展风暴（某个上游失败触发全量重试，重试又各自申请 N 条）；验证器成为单点（过滤全依赖一个执行服务，它一挂就全部退化成”零幸存者”路径，进而把所有请求推向串行细化）；取消未传播（客户端断开后分支继续跑满，成本与延迟都记在自己头上）。前两类靠幂等标识与账户回收解决，后两类靠降级路径与传播链设计解决，都不是提示词层面能修的问题。

与其他手段的分工

  • 与路由和级联：路由回答”这次请求交给谁”，推理时扩展回答”交给它之后要不要多算”。两者共享同一份延迟与配额账，预算不足时先降扩展档位，再考虑降级路由，顺序反了会同时损失质量与延迟。
  • 与 Agent 规划：规划决定动作序列的结构、依赖与失败处理，本文决定在既定结构上投入多少采样与校验；搜索、回溯与执行反馈在规划里的具体组织方式属于前者。
  • 与长上下文：窗口是容量问题，预算是花算力的方式问题。长输入带来的成本属于容量口径，不该被读成”多想”的收益或负担。
  • 与长上下文压缩：压缩在信息过剩时降低单次成本，扩展在推理不足时增加单次成本，方向相反；同一份预算不要同时买这两件事，否则永远看不出哪个在起作用。
  • 与推理模型和思维链：把中间推理内化进解码过程的模型，已经替我们决定了”要不要写中间步骤”，外部预算控制依然需要，但作用点移到候选条数、校验强度与复核预留。
  • 与微调和蒸馏：如果某类任务上扩展收益长期稳定，成本更优的长期解法是把模式沉进权重，把每次请求都要付的算力开销变成一次性投入；这属于权重更新流程，不在本文范围。

小结

推理时计算扩展不是”多花点算力换好答案”这么含糊的一件事，它有清晰的机制边界。并行扩展的价格曲线由错误相关性决定，串行扩展的价格曲线由长度成本与误差累积决定，两者的收益上限都握在验证器手里。预算要挑一个能被执行层强制的口径，并把复核段作为预留而不是善意请求。best-of-N 的数学形态就是沿着验证器误差方向做优化，所以 N 越大越要警惕”通过率上升、自信的错误也上升”这个组合；把验证器当过滤器而不是排序器、要求可核对证据、保留 top-k 而不是造全序，是对抗这条机制的三个具体动作。自评在所有信号里最便宜也最容易失真，凡能用执行、规则、检索和位置可核对性替换的地方都该替换。延迟上，并行是求最大值而不是求平均，P99 的账要单独算，取消与超时必须传播。最后，预算是一种资源：它有账户、有优先级、有抢占语义、有自己的故障模式。什么时候不该用它也很清楚——缺信息就检索，缺能力就换手段，已经稳定正确就别加档。
