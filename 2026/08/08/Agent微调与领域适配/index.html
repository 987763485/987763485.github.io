Agent 微调与领域适配

本文属于《Agent 智能体开发》第 55/55 篇
上一篇系列目录下一篇

Agent 落到某个具体领域时，最常见的落差不是模型不够聪明，而是它按通用习惯说话、按通用格式发起动作。领域适配真正要做的，是把模型对齐到这个领域的动作分布上：什么样的观察应当触发什么样的决策，决策又应当落成执行器能够解析的什么格式。本文只走这条适配链路上的几个关键工位。低秩适配为什么能用少量参数改写行为，第 780 篇已经讲透了机制，本文只把它当作领域微调里最常用的那条参数高效路线来使用，不重讲它的低秩原理。

微调、提示与 RAG 各守哪一段

第 935 篇给过“到底该用 RAG 还是微调”的通用决策树，本文只在 Agent 语境里补一条更具体的判据：看失败的性质是事实错还是形式错。提示词修的是表面的说话方式，成本最低，改一个模板当天就能验证。RAG 修的是知识边界，它把领域事实塞进上下文，改变的是模型能够引用什么，而不是它习惯怎么产出动作。这两者都碰不到 Agent 最容易出问题的地方。

当执行器解析不了模型的输出，或者模型在知识完全正确的情况下仍然选错动作、错调用时机、错调用格式时，提示和检索都救不了它——因为毛病出在动作的形态与策略上，而不是知识缺口上。这类错误的典型特征是：它会反复复发，与你换了什么措辞无关，换一套提示模板仍然复现。此时该动的是权重，而不是上下文。把模型从通用调到可用的整套工程流程，第 832 篇已经给过完整走法，训练范式层面的近期演进则由第 1047 篇展开，本文既不复述流程也不复述范式史，只聚焦“把模型对齐到领域动作分布”这一件事。

工具调用格式对齐是第一条硬约束

Agent 的输出不是给人读的句子，而是给执行器解析的结构。一个在自由对话里表现很好的通用模型，完全可能把本应是动作负载的东西包进一句解释里，或者临场发明一个下游根本不存在、也不该存在的键名。格式对不齐，后面的推理再漂亮也没用，因为动作压根发不出去。

格式对齐的做法，是用成对的样本把线上格式钉死：一次调用还是并行多路、参数该是什么类型、嵌套对象怎么组织、枚举有哪些合法取值、当这一步不该调用任何工具时如何显式地表达“不动作”、以及调用出错后应当给出什么样的恢复话术。下面是一段描述单个工具契约的模式定义，字段名与含义都只是团队约定示例，落地时以你自家执行器实际接受的形状为准。

模型在“用户报了个单号、想查状态”这类指令下，被要求恰好产出下面这种可解析的动作，而不是一句带 JSON 碎片的散文。期望形态与违规形态要一起进训练集，让模型既学会怎么写对，也学会哪里算写错。

对齐时有一条纪律：不要指望模型记住你写在散文里的口头约定，而要把约定物化成可解析的结构，再让一个校验器充当格式的最后一道闸门。下面这段 TypeScript 归一化函数就是这道闸的示意——它只承认能从输出里抠出来的、且通过模式校验的动作，其余一律判为格式违规回炉。

领域动作轨迹的构造与清洗

Agent 的训练单位不是单轮问答，而是一条 observation → decision → action 的轨迹：模型看到什么、据此判断什么、最后做了什么，三者必须成对且步界清晰。第 978 篇已经覆盖了通用语料的抓取、去重与配比，本节只补轨迹这一类数据特有的处理，通用清洗流程不再重复。

轨迹的来源大致有三类：把生产环境的真实会话回放、切分成步；请领域专家演示标准操作路径并录下每一步的观察与动作；在一个受控沙箱里让模型自己反复采样、再筛出成功的路径。三类里最省心的是回放、最可控的是沙箱自采样，但三者都会引入各自特有的脏数据，清洗因此成为领域适配里最脏也最关键的一道工序。

下面这条流水线描述清洗的整体走向，核心判据只有一个：动作是不是真的能在沙箱里跑通。跑不通的动作不该进训练集，否则模型学到的就是执行器接收不了的形态。

flowchart TD
    A[生产日志与专家演示与沙箱自采样] --> B[切成观察-决策-动作三元组并标步界]
    B --> C{动作能在沙箱里执行吗}
    C -->|能| D[保留并标注关键步与终止步]
    C -->|不能| E[直接丢弃或回退重采样]
    D --> F{是否陷入重复空转}
    F -->|是| E
    F -->|否| G[拼装成领域轨迹集]

清洗里几个 Agent 特有的动作值得单独点名。其一，去死循环：同一条观察反复触发同一个动作，是轨迹里最常见的退化，留着它等于教模型原地打转。其二，剔除把内心推理泄漏进动作负载的样本——观察和决策应当落在合适的字段里，而不是混进发给执行器的那段结构里。其三，给终止步打标记，让模型学会“任务到此为止、不再调用”。下面这段清洗函数是示意实现，判循环的阈值只是团队约定示例，实际取值由各家沙箱与会话长度决定。

指令跟随与安全能力不能被磨掉

领域微调本质上是把模型的行为往一个很窄的分布上收，而收得太狠时，会顺带磨薄两样不该丢的东西：一是宽泛的指令跟随能力，二是对越权与滥用请求的拒绝能力。前者掉了，模型只认领域内的话，遇到一句元指令、一次格式纠正就发懵；后者掉了更危险——格式终于学会了，可现在连本不该做的动作也照做不误。

防范的做法不是把安全话术写进提示词祈祷它生效，而是在轨迹集里固定混入一小片通用指令样本与安全样本，把它们当作锚点，让窄分布不至于把宽能力覆盖掉。上线之前要专门跑一轮拒绝行为回归：拿越权请求、危险操作请求去问微调后的模型，确认它仍然会拒绝、仍然会要求确认，而不是因为“学会了一套漂亮的调用格式”就忘了自己不该调用。

基座模型自带的对齐策略，以官方当期公布的版本与其说明为准，不同家族的可微调性与许可证条款也不同——微调前务必先确认权重用途与再分发的条款，别在许可不明的权重上做领域适配。要强调的分工是：微调不替代基座已有的安全对齐，而是在它之上叠加一层领域动作约束；两者是叠加关系，不是覆盖关系，一旦把它理解成覆盖，安全退化几乎是必然结果。

评测对照：同任务、同指标

领域适配的评测只有一条原则：对照必须在同一批任务、同一套指标上做。微调前后跑的是同一个留出的轨迹集，评分口径、执行器版本、沙箱环境都不变，否则你观察到的差别无法归因到“微调”这件事上——很可能是评测环境自己漂移了。端到端评测的一般走法前面已有交代，本节只把其中与 Agent 强相关的几把尺子摆出来，且只讲怎么搭尺子，不写任何分数或提升幅度，具体读数留给你自己那批数据。

可用来对照的维度大致如下。格式有效率看执行器能不能把输出解析成合法动作，重点盯那些把 JSON 包进散文、或者越界发明键名的样本；可执行动作率看解析出来的动作喂进沙箱是不是真跑通，参数类型错、枚举越界都在这里暴露；步数效率看完成任务用到的步数分布，冗余观察和反复空转都会把它推高；任务完成率看端到端结果是否满足领域验收；安全保持看越权与滥用请求是否仍被正确拒绝，这一项专门用来兜住微调可能带来的退化。

评测维度 度量方式 主要关注点
格式有效率 解析器能否读出合法动作 是否把结构包进散文、是否发明键名
可执行动作率 动作喂进沙箱能否成功 参数类型、枚举越界、调用时机
步数效率 完成任务的步数分布 冗余观察、重复空转
任务完成率 端到端结果是否达验收 领域口径是否正确
安全保持 越权请求是否仍被拒 微调后是否把拒绝能力磨没了

对照时有一个陷阱：只测成功路径会让格式有效率虚高，因为失败样本恰恰是格式最容易崩的地方。留出集里要故意保留一部分上游会报错、参数会缺、动作会被拒的困难轨迹，让它们专门去考模型的恢复话术与“该不动作时不动作”。

对照还有一条容易被忽略的前提：留出集必须冻结。同一批评测轨迹一旦被拿去回炉训练，就不再是留出集，格式有效率会因为记忆而虚高，读数随之失去意义。领域任务往往带时间性，把最新一段真实会话单独留出来当作时间外推的考卷，能比常规切分更早暴露分布漂移，而不是等到上线才发现评测集早就失真。

上线后的回归与蒸馏的分工

上线不是终点。领域的动作分布会随着上游工具的接口调整、数据口径变化而悄悄漂移，昨天还合法的调用今天可能就解析不过。回归要盯三类信号：格式违规率是否抬头、某一类动作的报错是否集中出现、拒绝行为是否出现异常。发现漂移后不要急着在全量流量上试错，先让新适配器在影子里跑一份新鲜留出的轨迹，确认格式有效率与安全保持都没有退化，再决定放量还是回滚。适配器要带版本、可回退，出问题能一键退回上一个已知良好的行为。

stateDiagram-v2
    [*] --> 候选适配器
    候选适配器 --> 离线评测
    离线评测 --> 影子上线: 通过留出集
    离线评测 --> 候选适配器: 不通过则回炉
    影子上线 --> 全量上线: 违规率与安全保持稳定
    全量上线 --> 候选适配器: 分布漂移触发回滚

至于和蒸馏的分工，用一句话交代清楚先后即可：本文讲的微调负责把基座对齐到领域的动作分布上，把一个通用模型变成会用这套格式、会走这条路径的领域 Agent；而第 968 篇专门讨论的蒸馏，往往是把这份已经对齐好的行为进一步压进一个更小、更便宜、更适合边缘或高并发部署的学生模型。合理的顺序是先对齐、再按需蒸馏——先让一个大模型把领域动作做对，再把它当成教师去蒸馏小学生，比直接蒸馏一个还没对齐的分布要稳得多。

小结

领域适配在 Agent 语境下有一条清晰的主线：它要改的是动作的形态与策略，而不是知识的有无。判据先看失败是事实错还是形式错，形式错且反复复发，就该动权重。落地上有三块 Agent 特有的硬骨头：把工具调用格式钉死、构造并清洗 observation → decision → action 的轨迹、以及在收窄分布时守住指令跟随与安全能力。评测只在同任务同指标上做对照，尺子讲方法不讲分数；上线后把格式违规率、动作报错集中度和拒绝行为当作回归信号，用影子评测和可回滚的适配器管住漂移。低秩机制、通用清洗、RAG 取舍与蒸馏工艺都已在前几篇各就各位，本文自始至终只占住“把模型对齐到领域动作分布”这一个工位。把这条链路走稳，模型就从“能聊”真正变成“能在这个领域里正确地做事”。
