Agent 规划能力提升实践

本文属于《Agent 智能体开发》第 29/55 篇
上一篇系列目录下一篇

本文讨论的是一件事：怎样把 Agent 的规划能力当成一个可度量、可迭代、可回滚的工程指标来改进。我们不谈分解结构应该怎么表示，也不谈提示词的花样，而是从提示骨架、搜索式规划、错题沉淀、可验证里程碑、执行反馈、数据构造与评测设计这七个抓手入手，逐一给出工程写法、失效形态与成本。读完你应该能回答三个问题：下次想再强一点该动哪一层，那一层需要配什么基础设施，以及怎么确认它是真的变强了而不是记住了答案。

把规划能力当成一个指标

规划能力在日常讨论里常被当成一个模糊的形容词。本文把它拆成一个具体对象：在同样的模型、同样的工具集、同样的预算档位下，系统产出的计划有多接近“可执行且可被验证”，出错以后又恢复得有多快。这个定义本身并不新鲜，但它带来一个关键差别——只有先把规划变成指标，改进才有方向，否则任何改动都只是风格变化。我们的做法是给每个任务族维护一条规划流水线的可观测记录，四列就够：计划原文、执行时的实际偏离、判定结果、失败归因。有了这四列，“下一步该动哪里”就不再靠争论决定。

先把边界划清，避免与同语料库的其他文章重复。任务如何表示为分解结构、重规划在什么条件下触发，属于机制层，另有专文讨论，本文只把分解结果当作待打分对象。思维链与推理型模型是承载规划的形态，本文不讨论形态本身。提示技巧是通用工具，本文只截取其中与规划输出形状直接相关的骨架部分。工作流编排是外层抽象，本文只关心编排里“计划”这一环节的输入与输出。推理预算与对齐方法各属另一层，本文只在“用什么信号来训练和评测”这一维度上与它们相接。每处一句，不再展开。

一条可用的改进循环通常有五个动作：定义度量；定位失败集中在哪一层；选一条最便宜的路径先动；用小规模对照确认方向；把结论固化成基设施工件，也就是示例库、判定函数、错题条目、训练集与评测集。顺序比技术选择更重要。我们见过的失败改进，多数不是选错了算法，而是跳过了第一步的度量定义，直接改提示、加搜索，最后无法判断是系统变强了还是任务变简单了。

还有两条原则值得提前说清。第一，改进的单元不是“某一次对话变好了”，而是“这一类任务在留出集上更容易通过”，所以任何改进都要跟着一个任务族标签，否则无法复用。第二，改进要能归因，因此一次只动一层：同时换示例、加搜索、改判定函数，即使指标动了也不知道该记在谁头上。本文后面每一节都按“工程写法—失效形态—成本”三段展开，就是为了让“只动一层”这件事在操作上成立：你总能指出这一次动的是哪一节。

提示与示例：把规划骨架固化成资产

最便宜的一层是提示。这里的改进不是把话说得更客气，而是把规划的输出形状钉死，使它可被机器解析、可被判定函数打分。下面这个骨架是我们在若干任务族上反复删改后留下的版本，可以直接复用；尖括号里的内容按项目替换。

骨架里真正起作用的是三条：里程碑必须自带完成判据；猜测必须与已知事实分栏；最可能失败的步骤必须显式列出。第三条常被忽略，但它决定了错题沉淀能不能自动归类——如果模型每轮都先押注“哪里会错”，我们就得到一份可对照的记录，事后能区分“意料之中的失败”和“没想到的失败”，这两类的处理路径完全不同。

示例设计比骨架更容易出问题。我们的做法是按任务族分桶，每桶放两到三条示例（示意值），并且要求：示例里保留失败与纠正的痕迹，而不是只给一条干净的成功计划；至少一条示例展示“计划被判定函数打回之后如何重写”；示例只写抽象的输入输出类型，不写工具签名，避免模型把示例里的接口当成事实；示例顺序保持稳定，减少与顺序相关的方差；评测任务的形状不得出现在任何示例里。

失效形态主要有四种。示例过拟合：模型学到示例的表层结构，比如固定的里程碑命名，换个任务族就整套失效。骨架僵化：在探索型任务里强行输出线性里程碑，反而压制了本该出现的试错。长上下文稀释：示例加得越多，约束被遵守得越差，最后要靠后置校验器把输出格式硬扳回来。示例污染：某个评测任务的影子混进示例，指标上涨但能力没变。成本方面，这一层几乎不需要训练，改一次提示当天就能上线；真正的成本在维护——示例库要有版本，骨架要有变更日志，而且必须有一份跨任务族的回归集，用来确认新改动没有把老任务族做坏。

搜索式规划：多候选、价值评估、回溯与剪枝

单条计划的质量有上限，搜索是把上限抬起来的直接手段。工程上它由四个部件组成：候选生成、价值评估、扩展与回溯、剪枝。我们的最小实现不是图搜索框架，而是一个显式的节点队列加上快照，代码形状如下，函数名与字段是本项目的示意写法，不对应任何公开接口。

候选生成要控制多样性。同一个提示、同一个温度反复采样，得到的是同一条计划的七种说法，搜索宽度看起来很大，实际有效分支极少。我们见过两种可行的做法：一是让候选之间显式互斥，把“这条路线的核心假设”写进候选头，生成时要求新候选必须否定至少一条已有假设；二是用不同的提示模板代表不同的规划策略——保守的、贪心的、先做信息收集的——让策略差异而不是采样噪声提供多样性。

价值评估是整条路径的瓶颈，也是最容易把系统做坏的地方。规则分便宜但窄，只能覆盖能被写死的约束；校验器分可靠但慢，而且往往只能在计划走完一段之后才有输出；模型评审分灵活但可被讨好，一旦把它当主信号，搜索会优先找到“最能骗过评审器”的计划。我们的默认配置是把模型评审降级为软信号，权重压低，并且永远不让它单独决定是否回溯。

回溯的前提是状态可回滚。规划搜索里的节点必须持有环境快照，否则回溯只回退了计划文本，没有回退世界状态，系统会在一个已经被自己改坏的环境里继续规划。这一条在写文件、改配置、发消息这类有副作用的任务上尤其关键：能快照的动作才允许进搜索，不能快照的动作应该被约束成“只在里程碑确认后执行”。剪枝按成本从低到高排：硬约束检查、语法与接口可行性、去重、预算剪枝、最后才是价值分排序。便宜规则先跑，能把贵的评估调用量压下来。

    gen --> hard{硬约束检查}
    hard -->|不通过| drop[剪枝并记录原因]
    hard -->|通过| dedup{与已有候选语义去重}

    budget -->|耗尽| done

失效形态值得逐条记住。评估器被讨好：搜索把弱评估器的漏洞当成功信号，指标好看但计划更差。候选同质化：宽度是名义上的，实际只有一条路线。回溯不彻底：只回退文本不回退状态。深度限制导致循环：搜索到上限就整体放弃，长任务永远走不完，正确做法是里程碑级的局部搜索加全局重规划，而不是一层深搜到底。成本方面，搜索的开销是乘法级的——候选宽度、评估调用次数、快照存储与恢复时间一起涨，延迟和费用同时上升；并且它把质量重心从模型转移到了评估器，评估器本身需要一整套测试。这条路径的收益上限，就是评估器的准确度。

反思与错题沉淀：把失败变成可检索条目

反思不是让模型再想一遍，而是把失败变成下一轮能用上的结构化数据。第一步是归因分类。分类表要小，要互斥，要能被自动或半自动判定，否则它会退化成自由文本。我们用这六类作为起点：

最后一类必须有。没有它，所有失败都会归到模型能力上，于是改进方向永远只有“加搜索、加示例”，而真实原因可能只是一条脆断言。归因可以由规则初判、模型复述、人工抽查三层完成；抽查的比例不必大，但必须固定做，因为初判和复述都会漂移。

错题条目是这段流程的落点。条目要能被检索到才有意义，所以它的字段要为检索设计，而不是为归档设计：

检索用两条腿：语义相似度负责召回宽，任务族与触发条件的结构化过滤负责精度高。只有语义检索的条目库，跑半年就会变成噪声源——每个条目看起来都相关，注入提示后互相冲突。写入前要做三件事：与既有条目做近重复合并；要求证据字段非空，也就是必须能指回至少一条轨迹；做一次重放验证，把纠正写进提示在同一任务上重跑，通过才标记为有效。条目要有失效机制：环境版本变了、工具集变了、连续若干次命中后仍失败，就该降权或下线，靠 ttl_days 这种粗机制只是兜底。

失效形态有四种。把相关性当因果：一次失败与某个特征同时出现，就被写成“遇到该特征就会失败”。错题污染：未经重放验证的条目进库，之后被反复注入，反而误导。经验条目过长：库变大后每次注入的 token 开销挤掉了任务本身的信息。把能力问题当知识问题：模型本来就不会做这件事，被记录成“缺一条经验”，于是补了十条经验还是不会。成本上，这一层是中等偏高——归因需要人，验证需要重放基础设施，条目库需要检索服务与生命周期管理。但它是唯一能把单点失败转化为系统长期资产的路径，性价比在半年尺度上通常最好。

可验证里程碑与判定函数

长任务之所以难规划，不是因为步骤多，而是因为中间没有真信号：一路做到最后才知道对不对，于是计划本身无法被局部证伪。把长任务拆成里程碑，本质是在任务内部制造若干可以立刻判定的小目标。这里的关键不是“拆得更细”，而是每一段都要有一个可计算的谓词。判定不了的里程碑等于没有里程碑。

判定函数怎么写，决定了这套机制是资产还是负担。三条经验。第一，尽量判结构与行为，不要判文本形状：断言“配置文件里存在某个键且类型正确”比断言“输出包含某句话”稳得多。第二，每个判定函数都要配一对样例——一个必须通过的输入、一个必须失败的输入；没有负样例的判定函数会在半年内变成永远返回真的摆设。第三，判定要能输出机器可读的原因片段，而不只是布尔值，因为错题沉淀和搜索的评估器都吃这个字段。

部分得分值得单独说一句。它不是为了好看，而是为了让搜索和训练有中间信号：只有二值结果时，“差一点就对”和“完全不对”在评估器里等价，搜索就会把两者同样剪掉。给部分分要保守——每加一档宽松，就多一个讨好判定的入口，所以档位要少、边界要写死，改动必须过回归集。

失效形态有四类。里程碑与真实目标错位：所有里程碑都绿了，需求没满足，这是最典型的指标替代。判定过脆：一个无关紧要的命名差异让整条链路红，团队开始手动放宽，判定随之失去意义。判定过宽：形同没有，只是把错误推迟到最后。把不可判定的目标硬编成判定：比如“架构清晰”，任何写法都是假的。成本上，这是全文最贵的一层之一——判定函数写的是真实业务谓词，需要熟悉领域的人参与；里程碑拆解还需要为每个任务族准备样例环境。好处是它一次写成、长期复用，并且同时服务搜索评估、错题沉淀、训练数据筛选与离线评测，是所有路径里“一份投入多处收益”最明显的一条。

用执行反馈替代模型自评

模型自评能给出流畅的批评，但它的可靠性取决于被评内容与模型自身的知识重合度；越是规划得远的步骤，自评越像复读。执行反馈不同：测试跑过了就是跑过了，校验器报错就是一条具体的、可复现的信号。把规划质量的判据从“模型觉得对不对”挪到“世界说对不对”，是这一节的全部内容。

可用的反馈源按获取成本排：单元测试与集成测试、类型检查与静态分析、linter 与结构校验、schema 与契约校验、沙箱里的 dry-run、构建产物比对、以及人写的判定函数。共同点是它们都能输出结构化裁决，可以直接进我们的四列记录。下面这张时序图是我们实际使用的最小回路，反馈不是终点而是下一轮计划的输入。

把反馈接进规划循环有三件具体的活。其一是把反馈翻译成计划级语言：一条断言失败要能映射到“哪个里程碑的哪个假设错了”，否则规划器只会拿到一堆日志。其二是控制反馈的到达时机：反馈越晚，回溯代价越大，所以把校验拆成计划期可跑的静态检查和执行期才有的动态检查两批。其三是裁决状态，避免“半通过”被当成通过：

unknown 这一支是这套回路里最容易漏的。构建机挂了、外部服务超时、测试本身不稳，如果都记成失败，归因就被污染，错题条目会把基础设施问题写成“经验”，搜索评估也会把环境抖动当成计划质量差异。我们的做法是把 unknown 从训练筛选与评估分母里剔除，只进运维告警。

失效形态：测试套件自身错或被写得过窄，通过变成廉价事；覆盖偏差让规划器学会只做有测试的部分；不稳定用例制造假失败，触发不必要的重规划；通过全部测试但需求没满足——这是执行反馈路径的天花板，它只能证明“没打破已知约定”；反馈延迟过高时，边做边调反而不如先做完。成本主要在环境：可复现的沙箱、隔离的数据、能并发跑的执行资源，这三项通常是团队里最先耗尽的预算。当目标本质上无法执行验证时，例如需要人来判断的设计取舍，仍然只能用模型评或人评，但要把它标成弱信号，不与执行反馈同权。

数据侧：把成功轨迹变成可训练样本

前几层都在推理时做事。真正把能力沉淀进模型，需要数据与训练。这里最容易犯的错，是把“跑出来过”当成“值得学”。一条成功轨迹里含有大量非必要动作，直接切成样本训练，模型学到的往往是那些偶然成分。

第 4 步与第 5 步是质量的分水岭。切片粒度上，我们只在“有外部信号的地方切”：判定通过的点、校验器给出原因的点、动作被环境拒绝的点。在这些点构造监督对象，标签来自世界；在没有信号的地方切，标签来自模型自己，等于把噪声蒸馏了一遍。

反事实验证回答的是“这步真的必要吗”，具体做法有四种，按可信度递增：把该步删掉后重放，看是否仍能通过；把它替换成一个明显的错误动作，看是否被抓到；换随机种子与解码设置重放，看结论是否稳定；换一个同族但改写过的新任务重放，看这条经验是否泛化。四种都做完才能标为高置信样本，代价是重放资源——这也是训练路径最实在的成本。偶然的幸运轨迹通常在这一层被筛掉：没核对状态却刚好正确、依赖外部服务的默认值、跳过校验但测试恰好没覆盖。

失效形态要提前预期。分布偏移：训练集来自内部少数任务族，上线后遇到新族行为退化。学到表层风格而不是决策：模型模仿了成功轨迹的措辞与结构，遇到需要真正权衡的岔路口仍然按原样走。把重试学成必要动作：一次因网络抖动而重试的轨迹，被学成“任何动作都先重一次”。教师污染：用强模型生成的轨迹训练，学生把强模型不犯的特定偏好一起继承，同时把它悄悄回避的难点也回避掉。过拟合任务模板：换掉变量名就失效。成本最高的是这条路径——训练、评测、回滚、数据版本与审计缺一不可，而且每轮迭代周期以周计。它还带来一个组织问题：一旦开始训练，示例库、判定函数和评测集就成了需要治理的资产，不再是脚本。

评测侧：在不作弊的前提下证明规划变强

改进到这一步，唯一有意义的提问是：怎么知道它真的变强了。规划任务在这里格外危险，因为答案可以被记住，判定函数可以被讨好，任务集可以在无意中被污染。

任务集设计要同时满足四点。分层：每个任务族按所需能力打标签——是否需要多约束权衡、是否需要先收集信息再动手、是否存在不可回滚动作、是否需要跨子系统一致性。没有标签的任务集只能给你一个数字，不能告诉你为什么。留出家族：新写、不共享模板、不参与任何调优的任务族，只在版本切换时跑一次，这是判断泛化的唯一依据。时间切分：把最近实际遇到的工单变成任务，而不是只维护一批老题。污染检查：与公开语料、示例库、训练集做相似度比对，命中就换题，而不是“人工看一下觉得不像”。

随机性要当成一等公民处理。规划类任务的方差很大，一次运行的结果几乎没有信息量。我们的约定是：采样重复次数写进评测配置并对所有对比统一；温度与解码设置属于实验变量，改动它们等于换一个实验；跨版本比较必须在同一沙箱镜像与同一工具集上做，否则环境变化会被读成能力变化。统计上谨慎一点：小样本的成对比较更适合看逐任务的胜负分布，而不是急着宣称差异显著。

防作弊是评测侧最耗人的一面，因为作弊往往不是恶意的，而是自然发生的。有效手段有：把答案来源封在工具白名单外，禁止检索原题解；判定函数在评测期间对规划器不可见；轨迹日志全量留存并做人工抽检，专门看有没有硬编码结果、绕过校验、直接写入产物、把测试改成迁就实现；同一任务做等价改写后重跑，靠背诵通过的方案会立刻退化。评测集规模不必大，但必须有“背下来也没用”的那部分——判定依赖实时环境状态的题，本质上无法背。

失效形态：指标驱动优化——团队开始只对评测集写作，留出家族暴露真实退化；指标漂移到无关项，比如输出格式越来越规整但计划质量没变；把过程分当结果分，里程碑全绿而需求未满足；评测集泄漏进示例库或训练集，于是所有改进都“有效”；对 unknown 的剔除比例失控，让分母悄悄变小。成本上，这套基础设施需要独立维护任务集与判定函数的版本、一套隔离的评测环境与沙箱镜像、以及日志审计的人手。推理预算与对齐方法各自有自己的机制层文章，本文只承认一个事实：这两条路的结论都依赖本节这套评测当裁判；裁判不独立，两边结论都不可信。

六条路径的对照与落地顺序

把前面的内容压成一张表，方便按团队现状选路。见效速度是“从动手到能观察到指标变化”的量级感受，不是任何测量结果；主要风险指最容易踩的那一个，不是全部。

落地顺序我们给一个明确建议。先做度量与四列记录，这一步不做，后面所有路径都无法归因。接着做里程碑与判定函数，因为它同时服务搜索、沉淀、训练和评测，是唯一一份投入四处收钱的工件。判定函数稳定之后，再考虑把搜索接进来——此时评估器才有可靠主信号。错题沉淀与执行反馈回路可以和搜索并行，但要注意搜索会把评估器的缺陷放大，所以顺序上永远让“便宜的硬约束检查”排在“贵的模型评审”前面。数据与训练放最后，理由是它完全依赖前面几层产生的干净标签：判定函数不可信、执行反馈缺失、错题没有归因时开始训练，只会把噪声固化进权重。

小结

本文把规划能力当成一个工程指标来谈，落点是七件事：把输出形状钉死的提示骨架；带互斥候选、状态快照与便宜规则前置的搜索；有归因分类、重放验证与失效机制的错题条目；必须自带可计算谓词的里程碑；以结构化裁决和 unknown 分支为特征的执行反馈；靠硬筛与反事实验证撑起来的数据流水线；分层、留出家族、时间切分与防作弊四件套组成的评测。它们各自的失效形态与成本完全不同，所以改进必须一次只动一层，并且动之前先确认度量存在。如果只允许记住三句话：第一，没有判定函数就没有规划改进，因为无法归因；第二，执行反馈永远优先于模型自评，除非目标本质上不可执行验证；第三，评测集是这条路上最稀缺的资产，它一旦被污染，所有历史结论一起作废。规划能力变强不是一次灵光，而是一整套让“变强”这件事可观测、可复现、可回滚的基础设施。
