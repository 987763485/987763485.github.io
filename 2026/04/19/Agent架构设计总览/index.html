Agent 架构设计总览

本文属于《Agent 智能体开发》第 30/55 篇
上一篇系列目录下一篇

本文把 Agent 系统拆成可以命名的层次，给出每层的一句话职责、三个关键设计选择，以及该层与相邻层之间的边界。它不深入任何单层的实现细节：遇到细节，本文只写一句划界，然后把读者指向对应的主题。目标只有一个——读完之后，你碰到一个新问题应该能回答”这属于哪一层、这层的默认方案是什么、什么信号说明该换”。

从最小回路讲起

所有 Agent 都从同一个回路长出来：一个模型、一个循环、一组工具。三件东西各自补上纯语言模型缺的一块能力。模型负责在给定的上下文里做出下一步判断，这是”决策”。循环把一次性的问答变成可迭代的过程，让上一轮的结果成为下一轮的输入，这是”时间”。工具让模型的输出落到模型之外的世界——读文件、查数据库、发工单——再把世界的回答原路带回上下文，这是”作用力”。缺任何一件，系统就退化成别的东西：没有循环是单次调用，没有工具是聊天机器人，没有模型则只剩一串写死的脚本。

这个不到三十行的回路，是本文后面全部内容共同参照的基准形状：每一层都是它的某一部分被拉伸、被复制，或者被外部要求之后长出来的。要记住的是回路里没有”框架”这个词——框架只是后来给这些部位起的名字。

    B --> C["模型决策"]
    C -->|"需要调用工具"| D["执行工具"]

两条划界提前说清：模型本身怎么部署、怎么扛并发与延迟，属于推理服务那一侧，见《大模型推理服务架构》；回路里”怎么把大目标拆成小步、步与步怎么排”属于规划那一侧，见《Agent 任务规划与分解》，本文后面也不再碰这两块。

六层框架

最小回路能跑，但生产系统围着它会长出六种彼此独立的关注点。本文用六层给它们编号：接入、编排、执行、记忆、评测、治理。编号的全部价值在于——任何讨论都得先说清在哪一层，跨层的抱怨才有资格被称为问题，而不是口味之争。

接入层。职责：把外部请求变成一次可追踪的运行，并把运行过程中的状态变化送回外部。三个关键设计选择：协议形态（REST、SSE、WebSocket 各承担什么）；会话与租户标识怎么生成、怎么一路透传；流式与取消的边界划在哪。

编排层。职责：决定下一步跑什么、由谁来跑、失败往哪走。三个关键设计选择：编排范式（代码式链、声明式图 / DAG、状态机 + 事件）；运行状态放在哪一层手里；单智能体还是多智能体分工。

执行层。职责：安全地产生副作用，并把世界的回答整理成结构化结果。三个关键设计选择：工具粒度做多粗；权限与确认门槛设在哪里；沙箱与网络出口怎么收。

记忆层。职责：决定什么留在上下文里、什么写出去、什么时候忘掉。三个关键设计选择：上下文窗口 / 会话记忆 / 长期记忆三层怎么划界；写入策略（谁能写、写什么、要不要人签字）；检索与淘汰用什么口径。

评测层。职责：让”这次改动变好了”成为可复核的命题，并把复核结论接回架构决策。三个关键设计选择：黄金集怎么建、怎么维持不过期；离线门禁挂在流水线的哪一步；线上真实交互怎么回灌成用例。

治理层。职责：让运行可归责、可追责、成本可控、义务可满足。三个关键设计选择：身份与凭据模型（人、服务账号、智能体代理身份三者怎么区分）；审计留痕记到哪一层保真度；成本预算护栏与合规义务怎么落到同一个链路上。

六层的顺序有讲究：接入在最外，因为它最先接触不可信输入；治理在最上，因为它对所有层都可能行使否决权；评测与治理是仅有的两个横向层，它们不产生业务步骤，只约束别的层怎么产生步骤。后面每层各给一次地图，不给路。

接入层

接入层解决的问题是：外面的人怎么把一个意图交进来，以及交进来之后他怎么知道自己没有被遗忘在某个队列里。形态上通常是三种协议搭配使用，而不是三选一。REST 承担提交任务、查询历史、拉取工件这些”一问一答”的动作，好处是能复用现成的网关、限流与鉴权设施，任何语言的客户端都写得出来。SSE 承担过程可见性，把生成中的文本增量、工具调用开始与结束、阶段变更按序推给调用方；它单向、走普通 HTTP、容易被中间设备透传，代价是断线重连必须自己补齐语义。WebSocket 留给真正双向的场景：用户在运行中途补充信息、多路复用若干条运行、需要低延迟取消指令。判断标准很朴素——只推不需要收，就别升级到 WebSocket。

会话标识是接入层第二件事，也是最容易被拖到最后才补的一件事。一个可用的最小集合是四个标识：租户标识、会话标识、运行标识、步骤标识。租户标识决定配额、数据边界和审计归属，必须来自鉴权结果而不是请求体；会话标识把多轮对话与同一批记忆绑在一起；运行标识对应一次回路执行，是所有日志与追踪的根；步骤标识把运行内部的每次模型调用与工具调用排出来。四个标识一路透传，评测层与治理层才有可能把数据接回来——这也是本文反复强调”先分层、后细节”的原因：这四个字段是跨层的接口，不是接入层的私事。关于 Agent 应用怎么把这套接口做成产品形态，属于《Agent 原生应用架构》的范围，本文不展开。

流式与取消的边界要说清楚，否则后面所有的”卡住”都会被归咎于模型。流式的边界在于：可以流的是文本增量与阶段事件，不可以流的是尚未确定的副作用承诺。工具结果在确定之前不能当成最终回答推给用户，否则取消时无法解释”你说了一半又说不算”。取消的边界在于：接入层只负责把取消意图变成一个带运行标识的信号，真正决定”现在能不能停”的是编排层和执行层。已经发出但尚未提交的外部写操作，必须靠幂等键与补偿动作收尾；沙箱里正在跑的进程可以强杀，外部世界的 API 不能强杀。因此一个诚实的取消语义至少有三种结果——已停止、已提交无法撤回、正在收尾——把取消实现成布尔值是最常见的架构错误。

编排层

编排层是六层里唯一”每层都可能变成它”的一层，所以最需要划界。它只做三件事：决定下一步、把状态推进、失败时选择去哪。范式有三种。

代码式链：编排逻辑就是宿主语言的函数组合，控制流写在 if 和 for 里。它的长处是迭代快、调试直接，模型输出的中间形态不必先映射成数据结构。代价是运行状态散落在调用栈和闭包里，进程一死就没了，恢复要靠外部补齐；同时”这段链跑到哪儿了”对上层不可见。LangChain 1.x 主线与 OpenAI Agents SDK（仍是 0.x）这类以代码为中心的取向，基本落在这个范式里。

声明式图 / DAG：把步骤与边写成一张可序列化的图，运行时按拓扑推进，节点状态可持久化、可重放、可从中间节点恢复。长处是可视化、可在图层面做并发与重试策略，天然适配”流程固定、内容由模型填充”的业务；代价是灵活性被图的结构约束住，模型在运行时想加一步就得走动态子图这类补丁。LangGraph 1.1 的取向属于这一范式。

状态机 + 事件：状态显式建模，转移由事件触发，编排器只做匹配与派发，副作用留在事件处理器里。长处是与消息中间件、工作流引擎、审计系统最合拍，分布式部署与故障恢复是它的主场；代价是事件风暴，以及”看起来什么都能接”导致意图散落在几十个处理器里，很难回答”这个流程整体在干什么”。

CrewAI、AutoGen、Eino 在本文只按定位提及：前两者偏多智能体协作的角色编排，Eino 偏 Go 生态的组件化编排，三者各自覆盖前述一到两种范式。三种范式在同一个真实系统里怎么选、怎么混用、怎么比价，是编排对比主题的范畴，本文只承认”必须有名字”这一件事。同样，多个智能体之间怎么分工、怎么通信、怎么收敛，属于《多智能体协作模式设计》，本文只把它记为编排层的一个设计选择。一句必须写下来的提醒：不要因为一张图能画得漂亮，就把所有决策都塞进图里；图的价值在可恢复，不在表达力。

执行层

执行层是系统里唯一真正改变世界的地方，因此它的架构问题全都是安全问题，只是表现成接口问题。第一个选择是工具粒度。粗粒度工具（”部署这一版”）让模型少做决定、少犯错，但一次调用背后是十几个不可见步骤，失败时无法定位、权限上无法分级；细粒度工具（”读这个文件””执行这条命令”）可组合、可审计，代价是模型要在长序列里保持一致意图，上下文负担和步数预算都涨上去。实践里有个朴素判据：一个工具应当在权限边界处切断，而不是在功能边界处切断——两件事需要不同的授权，就应该是两个工具。工具接口本身怎么跨进程、跨语言暴露，属于协议层，本文只承认 MCP（2025-11-25 修订版）已经把工具与资源的声明形态标准化、其 Registry 仍在预览这一事实。

第二个选择是权限与确认门槛，它是执行层与治理层唯一的交接面。要回答的三个问题是：智能体以谁的身份行动；哪些动作可以自动做、哪些必须人签字；签字发生在执行前还是可以在执行后补救。门槛通常按”可逆性 × 影响半径”两个轴摆放，最激进的组合是不可逆且影响半径大（对外付款、删库、发生产变更），这类动作的正确架构不是”提示模型谨慎”，而是在工具实现里强制两段式：先申请、拿到带运行标识的一次性凭据，再执行。具体阈值由团队约定，示例值是”影响半径大于 100 个对象或不可逆即需人签字”（示意值）。至于沙箱怎么隔离、网络出口怎么收敛、越权与提示注入在执行层怎么拦截，属于沙箱与权限主题，本文一句带过；但要提醒一句：沙箱是执行层的架构属性，不是可插拔的安全附件，等工具集稳定后再补沙箱，几乎必然要重写工具签名。

第三个选择是出口。所有对外调用收敛到统一网关，才能同时满足审计留痕、成本控制与幂等重试；否则这四件事要在每个工具里各写一遍。运行时的宿主形态也归执行层：容器编排走 K8s 1.35，Node 24 LTS 与 Go 1.26 是当前主线，Python 侧的数据类运行时以 PyTorch 当时主线 2.x 为参照——这些版本号只用来定位年代，不构成选型理由。

记忆层

记忆层只处理一个问题：模型的上下文窗口是有限的、昂贵的、且会过期的，那么什么该在里面、什么该在外面、什么该消失。本文用三层切法。第一层是上下文窗口本身，装的是一次推理真正能看到的全部内容，它的架构问题是预算分配而非容量。第二层是会话记忆，跨越同一会话的多次运行，通常以结构化摘要、待办清单或工件引用的形态存在，特点是与租户会话同生命周期。第三层是长期记忆，跨会话、跨用户边界持久保存的偏好、事实与经验，写入需要授权，读取需要过滤。三层之间是”提升”与”降级”两条通道：反复出现且被验证的信息往上提升，过期、被证伪或触及隐私边界的信息往下降级。上下文里各部分具体怎么组织、压缩与排序，属于《Agent 上下文工程》，本文不碰；至于长期记忆怎么召回更准，本文只强调它与分层是两件事——先有层，再谈层内的检索，长期记忆的具体召回手段见《Agent 记忆检索优化》。

写入与遗忘的边界比读取更难，也更值得在这一层先定下来。写入侧要看三个信号：谁有权发起写（模型自己、编排层，还是只有人能写）、写进去的东西以什么证据支撑（有无来源与时间戳）、写错了怎么撤回。默认策略应是保守的——模型可以建议写入但不能直接落库，因为错误记忆的特点是会被反复读回并自我强化，一次污染长期生效。遗忘侧要同时支持三种删除：按主体删除（某个用户的记忆全清）、按来源删除（某次错误写入的回撤）、按时间过期。一个可复核的实现要求是：每条长期记忆都能回答”从哪来、什么时候写的、被引用过几次”——这三个字段同时是治理层审计的输入，所以记忆层不是纯效率层，它是治理的落点之一。

评测层

评测层的架构职责不是”跑出分数”，而是让分数有地方挂。没有挂载点的评测会在两次迭代后变成没人信的私有脚本。三个挂载对象依次是黄金集、离线门禁、线上回灌。

黄金集是一组有明确期望输出的任务，覆盖你最不希望退化的行为。它的架构要求是版本化与被引用：每个用例要记录它测的是哪一层（接入、编排、执行还是记忆），期望输出由谁确认、什么时候确认，以及它对应的真实故障编号。一份不记来源的黄金集会缓慢腐烂成”模型刚好会做的那些题”，这时分数只反映运气。离线门禁挂在两个位置：一是代码与提示变更的合并前检查，跑固定子集，反馈周期以分钟计；二是发布前的完整跑批，比较新版本与当前线上版本在同一批任务上的表现，未通过就不允许进入灰度。门禁的阈值是团队约定，示例值是”关键任务集合上退化超过 2 个百分点即阻断”（示意值）。线上回灌是把真实交互变成架构输入的唯一通道：接入层保留带运行标识的完整轨迹，用户反馈（纠正、重问、放弃）作为弱标签，每周从失败轨迹里挑出可复现样本进黄金集。回灌的价值取决于一个前置条件——轨迹必须可重放，也就是说编排层的运行状态与步骤标识要留得住，否则你只能重建环境，成本会让人放弃这件事。评测怎么做指标、怎么建评分器、怎么用人工复核校准自动判断，属于评测体系主题，本文只规定它在架构里的挂载位置。Anthropic 在其官方 engineering 栏目发过题为《agent evals》的文章，可作为这一挂载思路的当代参照。

治理层

治理层解决的是”出事之后能不能说清”和”钱花在哪能不能拦住”。四个关注点，本文把它们压回三个设计选择加一条底线。

身份与凭据。第一件事是把三种主体分开：人、服务账号、智能体代理身份。智能体最危险的状态是用人的完整凭据行动——它既继承了人的所有权限，又不具备人的判断节制。可用形态是代理身份加短时凭据：由编排层为一次运行申请范围受限的令牌，作用域就是这次运行要碰的资源集合，用完即失效。跨组织的智能体互通也需要身份这一层，可点名的协作协议是 A2A（v1.0.0 距今刚过一个月）与 AGNTCY，本文只把它们记为”身份与互通有标准可对接”这一事实。

审计留痕。留痕范围要按层的接口来定而不是按日志级别：接入层记录谁在什么时候提交了什么意图，编排层记录状态转移与决策依据的摘要，执行层记录每个副作用的目标、参数摘要与结果，记忆层记录写入来源与撤回。跨层串起来的还是那四个标识。载体上可复用 OpenTelemetry 的追踪语义，避免自建一套无人能读的私有格式；保真度要设 retention 与脱敏策略，因为完整留痕本身就是一种数据风险。

成本与预算护栏。成本是治理对象而不是报表：预算护栏要能在运行中被触发，触发结果是降级、暂停还是拒绝，属于编排层要处理的显式事件。至少三级：步骤级（单轮工具调用上限）、运行级（一次任务的令牌与费用上限）、租户级（周期预算与并发上限），阈值都是团队约定，示例值如”单运行 20 步、单租户日预算触达 80% 时告警”（示意值）。合规义务是底线而非选择项：数据出境、留存期、可解释性、被删除权，这些要求在架构上的唯一表现是”有些层的接口必须能导出、必须能撤回”，所以它天然和记忆层、审计留痕绑在一起。安全与合规的具体控制项属于安全与合规主题，本文一句划界。治理最后一个常见误区是把它理解为”开源生态里有没有中立基金会”——事实上 MCP、AGENTS.md 与 goose 已进入开放基金会治理（AAIF 于 1 月发布公告），但这只解决标准归属，不解决你系统里的问责链，后者仍然是架构问题。

各层常见耦合与拆分时机

分层不是道德义务，它只在耦合造成真实故障时才值得拆。这四组是最常见的过早耦合，每组给一个可观察信号——出现信号再拆，比一开始就搭满六层要省得多。

编排与执行耦合。表现是编排代码里直接写着外部调用：图节点里内联一条 SQL、一个 HTTP 请求或一次文件写入。好处是快，代价是权限、沙箱、重试、幂等、审计这五件事全部散落在编排逻辑里，改一个执行细节要在十几个节点上各改一遍。信号：同一类副作用的代码片段在编排层出现第三次；或者你发现没法在不给生产凭据的情况下跑通一个编排单测。拆分时机通常在第二个租户或第二类副作用接入时。

记忆与上下文混用。表现是”上下文不够就往库里塞”，会话记忆、长期记忆和一次推理的上下文被当成同一个桶，写入没有来源、读取没有边界。它的故障形态很特别：系统看起来更聪明了，然后开始稳定地重复某个已被纠正过的错误。信号：一次回答里出现了当前会话没说过、也查不到来源的”事实”；或者你无法用一条查询列出某条持久记忆的写入时间与引用次数。这个信号一旦出现就必须立刻处理，因为污染是自我强化的。

评测被离线化。表现是评测跑在团队私有的脚本和一份没人维护的表格里，与线上轨迹、与流水线都没有连接。它不报错，只是慢慢失去发言权，最后架构决策重新变回口味。信号：出现”线上有用户抱怨但所有评测都满分”的季度；或者新用例进黄金集需要手工复制粘贴。拆分方式是把轨迹采集挪进接入层、把门禁挪进流水线，让评测层只剩用例与判据。

治理后置。表现是系统能跑、能上线，但智能体用的是人的凭据、日志里没有运行标识、成本只在账单上看得见。这是四种耦合里唯一会一次性造成不可逆损失的：出事时无法重建因果链，退款与合规义务无法履行。信号：需要回答”上周三那次错误写入是谁发起的”却要在三个系统里翻日志；或者某次实验的 token 消耗要到月末才知道。治理不需要提前建完，但身份透传、运行标识、预算护栏这三件事必须在有真实用户之前就有，后补的代价是改一遍所有层的接口。

四组之外还有一条通则：任何”为了架构干净”而做的拆分，如果不能说出它消除了哪个信号，就只是把一次耦合换成十次远程调用。

按业务形态给的默认配置

四种业务形态的差别不在模型，而在哪一层先承受压力，以及哪一层最该先补。以下是推荐的默认配置与第一块补丁，都是”先按这个搭、出现相应信号再改”的意思。

对话助手。默认配置：接入层做全（SSE 为主、WebSocket 只在需要中途补充信息时启用、取消语义完整），编排层保持简单的一条代码式链，执行层只暴露读类工具，记忆层重视会话记忆。最该先补的是记忆层的写入边界——对话产品里用户会主动要求”记住这件事”，如果模型可以直接落库，你会在短时间内收到大量未经确认的偏好，之后每次召回都在放大它。

编码智能体。默认配置：执行层最重（细粒度工具、强沙箱、明确的出口收敛、两段式确认），编排层用声明式图或状态机把”改—测—修”的循环固定下来，接入层的流式要能表达 diff 与阶段事件。最该先补的是执行层的权限与确认门槛——编码智能体天然会碰文件系统和版本控制，一个自动 commit 或自动推送的边界不清，故障半径就是整个仓库。

数据分析。默认配置：记忆层的上下文预算与执行层的沙箱是主战场，编排以声明式 DAG 为主以便复用中间结果，评测的判据最容易做硬（数值可比对）。最该先补的是评测层的黄金集与口径版本化——分析型 Agent 最危险的失败不是崩溃，而是给出一个看起来合理但口径错误的结论，而这类失败只有固定口径的用例集能提前抓住。

流程自动化。默认配置：编排层用状态机 + 事件，与既有工作流引擎和消息中间件对齐；治理层身份、审计留痕与幂等键先行；执行层的工具粒度按审批边界切。最该先补的是治理层的身份模型——自动化流程往往要跨部门、跨系统代人办事，如果没有代理身份与范围受限凭据，就只能给每个环节发一份管理员凭据，这在审计上无法交代。

这张对照还有一层意思：四种形态里”最该先补的一层”彼此不同，说明 Agent 架构没有通用的第一优先级，只有先承受压力的那一层。真正通用的建议是本文反复出现的那条——先把跨层的四个标识与两个接口（取消、留痕）定下来，其余都可以晚一点。

术语对齐

同一个词在不同框架的文档里指向不同东西，是分层讨论失败的主要原因。这张表把本文的用法钉住，右边是本文会遇到的同义或近义叫法。

本文用法 常见同义叫法 需要警惕的差异

层 关键选择 默认方案 该换的信号

小结

本文的全部主张可以压成三句。第一句，Agent 系统的起点是一个回路：模型决策、循环给时间、工具给作用力，其余都是这三者的延伸。第二句，用接入、编排、执行、记忆、评测、治理六层给关注点编号，任何讨论先声明在哪一层，跨层的意见才能被检验。第三句，分层的时机由信号决定而不是由审美决定——同类副作用复制到第三处、无来源的事实出现在回答里、评测满分而线上抱怨、事故后拼不出因果链，这四个信号分别指向编排执行耦合、记忆上下文混用、评测离线化与治理后置。把四个标识与取消、留痕两个跨层接口先定下来，是本文唯一愿意无条件推荐的架构动作。至于每一层内部怎么做好，请看对应的主题文章；本文只负责让你知道该去哪一层找。
