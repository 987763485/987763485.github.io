Agent 原生应用架构

本文属于《Agent 智能体开发》第 50/55 篇
上一篇系列目录下一篇

本文讨论的不是怎么把模型接进来，而是当模型输出会直接变成对系统的操作时，应用该长成什么形状。核心命题一句：把模型主导的不确定执行当作默认形态而不是异常分支，并为它准备可观测、可中断、可回退的基础设施。范围限于应用层形态与前后端职责。

什么算 Agent 原生

传统应用的执行路径由代码写死，输入只是数据，分支在设计时已枚举完备，异常路径是少数，出现即视为故障。Agent 原生应用把这套假设反过来：一次请求走几步、调用哪些工具、何时收尾，由模型在运行时决定。架构上的后果是，路径不可预知、结果不可保证必须被当作常态来设计，而不是需要兜底的意外。

与“在应用里加个聊天框”的区别正在于此。聊天框形态下模型是终端消费者，输出到文本为止，副作用仍由既定代码触发；Agent 原生形态下模型是执行主体，输出会变成对内部系统的写入。此时继续沿用“凡从入口进来的都只是数据”的信任模型，会同时打开越权与注入两道口子。判断标准因此不是有没有对话界面，而是模型的决定能否直接产生副作用，以及这条链路有没有被架构性约束。

边界要说清楚。本文只讲应用层的形态与前后端职责：分层视角下的组件归属另有专文讨论，推理服务侧的调度与容量不在这里出现，从传统架构到 AI 架构的阶段划分以演进那篇为准，规划、记忆与工具的总体设计见 Agent 架构设计总览，上下文如何裁剪与组装也不属于本文范围。

前后端职责重划

一句话原则：工具执行与凭据留在服务端，前端只负责呈现、中断与确认。

理由有三层。其一，浏览器不可信——脚本可被改写，长期凭据一旦下发就等于交给任意租户，令牌存在本地既挡不住 XSS，也没有撤销的即时性。其二，工具通常要访问内网系统，浏览器没有这条路，也不该为了前端方便把它开出来。其三，审计只能发生在服务端：谁批准了哪次写入，以服务端日志为准。

落地时把接口按能力分三类。呈现类只读地返回结构化片段供渲染；执行类只在服务端凭证域内调用工具，前端拿到的是回执；决策类把模型发起的高风险动作先转成待确认对象，前端渲染成预览与按钮，用户点击才推动执行。前端唯一能控制模型的是中断信号，不是执行参数。

参数校验也归服务端。确认消息只携带动作标识与一次性批准令牌，服务端据此取回原始待执行对象。若允许前端回传参数，攻击者就能在预览所见与实际执行之间做替换——这是 Agent 应用特有的一类漏洞，传统 Web 的防御经验覆盖不到。

流式与中断恢复

一次轮次动辄数十秒，结果必须边生成边回传。SSE 走普通 HTTP，方向单一，自带浏览器重连与 Last-Event-ID，能复用现有鉴权、网关与重试语义；WebSocket 提供双向低延迟通道，代价是心跳、重连与鉴权都要自己实现。多数 Agent 应用前端只有开始与取消两个控制信号，各走一次 POST 就够，因此首选 HTTP POST 加 SSE；只有交互真的需要频繁双向时才换 WebSocket。选 SSE 要记住两个坑：关掉网关侧响应缓冲，服务端周期性发心跳注释帧，否则空闲连接会被中间设备掐断。

取消语义必须传到模型与工具两侧。前端的 abort 只关掉了本地那条流；服务端要显式停止生成、释放推理槽位，并区分可中断与不可中断的工具：可中断的终止后落一个 cancelled 状态，不可中断的（转账、发信）跑完再如实汇报，绝不假装已取消。取消后的部分结果仍要写进会话历史，否则下一轮模型看不到这段被打断过，会重复同样的动作。

断线重连靠持久化的事件日志而不是内存。每条事件带全局自增 id 与轮次 id，重连时凭 Last-Event-ID 续播；超出保留窗口则降级为返回该轮次最新快照，让前端重建界面。

会话状态放哪里

状态按性质分开放。结构化状态——轮次索引、工具回执、待确认对象、事件日志——放事务型存储，保证按会话可恢复；大段原始产物放对象存储，会话里只留引用；跨轮摘要与检索内容放向量或关键词索引，它们是加速手段而不是真相来源。

过期由状态所有者负责。应用服务是唯一写入者，TTL 在写入时由服务端打上，不交给浏览器或客户端定时清理；同一会话里事件日志保留短、审计记录保留长。恢复语义分三档提前设计：完整重放、快照恢复（只回到最近检查点，缺失的中间结果要在界面标注出来）、不可恢复（明确告知用户并保留已执行动作的记录）。最忌讳的是把三档压成一种，让用户以为什么都没发生过。集群部署、会话亲和与容量规划属于生产部署架构的话题，本文不涉及。

幂等与并发

不确定执行带来大量重复触发：模型重试一次工具调用、超时后前端再点一次、用户在两个标签页各发一轮。三条约束把它收敛掉。

第一，同一会话同一时刻只允许一个活动轮次，第二个请求凭轮次租约被拒绝或排队——两条并行的写入流互相踩对方上下文，是最难复现的一类线上问题。第二，每个动作带幂等键，由客户端生成、服务端连同工具回执一起入库，重试撞上同一个键直接返回旧结果；上游工具不幂等时在服务端做键到结果的映射层。第三，写操作确认门槛按副作用可逆性分级：只读免确认，可逆写自动执行但留撤销，不可逆写必须经过人工预览确认。分级在服务端判定，绝不由模型自己声明是否需要确认——它会照自己的乐观估计回答。

把提示词当配置管理

提示词是配置，不是常量。一旦它决定工具选择与写入风险，就要按配置的待遇管理。版本化：每份提示词带版本号与改动说明，会话记录里写入本轮实际使用的版本，出问题能定位到具体文本。灰度：按租户或流量分桶下发不同版本，使提示词发布与代码发布解耦。回滚：一键退回上一版，且不依赖完整的部署权限。审计：改动需双人复核，发布前留存差异与评测结论。运行时传版本指针而不是内联长文本，既省流量又让版本可查。提示词本身的写法与治理体系在专门讨论提示词管理的文章里，本文只关心它在应用里如何被下发、回滚和记录。

UI 形态要点

界面是这套架构最后一层防线，五件事必须做齐。

  • 动作前预览与确认：把准备执行的写入渲染成人能读懂的差异，而不是原始 JSON 或参数列表；确认按钮绑定一次性令牌，过期即失效。
  • 执行过程可见：流式展示步骤、当前工具与已耗时，并明确标注这是计划不是结果，避免用户把中间态读成完成态。
  • 可中断与可撤销：停止按钮在整个生命周期内可用，包括等待确认阶段；能撤销的提供撤销入口，不能撤销的写清原因。
  • 成本与用量呈现：展示本次会话的 token 与费用估算、步数上限消耗，让贵在使用时被发现。
  • 失败后人工接管：报错或触达阈值时，把会话连同已执行动作转成人类可编辑的工单。接管入口本身是产品功能；谁值班、如何排班属于运营机制，不在此展开。

评测与灰度在应用层的接口

评测系统要放量，应用层就得先把钩子留好。功能开关控制两件事：某类工具是否开放，以及单轮允许的自治步数上限。放量按租户粒度做，新版本先在一批可承受的租户上跑。发布卡点是硬约束：离线评测门禁通过才允许打开写操作开关，未通过就停在只读形态。实现上把模型版本、提示词版本、工具集版本与开关配置合成一个可命名的发布单元，出问题整体回退，避免只回退一半导致新提示词配旧工具。Anthropic 工程栏目《agent evals》一文在应用层的落法是：离线评测通过只是放开写操作的前置条件，线上样本不足时不能用离线分数补位。

反模式

下面几条在实际代码里出现得最多，按危害排序。

  1. 把模型输出直接拼进 SQL 或 HTML。本质是把模型当成可信来源，模型说了什么就执行了什么，注入面从输入框扩大到查询与渲染层。参数化查询与输出转义仍是第一步。
  2. 前端持密钥。为省一次往返把长期凭据下发到浏览器，换来租户边界整体失效，且无法即时撤销。
  3. 用轮询代替流。既有秒级延迟，成本又随会话数线性膨胀，还让取消信号晚到好几拍。
  4. 把上下文窗口当数据库。要长期记住的东西全塞进提示，窗口越挤越贵，历史也没有可查询的结构。
  5. 取消不做传播。界面停了，模型继续生成、工具继续写入、账单照算，这是最容易被当成小 bug 的严重缺陷。
  6. 让模型自己声明是否需要确认。风险分级交给被评估对象，等于没有分级。
  7. 事件不持久化。刷新即丢，断线无法重放，事后无法审计。

迁移路径

从既有应用出发，稳妥的顺序是三步走，每步都有可判定的验收标准。

第一步，只读工具。模型能调的能力限制在白名单内的查询接口，不给任何写权限。验收判据：工具清单可枚举且无凭据外泄；注入测试用例全部被拦下；每条回答能溯源到它实际读过的资料。

第二步，受控写操作。开放少量可逆写入，高风险动作一律走预览确认。验收判据：不可逆动作百分之百经过人工确认；幂等键覆盖所有写接口；取消能真正中止模型生成并留下记录；审计日志能完整复原一次动作的因果链。

第三步，多步自治。允许模型决定步数与工具序列，同时收紧硬上限。验收判据：步数与预算上限由服务端强制；三档中断恢复语义可用；按租户灰度与一键回滚演练过。工程栈上通常两端并行：前端与接入层跑在 Node 24 LTS，编排与工具执行用 Python，性能敏感的服务端执行器再考虑 Rust；图状态机可用 LangGraph 1.1，LangChain 已是 1.x，OpenAI Agents SDK 仍在 0.x，选型要留抽象层；工具接入按 MCP 到 2025-11-25 修订为止的能力，异步 Tasks 与 Extensions 已可用，Registry 仍在预览；多智能体协作可关注 A2A 这类早期规范，它刚过一个月，不建议押上核心链路。

小结

Agent 原生架构的判别方式很简单：让模型输出直接变成可执行的动作，看系统还站不站得住。站得住的前提是三条边界清楚——执行与凭据在服务端，呈现、中断与确认在前端，事件与状态可持久恢复；再加三件配套——幂等键收敛重复、提示词按配置管理、发布按开关放量。反模式清单里每一条都对应一处把模型当可信来源的疏忽。三步走之所以按只读、受控写、多步自治排序，是因为风险只在副作用这一侧增长，模型能力本身不需要我们抢跑。
