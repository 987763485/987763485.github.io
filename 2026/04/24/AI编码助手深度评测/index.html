AI 编码助手深度评测

本文给出评测设计与记录口径，不给具体分数与名次。文中所有表格都是空白模板、所有阈值都标”团队约定示例”，读者要带走的是”怎么把一次改动请求变成可复核的实验”。适合准备在自家仓库里做编码助手选型的工程负责人，读完可直接复用任务集建法、指标口径、判定伪码与记录表。

评测对象、口径与事实边界

评测单元的定义

一切设计都从最小可复核单位开始。本文把”评测单元”定义为一次仓库改动请求，由五元组唯一确定：固定的仓库快照（精确到提交号）、不改写的任务描述、一条验收命令、一份上下文预算、一次运行记录。五元组齐备，第二个人在同一快照上重跑才能得到同类判定；缺任何一项，这次结果就只是演示，不是证据。

粒度定在”一次改动请求”而不是”一次对话”，是因为这类助手的价值最终要落到能否合入主干；对话体验与补全顺手度属于实现层感受，本文不纳入判定。

与相邻文章分轴：通用智能体基准的口径、公开榜单本身该怎么解读、编码助手自身的循环与上下文实现，都不在本文展开；黄金集建设、模型评分器偏差校正、人评抽样与仲裁、泄漏检测、回归门禁这些通用件已另文写过，本文只从编码任务的特有部分切入——可合入、改动量与持续集成判定。

一条流水线而不是一个分数

  A[选定仓库快照] --> B[抽取任务描述]
  B --> C[固定验收命令与上下文预算]

  D --> E[CI 判定: 构建加测试]

  H --> I[多轮重跑看离散度]

事实边界

本文只写公开时间已核实的产品事实：GitHub Copilot 的 agent mode 于 2025-02-06 进入 VS Code Insiders 公开预览，于 2025-04-04 面向全部用户并带上 MCP 支持；Devin 于 2024-03-12 以 early access 形态公告；Claude Code 只写”2025 年公开”，精确日不写；SWE-bench 出现在 2023 年、SWE-bench Verified 出现在 2024-08，本文只用其存在年份说明”编码任务基准”这一形态早已成立。Cursor、OpenAI Codex、Jules 只写产品形态差异，不写发布日期与版本号。全文不出现分数、通过率与名次，也不写”某助手明显更强”。关于榜单污染，只写业界普遍担忧，不写成任何官方承认。

任务集怎么建

任务集决定结论的边界：四类任务的取材方式与验收判据各不相同。

真实历史需求改动：从自家仓库已合并的提交里往回取，选那些”需求单还在、diff 还在、评审意见还在”的改动，把需求单原文当任务描述，把当次合并后的提交当参考实现但不进上下文。验收判据是接口与行为对齐，不要求字形一致：函数名、文件切分与参考实现不同但测试全绿、评审无异议，也算通过。

缺陷修复：取已关闭的缺陷单，要求缺陷在快照上仍可稳定复现，验收判据是”复现用例先红后绿，且原有测试不新增失败”。提示里只给报告描述，不给缺陷单中工程师留下的定位线索。

跨文件重构：取一次触及多个文件的既有重构，验收判据是公开调用面不变——对外导出的符号、配置键、命令行参数、序列化格式保持兼容，构建与全部测试通过。这类任务口径最难统一，任务单里必须写清允许改与禁止改的文件。

小特性实现：取一个从未实现过、但能在一个迭代内落地的小需求，验收判据是新增测试与新增代码同时存在——只有代码没有测试的产出，按”未完成”记。

四类任务的配比属团队约定示例，目的是让难度分布在所有被测产品之间一致：同一任务只出现在一档难度桶里，分档标准跨任务、跨产品统一。

私有化取材是这一节的关键约束。业界普遍担心公开题目因反复接触而失真，因此本文的任务全部来自自家仓库：快照归档、任务描述内部编号、参考答案单独存放并访问隔离，题目文本不写进任何公开工单与共享文档，也不出现在提示模板的示例里。取材流程清单如下：

指标定义与取数口径

每个指标都要写清两件事：怎么取数，以及在什么情况下会被钻空子。只写名字不写取数方式的指标等于没有。

可合入率。取数是”判定函数返回可合入的单元数，除以该难度桶内计入统计的运行数”。分母要显式声明计入哪些运行，超时与环境故障的外因剔除规则必须在开跑前写死，不能看完结果再定。钻空子的路径有两条：任务描述含糊时把”可合入”的解释权交给被测方；把重试到某一次成功当成该任务的固有表现。口径上把首次运行与迭代上限内的最终产出分两列记。

人工改动量。取数是”从助手产出提交，到评审通过实际合入那一版之间的差异”，用差异工具算行数与文件数，并由收尾人按语义类别标注：改名、补测试、修边界条件、推翻重写。钻空子的路径是只看行数不看语义——一行关键判断的修正，可能比大段格式化重排更贵；也只记新增不记重命名与删除。这一列是本文最看重的，因为省下的时间最终都在这里结帐。

迭代次数。分两列：助手在循环里自行重跑构建与测试的次数，以及人工给出反馈后返工的轮次。钻空子的路径是把两列合成一列，或只在成功样本上记数。计数口径以运行日志里的工具调用序号为准。

端到端时长。取数是从任务投送到产出可合入差异的墙钟时间，同时记人工占用时间；钻空子的路径是只计模型生成时间，把排队与审批全部排除。时长一律档位化，避免用秒级小数制造精确感。

成本口径。单价按官方当期价目核对，本文不写价格数字。记录项是用量类型（输入、输出、缓存命中）、请求次数与失败重试带来的重复消耗，再折算到成本档位。钻空子的路径是只算模型成本、不算人工收尾与重跑，长任务因此被平均值掩盖。

控制变量与随机性

编码任务的方差来自三个方向：模型采样、环境状态、评审主观。控制变量的目的不是消灭方差，而是让方差可归因。

仓库快照必须同一份：提交号、依赖锁文件摘要、构建缓存预热状态、工具白名单与网络出口都固定。工作区里凡可能泄漏参考实现的文件——历史分支、补丁目录、评审记录导出——在快照阶段删除，而不是靠提示里写”不要看”。

测试命令必须同一句：构建、单元测试、集成测试合成一条可复制的命令，锁定超时上限、并发度与随机种子，尤其是时间相关的夹具与随机化测试顺序。

上下文预算必须同一档：可达文件数、检索回填的字节上限、是否允许读整仓索引，逐项对齐。允许某一方无限检索、另一方按文件数截断，比较的就不是产品而是检索配置。

采样温度与解码配置按各产品默认值记录，不为任何一方专门调低；配置不可见或不可改的，就在记录表里写”不可配置”。模型档位名只作为运行环境字段记录，不记参数量、上下文长度与单价。

每个单元重复运行若干轮，轮次下限属团队约定示例，观察离散度而非均值：同一任务同一配置下结果的极差、稳定落在同一档的占比、判定翻转的次数。这正是不给单次结果下结论的原因——一次成功可能来自采样运气，一次失败可能只是环境抖动，而判定翻转往往还是任务分档失准、指标口径不够硬的信号。

盲评与污染防护

盲评在编码任务里要防三种泄漏：任务来源、测试集、产品归属。

任务来源泄漏：任务单里出现仓库名、工单号、原始分支名、日期，等于把这段历史交还给模型的先验。做法是脱敏后重新编号，与题目同源的提交信息和注释在快照阶段清理；参考答案不进提示、不进检索索引、不进示例库，也不留在工作区，只放在隔离目录由评审协调人单独保管。

测试集泄漏：验收测试文件在运行前对助手不可见，判定所需的新增用例在产出落地后才注入，否则”通过测试”会退化成”照着测试写实现”；提示模板里的示例代码也要单独审查，确认不与候选任务同源。

产品归属泄漏：交给评审人的只有编号化差异包——补丁文本、日志摘要、改动文件清单，产品标识统一替换为随机代号，映射表由第三方保管到评审收口后公开。客观判定与主观评审由两批人分别做，前者只跑命令，后者只看差异包，两批人之间不交换结论。

用 CI 结果落地客观判定

客观判定全靠持续集成的退出码，本文写成一段判定伪码。字段名均为本文自拟，落地时按各自流水线改名，构建与测试命令按项目栈替换（rust 用 cargo，python 用 pytest 加 lint）。

三点强调。第一，退出码优先于自然语言自评，助手声称”已完成”不参与判定。第二，外因剔除与真失败必须分开：把环境故障混进失败样本会同时压低所有产品，全部丢弃又让侥幸产出占比虚高。第三，需要人工收尾不等于失败，它计入人工改动量，代表”能跑但不敢合”这类最容易被统计抹掉的产出；而客观门槛通过只是必要条件，可合入率的分子还要与盲评语义判定做与运算。

空白记录表

记录表是这套方法能被别人照着跑的关键载体，只给字段与空模板，不给任何示例值。三条约定：一行对应一次运行而不是一个任务；缺数据留空而不写零；任何剔除必须写明剔除代码。表头另存为逗号分隔文件即可被脚本聚合。

多轮重跑的离散度按同一 task_id 下的多行计算，不在表里预先折算成均值——一旦折算，判定翻转与极差就再也看不见了。

常见偏差与对策

下面六条最容易把结论带偏，清单形式便于开跑前逐条对照。

换算成自己仓库的选型判断

外部跑出来的分布不能直接搬进自家决策，能搬的是口径。迁移只用三个维度：同难度桶的可合入表现、每单元的人工改动量档位、迭代与成本档位。做法是把外部报告里的任务类型映射回自家仓库的同类历史改动，用同一份判定函数与同一句验收命令重跑，再看两条分布是否指向同一档结论；若不一致，说明外部任务集的难度结构与自家仓库不匹配，此时放弃外部结论、只沿用方法。

阈值一律团队自定并事先写进文档，本文只给占位形式（团队约定示例）：可合入档位与基线相差一档以内视为无差异；人工改动量的语义档位到达”推翻重写”即判不通过，无论测试是否全绿；迭代或成本档位超出预算的单元，改记为流程问题而非产品问题。阈值的作用是把”要不要继续投入评测”变成可复核的判断。

小结

本文交付的是实验设计而非结论：可复用的是评测单元五元组、四类任务的取材与验收判据、每个指标的取数与钻空子路径、离散度观察、盲评流程与判定函数。全文没有分数、没有通过率、没有名次，也不判断谁更强，读者只需按自家仓库把记录表填起来。末表可作落地检查清单。
