Node.js 集群 cluster 模式

Node 的 JavaScript 执行是单线程的：一个进程再忙，也只会吃满一个 CPU 核，其余核心看着它排队。cluster 模块给出的答案不是线程，而是进程——主进程负责监听端口和调度，多个 worker 进程共同处理请求。本文从最小的可运行示例讲起，解释端口为什么能被多个进程“共享”、worker 崩溃后如何拉起、怎样做到重启时不断连接，以及多进程带来的会话、定时任务和日志问题。读完之后，你应当能判断一个服务该不该上 cluster，以及上了之后要补哪些配套。

NestJS 微服务实践

单体应用写到一定规模，模块之间的调用会织成一张看不见的网：改一次下单流程，要同时理解库存、优惠与支付三段代码；发一次版，要把整块应用一起重启。微服务不是银弹，但当团队边界、部署节奏与技术栈开始互相牵制时，它提供了一种把复杂度切开的手段。本文以 NestJS 5.x 为基准，从“该不该拆”的判断讲起，依次说明 @nestjs/microservices 的抽象、传输层选择、消息与事件模式、混合应用与网关，最后用一个电商拆分案例把契约、补偿与灰度上线串起来。读完之后，你应当能判断自己的项目是否到了拆分的时候，并写出第一个可运行、可观测、可回滚的 NestJS 微服务。
