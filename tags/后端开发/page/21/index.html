GORM 关联查询与预加载

一个列表接口只返回 20 条订单，日志里却留下 21 条 SQL；等数据量涨到一百条，慢查询监控开始报警，而索引其实一直都在。这类问题多数不是数据库写错了，而是 ORM 取关联数据的方式错了。本文从 N+1 讲起，把 GORM 1.x 的四种关联定义、Preload 与 Joins 两条预加载路径、关联写入与事务边界、软删除和 Hook 在关联场景下的连带影响依次拆开。读完你应该能算清一次请求该发几条 SQL，并知道每条 SQL 上该带什么条件。本文只讨论关联与查询，连接池参数与单表 CRUD 的基础留给同系列的其他篇目。

Go 中 for range 的变量语义

for k, v := range x 大概是 Go 里写得最多的一行代码，正因为太顺手，很多人从没想过 k 和 v 到底是什么。本文要回答的就是这个看似细小、实际会影响并发正确性的问题：循环变量是每轮新建，还是自始至终只有一组？想清楚这一点，才能解释为什么循环里启动的 goroutine 总是打印最后一个值、为什么把 &v 收集起来会得到一串相同地址。本文面向已经能写 Go 循环、但还没仔细读过 range 语义的读者，读完后你应该能判断什么时候必须显式复制变量，以及 range 后面的表达式在何时被求值。

Node.js 集群 cluster 模式

Node 的 JavaScript 执行是单线程的：一个进程再忙，也只会吃满一个 CPU 核，其余核心看着它排队。cluster 模块给出的答案不是线程，而是进程——主进程负责监听端口和调度，多个 worker 进程共同处理请求。本文从最小的可运行示例讲起，解释端口为什么能被多个进程“共享”、worker 崩溃后如何拉起、怎样做到重启时不断连接，以及多进程带来的会话、定时任务和日志问题。读完之后，你应当能判断一个服务该不该上 cluster，以及上了之后要补哪些配套。

Go 内存对齐与 unsafe 包
