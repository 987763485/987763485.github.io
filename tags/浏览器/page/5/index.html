DOM 尺寸与位置：offset、client 与 scroll

去年年底处理过一个下拉菜单在 IE8 上偏出屏幕的 bug，前前后后排查了两天，最后发现根因是把 offset、client、scroll 这三组属性的口径混用了。这三组属性是原生 JS 里做定位与滚动计算的全部家当，但它们各自的”尺子”从哪量到哪、含不含边框和滚动条，很多文章语焉不详。本文把三组属性一次讲清，再补上 offsetParent 规则、quirks 模式下的读数差异、视口与滚动位置的兼容取值函数，以及一个不依赖库的浮层定位实战。适合被”差 8 像素””差 17 像素”困扰过的同学。

HTML5 文档大纲与标题层级的正确用法

HTML5 引入了 sectioning content，理论上改变了标题层级的计算规则——每个 section 内部的 h1 都重新开始一级。这个设计在规范里写得很漂亮，但 2014 年初的现实是：没有任何浏览器实现了它。本文从入门角度，讲清 HTML4 与 HTML5 大纲规则的差异、为什么不能真的按新规则写，以及当年务实的标题层级实践。结论先给出：继续按 h1 到 h6 逐级递减排，不要跳级，把 section 当作分组容器而不是层级计数器。

DOM 样式操作与 getComputedStyle

给元素改颜色、改尺寸，最直接的办法是 el.style.color = 'red'，但这只对写在行内样式上的属性有效。一旦想知道”这个元素现在实际是什么颜色”，就必须问浏览器要计算后的值，这就用到了 getComputedStyle。它读起来很方便，却藏着两个大坑：一是读回来的格式和你写进去的格式不一样，二是每一次读取都可能触发重排。本文从”指定值”与”计算值”的区别讲起，覆盖 IE 的 currentStyle 兼容、float 的属性名之争、颜色返回格式，最后落到批量读取的布局抖动与 jQuery .css() 的封装思路。
