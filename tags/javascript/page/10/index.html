DOM 事件委托的失效场景与排查思路

事件委托的代码只有十几行，但要让它在一个真实项目里长期不出事，靠的是对三件事的判断：事件会不会冒泡到这个容器、冒泡路径上的节点是不是都”够格”参与匹配、以及委托绑定与直接绑定混在同一页里时谁先谁后。过去半年我写过三篇事件相关的文章：《jQuery 的 on、off 与事件委托》解决库 API 的选型与迁移，《DOM 事件移除与内存泄漏》解决绑定与解绑的生命周期，《DOM 事件对象与事件委托》解决事件对象的属性差异并给过一个二十多行的原生委托。它们各自把一条线讲完了，但线上问题从来不按我文章的章节出——这半年我处理过的委托故障里，没有一起是”委托代码本身写错”。本文换一个视角，把委托失效的场景逐类拆开，每一类给出排查方法和当时能落地的兼容结论。适合委托已经用起来、正准备把功能铺到 IE8 与老 Android 上的读者；读完你应该能在遇到”委托怎么没反应”时，按一条固定的路径在三分钟内定位到断点。

DOM 事件委托的边界情况
