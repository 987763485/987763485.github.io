备份是数据库运维中最容易被拖延的一件事：平时它只是磁盘上的几个文件，真出事时它却是唯一的退路。本文以 MySQL 5.7 与 8.0 为背景，梳理逻辑备份与物理备份的取舍、binlog 与时间点恢复的配合方式，并给出一套可以落地的备份策略与恢复流程。文中的容量与耗时为说明用的假设值，读者需要按自己的数据量和硬件重新估算。

MySQL 主从复制与读写分离

单机 MySQL 迟早会遇到读请求压满 CPU、备份把磁盘 IO 打满、主库维护只能停服这几类问题，主从复制是最常见的第一层解法。本文从复制到底解决了什么讲起，依次拆解 binlog 格式、GTID、半同步与延迟成因，再落到读写分离的几种实现与读一致性的补偿手段。读完你应该能独立搭起一主两从，并清楚哪些问题复制本身答不了。

MySQL 事务隔离级别与锁
