Rust trait 对象与动态分发

Rust 没有内建的继承，也没有垃圾回收堆上的接口指针，但”对某种行为编程、运行时再决定具体实现”的需求照样存在，它在 Rust 里的答案就是 trait 对象与动态分发。本文从静态分发与动态分发的本质差异讲起，拆到宽指针的内存布局与 vtable 的内容，逐条解释对象安全规则，再讨论所有权形态、向下转型、性能代价，以及插件式架构和 async 方法在 2023 年遇到的边界。适合已经熟悉泛型与 trait bound 的读者（泛型与约束本身另见《Rust 泛型与 trait》一文），读完你应当能对着任何一条与 dyn Trait 相关的编译错误，说出它踩中了哪条规则。全文以写作时最新的稳定版 Rust 1.70 为口径。

Rust 所有权与移动语义

很多初学者把 Rust 的所有权当成一组要背的语法规则：什么时候该报错、什么时候该补一个 clone()、& 和 mut 怎么排列组合。这样学很容易停在“能编译，但说不清为什么不编译”的状态。本文换一个角度，把所有权看作描述资源归属的语义模型：每个值在同一时刻只有一个主人，主人到期就负责把资源释放干净，移动就是把这份责任交给下一个人。读完你应该能解释移动在内存层面改了什么、String 为什么不能是 Copy 的、结构体被部分移动后还能借用哪一部分、Drop 按什么顺序发生，以及怎么反过来用所有权表达设计意图。内容以 Rust 1.69（2023-04-20 发布）的稳定语义为准，适合写过一些 Rust 代码但还没把这套模型理顺的读者。

Rust RefCell 与内部可变性

所有权与借用规则让 Rust 在编译期就挡住了数据竞争，但也带来一个具体的困扰：有些值明明只有一个所有者，我却要透过共享接口去修改它的内部状态。标准库对这个困扰的回答是内部可变性（interior mutability），而 RefCell 是其中最常用的代表。本文面向已经熟悉借用规则的读者（相关细节见第 724、755 篇，这里不重复），讲清楚 RefCell 的运行时机制与代价、Cell 与它的分工、与 Rc 的组合用法、常见坑，以及什么时候你应该退回所有权清晰的设计，而不是继续往外套 RefCell。

Rust 生命周期完全解析

生命周期大概是 Rust 里最容易让人紧张的一套语法：它不参与内存管理，也不产生运行时代码，却在你返回引用、写泛型结构体时凭空多出一堆 'a。原因很简单——生命周期是借用检查器使用的表达语言，借用关系一旦写出来，约束就在那里，标注只是把编译器推不出来的那部分补全。本文面向已经熟悉所有权、移动与借用的读者，讲解生命周期参数与省略规则、结构体和 impl 块中的标注、'static 的真实含义、for<'a> 高阶边界与 trait 对象的默认生命周期，最后回答一个实践问题：什么时候别跟生命周期较劲，改用所有权或克隆。文中代码以 2023 年 4 月底的稳定工具链为准，写作时 1.69 刚发布，涉及的语法在 1.31 之后的版本里都已稳定。

Rust 单元测试与基准测试

写测试的成本，往往不在写断言，而在“这段测试该放在哪、怎么跑、跑得慢不慢”。Rust 把测试能力直接编进了工具链：cargo test 一次收集单元测试、集成测试与文档测试，#[test] 只是普通属性，不需要额外的测试框架与配置文件。本文按 Rust 1.67、2021 edition 的口径，把这三类测试的边界、测试代码的组织方式、常用运行参数，以及基准测试在稳定版上的现实选择讲清楚。读者应当已经能读写基本的 Rust 函数与结构体；本文不涉及异步测试框架，也不重复某个具体项目的实现细节，讲的是方法本身。

Rust 函数与控制流
