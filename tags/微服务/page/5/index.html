Fiber 框架入门实战

Fiber 是 2019 年出现在 Go 社区的一个 Web 框架，写法接近 Node.js 的 Express，底层则换成了 fasthttp。它上手快、跑分好看，但代价是离开 Go 标准库的舒适区。本文以 Fiber 1.x 与 Go 1.13 为例，从路由、Context、中间件讲到校验、错误处理、测试与部署，并持续与 Gin 对照。读完后你应能判断一个项目该不该选 Fiber，以及选了之后要提前避开哪些坑。

Go 连接 Redis 与缓存设计

读多写少的接口最容易在流量上来时暴露问题：数据库连接被占满，慢查询排队，响应时间从几十毫秒涨到几秒。缓存是最直接的缓解手段，却也带来一致性、失效与故障扩散。本文以生产环境常见的 Redis 5.0 与 go-redis v6.15/v7 为例，讲连接管理、cache-aside、TTL、穿透与雪崩、分布式锁和 Pipeline，适合准备把缓存接进 Go 服务的读者。

Go 调用外部 HTTP 服务封装

Gin 中间件开发与洋葱模型

路由决定请求交给谁处理，中间件决定它在到达业务函数前后经过哪些关卡。Gin 的中间件就是签名相同的处理函数，按注册顺序拼进切片，再由游标依次调用。本文以 Gin 1.4 与 Go 1.12 为例，先讲清执行顺序与三种注册位置，再落到鉴权、超时、跨域、错误处理和测试。读者应已能用 Gin 写路由；读完后应能设计一组顺序正确、职责清晰的中间件，并知道哪些写法会在线上出事。

Go 错误码设计规范

HTTP 状态码只能说明“哪一类请求失败了”，却说不清“具体为什么失败”。同一套接口同时服务 Web、移动端与第三方系统时，靠匹配错误文案来分支处理既不牢靠，也无法跨语言复用。本文从码段划分、错误类型、分层转换、文档契约与可观测性几个角度，整理一套可以直接落地的 Go 错误码规范，适合刚开始做多团队协作的后端开发者。读完后你应当能为自己的业务设计出一套稳定、可治理的错误码体系。

GORM 关联查询与预加载
