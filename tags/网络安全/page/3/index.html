漏洞复现与修复验证

商用密码应用安全性评估要点

密码用得对不对，和有没有用密码，是两件完全不同的事。很多系统在等保整改时被要求“上密码”，于是加了一层 HTTPS、给数据库字段做了加密，验收材料上也写满了 SM2、SM3、SM4，但真到密评现场，仍会被指出一堆问题：密钥写在配置文件里、随机数来自时间戳、传输加密只做到网关、签名环节干脆没有。本文围绕 GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》，讲清商用密码应用安全性评估（以下简称密评）的定位、四个层面的要求、密钥管理的七个环节、测评流程，以及它与等保测评的关系，并给出六类最常见的问题及其改法。适合正在做密码改造的开发、运维与安全负责人阅读，读完应能梳理出一份“密码应用点清单”，并判断哪些做法只是看起来合规。

等保测评项详解：安全通信网络

很多团队第一次做等保，都会把“安全通信网络”理解成一句话：上没上加密。真到测评现场才发现，这一层问的东西比加密多得多——链路是不是单点、区域之间有没有控制点、证书谁来管、可信验证做到了哪一步。本文按 GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》的组织方式，把安全通信网络拆成网络架构、通信传输、可信验证三个方向，逐项讲清楚“标准想要什么、现场通常长什么样、证据怎么准备”。适合正在做差距分析的系统负责人与运维、安全工程师阅读，可当自查清单用。

勒索软件防护实践

勒索软件并不神秘，它把“入侵、提权、扩散、破坏、勒索”压缩到了几个小时之内。真正让企业付出代价的，往往不是加密本身，而是暴露在公网的服务、长期不修的补丁、共用一套管理员口令，以及一份从未验证过能否恢复的备份。本文从防御方视角，按攻击链阶段拆解风险面，给出预防、检测、备份、响应与演练五个环节的落地方法，适合安全工程师、运维负责人和需要向管理层解释防护投入的技术人员。读完后，你应能为所在组织画出一张可执行的防护清单，并用演练数据而不是口号说明恢复能力。

数据脱敏与匿名化

开发同学为了复现一个线上问题，把生产库整个导出到测试环境，姓名、手机号、身份证号一应俱全。这个场景并不罕见，却同时踩中了《个人信息保护法》与《数据安全法》最在意的几条红线。本文要回答的正是这一类问题：脱敏、匿名化、假名化、令牌化到底差在哪里，静态脱敏与动态脱敏各自解决什么问题，常见的掩码、洗牌、日期偏移、格式保留加密与哈希加盐该怎么选，以及为什么“把姓名列删掉”不等于匿名。本文面向需要落地数据安全治理的后端工程师、DBA 与合规同学，读完应当能为一张业务表写出可执行、可审计、可验证的脱敏方案。

SDL 安全开发生命周期
