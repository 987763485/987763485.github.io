jQuery 选择器完全指南

$('#id')、$('.cls') 写熟了之后，选择器很容易退化成一堆靠直觉拼出来的字符串。本文面向已经把 jQuery 用顺手、但没认真想过”这串选择器在库内部走了哪条路”的读者：先把 jQuery 1.11.3 的选择器能力按层梳理一遍，再划清哪些语法是 jQuery 私有扩展、原生 CSS 里根本没有，然后讨论它与 querySelectorAll 的边界在哪、性能分界线在哪，最后收口成一组可执行的书写规约。版本语境说明一句：jQuery 2.1 系列在选择器上与 1.11 行为完全一致，本文结论对两者通用；文中所有”实测”，指在 node 里加载 jQuery 1.11.3 配一个 jsdom 环境跑出来的数量与顺序。至于选择器字符串是如何被解析、编译、缓存的，那是 Sizzle 引擎的事，已在《jQuery 源码架构：Sizzle 选择器引擎》一文中拆过，本文不再展开。

一、选择器能力分层

jQuery 1.x 的选择器语法可以分五层，一层比一层”偏离标准”。下文实测统一基于这段 HTML（整页共 50 个元素，五组结构分别服务层级、过滤、属性、表单与可见性几节）：

基本选择器

*（全部元素）、#id、.class、element，以及用逗号并列的多选择器。逗号把各组结果合并为一个集合，去重后按文档序返回，上面这段结构里 $('#tree, .level, .note') 实测得到 5 个元素。这一层全部是标准 CSS 语法。

层级组合符

四个组合符是 （后代）、>（子代）、+（紧邻兄弟）、~（后续兄弟）。同一段 HTML，四种写法选出完全不同的集合，实测对照如下：

选择器 语义 命中 个数
#tree .note 后代，不限深度 One、Two、Three 3
#tree > .note 直接子代 只有 Three 1
.note + .tag 紧跟在 .note 后的兄弟 A、C 2
.note ~ .tag .note 之后的所有兄弟 A、B、C 3

+ 与 ~ 的差值就体现在 B 上：B 的前一个兄弟是 .tag（也就是 A）而不是 .note，所以只有 ~ 能命中它。

属性选择器

语法族：[attr]、[attr=val]、[attr^=val]（前缀）、[attr$=val]（后缀）、[attr*=val]（包含）、[attr~=val]（空格分隔词表中的一项）、[attr|=val]（等于或以 val- 开头，为语言码设计）。此外还有一个 jQuery 私有货：[attr!=val]，注意它在标准 CSS 里不存在。

最后一条要留意语义：!= 把”根本没有这个属性”的元素也算进去，实测 10 个命中里有 3 个是无 name 的输入框。大小写规则：在 HTML 文档里属性名不敏感，[NAME=user-name] 实测能命中；属性值默认敏感，[name=USER-NAME]、[type=TEXT] 实测均为 0 命中。个别上古 IE 对值也做不敏感匹配，是当年的兼容坑，保守做法是属性名与值一律写小写。值不含特殊字符时可以不加引号，但一旦含 /、: 等字符（如整段 URL）必须加引号，实测 [href="https://..."] 这种带引号写法工作正常。

内容、可见性与位置过滤

这一族按当前匹配结果集或元素内容做二次筛选：:first、:last、:eq(n)、:even、:odd、:gt(n)、:lt(n)、:not()、:has()、:contains()、:header、:animated、:hidden、:visible。写测试时最容易记错的是 :even/:odd 按 0 基下标算。页面有两组列表共 8 个 li 时实测：

两个易踩的语义点。:contains('Three') 不限定标签时会把祖先行一并揪出来——实测全局写法命中 6 个元素（html、body、两个容器、目标 p 与目标 li 各一），所以它前面永远要有个收窄作用域的左端条件。:has() 同理，$('div:has(p.note)') 实测命中 #tree 与 .level 两层容器，说明它判断的是”后代里有没有”，而非”子级里有没有”。:header 只收 h1 到 h6，测试页实测 1 个（那个 h2）；:animated 只匹配正在跑 jQuery 动画的元素，静止页面上实测为空。:hidden/:visible 单独放到第二节讲。

表单选择器

:input、:text、:password、:radio、:checkbox、:submit、:button、:enabled、:disabled、:checked、:selected。实测 #form 内 :input 得 11 个（input、select、button 全算），:checkbox 4 个，:radio 2 个，:disabled 1 个。注意 :submit/:button 同时匹配 input 和 button 两个标签，判定依据是 type，<button type="button"> 会被 :button 命中而不会进 :submit。

二、jQuery 私有扩展与性能分界线

把上面出现过的语法做一次清点，以下这些在 2015 年的原生 CSS（以及浏览器的 querySelectorAll）里没有对应物，或语义对不上：

  • :eq(n)、:first、:last、:even、:odd、:gt(n)、:lt(n)：位置类伪族，且语义是”结果集下标”而非”结构位置”，CSS 规范里只有 :nth-child() 这类结构伪类，两者含义不同；
  • :contains()、:has()：按内容文本、按后代存在性过滤，原生当时均不可用（:has() 还停留在草案阶段）；
  • :not() 的宽松入参：CSS3 原生 :not() 只收一个简单选择器，jQuery 实测支持 :not(:checkbox, :radio) 这样的逗号并列甚至更复杂的写法；
  • [attr!=val]：上一节已注明；
  • :input 族与 :enabled/:disabled/:selected：CSS 里对应写法要么冗长要么没有。:checked 虽属 CSS3 规范（按规范它也该覆盖选中的 option），但当年浏览器实现参差、老 IE 干脆不支持这个伪类；jQuery 用 DOM 属性把它统一成”勾选的 input 加选中的 option”，实测测试页命中 3 个，其中 1 个就是 option；
  • :hidden/:visible/:animated/:header：纯 jQuery 语义。

:hidden 的判定值得展开。jQuery 1.11.3 源码里没有 getClientRects，jQuery.expr.filters.hidden 的判据是 offsetWidth 与 offsetHeight 同时不大于零，外加一个针对 IE8 表格单元 bug 的 display 兜底分支（对照源码，直到 jQuery 3.x 才把 getClientRects 纳入可见性判据，改为三者取其一非零）。这带来两个直接后果：第一，判的是”渲染盒”而不是样式表，所以 display:none 的父容器里的元素一律算隐藏——给 jsdom 的 offset 属性按 display 补上最小桩之后实测，#vis 区块中 p:hidden 命中”藏于隐藏父级内”与”自身 display:none”两个 p，p:visible 只剩 1 个，visibility:hidden 在多数浏览器下仍有盒、会被算作可见；第二，不加桩的 jsdom 里所有元素的 offset 都是 0，实测 :hidden 会把整页 50 个元素全部收走——恰好反证了这套判定完全依赖布局数据。

于是性能分界线就很清晰了：只要选择器里出现上述扩展语法，jQuery 就无法把整串交给浏览器原生的 querySelectorAll 快路径，只能退化为手动遍历候选集再逐个过滤（分流机制本身见《jQuery 源码架构：Sizzle 选择器引擎》）。扩展语法不是不能用，而是要知道自己正在为它付遍历的钱，并且要付在对的地方。

三、与 querySelectorAll 的边界

2015 年 4 月这个时间点的原生选择器版图：IE 8 的 querySelectorAll 名存实亡（只支持 CSS 2.1 子集且 bug 不少，工程上当它不可用）；IE 9 起原生支持 CSS3 选择器，但只认标准语法；Chrome 40、Firefox 35、iOS 7/8 与 Android 4.x 的原生实现大体都可靠。原生侧对 jQuery 扩展的态度是直接拒绝：实测在 document.querySelectorAll(':eq(1)')、document.querySelectorAll('input:not(:checkbox)') 上都会抛 SyntaxError。

jQuery 的分流策略只有一层意思：能用原生就整串交给原生，扩展部分自己实现，异常再降级。所以开发者能做的设计是让自己的选择器始终落在可交给原生的那一侧，具体就是养成”只用标准 CSS 选择器”的书写习惯：写 input[type=checkbox] 而不是 :checkbox，写 :nth-child(3) 而不是 :eq(2)（注意语义差异，见下节），能不用 :contains、:has 就不用。这样做的回报是迁移成本：哪天要脱离 jQuery 直接写 querySelectorAll，或者要在热路径上换成原生 API 提速，选择器字符串可以原样搬走，不需要重写。

老浏览器上的代价集中在一处：多层后代字符串（如 #box .cls .sub）在原生 querySelectorAll 不可靠的 IE 8 上要靠从右往左的遍历回溯父链，层级越深、右端越泛，候选集越大。$('#box') 这种纯 ID 选择器则有快路径，内部直接映射到 getElementById，一步到位。所以老浏览器上的习惯是：先用 ID 把范围锁死，再用 find 在小范围里收窄，别让一条长后代串横跨半个文档树。

同一串选择器被反复执行时，把结果存进变量复用，而不是重复执行——这是 jQuery 对象缓存的基本习惯，展开后就是《jQuery 性能优化实践》整篇的内容，本文只强调一句与选择器直接相关的：缓存的是 jQuery 对象，不是选择器字符串，字符串本身每变一个字符就是一次新查询。

七、选择器书写规约

把全文收口成可执行的规约：

  1. 优先 ID 与类，其次是带明确语义的属性选择器；* 与多层属性组合只配出现在一次性脚本里。
  2. 不依赖标签层级结构（div > div > div 这种），给需要钩住的节点加一个专用 class，DOM 改版时选择器不至于成片断掉。
  3. 扩展伪类只在过滤不可避免时使用，且优先考虑挪进 filter：选择器字符串保持标准，过滤逻辑随集合复用。
  4. :contains()、:has() 不上热路径。替代做法是在渲染 HTML 时就把特征写进 data-* 属性，查询退化为一次标准属性选择。
  5. 用 :contains() 时左端必须限定标签或容器，否则祖先行会连坐命中（实测过 6 个）。
  6. 索引收窄用 eq()/slice()，别把会变的下标拼进选择器串（:eq(' + i + ')），否则每次都是新字符串、新解析。
  7. :hidden/:visible 涉及布局读取，大规模查询前先确认是不是可以用业务侧的状态 class 代替。
  8. 上下文统一用 find 表达，与 $(sel, context) 二选一并在团队内定死。

小结

jQuery 选择器的能力分五层：基本、层级、属性、内容/位置过滤、表单。其中位置伪族、:contains、:has、:not() 的宽松入参、[attr!=val]、:checked 的 option 扩展语义、:hidden/:visible 的布局判定，都是 jQuery 私有或语义偏移的部分——它们决定了选择器能否走 querySelectorAll 快路径，这就是性能分界线。工程上把选择器尽量写成标准 CSS 的样子，用 find 收窄上下文，用 filter 承接复杂谓词，用 eq() 而不是字符串索引，扩展语法只在热路径之外为可读性买单。
