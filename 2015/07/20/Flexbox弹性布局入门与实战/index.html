Flexbox 弹性布局入门与实战

本文属于《HTML 与 CSS》第 30/62 篇
上一篇系列目录下一篇

到 2015 年年中，Flexbox 的问题已经不是”能不能用”，而是”怎么安全地用”：现代语法在 Chrome 与 Firefox 上早就稳定，IE10 和 IE11 却各自停在中间草案与一份不完整的实现上，Android 4.4 的 WebView 与 iOS 8 的 Safari 还可能把你拽回 2009 年的老 box 语法。本文不讲属性大全——那部分我在《Flexbox 布局完整指南：主轴与交叉轴》里已经逐个写过了——只解决三件事：今天的浏览器现场支持哪套语法、Autoprefixer 能补什么补不了什么，以及三个可以直接抄进项目的实战件。适合正要把老页面从 float 迁过来、又被 IE 的表现反复折磨的同学。

两个开关与两根轴

flex 布局只有一个开关，写在容器上：display: flex 或 display: inline-flex。两者的区别不在内部排布，而在容器自己在父级里的形态——前者是块级盒，后者是行内级盒，可以和文字站在同一行。开关一旦打开，容器内的直接子项就进入 flex 格式化上下文，子项上的 float 与 clear 不再起作用。

inline-flex 要单独提醒一句：IE11 不支持它，写了会退化；新版浏览器的支持时间也比 flex 晚一拍。2015 年真要一个”跟文字混排的小 flex 容器”，我宁可退回 inline-block，别为一个开关多写两份代码。

两根轴一句话说清：主轴由 flex-direction 决定，默认 row 时它是水平方向、起点在左；交叉轴与主轴垂直。于是 justify-content 永远管主轴，align-items 永远管交叉轴。我遇到过的”Flexbox 没生效”，八成是把这两根轴搞反了——先读 flex-direction，再读其余属性，这个顺序养成习惯就不容易错。

三个子项属性：grow、shrink、basis

子项上真正需要理解的是三个值和它们的先后关系：

  • flex-basis：分配剩余空间之前我有多大。主轴水平时它顶替 width，写了 flex-basis 就别再留 width，两个来源会让基准尺寸变得没法预测。
  • flex-grow：容器有富余时，我按什么比例去抢。默认 0，即不放大。
  • flex-shrink：容器不够分时，我按什么比例让步。默认 1，即默认可压缩——这正是很多”内容被挤变形”的源头。

2015 年的兼容地形

动手前把地形看清。Flexbox 规范几经修订，浏览器各自停在不同阶段，于是同一份布局存在三套互不兼容的语法：

语法 容器写法 子项写法差异 2015 年还会遇到谁
2009 老 box display: -webkit-box -webkit-box-flex、-webkit-box-orient、-webkit-box-pack 老 Safari、iOS 早期版本、部分 Android 原生浏览器
2011 中间草案 display: -ms-flexbox -ms-flex-order、-ms-flex-align、-ms-flex-pack、-ms-flex IE10
2012 标准草案 display: flex 今天这套属性名 Chrome 29+、Firefox 28+、IE11（实现不完整）、刚随 Windows 10 发布的 Edge（内部版本 12）

无前缀的现代语法从 Chrome 29、Firefox 28 起可用，IE11 支持但有已知缺陷（下文两个坑都在它身上）；Safari 8 与 Android 4.4 的 WebView（内核是 Chrome 33）我建议仍带上 -webkit-，成本只是构建工具多输出两行。IE9 及以下完全没有 Flexbox，这一档用户还在的时候，回退方案就不能省。

手写三份语法只适合小页面。工程上的做法是让 Autoprefixer 生成。

Autoprefixer 能补什么、补不了什么

2015 年 7 月我用的版本现场是 autoprefixer 5.x，Gulp 3 与 Grunt 都有对应插件，配置项就是一份 browsers 数组（6.0 才把目标浏览器抽成独立配置文件，这里按 5.x 写）：

它能补的：给现代语法自动加上 -webkit-flex、-ms-flexbox，并往前翻译到 2009 的 -webkit-box；把 flex-direction: column 换算成 -webkit-box-orient: vertical；把 align-items、justify-content 映射成 -ms-flex-align、-ms-flex-pack。这些是纯语法层面的对应，写完 CSS 就不用管。

它补不了的，必须自己心里有数，这才是 Flexbox 在 2015 年真正的难点：

  • **老语法里根本没有的取值，翻译不出来。**2009 与 IE10 都没有 flex-wrap，也没有 row-reverse 这类反方向；space-around 在 2009 和 IE10 上都不存在。用了这些取值，就要准备一套视觉可接受的回退，而不是指望前缀工具。
  • IE 的简写语义不等价。-ms-flex 与标准 flex 的默认基准不同，翻译过去只是”语法上成立”，尺寸表现仍要靠显式取值兜住。
  • **它只看 CSS 文件。**JS 里 element.style.display = 'flex'、组件库输出的内联样式、@media 之外动态拼接的声明，都在它的视野之外。
  • **calc() 与 flex-basis 的组合在 IE 上不稳。**做等分网格时我宁可写 flex: 1 1 0% 靠 grow 分空间，或者退回百分比宽度加 padding 撑间距，别在前缀工具补不到的地方赌运气。

另外提醒一句：前缀输出会让样式表体积明显上涨，构建链里压缩这一步别漏。

IE 上的两个必踩坑

**第一个坑：flex: 1 的基准值。**标准里 flex: 1 的第三个值取 0%，IE10/11 在这条上的表现却是按内容尺寸分配基准，于是”本该严格等分的三列，在 IE 上成了内容宽窄不一的三列”。规避办法是显式写全三个值，再给交叉轴留一个兜底尺寸：

min-height（竖直方向布局时换成 min-width）的作用是给项目一个不为零的底，IE 在少数场景下会把基准归零的项目算成塌陷。这两处兜底写起来难看，但比线上出事故便宜。

**第二个坑：长文本撑破容器。**Flexbox 规定项目有一个”自动最小尺寸”，大致等于内容的最小宽度：一段不换行的长 URL、一长串英文单词、一张定宽图片，都会把项目顶到那么宽，然后溢出容器。此时容器的 overflow: hidden 救不了你，因为项目本身就没算小。解法是显式解除保护：

实战一：底部固定的等高侧栏布局

圣杯布局（页头、页脚、左右侧栏、主内容，主内容与侧栏等高、页脚贴在内容不足时的视口底部）在 float 年代要靠负 margin 与三层包裹元素，换成 Flexbox 是一份直观的容器树：

flowchart TD
  P["page：flex 容器，column"] --> H["hd：固定高度"]
  P --> B["bd：flex 1 0 auto，吃掉剩余高度"]
  P --> F["ft：固定高度"]
  B --> M["main：flex 1 1 0%，min-width 0"]
  B --> A["aside：flex 0 0 220px"]
  B --> S["sub：flex 0 0 180px"]

三个关键点。第一，min-height: 100vh 加内层的 flex: 1 0 auto 负责”页脚贴底”，等高则由外层默认的 align-items: stretch 白送——这正是 float 最麻烦、Flexbox 最省事的地方。第二，stretch 只在项目自己没写交叉轴尺寸时生效，一旦给 aside 写了 height，它就不再拉伸，这是”我明明写了 stretch 却没等高”的标准答案。第三，源码顺序里主内容在前、侧栏在后对无障碍更友好，但视觉上需要左栏在前时用 order 调整——表单和可交互元素所在的区域别用 order 做重排，视觉顺序和 Tab 顺序不一致会坑键盘用户。

实战三：移动端导航条

移动端底部标签栏的典型需求：四格严格等分，中间一格按内容自适应（一个突出的”发布”按钮）。这正好把 flex: 1 1 0% 与 flex: none 配在一起用。

老浏览器降级路径

2015 年的正确姿势仍是渐进增强：先让页面在 float 或 inline-block 下可用，再给支持 flex 的浏览器叠一层。检测交给 Modernizr，它会把 flexbox 类挂在 html 上：

@supports 看着比类名优雅，但 2015 年不能当唯一开关：IE 全系不支持它，iOS 8 的 Safari 也不支持（Safari 9 起才有），Chrome 28 与 Firefox 22 之后支持。也就是说恰好是最需要回退的那些浏览器听不见 @supports。要用它，就配合 Modernizr 的类名一起写，别单靠它。

最后一层取舍说清楚：回退版与增强版的视觉不必完全一致。回退版只要不破版、层级清楚，侧栏稍窄一点、等高差一点都可以接受；为了让两套方案像素对齐而堆 hack，维护成本会迅速超过收益。跨设备实测省不掉——老 Android 原生浏览器上的 Flexbox 事故，多数不是语法错，而是那套 2009 语法的表现和你想的不一样。

小结

2015 年年中上 Flexbox，我会按这个顺序推：先用 display: flex 打开容器、心里认准主轴与交叉轴；子项只记 flex-basis、flex-grow、flex-shrink 三个值和 flex: 1 / auto / none 三种简写；接着把语法版本摊开看，用 Autoprefixer 5.x 生成前缀，同时清楚它补不出 flex-wrap、反方向和 space-around；然后专门处理 IE 的两个坑——flex: 1 1 0% 写全加 min-height 兜底、min-width: 0 解除自动最小尺寸；最后用 float 打底、.flexbox 类名叠加增强。圣杯、居中、移动端导航条这三个件，覆盖了日常需求的大部分，代码可以直接抄走改类名。规范本身还在动，但”安全地用”这件事，今年已经足够清晰。
