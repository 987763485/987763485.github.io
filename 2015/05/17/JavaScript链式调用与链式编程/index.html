JavaScript 链式调用与链式编程

《jQuery 链式调用与隐式迭代原理》拆过别人家的链子：链式靠方法末尾一句 return this 续命。那是”读现成的库”，这篇聊反过来的事：轮到你设计一个链式 API 时，手上有好几条路，每条路的账单分别是什么。 查询条件构建器、埋点参数拼装器、图表配置、表单校验，我都是顺手写成 foo.a().b().c()，要做成给同事用的库就得先回答四个问题：方法是改自己还是造新对象，当场做完还是攒到最后，链子从哪里退出，出错时由谁报。四组对比的结论都在 node 里实跑过，代码全部 ES5，数字只当数量级看。

链式的本质：一句话和十五行代码

链式没有别的机制：方法返回对象本身，或者同类的一个新对象，于是下一个点号还有东西可以挂。 剩下的都是设计选择。

调试时中间状态看不看得见。 原地修改只有一份终态：断点停在第 4 步，就看不见”第 2 步之后它长什么样”；提前 console.log(builder) 也没用，控制台展开的是同一个活对象的当前值。不可变版每步快照独立，存进数组就能翻账，代价是同名对象一堆，得自己编号。

分配代价。 一条 6 步链跑 10 万次，原地修改实测 4 到 7 ms、每步新对象 14 到 23 ms，三倍上下；链一长更难看——2000 步跑 5 轮，原地不到 1 ms、不可变 30 到 40 ms，因为每步都要把整条 conds 拷一份，成本是步数的平方。所以结论不是”不可变慢所以别用”，而是链只有几步时随便用，长序列别拿链式构建器去扛。还有个细节：extend 只拷一层，元素对象也得换引用（上面 patchLast 那一行）——我用”只拷数组不拷元素”的偷懒版跑过，base.run() 从 [] 变成 ["age：校验不通过"]，不可变性整个失效。

对比二：当场做完，还是记一笔账到最后

上面的 run() 暴露了第二个选择：链的每一步是立即把活干完，还是只登记一条待办，终点一次算完。

收集式的四个好处都是实测出来的：可校验（一次报全，不用改一个跑一次）、可重排（steps 是普通数组，链的顺序不再等于执行顺序）、可序列化（JSON.stringify(plan.steps) 直接得到一段配置，JSON.parse 喂回另一个实例再 build()，输出与原来一字不差——这就是把筛选条件存进 location.hash 或者交给后端的那条路）、不会链走到一半才发现问题（A 版第 2 步写错当场抛 where: 未知字段 nickname；B 版照样走完，实测 steps.length 从 1 涨到 4，错误在 build() 才爆）。

代价也是两笔：多写一个 build()，校验逻辑从”每个方法自己管”变成”终点集中管”，方法越多越啰嗦；错误定位落在终点而不是那一步——A 版的栈顶帧是 Live.where，B 版是 Lazy.build，所以必须自己把步骤序号写进报错信息，否则同事拿着栈也答不出是哪一行。

还有个隐蔽的坑，也是实测：B 版按 steps 的顺序追加子句，把 orderBy 挪到第 1 步就拼出 SELECT * FROM t ORDER BY age WHERE age > 18 AND status = 1，语法当场废掉。收集式必须按子句归组装配（WHERE 归 WHERE、ORDER BY 归 ORDER BY），否则”可重排”这个卖点是假的——文末那个 Query 就是这么写的。

中间数组那行是我加计数器实测的：链式、Underscore 链式、pipe、嵌套回调四种写法都是 filter、sort、map、slice 各产一份（12 | 12 | 12 | 4），最终 HTML 字符串逐字符相同。所以”每步产生新数组”是数据流风格的账单，跟链不链式无关；真能省的只有命令式那版：把过滤和映射并进一次循环，4 份降到 2 份。别为了”链式好看”自建 Seq 去扛万级列表，那是《函数式编程思想在前端的应用》里算过的账。

我的判据：同类操作重复施加用链式；每步产出类型不同就用管道或者语句。 filter→map→page 每步都是”数组进数组出”，链式成立；一旦混进”渲染成 HTML”这种”数组进字符串出”，那一步就该是链的终点（上面 render 就是这么设计的）。

对比四：这条链怎么退出

链式 API 必须回答”什么时候不再是链”。四种办法，实测的差别如下。

隐式退出：toString 与 valueOf。 给 Query 挂上这两个方法（文末那个实现就挂了 toString），'sql = ' + q 和 String(q) 都能直接拿到字符串。但要弄清优先级：

+ 和 == 先试 valueOf，String() 和 join() 先试 toString；只定义 valueOf 时 join 那条路拿到的是 [object Object]。所以两个都要写、都指向同一个 build()，否则就是”某条路径静默失效”这种最难查的形态。

显式退出：value()、build()、ES5 访问器。

q.result 读起来像属性（实测交出的是数字，不是链对象），适合”这条链的产物就是这个值”；但它和 jQuery 的 getter 一样会打断链式，后面就别再挂方法。回溯型退出（end()）的机制在《jQuery 链式调用与隐式迭代原理》里写过，本文不重复，只提一句：自己实现时它是 O(1) 的引用回交，不是重新计算。

  1. 守卫只管构造函数，管不了方法。 摘下来当回调用的那句，this 就是全局对象（浏览器里是 window），实测返回值 === global 为真、global.tagName 被写成 退款，全程一声不响，到下一步才炸；在原型上直接调那一句，脏的是原型本身，之后每个新实例都带着 tagName。这种污染比抛错危险得多。
  2. 不严格才是污染的前提。 没有守卫时忘记 new，实测 global.table 变成 users、函数返回 undefined；同一句放进 'use strict'，实测当场抛 TypeError: Cannot set properties of undefined (setting 'table')。污染只在 sloppy 里发生，而且不报错——只有严格模式能把它换成一次响亮的失败。
  3. 守卫还会改写借用调用。 Chain.call(host, 'orders') 本意是把 host 初始化成链，实测 host 一个字段都没多，返回的是另一个新对象。用它做借用构造函数的继承时，必须把原型接上（Sub.prototype = Object.create(Chain.prototype)），实测这样 new Sub('orders') 一切正常；没接原型时 instanceof Chain 不成立，守卫转身另造一个对象，实测拿到的是 table 和 conds 全空的壳，到下一步才报 b.where is not a function。

结论：守卫该写，但它只兜住”忘记 new“这一种手滑。this 丢失要靠另外两条：方法里读状态前先判一句（if (!this.conds) { throw new TypeError('方法不能脱离实例调用'); }），加上新文件一律开严格模式。

设计规约：什么时候配得上一套链

适合链式的两件事：配置或构造一个对象（查询条件、埋点参数、图表选项），以及同类操作重复施加（一路 filter、一路 where）。不适合：每步产出不同类型数据的流程——那种地方写顺序语句或者管道，硬套链式就得在中间塞 value() 打断，读起来两头不是人。

别在链上做副作用重活。 链上某一步去发请求、写 DOM，这条链就不能重排、不能序列化、也没法在单测里空跑。要发请求就留在链外：ajax(cfg.build(), cb)。

方法名一律动词开头，返回类型保持一致。 一条链上 where() 回自己、orderBy() 回自己、fields() 回数组，这种混合接口三天内必然有人写出断链调用。真要提供读操作，就明确命名成 getXxx() 或者放到链外。

回调只能出现在链的最后一步。 约定是 cb 永远是最后一个参数，且这一步返回 undefined 而不是链对象，摆明”到此结束”：

选型结论表

方案 状态可见性 可复用性 实现成本 调试体验 适用规模
return this 原地修改 只有终态 差，共享即串扰 最低 好，帧名是自己的方法 单次使用、3 到 8 步
每步返回新对象 每步快照都在 好，能分叉 中，要手写拷贝 中，同名对象要编号 短链且要复用起点

我的建议很明确：内部工具就写 return this ＋ 收集式 build()——链短、代码省，build() 负责校验和序列化，外面再包一层工厂门面省掉 new；把”实例不跨模块共享”写进约定，串扰就不存在（非要共享就导出工厂，或者改成每步新对象，代价是三倍分配）。数据处理别为了链式而链式：优先 _.chain(...).value()（它是即时求值，value() 不能省）或者普通函数配 pipe 一次算完；自建 Seq 只在你要的是一份”可序列化的查询描述”时才值得，那本质上是回到收集式。中间结果需要被看见、被单测、被打日志的地方，管道和语句永远比链式省事。

小结

链式的全部原理是”把对象本身或同类的新对象交回去”，剩下四个问题才是设计。改自己还是造新对象：共享单例会让两个模块的条件互相污染（实测 conds 涨到 4 条），不可变能分叉但要多付三倍分配，而且 extend 得连元素一起换引用。当场做完还是记账：收集式换来校验、重排和序列化，代价是栈顶落在 build、必须按子句装配。链从哪退出：+ 和 == 先走 valueOf，String() 和 join 先走 toString，安全链会咽掉错误，判据永远是”上一步返回的是不是同类对象”。出错谁来报：交互式 fail-fast，批处理收进数组、终点 allMessages() 一次报全。至于省 new 的守卫，它只挡得住构造函数那一次手滑，方法被摘下来当回调时照样写脏 global 和原型——四组取舍没有标准答案，但每条都得有实测数字和复现的 bug 撑着。
