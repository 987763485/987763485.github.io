ES6 默认参数与剩余参数

这两个特性看着像糖，实际上替我们删掉了项目里两类重复代码：函数开头那三四行判空赋值，和 Array.prototype.slice.call(arguments) 那一句。但它们的语义比看上去细：默认值只在 undefined 时生效、每次调用都会重新求值、默认表达式有自己的一层作用域；剩余参数会把 function.length 改成 0，而这个属性有几处代码正在读它。本文按工程实践的写法来：先把 ES5 的三种惯例和它们失真的地方摆平，再逐条给准确语义、四个改写练习、转译产物和引擎现状，最后收在六个坑上。年代前提：规范 2015 年 6 月 17 日定稿，本文写于 10 月初，浏览器侧基本没有可用面，node 那侧也要看版本与开关，线上仍以 Babel 5 转译为默认路径。

= 的准确语义：只有 undefined 才触发

规则一句话：实参缺失、或者实参恰好是 undefined 时，才求值默认表达式；null、0、''、false 都算传了值，默认表达式一次都不执行。

第二件事是求值时机：默认表达式在每次调用、且只在需要时求值。顺带一个副作用要提前知道：ES5 里有人用 arguments.length 区分”这个参数没传”和”传了 undefined“，默认参数把这两种输入合成同一件事，这个技巧从此失效；真要区分，只能收进配置对象或者拆成两个函数。昂贵的兜底则第一次获得了”不传才算”的待遇：

默认参数有自己的作用域，这是最反直觉的一处

还有一个纯粹由这条结构推出的语法限制：只要参数表不是”简单参数表”（出现了默认值、剩余参数或解构），函数体内第一条语句就不能是 'use strict' 指令，写了就是 SyntaxError（我把它放进 eval 才接得住，因为这是解析期错误）。所以这类函数的严格模式必须从外层文件或整个 IIFE 打开，不能靠函数自己声明。同理，在函数体里用 let 或 const 重新声明形参名一律 SyntaxError；换成 var 不报错，但值以函数体那行为准，读代码时很容易看错初值。

arguments 的历史包袱在《arguments 对象与 callee、caller》里展开过，这里只取三条结论：它不是数组，只是有个 length 的类数组对象，数组方法一个都用不上；在松散模式里它的下标与形参双向联动，内核为了维护这层联动会放弃一部分优化；arguments.callee 在严格模式下直接 TypeError。剩余参数把这三条一起消掉，代价是它必须放在参数表最后（function f(...a, b) 是语法错误），且此时如果还要数”总共传了几个”，得靠 arguments.length 而不是某个形参的 length。

另外要清楚一点：arguments 在有剩余参数的函数里依然存在（严格模式里也还能读它的 length），但两者混用只会造成混乱，规约上选一个。至于把数组反过来当参数列表传进去，那是展开运算符的地盘，《ES6 展开运算符实战》里已经写过，本文只在后面的聚合例子里用一次。

引擎现状：node 那一侧要看版本与开关

标准里这两块是正式语法，不该再谈开关；现实是引擎没跟上。2015 年 9 月 9 日发布的 Node.js 4.0 是 io.js 与 Node 合并后的第一个 LTS，V8 升到 4.5，模板字符串、let/const、剩余参数在这个版本里可以直接跑；但更早的 io.js 3.x 与 Node 0.12 要挂 --harmony，个别特性还有专门的开关名（--harmony_default_parameters 之类）。默认参数这条尤其别扭：我手上这几个版本里，它在非严格函数中的表现和严格模式并不一致，具体从哪个小版本开始完全不用开关我没有可靠对照表，所以结论是以你部署环境实测为准，不要把”node 4 能跑”当成上线依据。浏览器那一侧更简单：当时的主流稳定版没有一个能完整接受默认参数与剩余参数，IE 全线是解析期语法错误，Android 4.4 的 WebView 基于很老的 Chromium，iOS 8 也弱。所以 2015 年 10 月，这两个特性的正确用法只有一种：源码写 ES6，产物发布 ES5。

具体到工程动作，我们现在是两条。一条是按目录灰度：src/legacy 里的老文件不进 ES6 转换链、也不许写这两个语法，新模块放 src/modern，构建产物合并成同一份发布文件——这样能避免”一个没转译的反引号或默认参数把整个老文件在 IE 上打成解析失败”。另一条是让 CI 把运行时差异当真事：构建机上按 node 0.12、io.js 3、node 4 排一个矩阵跑同一套用例，加不加 --harmony 造成的差异在这个环节暴露，比上线后靠报错发现便宜得多。测试代码里我会留一条最简单的断言：foo.length 与文档里写的必填参数个数一致，把 arity 那节说的坑钉住。

六个会咬人的坑

  1. 默认参数后面不能再跟没有默认值的参数：function f (a = 1, b) {} 是 SyntaxError。要么把可选的重排到最后，要么收进配置对象，要么用 ...rest 兜住。
  2. null 不触发默认值：接口返回 { max: null } 时 max 就是 null，比较运算会静默出错。前端把”没给”与”给了 null”混为一谈是联调阶段最常见的一类 bug，需要显式约定。
  3. 默认值每次调用重建：对象、数组默认值不共享；反过来，跨调用共享的东西要放到函数外面去。
  4. 形参名遮蔽外部变量：function f(cfg = cfg) 之类自我遮蔽直接 TDZ 报错，配置对象传默认值时先换个名字或走函数取。
  5. 函数体内 'use strict' 非法：非简单参数表配严格模式指令是语法错误，严格模式得从文件级或外层 IIFE 打开。
  6. arity 变化：function.length 只数到第一个默认参数为止，框架判断、柯里化、文档生成都读它，公开 API 别拿默认参数表达可选。

小结

默认参数替我们消灭了 x = x || 值 这一类静默误伤，代价是要接受三条细规则：只有 undefined 触发、每次调用惰性求值（所以对象默认值每调用新建一份）、参数表是一层独立作用域（所以能引用前面的形参、会遮蔽同名外部变量、且函数体里不能写严格模式指令）。剩余参数把”可变参数当数组用”这件事从 slice.call(arguments) 里解放出来，但它和默认参数一起会改掉 function.length，而框架、柯里化和文档工具都在读这个属性，公开签名要谨慎。按 2015 年 10 月的现实，浏览器没有可用面、node 要分版本与开关，所以正确姿势仍是 Babel 5 转译发布，同时清楚产物里多出来的判空与拷贝循环——热路径上的包装函数我会退回 ES5 写法，这不是怀旧，是那一层每帧数组分配的账。
