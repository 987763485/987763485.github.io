Math 对象常用方法与随机数

刚学 JavaScript 的朋友大多是从 Math.random() 开始接触这个对象的：一行代码就能出一个随机数，看起来毫无难度。可真要写”从 1 到 6 摇一颗骰子””把一组分数里的最高分找出来””随机打乱一个列表”这类需求时，出错率却相当高——区间少了一头、随机数分布不均匀、大数组求最大值直接把调用栈撑爆，都是常见的坑。本文按入门顺序把 Math 讲清楚：它是什么、有哪些取整方法、随机数怎么写才不会错，代码全部是 ES5，可以直接抄进项目里用。

Math 是一个普通对象，不是构造函数

Math 只是全局对象上的一个普通属性，它的值是一个对象，规范给它起了个内部类别叫 Math，用 Object.prototype.toString.call(Math) 能看到 '[object Math]'。很多初学者会把 Number、String、Array 的用法套到它身上，写出下面这种代码：

这行一定会报错。Math 不是构造函数，它压根没有 prototype，也不提供任何实例方法，所有功能都以”对象属性”的形式平铺着：属性值要么是常量（Math.PI），要么是静态方法（Math.floor）。你写成 Math.floor(3.7)，就是在读 Math 这个对象上名为 floor 的属性，它恰好是个函数。

由此还有两个实用的推论。第一，Math 里的方法都是普通函数，可以安全地取出来复用，但别指望在数字字面量上找到它们——String、Array 的方法挂在原型上，所以 'abc'.toUpperCase() 能写；而 Math 不包装 Number，3.7.toFixed() 是语法错误，3.7..toFixed(1) 这种别扭写法才勉强能过，正式代码一律写 Number(3.7).toFixed(1) 或 (3.7).toFixed(1)。第二，正因为它是普通对象，做特性检测时可以直接判断方法存不存在：

Math.trunc 的语义是”把小数部分直接砍掉”，也就是向零取整，Math.trunc(3.9) 和 Math.trunc(-3.9) 分别是 3 和 -3。上面这段兜底实现可以原样抄进兼容层。至于 ES6 草案里新提的那批数学方法，今天还不能用，也别急着找替代库——绝大多数场景用下面的几个老方法就够了。

最后一行值得多说两句。Math.round 遇到正好一半的情况，统一往正无穷方向靠：Math.round(0.5) 是 1，Math.round(-0.5) 是 -0。这里得到的是负零，它和 0 用 === 比较是相等的，打印出来也是 0，只在取倒数或处理方向角这类场景里才露出迹象。真正要小心的不是负零，而是”负数四舍五入的结果比直觉大 1”：写 Math.round(-2.5) 期望 -3 的人会拿到 -2。若你的业务需要对称的四舍五入（正负数都往绝对值大的方向进位），标准做法是先 Math.abs 再取整、最后补回符号：

坑在于溢出：只要数字超出 32 位带符号整数的范围，结果就会绕回去，变得面目全非。

时间戳、订单号、微秒计数这些值很容易超过 21 亿，用位运算取整就是埋雷。入门阶段的结论很简单：需要取整就写 Math.floor 或 Math.round，别用位运算。它为什么折回 32 位、涉及哪个内部操作，属于类型转换那套规则，我在《JavaScript 数据类型与类型转换详解》里推过，此处不重复。

随机数：Math.random 只给 [0, 1)

Math.random() 返回一个大于等于 0、小于 1 的浮点数，也就是区间 [0, 1)，并且在这个区间内近似均匀分布：0.3 附近出现的概率和 0.7 附近差不多。三个要点：它取不到 1，这个”开区间”属性是后面所有正确写法的基础；它不接受任何参数，Math.random(6) 里的 6 会被直接丢掉；它没有规律、不可预测，同一个页面刷新两次结果就不同。

想要”可重复的随机数”：极简线性同余

有两个场景会让 Math.random() 变得不好用：写单元测试时希望每次跑出的随机数据完全一样，方便复现失败；做随机动画时想让同一颗种子每次渲染出同样的轨迹。这两个需求指向同一个词——种子（seed）。给一个种子，就能得到一串固定不变的”伪随机”数字，这叫可重复随机。

必须说清它的边界。第一，这是纯教学实现：常数 a、c 选得不好会周期很短，状态只有 32 位意味着最多 42 亿多个不同的值，看久了会出现重复模式。第二，也是最重要的：这类伪随机数绝不能用于安全场景。要生成验证码、重置密码的随机串、会话标识时，攻击者只要猜到种子或者观察到足够长的序列，就能反推出下一个数。当时浏览器的密码学接口也还没普及到可以随手用的程度，所以真要这类随机数，请交给后端生成。

洗牌：Fisher-Yates 是对的，sort 加 random 是错的

它有两个问题。第一，分布不均匀：sort 的比较函数被调用几次、比较哪两个下标，完全由引擎的排序算法决定，规范对此不作承诺；于是某些排列出现的概率就是比其他排列高。第二，各引擎实现不同，同一份代码在 IE、Firefox、Chrome 里打乱的结果形态都不一样——它甚至可能根本不改数组，最后顺序原样保留。《JavaScript 数组常用方法详解》里说过 sort 是原地排序、且不保证稳定，这里只借用这个结论，不再重复那些 API 细节。

正确的洗牌是 Fisher-Yates（也叫 Knuth 洗牌），思路朴素：从最后一位开始，每一位都和它前面（含自己）的随机一位交换。这样每个元素落到每个位置的概率都是 1/n，n 个元素的全部排列等概率出现。

注意 randomInt(0, i) 的上界是 i 而不是 i - 1：元素允许和自己交换，一旦少了这一档，每个位置的概率就偏了。它是原地修改，不想弄脏原数组的话先复制一份，arr.slice(0) 就够（浅拷贝，方法本身在那篇数组旧文里已经讲过）。

常量与一个圆周取点的小例子

Math 上的常量里，入门用得最多的是这两个：Math.PI 约等于 3.141592653589793，Math.E 约等于自然对数的底 2.718281828459045。它们是只读的普通属性，别去改它们。加上 Math.sin、Math.cos，就能做一件很实用的小事：在一个圆上随机取一个点。

弧度转角度的换算是 角度 = 弧度 * 180 / Math.PI，这个换算式建议直接写成函数，别在业务代码里到处手写。顺带一提，Math.random() * 2 * Math.PI 之所以能均匀覆盖整圈，靠的还是前面那个 [0, 1) 的均匀分布；而随机角度是均匀的，随机点却不会均匀落在圆盘内（半径也随机时还要再处理一次），做撒点测试时会发现点全挤在圆心附近——这属于下一个话题了。

小结

Math 是普通对象而非构造函数，方法全是静态挂上去的，取整用 Math.floor 与 Math.round，负数请认准”地板往下、天花板往上”，不要用位运算取整来省那几个字符。Math.max.apply(null, arr) 在万级数组上会炸栈，老老实实写循环。Math.random() 给的是 [0, 1) 的均匀浮点数，随机整数的唯一正确姿势是 Math.floor(Math.random() * (max - min + 1)) + min，Math.round 版本会把两端概率砍半。需要可重复随机可以自己写一个 LCG，但要清楚它跟安全无关。洗牌请用 Fisher-Yates，sort 配 random 是个分布不均匀又依赖引擎的坏习惯。最后，浮点数有舍入，比较要带容差，算钱请用分为单位的整数。
