ES6 箭头函数与 this 绑定

ECMA-262 第 6 版在 6 月 17 日刚定稿，规范里关于箭头函数的每一条都写得明明白白，可我手上的浏览器基本还没跟上——所以这篇是”靠转译尝鲜”的笔记，不是”上车指南”。它只解决一个非常具体的问题：回调里那个总是丢失的 this。读完你应该能说清箭头函数的 this 从哪来、哪几种地方千万别用它、以及 Babel 5 把它变成了什么。文中的 ES5 对照代码都能在 jQuery 1.11 与 io.js 3.x 上直接跑，箭头函数部分要靠转译。

ES5 里那三个熟悉的补丁

this 的判定规则我去年在《this 指向的四种绑定规则详解》里已经整理成一套五步流程了，这里只取结论：this 由调用点的语法形式决定，而回调函数恰恰是”由别人调用”的，所以我们这三年一直在打补丁。

三个补丁各有代价。var that = this 每个函数多一个变量，而且回调里的 this 语义从此消失，读代码的人得先确认 that 是谁；bind 每次调用都产生一个新的函数对象，所以 .on() 和 .off() 现绑现摘是无效的（那篇里踩过这个坑）；包装函数最直白，但每次都是新引用，同样摘不掉。更要紧的是，这三种写法都在重复同一句话：我知道这次调用会把 this 绑到别处，我手动把它拽回来。

差点漏掉的第四个补丁：thisArg

还有一类补丁被我漏在上面，因为它只覆盖部分宿主——ES5 数组方法普遍带第二个参数 thisArg：

词法 this：不是第五条规则，而是绕过判定

箭头函数的做法是把”拽回来”这件事挪到定义时。规范的说法是：箭头函数体内不创建自己的 this（也不创建 arguments），它对 this 的引用是一个自由变量，沿着作用域链找到定义它的那个外层函数，用那次调用已经绑好的值。

这就是全部秘密。它没有给四种绑定规则添第五条，而是让箭头函数根本不走那套判定——引擎不会为它做成员绑定、不会给它默认绑定，call / apply / bind 传进去的 thisArg 一律被忽略。

用一张图把上溯过程画出来：

flowchart TD
  A[箭头函数体内引用 this] --> B[它自己不建立 this 绑定]
  B --> C[沿作用域链找定义处的外层函数]
  C --> D{外层是普通函数吗}
  D -->|是| E[取那次调用绑定的 this]
  D -->|还是箭头函数| C
  D -->|没有外层函数| F[全局或模块的 this]

理解了”它是被捕获的变量”，前面那三个补丁的账就能对齐了：箭头函数就是机器版的 var that = this，语义一致、成本也一致，没有什么新魔法。《JavaScript 闭包从原理到实战》里讲过闭包捕获的是外层变量环境，词法 this 不过是这套环境里多了一个我们从前拿不到的成员；也正因为它是普通变量，外层函数的调用早就结束了它照样读得到值——这一点和 arguments、形参的表现完全一致。

语法形态与三条硬限制

三个容易写错的地方：表达式体是隐式返回，一旦加了花括号就得显式 return；返回对象字面量时不加括号，{ 会被当成语句块的开头，解析到 id: 就报语法错误；单参数省括号的前提是没有默认参数和剩余参数，一旦要写就别无选择地把括号加回来。

前两条合起来是最要紧的一条推论：凡是需要 new、需要挂在原型上被继承、需要靠 prototype 做文章的地方，都不能换成箭头函数——它连 prototype 属性都没有，new 它就是当场抛错。第三条则提醒我们，箭头函数里没有 arguments，真想收下全部实参得用剩余参数 (...rest) => ...，那个语法留给后面专门谈参数的那篇。

三条限制分别跑一遍

规范写得死，可 2015 年 8 月能把三条一次跑完的环境几乎没有——浏览器稳定版连 => 都解析不过去。只好分两头验证：开发版跑原生行为，上面那句”当场抛错”只在这一头成立；Babel 5 产物跑上线行为。两头结论不一样，这个差异最咬人。

检查项 原生支持箭头函数的引擎 Babel 5 产物
Made.prototype undefined，没这个属性 普通函数的 prototype，是 object
new Made() TypeError，V8 文案大致是 Made is not a constructor 不报错，静悄悄返回实例
体内引用 arguments 取最近普通函数的 arguments 改写成 _arguments，插在外层函数开头

第二行说出不太舒服的事实：转译后”箭头函数不能被 new“这条硬限制其实不存在，误用的代码一行错误都不报，等换回原生语法才炸出满屏 not a constructor。所以这三条得靠约定守——我的口径是”箭头不出现在 new 左边、不挂原型”。

把 jQuery 回调改写成箭头函数

$.each 的回调 this 是 jQuery 挨个绑上去的当前项，这个语义在箭头函数里必然丢失。所以改写的规矩只有一条：别指望 this，改用形参。$.each 给了 (index, value)，.each() 给了 (index, element)，够用。

省下来的正是 var that = this 那一行和满屏的 that。同类收益最大的是三类：数组的 map / filter / forEach / some / every 回调（只用形参，无 this 依赖）、sort 比较函数、setTimeout 里的一次性延时。反过来，Promise 的 then 回调我暂时还留着 function 加 bind，等把异步那套单独写一篇时再一并改写。

调试时这点看得最直白：一个函数里两个普通函数各含箭头，产物里就是 _this 和 _this2，认名字能对上外层。函数名别抱期待——有赋值的 var double = x => x * 2 栈里还认得出，当实参传进去的编译完是匿名函数表达式，栈上只有 anonymous 一类字样，定位靠行号。

另外两件事要分清。箭头函数是纯语法，转译完就不需要任何运行时补丁，不需要 polyfill；需要 polyfill 的是 Map、Set、Promise 这些新内置对象，我当时用 core-js 或 es6-shim，图省事就直接引 Babel 5 自带的 browser-polyfill.js。还有一点容易中招：Babel 5 默认会在产物文件顶部插一句 'use strict'（因为它按 ES6 模块语义处理），纯浏览器全局脚本里我一般用 --blacklist useStrict 关掉，否则全局脚本里的 this 会从 window 变成 undefined，那批老代码会莫名其妙地红一片。

浏览器现实与一条实践准则

别把”标准定稿”当成”能用”。2015 年 8 月的现场是这样的：桌面主流浏览器的稳定版多数还不支持箭头函数，直接在控制台里写 () => {} 大概率是语法错误；IE 11 对 ES6 是零支持，刚出来的 Edge 也只吃掉很小一块；移动端更别提，Android 4.4 的 WebView 还是老 Chrome 内核，iOS 8 的 Mobile Safari 对 ES6 的支持少得可怜。Node 这边现在跑的是 io.js 3.x，9 月要和 Node 合并成 4.0、换上新的 V8，官方那份支持率也就四成上下，不少语法还得靠 --harmony 一类开关，具体哪个开关管哪条我只能逐个实测。所以我自己的口径很明确：业务代码里箭头函数一律走转译，不指望任何运行时原生支持；转译产物再上 es6-shim 兜底。

至于什么时候用，我给自己定的准则就一句话：回调里用箭头函数，方法定义与需要 new 的地方不要用。 展开成三条检查：这段函数会不会被 new？它的 this 是不是框架绑好的（原型方法、事件处理、jQuery 插件）？函数体里有没有要用的 arguments？三个都答”否”，就换成箭头；有一个答”是”，老老实实写 function。

用与不用：一张对照清单

把前面的结论压成一张对照表，this 一栏写的是函数在该位置本该拿到的值。

位置 这里的 this 本该是谁 写法
map / filter / forEach 回调 用不到 箭头
sort 比较函数 用不到 箭头
setTimeout 一次性延时 外层函数 箭头
$.each / .each() 回调 当前项或元素 箭头可以，取值改用形参
对象字面量里的方法 调用点左边的对象 function
原型方法 实例 function
DOM / jQuery 事件处理 触发或绑定的元素 function，或箭头加 e.currentTarget
要 new 的构造函数 新实例 只能 function
被 call / apply / bind 复用的工具函数 传入的 thisArg 只能 function
体内要用 arguments 用不到 function，或剩余参数

下半张表那几行不是”不建议”而是”不能”，批量替换最容易一并扫进去，前面那次事故就撞在”对象字面量里的方法”上。方向也不对称：function 换成箭头丢了 this，十分钟能改回来；箭头用在原型方法或构造函数上，掉的是语义。

小结

箭头函数的全部语义就一句：它不建自己的 this 和 arguments，引用 this 时取定义处外层函数的值。它不是第四种绑定规则之外的第五种，而是绕开了整套调用点判定，call / apply / bind 对它无效。往深处还有一句：它只认最近的普通函数，穿不过 function。语法上要记住返回对象字面量得加括号、单参数省括号有条件；硬限制是没有 prototype、不能 new、没有 arguments，但转译产物上这三条并不会真报错，只能靠约定守。工程上它的收益是把 var that = this 和 $.proxy 这两类补丁自动化，代价则由转译器代付——Babel 5 的产物就是我们自己写的那个 _this。当前（2015 年 8 月）的浏览器现实决定了它只能靠转译尝鲜，写代码时守住”方法用 function、回调用箭头”这条线，就已经不会出错了。
