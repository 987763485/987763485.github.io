漏洞扫描与 Nessus 实践

漏洞扫描大概是安全建设里最容易采购、也最容易被误用的能力。装好扫描器、填一段 IP、点下开始，几十分钟后就能拿到一份带颜色的报告；但报告上的红色条目和真实风险之间，隔着授权、范围、策略、凭据和人工复核。本文以 Nessus 8.x 为例，讲清楚授权范围内的漏洞扫描该怎么做：范围怎么划、策略怎么配、凭据扫描为什么更准、误报怎么治理、报告怎么写给不同的人看。适合刚开始接手漏洞管理的运维与安全工程师阅读。

扫描在漏洞管理中的位置

漏洞管理是一条闭环，而不是一次动作：发现、验证、修复、复测，然后再发现。扫描器只承担第一环，也是成本最低的一环。它把存活主机、开放端口、服务指纹、补丁状态采集回来，与插件库比对，给出“可能存在”的结论。

flowchart TD
    A[资产与授权范围] --> B[扫描发现]
    B --> C[人工验证]
    C --> D[修复或补偿]
    D --> E[复测确认]
    E --> B

把扫描和渗透测试混为一谈是常见误解。扫描是广度优先的：自动、可重复，一夜之间可以覆盖上千个地址，擅长找出“已知漏洞没有打补丁”。渗透测试是深度优先的：人工、按业务路径推进，擅长把几个低危问题串成一条可用的攻击链。只做扫描，会漏掉逻辑漏洞和权限设计缺陷；只做渗透，会漏掉大量未修补的已知问题。合理的组合是：扫描做高频的基线覆盖，渗透测试按系统重要性每年做一到两次专项。

还有一层预期要提前对齐：扫描报告里的“高危”不等于“必须今晚停机”。它描述的是漏洞本身的技术严重性，是否紧急还要看资产承载什么业务、暴露在哪个网络区域、有没有其他控制措施。这个判断只能由人来做。

授权与范围先行

扫描会向目标主动发包，端口探测、服务识别、插件请求在流量上和攻击没有区别。所以第一件事不是打开扫描器，而是拿到书面授权：委托方、授权人、资产清单、允许的时间窗口、速率约定、应急联系人和中止流程。授权书要能对应到具体 IP 或域名，口头同意不算。

排除项和包含项同样重要。云主机要看 IP 归属，别把云厂商的共享设施扫进去；CDN、WAF、托管服务、外包系统、SaaS 域名往往不在授权范围内；办公网里的打印机、摄像头、工控设备对扫描非常敏感，宁可先排除。扫到第三方资产，轻则投诉，重则构成法律问题。

速率限制要提前写进策略。Nessus 允许限制每主机并发检查数、同时扫描的主机数和单次扫描时长，老旧设备和专线尤其要保守。扫描窗口放在业务低谷，避开批处理、备份和发布时段；开始前通知值班人员，准备好一键停止的预案。

部署形态与网络视角

扫描器放在哪里，决定了它能看到什么。放在互联网侧，看到的是经过 NAT 和防火墙映射后的端口，反映外部攻击者的视角；放在生产内网，看到的是东西向的真实暴露面，往往比外网报告多出几倍。两个视角都要有，不能只扫外网就宣布“没有问题”。

内网扫描器本身也要加固：独立管理网段、只允许运维终端访问、开启审计日志、插件库定期更新。隔离环境无法在线更新时，走离线激活和离线插件包：

离线包有时效性，季度更新一次是底线，否则新披露的漏洞扫不出来。扫描器不要直接暴露在公网，管理端口 8834 只对受控来源开放。

策略配置的取舍

Nessus 的模板已经覆盖了大部分场景：基础网络扫描适合资产普查，高级扫描用于自定义端口与插件族，凭据补丁审计专门核对补丁，合规模板用于基线核查。真正影响结果的是模板里的几项设置。

主机发现决定“扫不扫得到”。只开 ICMP 会漏掉禁 ping 的主机，建议组合 ARP、ICMP 与常见端口的 TCP 探测。端口范围决定“看多深”：全端口 1-65535 能发现跑在 8080、9000 之外的服务，但耗时成倍增加；日常扫描用常见端口加业务端口清单，季度做一次全端口抽查。

插件族要按资产类型选。Windows 主机开 Windows 相关族，Linux 开 Unix 与对应发行版族，Web 服务器加 CGI 与 Web 服务器族。全开插件是最常见的错误：扫描时间从一小时变成一天，老旧设备可能被打挂，报告里塞满信息级条目和误报，真正的高危反而被淹没。

性能参数要和服务窗口匹配：同时扫描主机数、每主机并发检查数、单次最长时长。用 API 建任务时可以把这些写进策略，便于版本化：

凭据扫描为什么更准

不带凭据时，扫描器只能从外部猜：看 banner、看响应头、看端口，再推断版本和补丁。带凭据后，它可以登录主机读取包列表、注册表、配置文件，直接判断某个补丁是否安装、某项配置是否生效。同一个漏洞，远程扫描可能报“版本疑似受影响”，本地检查能给出“补丁编号缺失”这样的确定结论。

三类凭据最常见：Linux 用 SSH，Windows 用 SMB，数据库用只读账号。SSH 账号需要能执行查询命令，通常要 sudo 权限才能读到完整的包信息；Windows 需要本地管理员或域账号；数据库账号只需要读元数据和版本信息。权限给到“够用”为止，不要图省事直接用 root 或域管理员。

凭据本身是高风险资产。专用账号、禁止交互登录、限定来源 IP、定期轮换，扫描平台里加密存储，导出策略和配置文件时确认不含明文。凭据失效不会让扫描失败，它会静默降级成远程扫描：任务照样完成，报告照样生成，但覆盖度已经掉了一半。每次扫描后要检查日志里的认证失败记录，这比看报告数量有用得多。

合规扫描与漏洞扫描的区别

合规扫描回答的是“配置是否符合基线”，不是“有没有漏洞”。它以 CIS Benchmark、DISA STIG 或内部基线为检查项，逐条给出通过、失败和证据。一台机器可以没有任何高危漏洞，却在口令策略、日志留存、SSH 配置上大面积不合规；反过来，配置很规整的机器也可能因为一个未打补丁的组件而被攻破。

合规结果要按条目读，不能只看总分。失败项先判断是“真的偏离基线”还是“基线不适用于这个角色”，比如数据库服务器不需要遵循 Web 服务器的文件权限要求。确认需要整改的，进入变更流程；确认不整改的，记录理由、风险接受人和到期时间。合规扫描同样依赖凭据，本地审计项没有登录权限根本读不到。

调度、分组与结果解读

扫描要变成制度，而不是运动。常规资产每周或每月一次，核心系统缩短到每周；重大变更、新系统上线、应急漏洞披露后加一次专项扫描。资产按业务线、网络区域、责任团队分组，报告按组下发，谁的孩子谁抱走。

新资产最容易成为盲区。定期做网段存活探测，结果与资产台账比对，差集就是要补录、补扫的对象；漏扫的那台机器，往往就是后来出事的那台。扫描覆盖率应当作为指标持续跟踪，而不是只统计扫出了多少漏洞。

结果解读从严重级别开始，但不能停在级别上。CVSS 基础分描述的是漏洞的技术属性，不含资产重要性、数据敏感度和网络暴露面；两个 7.5 分的漏洞，一个在公网订单系统，一个在隔离测试环境，处理顺序完全不同。除了分数，还要看插件输出里的证据：端口、banner、返回内容、检测到的版本号。没有证据的条目，先当疑点处理。

误报的常见来源有几类：发行版的补丁回移让版本号看起来仍然老旧，实际漏洞已修复；banner 可以伪装，版本号不能全信；服务跑在非标准端口，指纹识别错位；反向代理和虚拟主机让多个域名返回同一页面；凭据失败导致本地检查降级；WAF 拦截了探测请求，被误判为不存在。知道这些来源，复核时就有方向。

误报治理与修复复测

误报治理的流程是固定的：人工复核、补充验证、标记例外、写进工单。补充验证要落到主机上，比如直接查包版本：

确认是误报的，在扫描平台标记并写明理由和复核到期时间，到期自动重新出现，避免“一标了之”。确认属实的，按“可利用性、资产重要性、暴露面”三个维度排序，而不是按报告顺序。修复手段不只有打补丁：配置收紧、关闭不必要的端口、网络隔离、WAF 规则都是有效的补偿措施，要在工单里写清楚选了哪种、为什么。

复测是闭环的最后一环，也是最容易糊弄的一环。“插件不再报”不等于“修好了”：可能扫描器这轮没扫到、凭据失效降级了、端口被临时关闭、或者插件规则更新了。可靠的复测要结合独立验证：登录主机确认版本、手工发一次请求看响应、核对配置项的实际取值。修复记录里同时留下修复前和修复后的证据，评审时才站得住。

报告与工具配合

报告至少要有两个版本。给管理层的是风险摘要：资产覆盖率、高危数量与趋势、Top 风险、按期修复率、超期项和需要决策的资源问题，一页纸能看完。给技术团队的是明细：资产、端口、插件名称、证据、修复建议、责任人和期限，可以筛选、可以导入工单系统。

报告的分发要分级。未修复漏洞的细节不进入公开渠道，对外通告只写影响范围、处置计划和联系方式；内部也按需分发，避免一份 Excel 在多个群里流转。扫描器不是唯一的工具：Nmap 适合做资产发现和端口核对，SAST 和 DAST 覆盖应用层，配置核查工具负责基线，SIEM 收集扫描与修复日志。它们各自解决一段，谁也不能替代代码审计——扫描器看不到业务逻辑里的越权，也读不懂一段自定义的权限判断。

常见坑

第一，未授权扫描。这是唯一可能让技术问题变成法律问题的一条，授权书和范围清单必须先于扫描器启动。

第二，全端口加全插件。看起来“扫得全”，实际是拖垮业务、制造噪音，还容易触发防护设备告警。

第三，凭据权限过大。用域管理员做扫描，等于给扫描器配了一把万能钥匙，一旦平台被攻破，损失远超漏洞本身。

第四，只扫外网，忽略内网横向。大量真实入侵是从一台普通主机开始横向移动的，内网视角的报告往往更有价值。

第五，报告堆砌不排序。几千条结果直接发给业务方，等于没有报告。

第六，扫完不跟踪。没有工单、没有责任人、没有期限，下一轮扫描只是把同样的问题再打印一遍。

小结

漏洞扫描的价值不在“扫”，而在“管”：授权划清边界，策略决定覆盖度，凭据决定准确度，复核决定可信度，复测决定闭环是否真的闭上。Nessus 这类工具能高效地完成发现和基线核查，但它给出的永远是线索，不是结论。把扫描接进变更流程和工单系统，让每一条高危都有责任人、有期限、有验证，扫描才真正变成漏洞管理的一部分。
