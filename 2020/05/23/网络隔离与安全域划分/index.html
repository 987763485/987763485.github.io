网络隔离与安全域划分

很多团队的内网是从一个扁平大网段长出来的，直到某台终端中毒才发现横向移动毫无阻挡。本文从扁平网络的问题讲起，给出六个安全域的划分方法、一张可执行的访问控制矩阵，以及 VLAN、防火墙、主机防火墙和 Kubernetes NetworkPolicy 的分层实现。读完可以按文中的步骤梳理自己的网络，并把“谁能访问谁”写成可验证、可治理的策略。

扁平网络的四个代价

很多内网在早期都是一个大网段：办公终端、应用服务器、数据库、监控系统都放在 10.0.0.0/8 里，彼此三层可达。这样最省事，但也把安全压力全部集中到了边界设备上。边界一旦被绕过，内部就是一张全通的地图。

横向移动几乎没有成本

边界防火墙只能拦住从外到内的连接。一旦某台办公终端被钓鱼邮件感染，攻击者在内网看到的是大量可达目标：文件共享、未授权缓存服务、弱口令远程桌面都在同一广播域里。攻击者不需要突破边界，只需要找到一个入口，然后逐台尝试。隔离的第一目标不是把攻击挡在门外，而是让已经进来的主机只能看到它该看到的东西。

责任边界无法回答

“这个数据库允许哪些系统访问？”在扁平网络里，答案往往是“整个网段都可以”。出故障时无法界定影响面，做变更时也无法判断谁会受影响。安全域的本质，是把“谁和谁能通信”变成一份可评审、可审计的清单，而不是靠记忆和口头约定。

合规要求需要证据

等保 2.0 的“区域边界”要求划分不同区域，并在区域之间部署访问控制。测评需要的不是一句“我们做了隔离”，而是拓扑图、区域清单、策略和验证记录。扁平网络连第一步的证据都拿不出来。

故障与攻击的影响面

大广播域会让地址解析欺骗、地址池耗尽和扫描噪声波及所有主机，一次误配置的生成树或路由也会让全域抖动。域越小，爆炸半径越小。

六个安全域与不可直达原则

划分依据不是部门，而是信任等级、数据敏感度和运维职责。同域主机共享相似的暴露面和访问需求，跨域通信必须经过策略点。这套六域模型适合多数中小规模企业网络，可以按业务再细分。

各域放什么

  • Internet：不可信区域，只允许访问 DMZ 中明确发布的入口，不参与任何内网策略。
  • DMZ：反向代理、Web 应用防火墙、对外 API 网关等“必须被外网看到”的组件。DMZ 内不放数据库，也不放凭据。
  • 核心业务区：应用服务器、消息队列、任务调度等。它接受 DMZ 的代理流量和办公区的少量入口流量。
  • 数据区：数据库、缓存、对象存储、大数据集群。只接受核心业务区的固定端口，不接受办公终端和 DMZ 的直接连接。
  • 管理区：堡垒机、监控采集、日志平台、配置管理、持续集成控制端。被管设备只接受管理区的入向连接。
  • 办公区：员工终端、打印机、视频会议设备。它是失陷概率最高的区域，应当被当作“半可信”。

什么必须不可直达

有几条路径应当在拓扑和策略上同时禁止：Internet 不能直达 DMZ 以外的任何域；DMZ 不能直达数据区和管理区；办公区不能直达数据区；数据区不主动发起连接，日志与备份由接收端拉取或走专用通道；业务域不能反向访问管理区。把这些写成清单，比只写“允许什么”更容易发现遗漏。

管理面要单独成域

管理面包括 SSH、远程桌面、SNMP、带外管理口和各类控制台。它与业务流量的方向相反：不是用户访问业务，而是管理员访问设备。把管理面混在业务网段里，等于让任何一台失陷的业务主机都握有登录其他设备的跳板。管理区应当有独立网段和独立策略，运维流量只从堡垒机进入。

访问控制矩阵与默认拒绝

域画好之后，第二步是把域间关系写成矩阵。矩阵的行是源域，列是目的域，单元格填协议和端口；没有写明的组合一律拒绝。它是策略的唯一事实来源，防火墙、交换机和安全组都应当从矩阵生成，而不是各配一套再互相解释。

落地时有几个细节必须坚持。默认拒绝要写在链尾或策略的默认动作里，不能靠“先放行、后补拒绝”。规则要利用状态检测，只放行新建连接的方向，回程由 established,related 统一放行，否则规则数会翻倍。源和目的用地址对象或标签，端口写具体值，不要用 1-65535 糊弄。每条规则都要有申请人和到期时间。

矩阵还要覆盖“反向”路径。很多事故不是应用连不上数据库，而是数据库主动连出外网，或者备份服务器能反向登录数据库。为每个域补一行“出向”策略，只允许必须访问的目的，能提前堵住这类问题。

实现层次：从 VLAN 到微隔离

同一份矩阵可以用不同层次的技术实现。层次越低越靠近物理网络，越难绕过；层次越高越贴近工作负载，越容易随迁移变化。实际环境通常几层叠加。

VLAN 与子网分段

VLAN 把广播域切开，通常一个域一个 VLAN、一个三层网段。但 VLAN 本身不是安全边界：二层转发、VLAN 跳跃和配置错误都可能让流量绕过三层设备。真正起隔离作用的是跨 VLAN 的三层策略，VLAN 只是让策略有清晰的落点。

防火墙与交换机 ACL

域间策略的主力是状态检测防火墙，按“源域到目的域”组织规则，而不是按接口堆叠。交换机 ACL 无状态、线速，适合接入层兜底，例如在办公区端口直接丢弃发往管理网段的流量；但它不适合承载完整矩阵，规则一多就难以维护。

主机防火墙

主机防火墙是最后一道，也是唯一跟着虚机或容器迁移的一道。Linux 上用 nftables 或 iptables，Windows 上用自带防火墙，只开放业务端口并限制来源网段。即使域间策略漏了一条，主机上仍有拒绝。缺点是分散，必须有配置管理和基线检查，否则几十台机器的规则会逐渐分叉。

Kubernetes NetworkPolicy

在 Kubernetes 里，命名空间相当于轻量安全域，NetworkPolicy 表达 Pod 间的允许关系。先给每个命名空间加一条默认拒绝所有入向流量的策略，再按标签逐条放行。它只描述三层和四层可达性，是否生效取决于网络插件，也不提供加密和七层过滤，不能替代域间防火墙。

南北向与东西向

南北向流量穿越边界，经过防火墙和负载均衡，策略和日志较完整。东西向流量在域内或域间横向流动，量大、路径短，常常只经过交换机。仅靠边界防御的问题就在这里：攻击者进入办公区后，横向扫描和凭据传递根本不经过边界设备。因此域内还要分段，例如把 Web 层、应用层、数据层拆成三个子网，数据库子网只接受应用子网的固定端口。近年常提的零信任，本质上也是把这条思路推到身份和每次请求，本文不展开。

微隔离的定位

微隔离把策略绑定到工作负载标签而不是 IP 地址，策略跟着虚机迁移。2020 年前后它在虚机密度高、地址变化频繁的环境里开始被采用，但仍属新兴实践，需要主机代理和统一控制面，并不是所有网络的标准配置。对多数团队来说，先把 VLAN、防火墙和主机基线做扎实，收益更确定。

管理面隔离

管理面是攻击者最想要的目标：拿到一台业务机只是起点，拿到堡垒机或带外管理口才意味着可以控制整个机房。管理面隔离要回答四个问题：人怎么进来、设备怎么带外管理、数据库怎么被运维访问、日志和备份往哪里走。

  • 堡垒机是唯一入口。运维人员先登录堡垒机，完成多因素认证，再从堡垒机连接目标设备，会话全程录屏和命令审计。办公区到管理区只开放堡垒机的 443，管理区到各业务域只开放 SSH 等运维端口。
  • 带外管理独立组网。服务器的 BMC、交换机的串口控制台放在独立的管理 VLAN，不与业务网互通，只允许管理区访问。带外口默认口令必须修改，固件要及时更新，这类接口一旦暴露，可以绕过所有主机层防护。
  • 数据库访问路径要收敛。应用从核心业务区访问数据区的固定端口；DBA 通过堡垒机和数据库代理访问，办公终端不允许直连数据库。代理层同时承担账号管理和 SQL 审计。
  • 日志与备份是单向路径。业务域把日志送到日志平台，日志平台不反向连接业务域；备份服务器放在独立网段，由备份任务主动拉取数据，备份账号只读并限定来源。

验证与治理

策略写完不等于生效。先看计数器：nft list ruleset -a 能看到每条规则的命中次数，iptables -L -n -v 类似；上线初期可以只记录不丢弃，观察一周再收紧。再看流量日志：防火墙和交换机导出的 NetFlow 或 IPFIX 记录，按源域和目的域聚合，能发现矩阵之外的连接。路径验证用 traceroute 从每个域抽查，确认流量经过预期的策略点。端口探测只在自有且书面授权的实验环境进行，生产环境以配置复核和日志为主。最后把配置导出与矩阵逐条比对，重点检查被前序规则遮蔽的条目和长期零命中的规则。

最常见的六个坑：上线时留下的 any-any 规则没人回收；多个域网段重叠，NAT 之后源地址失真；双网卡主机同时接两个域，绕过防火墙；备份和监控路径被遗忘，形成反向通道；“临时开通”没有到期时间；规则没有负责人，离职后无人敢动。

治理上，变更申请写清源、目的、端口、期限和理由，审批后在窗口执行，执行完立即验证并归档。矩阵和规则表按季度全量评审，月度只看新增和命中；例外带补偿控制和到期日；拓扑图、矩阵、设备配置放在同一个版本库，保证可以互相追溯。没有治理的隔离，半年后一定会退回全通。

小结

网络隔离的目标不是把攻击挡在边界外，而是限制一台主机失陷后能走多远。先划出 Internet、DMZ、核心业务、数据、管理和办公六个域，再用默认拒绝的矩阵定义域间关系，最后用 VLAN、防火墙、主机防火墙和 NetworkPolicy 分层实现。管理面必须独立成域，堡垒机和带外管理是硬要求。策略要能被计数器和流量日志验证，也要有变更流程和定期评审，否则再好的矩阵也会被临时规则侵蚀。
