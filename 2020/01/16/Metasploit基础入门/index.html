Metasploit 基础入门

Metasploit 常被描述成“黑客工具”，在工程场景里更像一套组织漏洞知识的框架。本文面向刚接触它的安全工程师与后端开发者，讲清框架构成、控制台操作、模块类型、以 check 结束的验证流程，以及实验记录和报告怎么写。所有操作都限定在书面授权、网络隔离的实验室中，不涉及真实目标，也不提供完整利用链。

Metasploit 是什么

Metasploit 是 Rapid7 维护的漏洞利用框架，2003 年以开源项目出现，2019 年 1 月发布 5.0，本文写作时主流版本是 5.x。它把漏洞利用中反复出现的环节抽象成模块：影响哪些版本、需要哪些参数、发送什么数据、成功后执行什么代码，都写在模块描述里。

价值在组织方式，而不是“内置了多少漏洞”。模块库把漏洞信息、验证逻辑和利用代码放在一处，检索、比对、记录复用同一套流程；数据库把主机、服务、结果串起来，实验结束可导出复盘。社区版免费，提供控制台、模块库和数据库；商业版增加界面与支持，本文只用社区版。

模块多不等于效果好。同一漏洞可能有多个模块，质量参差；更新往往滞后于补丁；排名只表示可靠性，不表示危害。把框架当成“点一下就入侵”，是最常见的误解。

实验室准备：隔离、靶机与授权

Metasploit 的第一课不是命令，而是边界。练习应放在与办公网、生产网隔离的实验环境中：建仅主机网络，网段用 192.168.56.0/24，攻击机 Kali 取 192.168.56.10，靶机取 192.168.56.20；实验网不配默认路由，宿主防火墙禁止其访问公网和内网资产。更新工具时临时挂 NAT 网卡，用完立即断开。

靶机可选 Metasploitable 2、Metasploitable 3 或未打补丁的 Windows 7 虚拟机。装完先打快照，命名为“日期-用途-状态”，并记录基线：Metasploit 版本、Nmap 版本、镜像校验和、网络拓扑。实验结束回滚快照，避免残留状态影响判断。

授权不能省。内部实验由资产负责人签字，写明范围、时间窗口、允许的测试类型、禁止事项和应急联系人；个人实验至少写清目标仅限自己的虚拟机。不要用公网地址，不要桥接，也不要在别人的机器上“顺手试一下”。没有授权的测试，性质上就是入侵。

msfconsole 的常用操作

启动用 msfconsole -q，-q 省略横幅，提示符显示上下文，例如 msf5 >。help 列命令，version 看版本，db_status 查数据库。控制台支持 Tab 补全。

search 最常用，关键字可以是漏洞名、CVE 编号、平台或类型，例如 search type:auxiliary platform:windows smb。Rank 表示模块可靠性，从 excellent 到 low，不是漏洞危害等级。选中模块用 use，看说明用 info，看参数用 show options，看载荷用 show payloads，返回用 back。

实验前先建工作区：workspace -a lab-20200116，workspace 列出，workspace lab-20200116 切换。不同实验分开，结果不会互相污染。

模块类型与各自职责

Metasploit 把模块分为六类，理解分类比背模块名重要。

类型 职责 本文的处理
exploit 利用某个漏洞，并把载荷送达目标 只到 check
auxiliary 扫描、识别、验证、登录测试等辅助动作 只讲扫描与识别
post 获得会话后的信息收集与处置 不展开
payload 漏洞触发后执行的代码 只讲概念
encoder 对载荷字节做变换 不展开
nop 生成空操作指令，用于对齐 不展开

exploit 描述“如何触发漏洞”，auxiliary 描述“如何观察目标”，post 只在拿到会话后才有意义。payload 是触发后执行的代码，encoder 与 nop 服务于载荷生成。模块类型只是元数据，不代表可以随意使用；show payloads 列出兼容载荷，不是推荐清单；show targets 列出目标类型，选错往往失败。

一次以 check 结束的验证

check 是部分 exploit 模块提供的探测命令：按内置逻辑发送少量请求，判断是否可能存在对应漏洞，但不发送真正的利用代码。并非所有模块都实现 check，结论也可能是“无法确定”，它只是线索。

假设靶场有一台未装 MS17-010 的 Windows 7 SP1，地址 192.168.56.20。流程是搜索、看说明、设目标、检查、记录。

到这一步就停，不要输入 exploit 或 run。本文刻意不给后续步骤：check 只说明“可能”，真正的利用涉及载荷选择与会话管理，属于另一层风险，应在有人指导的实验课里进行。把“能检查”与“会利用”分开，是学习框架时最重要的自律。

check 也有副作用。检测请求会被目标记录，脆弱服务可能因探测崩溃；实验前打快照，实验中观察靶机状态。若返回“cannot reliably check exploitability”，不要当成安全，也不要反复重试，应改用厂商公告、补丁级别和配置基线交叉确认。记录模块全名、参数、时间和原始输出，这些就是证据。

auxiliary 扫描：用途与噪声

auxiliary 的 scanner 子目录最常用。端口扫描用 auxiliary/scanner/portscan/tcp，服务识别用 smb_version、http_version 等模块。它们补齐信息：开了哪些端口、跑什么服务、版本多少，为 check 或人工验证提供输入，结果自动进入当前工作区的 services 表。

扫描有噪声。全连接扫描会在目标上留下大量建立与断开记录，服务日志、防火墙日志、IDS 告警都会出现；线程越高，噪声越集中，也越容易拖垮脆弱服务。授权范围内也要控制节奏：先小范围、低线程，再逐步扩大；避开业务高峰；提前告知蓝队，把源地址加入观察名单，而不是加白名单绕过检测。时间窗、速率和并发数都要写进记录。

这里的 run 只针对实验网内的靶机。范围必须与授权清单一致，不能因为“顺便看看”就扩大到相邻网段；发现清单外的主机，应停止并报告。

payload 的两个维度

payload 是漏洞触发后真正执行的代码。按连接方向分，bind 让目标监听端口、攻击端主动连接；reverse 让目标回连攻击端。前者易被入站策略挡住，后者要求攻击端可达。按投递方式分，staged 先送一个很小的 stager，再由它下载完整 stage；stageless 一次送完，体积更大但少一次交互。命名可见差别：windows/x64/meterpreter/reverse_tcp 是 staged，windows/x64/meterpreter_reverse_tcp 是 stageless。

这些概念对防守方同样重要。回连对应异常外联，staged 对应短时间二次下载，stageless 对应单包或单文件偏大。

本文不提供 payload 配置，也不演示生成、编码与监听。载荷最容易被误用；脱离靶场的参数复制到真实环境就是攻击；编码器常被误认为绕过检测的手段，而本文不讨论规避检测。理解概念、看懂日志里的异常外联，比会敲几条命令更有价值。

数据库与结果管理

社区版默认用 PostgreSQL 保存主机、服务、漏洞与操作记录。首次使用执行 msfdb init，db_status 确认连接；数据库没起来时控制台仍可用，但 hosts、services 等命令会失效。工作区隔离实验，hosts 看主机，services 看服务，vulns 看漏洞；Nmap 的 XML 可用 db_import 导入，结束用 db_export -f xml 导出。

数据库是索引，不是报告。每条记录都要能追溯到原始输出：命令、时间、目标、参数、返回文本。check 结果、扫描端口、人工结论要分别标注来源，避免把推断当成事实。工作区可保留也可清理；保留时在名称里写日期与用途。

与 Nmap、Burp 的配合

三类工具的分工是：Nmap 找“哪里有门”，auxiliary 判断“门后是什么、是否可能虚掩”，Burp 分析“门里的业务逻辑”。Nmap 7.8 做主机与端口、版本识别，输出 XML；导入后，用 auxiliary 对关键服务精确识别与 check；Web 业务交给 Burp 逐请求分析。

工具之间不重复扫描。Nmap 扫过的端口段，不要再让 Metasploit 全量扫一遍；已确认版本的服务，Burp 不必再做指纹。重复扫描浪费时间，也放大噪声。

flowchart LR
  A[确定授权范围] --> B[Nmap 发现主机与服务]
  B --> C[导入工作区]
  C --> D[auxiliary 精确识别]
  D --> E[check 判断可能性]
  E --> F[Burp 人工验证业务]
  F --> G[记录证据与结论]

每个环节记录时间与源地址；扫描只是线索，人工复现或 check 才是证据，两者都不能替代对“可利用性”的判断。

防守视角：从日志看利用行为

框架行为在日志里有迹可循。扫描阶段，防火墙与 IDS 会看到短时间内的多端口连接，服务日志出现大量握手失败；check 阶段，SMB、HTTP 日志出现探测特征；利用阶段，主机侧可能出现异常子进程、服务崩溃或账户变化，网络中可能出现周期性外联。防守方抓住“扫描—探测—利用—回连”这条链，比堆规则有效。

补丁验证可以借助框架，但要理解局限。check 通过只说明探测逻辑没发现漏洞特征，不等于系统安全；补丁可能被回滚，配置可能重新放开，模块也可能误判。稳妥做法是以厂商公告和补丁编号为准，用 check 辅助复核，再结合配置基线、暴露面和回归测试。验证前后各记一次结果，才能说明补丁生效。

蜜罐是低成本补充。低交互蜜罐放在实验网或 DMZ 边缘，记录源地址、时间和请求特征，既能发现扫描，也能为溯源提供线索；蜜罐要与其他系统隔离，不要直接暴露公网。记住：检测到不等于可利用，可利用不等于已失陷。

实验报告怎么写

报告结构为：范围与授权、时间窗口、环境与版本、方法与工具、发现、证据、风险等级、修复建议、复测结论。范围写清地址、端口与排除项；时间精确到分钟；环境写清攻击机、靶机、网络模式与快照名；方法写清模块与命令。

发现与证据分开。发现是结论，证据是原始材料：命令、输出、截图、日志片段、时间戳、源与目标地址。风险等级不能只按扫描器分数，要结合暴露面、利用条件与业务影响；同一漏洞在实验网和公网的风险不同。修复建议要可执行，写明补丁编号、配置项和验证方法。

报告分发也有边界。未修复的细节不应公开，也不要在群里贴完整过程；通过约定的加密渠道提交给资产方，保留访问记录，按约定时间复测。复测只验证修复，不重复利用。截图要打码，去掉账号与业务数据。

合规与伦理

授权是底线，不是形式。《网络安全法》要求对非自有系统测试必须取得同意；等保 2.0 系列标准于 2019 年 12 月实施，渗透测试作为合规检查的一环，同样强调授权与范围。测试窗口、禁止事项、数据处理方式和披露流程，都要在开始前确认并留下书面记录。

发现漏洞后，先通知资产方或厂商，给出复现条件与修复建议，按约定时间表披露；未经同意不公开细节，不写入博客，不用于竞赛或简历。数据保护同样重要：只取证明问题所需的最少数据，不下载业务数据，不复制个人信息，不保留凭据；结束删除临时文件，报告脱敏。可能影响生产时立即停止并报告，不要抱着“再试一下”的心态继续。

伦理不是报告末尾的套话，而是每次敲命令前的判断。

常见误区

把框架当“一键入侵”。模块只管一段逻辑，目标版本、补丁、网络和防护都会影响结果，跑不通才是常态。

在公网练手。公网地址不属于实验范围，扫描和探测可能触犯法律。

扫描噪声过大。高线程、全端口、反复重试会拖垮服务，也淹没真正的告警；授权范围内也要限速、限时、限范围。

不留证据。只记得“好像有问题”，没有命令、时间和原始输出，结论无法复核。

把“检测到”当成“可利用”。check 和扫描器都有误报，版本匹配也不代表能利用。

把“会用工具”当成“懂安全”。工具解决操作问题，判断依赖对原理、配置和业务的理解。

忽视版本与时效。模块随漏洞披露更新，照抄旧文章可能找不到模块；本文以 5.x 为准，其他版本先看 info。

小结

Metasploit 是一套把漏洞知识组织成模块的框架。学习顺序是边界、环境、命令、模块、验证、记录，而不是直接找一条 exploit 命令。本文只走到 check：在隔离实验室里确认“可能存在问题”，再把结果写进可追溯的记录。真正有价值的能力，是知道何时该停、如何验证补丁、如何从日志识别行为，以及如何把发现交给资产方修复。
