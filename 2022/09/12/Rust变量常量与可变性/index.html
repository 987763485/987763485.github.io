Rust 变量、常量与可变性

本文属于《Rust 学习路线》第 3/68 篇
上一篇系列目录下一篇

Rust 的变量声明看上去和别的语言差不多，写起来却很快撞上编译器的红线：改一个值要先加 mut，同名变量却能重复声明，常量与静态量又各有各的限制。本文从 let 绑定讲起，说明 mut 的真实含义、重新赋值与遮蔽的区别，再讨论 const、static 与 'static 生命周期，最后落到作用域、解构与类型推断这些日常写法。读完之后，应当能判断一段代码该用哪种声明，也能看懂 E0384、E0308 这类报错背后的规则。示例基于 Rust 1.63 与 2021 edition。

默认不可变：let 的第一条规则

在 Rust 里，用 let 引入一个绑定，默认就是不可变的。这里的“不可变”指的是绑定建立之后，不能再通过赋值去修改它承载的值：第一次初始化是允许的，第二次赋值会被编译器直接拒绝。

把这段代码交给 cargo build，编译器会报出 E0384，并附带一句提示，建议把绑定改成可变。错误码 E0384 专指对不可变绑定重复赋值，多数人学 Rust 遇到的第一个编译错误就是它。把 let x = 5 改成 let mut x = 5，代码就能通过，x 也就可以被重新赋值。

把不可变设为默认，是一个刻意的设计选择。第一，读代码的人看到 let 就知道这个值后面不会变，不必在整段函数里追踪它的每一次修改，局部推理的负担小得多。第二，共享不可变数据天然是线程安全的，编译器的借用检查正是建立在“默认只读”这一前提上。第三，当确实需要修改时，mut 这个关键字本身就是一种声明，提醒审查者这里存在状态变化，值得多看一眼。

还要注意，不可变绑定不等于常量。let x = read_input(); 里的值来自运行时，每次执行都可能不同，只是绑定之后不允许再改。它和编译期就确定下来的 const 是两回事，后者留到后面讨论。

编译器给出 E0308，指出期望的是整数，实际得到的却是字符串切片。原因在于，mut 修饰的是绑定，而不是类型。一个绑定的类型在初始化时就已经确定，是否可变与此无关：不可变绑定不能重新赋值，可变绑定可以重新赋值，但两者都不能在运行过程中改变类型。想在同一个名字下换一种类型，要用的是遮蔽，而不是 mut。

类型可以显式标注，也可以交给编译器推断。Rust 是静态类型语言，推断只发生在编译期，不会带来运行时开销。整数默认推断为 i32，浮点数默认推断为 f64；当上下文不足以确定类型时，就必须标注，否则编译器会报 E0282。

mut 还可以只作用于解构出来的一部分。let (mut a, b) = (1, 2); 中只有 a 可变，b 仍然不可变。这种写法在同时处理“需要累加的计数”和“只读的配置”时很自然，也比把整个元组声明为可变更精确。顺带一提，函数参数前也可以写 mut，例如 fn normalize(mut s: String)，它只让函数内部的这个绑定可变，对调用方没有任何影响。

重新赋值与遮蔽不是一回事

遮蔽（shadowing）是 Rust 里很容易被低估的写法：用同一个名字再一次 let，新绑定会遮住旧绑定，从此这个名字指向新值。

重新赋值与遮蔽的差别，可以归纳为几点。重新赋值要求绑定带 mut，不创建新绑定，不能改变类型，旧值被原地覆盖。遮蔽不要求 mut，每次都创建新绑定，可以改变类型，旧绑定并没有被销毁。对于实现了 Drop 的类型，被遮蔽的旧值不会在遮蔽处立刻释放，而是一直活到作用域结束，再按声明的逆序析构。这一点在持有文件句柄或锁的时候尤其值得留意。

遮蔽的常见用途是“同名转换”：先拿到原始输入，再把它解析成目标类型，名字保持不变，读起来连贯。它也有边界：遮蔽不能跨函数，也不能靠内层遮蔽去修改外层绑定，内层的 let n = ... 只是另一个名字而已。

const：编译期就能算出来的值

const 用来定义编译期常量。它和 let 最直接的区别是：右侧必须是一个能在编译期求值的常量表达式，而且类型必须显式标注，编译器不会替它推断。

常量不是变量，也没有固定的内存地址。编译器在每一个使用处把值内联进去，因此读取常量没有间接寻址的开销，也不会出现“常量被修改”这种事。它适合放那些真正稳定的东西：数组长度、缓冲区大小、协议里的固定字段、需要参与模式匹配的字面值。常量可以写在模块顶层，也可以写在函数内部，后者的可见范围仅限于这个块；模块内的常量默认私有，跨模块使用时需要加 pub。在 impl 块里还能定义关联常量，通过类型名访问，适合给某个类型绑定固定参数。

static、static mut 与 ‘static 生命周期

static 定义的是全局变量：程序运行期间只有一个实例，并且有固定的内存地址。它的初始化同样要求常量表达式，不可变 static 的类型还必须满足 Sync，否则无法被多个线程安全地共享。

不可变的 static 读取时不需要 unsafe，上面的 APP_NAME 就是普通全局常量。真正危险的是 static mut：读和写都必须放进 unsafe 块，因为编译器无法验证是否同时有别的线程在访问它。即使当前程序是单线程的，这条规则也不会放宽。

这类代码能跑，但把“是否存在数据竞争”的证明责任交给了程序员。更稳妥的做法是用原子类型表达计数，用 Mutex 保护复合状态；如果全局值需要在运行时初始化，可以借助 once_cell 的 Lazy 或 lazy_static 宏，把 unsafe 封在库内部。命名规范与常量一致，都是全大写加下划线；static 即便写在函数体内，也仍然是全局唯一实例。

另一个高频混淆点是 'static 生命周期。&'static str 表示这个引用在整个程序运行期间都有效，字符串字面量天然满足；T: 'static 约束则表示类型内部不包含短生命周期的借用，并不等于“值永远不会释放”。一个 Box<T> 只要 T 同时满足 'static 与 Send，就可以跨线程传递，但它在离开作用域时照样会被回收。把 'static 理解成“引用的有效期足够长”，而不是“内存泄漏”，可以少走很多弯路。

作用域与生命周期入门

绑定的作用域从声明处开始，到它所在的那对花括号结束。花括号既可以单独划出一个块，也可以作为函数体、循环体或条件分支的主体；块本身还是表达式，最后一个表达式的值就是块的值。内层块可以读取外层绑定，反过来则不行。

变量在离开作用域时自动析构，顺序与声明顺序相反：先声明的后释放。这条规则在同时持有多个资源时很重要，比如先声明锁、后声明文件句柄，析构时文件先关闭、锁后释放，与获取顺序正好相反。函数参数的作用域是函数体，循环变量和 if let 引入的绑定则限于对应的块，出了块就不可见。

生命周期描述的是引用有效的那段时间。编译器要求任何引用都不能比它指向的值活得更久，这就是借用检查最核心的一条约束。多数时候生命周期由编译器推断，不需要写出来；只有当函数签名里出现多个引用、编译器无法判断返回值借用了谁时，才需要显式标注，这部分留到借用检查一篇展开。

这里的 s 在内部块结束时就被释放，而 r 还要在块外使用，编译器因此拒绝。修法有两种：把 r 的声明和使用都移进内层块，或者让 s 活到与 r 相同的范围。生命周期标注本身不会延长任何值的寿命，它只是把“引用之间谁活得更久”这层关系写给编译器看。

解构绑定与常见误解

let 左边不一定是单个名字，也可以是一个模式。只要模式能匹配，就可以从元组、结构体里一次取出多个值，这种写法叫解构绑定。

模式里可以用 _ 忽略单个位置，用 .. 忽略剩余部分；mut 也能只加在某个子绑定上，例如 let (mut a, b) = pair;。嵌套的元组或结构体可以一层层拆开，这在函数返回多个值时很常见。

需要提醒的是，let 只接受一定匹配的模式。let Some(v) = maybe; 无法编译，因为 maybe 可能是 None，模式并不保证成立，编译器会报 E0005。这类可能失败的解构要交给 if let 或 match，它们属于控制流与模式匹配的范畴，本文不展开。

最后集中澄清几个最常见的误解。

  • let x = 5; x = 6; 会报 E0384。Rust 的变量默认不可变，要重新赋值必须写成 let mut x。
  • mut 不表示“类型可变”。let mut x = 5; x = "six"; 仍然报 E0308，换类型只能靠遮蔽。
  • mut x 与 &mut 是两回事。let x = &mut y; 中 x 本身不必可变，也能通过引用修改 y；let mut x = &y; 中 x 可以改指向，却不能借它修改 y。引用与借用规则留给下一篇。
  • 常量不能靠运行时函数算出来。需要运行时初始化的全局值，应当用 static 配合 once_cell，或者在第一次使用时通过函数返回。
  • 遮蔽不是赋值。它不要求 mut，可以改变类型，旧绑定也不会在遮蔽处立即释放。
  • 'static 不等于“永不释放”，它约束的是引用的有效期，而不是值的回收时机。

至于版本，2021 edition 从 Rust 1.56 起可用，并成为 cargo new 的默认选择；1.60 前后的工具链在 let、mut、const、static 的语义上没有变化。edition 影响的是闭包捕获粒度、数组迭代等细节，不会把默认不可变改成默认可变，也不会让常量获得运行时求值的能力。

小结

本文围绕绑定、常量与可变性梳理了 Rust 声明语句的基本规则。let 默认不可变，需要修改时用 mut，但 mut 修饰的是绑定而非类型，类型在初始化时就已固定。遮蔽会创建新绑定，因此可以改变类型，也不会立即释放旧值，这与重新赋值有本质区别。const 在编译期求值、没有固定地址，static 有固定地址且全程序唯一，可变静态量必须用 unsafe 访问，实践中应优先选择原子类型或 once_cell。'static 描述的是引用有效期，不是内存永不回收。日常写代码时，先默认 let，确有状态变化再加 mut，需要跨作用域共享的常量才考虑 const 与 static，作用域和生命周期的直觉会成为后续理解所有权与借用检查的基础。
