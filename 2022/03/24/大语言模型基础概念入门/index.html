大语言模型基础概念入门

“大语言模型”这个词在过去两年里出现得越来越频繁，但围绕它的讨论常常从参数量直接跳到效果，中间的概念被略过了。本文面向有 Python 基础、想弄明白这套技术到底怎么运转的开发者，沿着“文本如何变成数字、模型如何被训练、生成时如何选词”这条线索，梳理一份概念地图。读完之后，你应该能看懂一份模型配置里的常见字段，知道哪些参数该调、哪些宣传话术该打折扣，也能判断一个任务是否适合交给语言模型。

从 token 说起：模型眼里的文本

语言模型不直接处理字符串。输入的第一站是 tokenizer，它把一段文本切成若干片段，每个片段叫一个 token，再查表把 token 换成整数 ID。模型自始至终只看见 ID 序列，输出也是 ID 序列，最后由 tokenizer 反向解码成文字。

切分粒度介于字符与单词之间，通常称为子词（subword）。英文里常见的是字节对编码（Byte Pair Encoding，BPE）一类的做法：从字符或字节出发，反复合并语料中出现频率最高的相邻片段，得到一个大小可控的词表；WordPiece 与 SentencePiece 是同一思路的不同实现。中文没有空格分隔，一个汉字可能独立成 token，也可能与相邻汉字合并，具体取决于训练语料与词表构造方式。数字被拆成几段、空格是否附着在前一个词上，都会影响 token 数。

这件事有两个实际后果。其一，token 不等于字，也不等于词，同样的内容用不同模型分词，长度可能相差不少；上下文窗口、计费、生成长度限制，计的都是 token。其二，词表大小是一个超参数，常见量级在数万；词表越大，嵌入矩阵（词表大小乘以隐藏维度）占的参数量越多，但序列会更短。分词器一旦随模型训练确定，推理时就必须沿用同一个，换 tokenizer 等于换了一套输入语言。

所谓上下文长度，指模型一次前向能接收的 token 上限。超出上限的内容只能截断、分块，或者用检索之类的外部手段补进来。窗口变大并不等于模型会均匀利用每个位置，长文档中段的信息被忽略是常见现象。

架构直觉：编码器、解码器与三种用法

今天的大语言模型几乎都建立在 Transformer 之上。它的内部结构值得单独拆解，这里只保留一个够用的直觉：模型由若干层堆叠而成，每层的核心是自注意力，序列中的每个位置都可以“看”其他位置，并按相关程度把信息聚合过来，再接一个前馈网络做逐位置变换。所谓“大”，主要指层数、隐藏维度与注意力头数都堆得很多。

按注意力的可见范围，常见三种形态。只保留编码器的模型（以 BERT 为代表）使用双向注意力，每个位置都能看到左右两侧，擅长理解类任务，例如文本分类、实体识别、句子相似度。只保留解码器的模型（GPT 系列）使用因果掩码，每个位置只能看到自己和左边，训练目标就是预测下一个 token，天然适合生成。编码器加解码器的模型（T5、BART）先用编码器读完输入，再让解码器通过交叉注意力参考编码结果，适合翻译、摘要这类从一段文本到另一段文本的转换。

形态决定了推理方式。解码器生成是自回归的：一次前向只在最后一个位置给出一个概率分布，选出一个 token 接到输入末尾，再跑下一次前向。生成长度为 n 的文本，就要串行执行 n 次前向，这是延迟的主要来源。训练时却可以并行，因为整段文本已知，每个位置的监督信号能一次算完。训练与推理的这种不对称，是很多工程优化（例如缓存已计算的键值、把请求攒成批）的出发点。

三个阶段：预训练、微调与对齐

一个可用的模型通常不是一次训练出来的，而是三段流程的产物。

预训练是成本最高的一段。它使用海量无标注文本，靠自监督目标学习语言规律。解码器模型用因果语言建模：给定前文，预测下一个 token，损失是正确 token 的负对数似然，序列里每个位置都提供监督信号。编码器模型用掩码语言建模：随机遮住一部分 token，让模型依据上下文还原，经典设定是遮住 15%。T5 则把连续片段整体遮掉，让解码器生成被遮的内容。语料来自网页、书籍、代码与百科，清洗、去重与质量过滤的影响往往不亚于模型结构。

微调是在预训练权重上，用带标签的任务数据继续训练。分类任务通常在模型输出上接一个线性层，用较小的学习率更新全部参数。得益于预训练打下的表示，几百到几千条样本即可得到不错效果。代价是数据分布一旦太窄，模型会向任务过拟合，通用语言能力出现退化，通常称为灾难性遗忘。

指令微调把“任务”改写成自然语言指令与期望回答的配对，再把大量不同任务混在一起训练。它的目的不是教会模型新知识，而是让它学会“按要求的格式做事”，从而对没见过的指令也有一定的零样本表现。FLAN 与 2022 年 1 月公开的 InstructGPT 都沿这条路线做过系统实验。

RLHF（基于人类反馈的强化学习）在此之上再加一步。先监督微调出一个初始策略，再让标注者对同一提示的多个回答排序，用这些比较数据训练奖励模型，最后用强化学习算法（常用 PPO）优化策略，使其获得更高的奖励，同时用 KL 惩罚约束它不要偏离初始模型太远。需要强调的是，奖励模型学的是人类偏好，不是事实正确性；策略会钻空子，产出“讨喜但空洞”的内容，这类现象称为奖励黑客。

    B --> C[基础模型]
    C --> D[监督微调：任务标注数据]
    D --> E[指令微调：指令与回答配对]

缩放规律与“涌现”：经验，而非定律

2020 年前后的几项工作给出了一个颇受欢迎的结论：其他条件大致固定时，随着参数量、数据量与计算量增加，模型在下一个 token 上的损失按幂律下降，小模型上拟合的曲线能在一定范围内外推。这让“先训小的、再按比例放大”成为可操作的预算规划方法。

但把它当成定律就会出错。幂律的指数与系数依赖数据分布、模型形状与优化设置，跨数量级外推时误差会放大；参数并不是越多越好，固定算力下参数量与数据量需要平衡，数据相对不足时，过大的模型反而学不充分。这些结论并不完全一致，宜把缩放规律看作粗略趋势，而非精确预测器。

“涌现能力”也容易被过度解读。观察到的现象是：某些任务上，小模型长期接近随机猜测，规模跨过某个区间后明显上升，曲线看似阶跃。批评意见指出，这种“突然出现”很大程度上取决于度量方式：换用部分得分而非精确匹配，或者换一套提示格式，曲线就会变得平缓；所谓阈值也会随评测集漂移。比较稳妥的态度是：承认规模带来能力质变的经验观察，但不把某个具体参数量当作能力门槛，更不要用单一榜单替代真实任务的验证。

解码策略：模型如何选出下一个词

模型在每个位置输出的是词表上的原始分数（logits），经 softmax 变成概率分布，解码策略决定从这个分布里怎么取词。这一步对观感的影响，常常比换一个稍大的模型还明显。

最直接的是贪心解码：每次取概率最大的 token。它确定、可复现、速度快，但容易陷入重复，生成的文本也偏保守。束搜索同时保留若干条候选序列，每步按累计对数概率扩展并剪枝，最后选总分最高的一条。它在翻译、摘要这类目标明确的任务上表现稳定，用于开放式写作时则容易产出四平八稳、缺乏变化的句子。

随机采样把多样性找回来。温度（temperature）是一个缩放系数：把 logits 除以 T 再做 softmax。T 小于 1 时分布更尖锐，输出更保守；T 趋近 0 就退化为贪心；T 大于 1 时分布更平坦，冷门词有机会被选中，但更容易跑题甚至语无伦次。常用的折中做法是先截断再采样：top-k 只在概率最高的 k 个 token 里抽；top-p（核采样）则取累积概率刚好达到 p 的最小集合，集合大小随分布形状自适应，通常比固定 k 更稳。两者可以叠加使用，先按 top-k 与 top-p 过滤，再在剩余候选上重新归一化。

除此之外，重复惩罚会压低已出现 token 的分数，禁止重复的 n 元组能阻止整句复读，最大生成长度与停止词负责收尾。这些参数没有普适最优值，需要针对任务试出来。

提示工程的基本手法

在不改变权重的前提下，提示是影响输出最直接的手段，它的本质是精心构造上下文。几条通用做法：把任务、输入与期望的输出格式写清楚，最好给出一个字段模板；用分隔符把待处理的材料与指令隔开，避免模型把数据当成命令；给两三个示例（few-shot），示例要覆盖边界情况而不只是典型情况；对需要推理的任务，要求先列步骤再给结论，通常比直接要答案更稳；明确长度、语气与“不知道时怎么说”。

需要克制的地方同样明显。角色设定（“你是一位资深工程师”）对风格有帮助，但不会凭空带来事实准确性；提示对模型版本、分词细节甚至示例顺序都敏感，今天有效的模板换个模型可能失效，因此值得把提示纳入版本管理，并配固定样例做回归。提示工程不是编程，它没有编译器保证，只有反复试验与失败样例的归纳。

能力边界：幻觉、知识截止与成本

最需要建立预期的是幻觉。模型优化的是下一个 token 的似然，而不是事实的正确性；流畅、自信的表述与真实性之间没有必然联系。缓解手段包括：允许模型回答“不确定”，要求它引用给定材料，对关键结论做外部检索或规则校验，并把生成结果当作草稿。涉及金额、法条、医疗建议等高风险场景，必须有人工复核环节。

知识截止是另一个硬约束。权重在训练结束后就冻结了，模型不知道此后的新事件，也不知道你公司昨天改的接口。靠提示无法写入新知识，可行的路径只有重新微调，或者在推理时把最新资料放进上下文。后者受上下文长度限制，也因此衍生出检索增强一类的工程做法。

最后是成本与延迟。自回归生成要逐 token 串行前向，输出越长越慢；输入越长，注意力的开销越大。线上服务通常用批处理提高吞吐，用缓存复用重复的前缀，但批处理会增加排队时间，吞吐与延迟需要权衡。容量规划看 P95 而不是平均值，并且要把失败重试与超时算进去。

小结

大语言模型的工作链条可以概括为：tokenizer 把文本变成 ID，Transformer 在预训练中学会预测，微调与对齐把通用能力收束到具体任务与人类偏好上，解码策略决定最终文字的样貌。缩放规律与涌现能力是有价值的经验观察，但不是可以外推的定律；幻觉与知识截止是结构性限制，不能指望靠提示根治。实践建议是：先用小模型跑通数据与评测，再决定是否放大；把提示、解码参数与评测集一起版本化；对高风险输出保留人工复核。
