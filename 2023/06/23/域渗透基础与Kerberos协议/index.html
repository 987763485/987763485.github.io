域渗透基础与 Kerberos 协议

导读：本文面向从事内网安全建设、等级保护测评与系统运维的读者，聚焦 Active Directory 域环境与 Kerberos 认证协议的原理与防御。我们全程只讨论协议如何工作、域结构如何划分信任边界、常见配置缺陷为何危险，以及如何在授权范围内发现并加固它们；不涉及任何票据窃取、横向移动或凭据导出的操作步骤。

域的本质与信任边界

Active Directory 域是 Windows 网络里身份与策略的核心容器，也是安全边界的起点。它把用户账户、计算机账户、组与目录对象集中存放在域控制器的数据库里，域控制器同时承担 DNS 解析与密钥分发中心（KDC）两项职责。多个域可组成一棵树，若干棵树再汇聚成林（forest），林共享统一的架构目录分区，林内根域之间默认建立双向且可传递的信任。

信任关系决定认证能否跨越域边界。可传递信任让信任沿链条延伸，甲信任乙、乙信任丙时甲与丙也能间接互认；不可传递的外部信任把延伸手动切断，常用于与合作方隔离。单向信任只允许一个域的用户被另一个域验证。域内认证一旦跨越信任边界，其效力完全依赖被信任那一侧的完整性：只要某个受信任域密钥管理松散，边界就成了薄弱入口。

KDC 是域内认证的中枢，对外表现为两个逻辑服务：认证服务（AS）与票据授予服务（TGS）。二者的权威身份都由一个叫 krbtgt 的账户代表，其长期密钥用来签发和校验票据授予票据。可以说 krbtgt 口令的强度与保密性，直接等同于整个域认证体系的信任根基；一旦它泄露或被弱口令拖累，所有票据的校验都将失去意义。

需要提醒的是，KDC 并不校验业务权限，它只回答”你是不是你所声称的身份”，授权由服务端与访问控制列表完成；把认证与授权分清，是理解后文过度授权风险的钥匙。

Kerberos 协议流程

Kerberos 的规范来自 RFC 4120，目标是让双方在不依赖明文口令的前提下相互证明身份，并为会话协商出共享密钥。整个过程可拆成三段：认证服务交换、票据授予服务交换，以及把服务票据呈交给目标服务。这里只描述消息语义与加密结构，不涉及构造或重放的实现细节。

在认证服务（AS）交换阶段，客户端向认证服务发起请求，带上自己的身份、所在域与所要申请的 krbtgt 服务标识。认证服务核对目录信息后返回一个票据授予票据（TGT）。TGT 用 krbtgt 的长期密钥加密，客户端既无法拆开也无法篡改；响应里附带一份会话密钥，它用由用户口令派生的密钥加密，只有知道口令的客户端才能解开。现代实现要求客户端用该会话密钥生成带时间戳的认证器来证明自己是票据持有者，这就是预认证。

票据授予（TGS）交换阶段，客户端不再提交口令，而是把先前拿到的 TGT 连同一个新的认证器提交给票据授予服务，并指明目标服务的 SPN。票据授予服务用 krbtgt 的密钥解开 TGT 验证其有效，再用其中的会话密钥校验认证器，随后签发一张服务票据（ST）。服务票据用目标服务账户的密钥加密，内含客户端与服务之间的会话密钥。

在服务票据的使用阶段，客户端把 ST 与一份新认证器交给目标服务；服务用自己的长期密钥解密 ST，取出会话密钥，再用它校验认证器与时间戳，从而确认对端身份并建立双向信任。可以看到，口令自始至终没有在网络上流动，加密摘要与时间戳承担了完整性与防重放的角色，票据有效期由生命周期参数约束。这套设计把安全责任压到密钥质量、算法选择与票据参数上，正是后文各节的落点。

    participant K as 密钥分发中心
    participant S as 目标服务
    C->>K: AS 请求，申请 krbtgt
    K-->>C: AS 响应，返回 TGT 与会话密钥
    C->>K: TGS 请求，携带 TGT 与目标 SPN
    K-->>C: TGS 响应，返回服务票据
    C->>S: 呈交服务票据与认证器
    S-->>C: 双向确认后进入业务

SPN 与服务账户

SPN（服务主体名称）把网络服务和它在目录中的 Kerberos 身份绑定，形如 serviceclass/host:port 的组合，注册在计算机账户或专用服务账户对象上。票据授予服务依据 SPN 找到对应账户、再用该账户密钥加密服务票据，因此 SPN 必须唯一且与实际服务、主机名与端口精确对应，重复或残缺的 SPN 会导致认证失败，或让票据落到错误密钥上。

服务账户是这些身份的载体，通常以某个口令长期运行一个网络进程，风险由此而来：任何已认证的域内主体，都能向票据授予服务请求某个带 SPN 账户的服务票据，而票据用该账户密钥加密。若账户口令偏弱或仍允许旧的弱加密算法，这张票据就成了可被离线检验口令强度的关卡，这正是 Kerberoasting 之所以成立的配置根源——问题不在协议，而在把服务账户当作普通账户、沿用人为设定的弱口令。加固方向：为服务账户使用长随机口令、优先用托管服务账户、只启用现代加密算法，并对大量 SPN 票据请求设置检测。

AS-REP roasting 同源，但触发条件不同：当某账户被关闭了”需要 Kerberos 预认证”这一选项时，风险来自预认证缺失而非 SPN。发现方式是盘点目录中被取消预认证标志的账户，加固方式是默认强制预认证、仅对确有兼容需要的遗留协议按需开放并记录审批。两类风险的共同教训是：认证选项与加密算法的每一次放松，都应在变更管理里留下明确理由与复查责任人。

委托与受限委托

委托解决的是”服务代替用户再访问后端”的问题：多层应用需要在用户登录后继续以该用户身份调用数据库或其他服务时，就要向下传递用户身份。无约束委托允许被标记的计算机接收并转发任意用户的票据，代价是该主机一旦失守，其缓存中任意用户的凭据都落入险境；协议转换又允许非 Kerberos 认证在接入 Kerberos 时换取票据，进一步放大信任面。

受限委托把这种传递收窄：管理员显式声明某个服务账户只能代表用户访问哪些目标 SPN，越界转发会被拒绝。基于资源的受限委托则把约束定义在目标资源一侧，由被访问对象声明谁可代表用户访问它，更适合跨域、多所有者的场景。防御上要把”受信任以进行委派”当作高价值配置：定期审计哪些账户被赋予无约束委托、评估其主机暴露面、能用受限委托就不用无约束委托，并避免让敏感账户所在主机与无约束委托节点重合。

GPO 里的关键安全选项

组策略（GPO）是把 Kerberos 参数落到全网的一致通道，几项关键设置决定票据体系的安全基线。最该盯紧的是加密类型策略：遗留的 ARCFOUR 强度有限，只要仍启用就为算法降级与弱密钥留口，应只保留现代 AES 组合。其次是各类票据生命周期参数，包括用户票据与服务票据的最大存续时间及续期上限，存续期越长，票据被不当持有后的可利用窗口也越大。再次是委派与协议转换开关，以及保护预认证与票据交换的复合票据、FAST（Kerberos Armor）等增强选项。计算机账户口令的自动更改若被禁用，会让机器账户密钥长期不轮换，也是隐性风险。

常见配置缺陷与加固

缺陷一是弱加密仍在生效，即策略允许 ARCFOUR 一类算法，使新签发的票据也能用弱密钥保护。发现时把域功能级别、GPO 加密策略与个别机器上的注册表覆盖放在一起核对；加固时收紧到现代算法、逐步淘汰依赖弱加密的遗留服务，并对无法立即整改者设定明确期限与责任人。

缺陷二是过期的票据参数，存续期与续期期被设成远超业务需要的值，或保留了不再使用的兼容开关。发现方式是比对当前策略与安全基线、识别偏离项；加固方式是把票据生命周期收敛到合理区间、让续期受更强约束，以缩短异常票据可用时间。

缺陷三是过度授权，包括过多账户被标记为可委派、服务账户权限超出运行所需、SPN 被注册在特权账户上。这类问题可在授权范围内用只读目录查询盘点，下面这段 PowerShell 仅读取账户属性、不涉及任何票据或凭据操作，可据输出评估风险：

缺陷四是共享的本地管理员口令，多机复用同一个口令会把单台主机的失守扩散为一组主机。它本身与 Kerberos 无关，却常与票据风险叠加放大后果；加固方式是引入随机化、集中托管的口令方案并按周期轮换，把本地管理员组变更纳入审计。

检测信号

检测的目标不是复现攻击，而是让异常的票据行为尽快暴露。值得关注的信号类型包括：短时间集中出现、针对大量 SPN 账户的服务票据申请，这与离线探测口令强度的形态吻合；缺少预认证的 AS 请求比例突增，提示预认证标志被改动；票据协商从现代算法回落到弱算法，提示降级尝试；来自异常来源或时间窗的高权限账户认证；以及委派属性、krbtgt 相关策略等目录配置出现未登记的变更。落地时应把上述信号结合 Kerberos 认证事件、目录服务变更与账户管理这几类日志做基线建模，先记录正常业务的票据请求分布，再对偏离基线的数量、目标集中度与来源做关联告警。本文只描述信号类型，不针对具体事件编号下结论，以自身平台文档为准。

授权演练的开展方式与报告口径

前述风险是否需要验证，取决于是否持有明确的书面授权。一次合规的域内评估应先划定范围与时间窗、约定禁止触碰的生产系统与数据、指定紧急联系人与中止条件，再在隔离环境或经批准的测试域里进行，不做进承载真实业务的域。报告口径同样关键：发现应以配置风险与暴露证据来表述，说明该缺陷为何危险、波及哪些资产、如何修复与复查，而不是提供可照做的利用步骤；风险定级结合可利用性、影响面与整改成本给出，整改后再以同口径复测确认。这样既满足验证需要，也把敏感操作关进授权边界，与等级保护的合规要求保持一致。

小结

域的本质是一圈由密钥与信任共同守住的边界，Kerberos 用票据把认证从口令明文里解放出来，却也把安全责任压到加密算法、票据参数、SPN 与服务账户、委派配置等细节上。弱加密、过长存续、过度授权与共享口令是反复出现的四类隐患；Kerberoasting 与 AS-REP roasting 提醒我们，危险往往来自被放松的配置而非协议本身。检测靠的是对票据请求与目录变更做基线与关联，演练靠的是授权、边界与不含利用细节的报告口径。把每一处算法与选项的放宽都写进变更管理并定期复查，才是让这圈边界长期稳固的根本。
