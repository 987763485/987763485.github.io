Rust 函数与控制流

本文属于《Rust 学习路线》第 4/68 篇
上一篇系列目录下一篇

函数与控制流是写任何程序都绕不开的两件事，Rust 在这两件事上各留了一个与 C 系语言不太一样的约定：函数体由一串表达式堆成，控制流结构本身也是表达式。如果按写 Java 或 C 的习惯去写，最先撞上的往往是“expected i32, found ()”这类报错。本文从 fn 的基本写法讲起，说明返回值与单元类型、尾表达式与分号的关系，再把 if、loop、while、for 和 match 逐个过一遍，最后落到一次把命令式代码改写成函数的小练习上。读完之后，你应该能看懂编译器关于类型不匹配、值已被移动的提示，并写出职责清楚的小函数。本文示例均在 Rust 1.66 与 2021 edition 下用 cargo run 验证过。

函数的基本形状

函数写在 main 之前还是之后都无所谓，Rust 没有 C 那样的前置声明要求，同一模块内的函数可以互相调用，递归也不例外。

这里有两处与脚本语言不同的地方。其一，参数类型不能省。let 绑定可以靠编译器推断类型，函数签名却必须写全，因为签名是调用方与实现方之间的契约，编译器不会跨函数去做推断。其二，返回值类型也不能省，除非函数不返回值。

不写返回值的函数，实际返回的是单元类型 ()，它只有一个值，也写作 ()。println! 这类只做副作用、不产出结果的函数就属于这一类：

语句与表达式：分号到底做了什么

Rust 把“表达式”和“语句”分得很清楚：表达式求值并产出一个值，语句执行动作但不产出值，其类型是 ()。let 绑定是语句，for、while、fn 声明也是语句。这解释了一个常被问到的问题：为什么 let x = (let y = 6); 编译不过？因为括号里需要一个值，而 let 不产出值。

顺带一提，return 也是表达式，类型是 !（never），它可以出现在任何需要值的位置。正因如此，return 才能写进某一分支而不破坏类型检查：这条路径永远不会正常结束，也就不必产出与其它分支相同的值。

这个特性带来两条约束，初学时几乎人人都会踩。第一，条件必须是 bool，Rust 不会把非零整数当成真，if 1 { } 会报类型错误 expected bool, found integer。第二，各分支的值必须是同一类型，因为编译器要在编译期为整个 if 定下一个类型：

缺少 else 时，if 整体相当于“可能什么都不做”，类型自然是 ()，不能拿来赋给一个整数。要当作表达式用，就必须把 else 补齐，让每条路径都产出同类型的值。块表达式本身也可以为空，{} 的值同样是 ()。

flowchart TD
    A[条件表达式] -->|true| B[then 分支求值]
    A -->|false| C[else 分支求值]
    B --> D[两值类型一致，整体成为一个值]
    C --> D

把 if 当表达式用，好处是变量一次初始化、之后不再改动，省掉了“先声明可变变量、再在分支里赋值”的样板代码。但分支一多，嵌套的 if 就会变得难读，这时更合适的是 match：它把一个值与一组模式逐一比较，写法是“模式 => 表达式”，分支之间用逗号分隔。

这里有三种最简单的模式形式。200 是字面量模式，只匹配这一个值；301 | 302 把多个模式并在一起，命中任意一个即可；code 是绑定模式，它匹配一切值，并把值交给分支里的变量使用。如果把 code 换成下划线 _，含义是“匹配一切但不绑定”，分支里就拿不到这个值了。

与 C 的 switch 相比，match 有两条硬规则。第一条是必须穷尽：编译器会检查所有可能的值是否都被覆盖，漏掉一种就报错 non-exhaustive patterns。整数和字符串的取值范围太大，实际上总要用绑定或 _ 兜底；枚举则要求列出每一个变体，这正是它比 switch 安全的地方。第二条是自上而下取第一个命中的分支，所以兜底分支必须放在最后，否则编译器会警告 unreachable pattern。

把逻辑拆成函数：可见性与文档

函数拆分的标准并不神秘：一个函数只做一件事，参数尽量少，结果通过返回值交出去，而不是顺手修改外部的可变状态。Rust 没有全局可变量这件便利工具，这条原则执行起来反而更自然。参数涨到五六个时，通常说明这些值本该收进一个结构体，或者这个函数承担了两件事，此时继续加参数不如先拆函数。

拆出来的函数放在同一模块里，默认就能被兄弟函数调用，不需要写任何修饰符。pub 管的是跨模块可见性：只有标了 pub，模块外的代码才能调用；pub(crate) 则把范围限定在当前 crate 内部。模块与路径的完整规则属于另一篇的主题，这里只需记住：pub 不是“导出到全局”，它只是在模块边界上开一扇门。

函数与所有权：传参是移动还是借用

这是 Rust 新手最容易卡住的地方：把 String 传给函数，所有权就一起交出去了。

String 的数据在堆上，赋值或传参时发生的是移动：指针交给新主人，旧绑定随即失效。好处是不会出现两个变量同时释放同一块内存，代价是调用之后原变量不能再用。shout 内部用 to_uppercase 造了一个新字符串返回，所有权又交回调用方，所以 t 可以直接使用。i32、bool、char、f64 以及元素全部实现了 Copy 的元组和数组不受影响，它们按位复制，传参后原变量照常可用。

小结

函数签名是调用方与实现方之间的契约：参数类型与返回类型都必须写全，不写返回值就等于返回 ()。函数体由表达式构成，最后一项不带分号就是返回值，多一个分号就会把类型从 T 变成 ()；需要中途退出时用 return。if、match、loop 都是表达式，前两者要求各分支类型一致，loop 可以用 break value 交回结果；while 与 for 的 break 不带值。传参默认是移动，只读传 &、要改传 &mut，这是绕开所有权报错的第一步。写代码时养成两个习惯：看到 expected T, found () 先查分号，看到 borrow of moved value 先查是不是在循环或函数调用里把值交了出去。涉及数值计算时，还要记得 cargo run 与 cargo run --release 的溢出行为不同，验证逻辑要两种构建都跑一遍。
