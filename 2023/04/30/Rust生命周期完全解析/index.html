Rust 生命周期完全解析

本文属于《Rust 学习路线》第 12/68 篇
上一篇系列目录下一篇

生命周期大概是 Rust 里最容易让人紧张的一套语法：它不参与内存管理，也不产生运行时代码，却在你返回引用、写泛型结构体时凭空多出一堆 'a。原因很简单——生命周期是借用检查器使用的表达语言，借用关系一旦写出来，约束就在那里，标注只是把编译器推不出来的那部分补全。本文面向已经熟悉所有权、移动与借用的读者，讲解生命周期参数与省略规则、结构体和 impl 块中的标注、'static 的真实含义、for<'a> 高阶边界与 trait 对象的默认生命周期，最后回答一个实践问题：什么时候别跟生命周期较劲，改用所有权或克隆。文中代码以 2023 年 4 月底的稳定工具链为准，写作时 1.69 刚发布，涉及的语法在 1.31 之后的版本里都已稳定。

生命周期是什么：引用的有效范围作为静态约束

先把三个概念摆正位置：所有权与移动语义回答“这个值由谁负责释放、何时释放”，借用检查回答“某一时刻能同时存在几个读者、几个写者”，这两件事在所有权与借用检查的专文里已经讲透；生命周期回答第三个问题——这个引用什么时候仍然有效，会不会活过它指向的数据。前两个问题关注时刻状态，第三个关注跨越时间的关系：一个引用创建时完全符合借用规则，可一旦被存进结构体字段、被函数返回，就可能在稍后被读取时指向已经析构的数据，这类问题只有生命周期能表述。

静态约束，而非运行时机制

第一件要说清楚的事：生命周期不改变任何值的真实存活时间。变量在哪里创建、在哪里析构，由作用域和所有权决定，标注 'a 不会让一个 String 多活一行代码。写进标注的是引用之间的比较关系，'x: 'y 读作“x 比 y 活得久”，也叫 outlives 关系。借用检查器在编译期推理这些“至少一样长”的关系，拒绝证明不出来的代码。编译通过后全部生命周期信息被擦除：类型里不多一个字段，生成代码里不多一次检查，运行期开销严格为零。后文所有“为什么报这个错”，都可以还原成“哪个 outlives 关系证明不出来”。

三者的关系可以总结成一张图：

flowchart TD
    A[所有权与移动语义决定值的创建与销毁] --> C[借用检查器推理]
    B[生命周期标注提供跨时间的约束] --> C
    C --> D[约束全部可证明:编译通过并擦除生命周期]
    C --> E[约束无法证明:报出编译错误]

什么时候才需要写标注

初学者容易以为每个引用都要带生命周期，实际上函数体内绝大多数借用不需要标注：区域推断结合“最后一次使用”的计算会自己定出范围。真正需要显式标注的场景非常集中——返回引用的函数签名、持有借用的结构体、涉及它们的 impl 与 trait 边界、要求“对任意生命周期都成立”的泛型场景。本文第 2 到第 6 节按这个顺序展开，第 7 节汇总离不开显式标注的典型报错，最后两节谈自引用的死胡同与改用所有权的判断标准。

函数签名中的生命周期参数与省略规则

第一个标注：longest

<'a> 声明一个生命周期参数，同时约束三处引用：传入 s1 的借用必须比 'a 久，s2 同理，返回值则最多只能用满 'a。要注意的是，'a 不是函数作者定的，而是每次调用时由调用方选定：编译器按两个实参的真实类型给 'a 选出交集，即两个输入生命周期中较短的那个。返回值在内层花括号内随便用，反过来，如果把 result 挪到内层块外面再使用，就会撞上 s2 已析构的错误。这不是标注“把返回值锁短”了，而是类型系统如实记录了“返回值有可能指向 s2”这个事实。

这样读下去，生命周期参数的全称语义就出来了：写 fn longest<'a>(...) 等于宣告“不论调用方选多长的 'a，只要两个入参都至少活到 'a，返回值就不超出 'a”。这与泛型类型参数由调用方实例化是同一个机制，生命周期参数可以看成对生命周期这个维度的泛型。

生命周期省略规则

编译器按三条机械规则给函数签名补全生命周期标注，补不出来才报错。规则按适用顺序是：

  1. 每个引用形式的参数各获得一个独立的生命周期参数；
  2. 如果恰好只有一个输入生命周期，那么它被赋给所有输出生命周期；
  3. 如果有多个输入生命周期，但其中一个是 &self 或 &mut self，那么 self 的生命周期被赋给所有输出生命周期。

第一条解释了为什么 longest(s1: &str, s2: &str) 会被看成两个匿名生命周期；第二条让 first_word 直接可用；第三条让 Vec 这类容器的方法返回借用时自动跟随容器，这也是平时写方法很少要手动标注的原因。规则之外还有个易被忽略的前提：函数没有任何输入借用、返回值却是引用时，省略规则帮不上忙，只能显式写成 'static 或改返回拥有所有权的类型。上一节的 dangling 正是这种情形。

还要强调：省略规则只适用于函数与方法签名，不适用于结构体定义，结构体哪怕只有一个借用字段也必须把生命周期参数写明，下一节展开。另外，'_ 可以在需要显式标注的位置替代手写名字，表示“这里确实有一个生命周期，交给推断决定”，日常代码里推荐优先用 '_，而不是复用其他参数的生命周期。

作为具体生命周期：整个程序运行期

作为 trait 约束：类型不依赖任何短期借用

'static 还有第二个身份，出现在泛型约束里：T: 'static。它说的不是“T 的每个值都要活到程序结束”，而是“T 的内部不引用任何比 'static 短的数据”。所有拥有所有权的类型——String、Vec<T>、Rc<T>——都自动满足它，哪怕马上就被 drop；带引用字段只有当引用本身是 'static 的才满足。

这个约束无处不在，因为泛型函数对类型参数的默认隐含约束就是 T: 'static。下面这个看似无害的调用会被拒：

常见混淆点

把两个身份分开记忆：写 &'static str 时，你在要一块永不失效的文本，多半该给字面量；写 T: 'static 时，你在要一个能安全转移、不藏短期借用的类型，所有权类型全都合格。'static 是生命周期标注，不是垃圾回收的标志——满足 T: 'static 的 String 该 drop 时照样 drop，别把约束读成“全局化”。

日常代码里的隐形 for<’a>

多数时候不写 for 也能过编译，因为带引用参数的函数指针与闭包 trait 会自动带上这条高阶约束：Fn(&i32)、FnMut(&str) -> usize 脱糖后都是如此。真正需要手写 for<'a> 的场景很有限，主要是给结构体字段显式写出闭包类型，或在泛型边界里跨多个调用点复用同一个带引用的回调。异步代码里也会遇到类似约束，留到异步专题展开。

trait object 的默认生命周期

Box 其实是 Box<dyn Trait + ‘static>

动态分发把具体类型擦成 trait 对象，对象内部可能仍藏着借用，于是“这些借用得多长寿”必须有默认答案。规则是：trait 对象出现在引用类型里时，默认跟随那个引用的生命周期；出现在 Box、Arc 等非引用容器里且没有显式标注时，默认是 'static，也就是说 Box<dyn Error> 的真实身份是 Box<dyn Error + 'static>。这个默认值造成的编译失败非常典型：

NLL 之后，还有哪些报错必须显式标注

NLL 放松了什么

2018 edition 起默认启用的 NLL（非词法生命周期）把借用的存活终点从“所在作用域的末尾”收紧到“最后一次使用的位置”，大量老代码里“明明后面不再用了却还不许改”的报错就此消失：

但要认清 NLL 的能力边界：它优化的是函数体内借用的推断结果；签名层面的约束仍由省略规则或显式标注给出，跨函数边界的借用关系——存进结构体字段、返回出去、装进 trait 对象——仍要求类型里写明生命周期。NLL 让“不用标注的代码”变多了，却没让“需要标注的场景”消失。下面的报错逐条看。

E0106：引用类型缺少生命周期标注

出现位置最广的一个，触发条件是省略规则推不出唯一答案：返回引用且输入引用多于一个又没有 &self；结构体字段是引用；trait 对象装在 Box 或 Arc 里、来源却不是 'static。修法按场景走：函数补 <'a> 并绑定参数与返回值；结构体加生命周期参数；trait 对象写 + 'a。如果返回的是局部借用的引用，见下一条。

E0515：试图返回当前函数拥有的数据的借用

这类错误不能靠加标注解决——你标注不出比数据本身更长的生命周期。正确修法二选一：返回拥有所有权的 String，或只返回入参派生出的切片。把“我造的”说成“我借的”是不成立的。

E0597 与 E0716：借用比被借用者活得久

局部块结束时 owner 析构，text 的借用随之失效，这就是 E0597，典型的借用逃逸：借用从块里逃到了块外。它的近亲 E0716 针对语句级临时值：let s: &str = format!("n={}", 1).as_str(); 里 format! 产生的临时 String 在语句末尾就被回收，s 当场失效。两者的修法都不是标注，而是延长数据本身：把所有权挪到借用之前的作用域，或拆成两行，先 let owner = format!(...)，再取 as_str()。

E0621：签名与实现里的借用路径不一致

标注说返回值只跟 'a 走，实现却允许它从 b 来，合并后的约束要求 b 也活到 'a，于是编译器要求给 b 显式标注。修法是把返回引用的所有来源都绑进相应的生命周期，或者改逻辑保证只从已标注的路径返回。

方法里 self 与返回借用的取舍

容器类型的方法返回内部数据的借用，靠省略规则第三条自动跟随 &self，通常不用手写。需要动手的信号有两个：方法同时接收外部引用、且返回值可能来自外部——两个来源约束不同，编译器无从选择，报 E0106 后给外部参数补第二个生命周期即可；想让返回值比 self 更宽松——从 &self 出发的引用不可能比 self 活得久，借用检查会拒绝，这时该考虑返回 String 副本。

自引用与常见误区

结构体不能借用自身的字段

生命周期标注能表达“我借用外面的数据”，但表达不了“我借用的数据在我自己肚子里”，这就是著名的自引用问题：

构造时 s 的所有权正要移入 owner，移动之后借用悬垂，编译器拒绝；即便构造侥幸成立，SelfRef 实例一旦再被移动或参与 mem::swap，view 仍指向旧地址。要同时挡住这两件事，需要指针固定这样超出生命周期表达能力的机制，生命周期参数天生管不了“借用者与被借用者在同一个值内部”的关系。标准做法是绕开：把 view 换成偏移量或索引，使用时从 owner 现取切片，或者两处都存拥有所有权的副本。自引用也是 Pin 话题的核心动机，这里只需记住结论：结构体里硬凑自引用是死路。

高频误区清单

误区一：报错就加 'static。'static 把约束推到最严，只会让调用方更难满足，借用来源不变，加什么标注都救不了所有权错误。

误区二：标注能延长借用。标注只是声明约束，编译器负责验证；约束事实上不成立时，标注写多漂亮都拒绝编译。

误区三：写了 'a 就是同一个生命周期。同一函数声明两个参数名就是两个独立约束，绑到同一个名字上才会互相牵制；反过来滥用同名会把本可独立的约束错误收紧，白白为难调用方。

误区四：省略规则能永远代替标注。结构体定义不适用省略；多输入、无 self 的函数不适用规则三；无输入却有输出引用时只剩 'static 一条路。这三类正是必须动笔的地方。

误区五：生命周期有运行时开销。它是编译期信息，运行期零成本；性能问题请去查找分配、复制与分支，不要在标注上找。

最后补一条签名评审里最容易漏的隐性问题：&self 方法返回的借用会被省略规则自动绑到 self 的生命周期上，如果把这个返回值存进比 self 长寿的字段，轻则编译被拒，重则整个实例被锁短；发现返回值跟随错了对象时，宁可显式写 '_ 或调整结构，也不要听凭省略规则猜。

什么时候改用所有权或克隆

生命周期传染的真实成本

加标注本身不花钱，贵的是约束沿调用链扩散后对接口与心智的损耗：一个函数返回 &'a str，调用方就得保证数据源比消费点长寿；结构体多一个生命周期参数，持有它的 Vec、HashMap、trait 对象全都跟着多一个；API 发布后，签名里的生命周期就是长期承诺。异步代码里传染更凶：async fn 生成的 Future 会把输入借用的约束背到自己整个存续期，调用与 await 拆开放、future 装进容器跨任务等待时，借用上下文都得活满全程。trait 里定义异步方法在 1.69 时代还没有稳定语法，社区普遍用 async-trait 这类宏把返回值脱糖成带显式生命周期参数的 Pin<Box<dyn Future>>，签名复杂度翻倍——这种地方省掉一个借用，往往比摆平一处标注划算。

三条判断标准

其一，借用跨不出当前作用域就别标注，直接返回 String，第 7 节的 build_greeting 属于此类：数据是本函数造的，返回所有权是唯一活路。其二，消费者与数据源的关系不稳定时改用克隆：把 &'a str 存进全局缓存、长命队列、trait 对象时，与其让 'a 传染一层层签名，不如在入口处 to_owned()，用一次复制换接口干净；切片、字符串这类小对象克隆极便宜，先测量再优化，不要提前为假想的开销上生命周期。其三，确实要在热路径上零拷贝传视图时，才把生命周期写进类型并接受它对调用方的约束——常见收益场景是解析器的输出视图引用输入缓冲区，一次分配多处消费。

折中工具是标准库的 Cow：平时借用，必要时才拥有，适合“多数情况返回输入的子串、少数情况要生成新内容”的函数：

Cow<'_, str> 不强迫调用方提供 'static，借用分支零成本，签名里只有一个匿名占位，传染性最低。

方案 代价 适用场景
返回引用加标注 签名复杂，约束传染调用链 数据源长寿、消费点集中、热路径
克隆为拥有类型 一次复制的运行时开销 数据跨作用域、进容器、进 trait 对象
Cow 延迟决定 多一层枚举判断 借用与生成二选一的函数返回值
Rc/Arc 共享所有权 引用计数开销 多处长期共享、所有权难归一

最后一行是提醒：共享所有权与并发在相关专文里讲，本文的边界划在“别拿生命周期硬顶”。

小结

生命周期是借用检查器的书写语言：它描述引用有效范围之间的比较关系，不改变任何值的真实存亡，编译后全部擦除，运行期零成本。需要手写标注的场景只有四类——返回引用且输入多于一个、结构体存借用、trait 对象装进非引用容器、要求对任意生命周期成立的泛型边界；省略规则与 NLL 处理了其余大部分情况。'static 有两副面孔：作为标注是程序全程，作为 T: 'static 约束是“不藏短期借用”，Box<dyn Trait> 默认后者，装借用要显式写 + 'a。遇到 E0515、E0597 这类所有权与逃逸错误，先修数据归属再想标注；碰到自引用，直接换索引或副本。实践建议：公共 API 上的生命周期宁少勿多，先用所有权把功能写对，确认热路径后再用引用和 Cow 回收成本——标注是最后的精细工具，不是第一反应。
