大模型微调 Fine-tuning 实践

本文梳理大模型微调（Fine-tuning）的完整工程流程：什么情况下真的需要微调、数据怎么准备、训练参数怎么配、效果怎么评、权重怎么部署，以及团队该怎么控制迭代节奏与成本。适合已经把模型调用跑通、准备把模型适配到自有业务任务的工程师。全文以 2023 年已公开的开源生态为背景，涉及 Llama 2（2023-07 发布）与 QLoRA（2023-05 提出），文中出现的显存与耗时数字均为示意值，落地前请用自己的负载重新测量。

什么时候需要微调

建议把微调放在方案清单的最后一项。任务效果不理想时，先做两件事：一是改进提示词，补 few-shot 示例、明确输出格式、把复杂任务拆成多步；二是判断问题是不是“知识缺失”。如果是模型不知道我们的私有知识，RAG（检索增强生成）通常比微调更合适：知识频繁更新，重建索引的成本远低于反复重训模型。

微调擅长的是改变模型的“行为”而不是“记忆”：稳定的输出格式与语气、对领域任务定义的理解、用更短的提示词达到同样的效果从而压低推理成本。经验上，满足以下信号时微调才值得投入：提示词与 RAG 都试过仍达不到验收线；任务的格式要求强且长期稳定；手里有一批质量可靠、带输入输出的示例数据。反过来，如果期望靠训练让模型“背下”经常变动的文档，大概率会陷入不断重训的循环，这正是 RAG 该解决的问题。

微调的几种形态

按训练目标划分，常见的是继续预训练与指令微调两类。继续预训练是在大规模领域文本上做无监督语言建模，目的是注入领域知识、降低困惑度，它教会模型“读懂”领域语料，但不一定教会它听从指令。指令微调（SFT）则用“指令-输入-输出”样本做有监督训练，教会模型按任务格式作答。做领域专属模型时两者常分两步走：先继续预训练再指令微调；多数团队起步时只应做后者，因为前者的数据量与算力门槛高一个数量级。

按更新的参数范围划分，则有全参微调与参数高效微调（PEFT）。全参微调更新全部权重，效果上限通常最高，但权重、梯度、优化器状态都要显存承载，往往需要多卡与 ZeRO 这类显存切分方案，适合数据量大、算力充足的场景。参数高效微调冻结原始权重、只训练少量新增参数，工程上最常用的是 LoRA：在每个线性层旁挂一对低秩矩阵。低秩分解的数学原理见我们此前关于 LoRA 的文章，本文只讨论工程取舍——LoRA 产物是“基座权重加低秩增量”，训练完可以先只存适配器，部署时按需合并，多任务共用一个基座、灰度与回滚都容易。QLoRA 的思路是把基座权重量化到 4 bit 再在其上训练 LoRA，让 7B、13B 级模型的单卡微调门槛明显下降（具体能开多长序列、多大 batch，取决于显存容量，见下一节估算方法）。至于基座选择，Llama 2 开源权重给了社区明确的 7B/13B/70B 档位，配合 Hugging Face 的 PEFT、TRL 等开源库即可搭起训练管线。

第一步是格式统一。指令微调的样本统一收敛到“指令-输入-输出”三元组，再套上固定的模板拼成一条训练文本，全套数据只用一种模板，改模板等于换模型。示意如下：

第二步是清洗与去重。删掉过短或截断的样本、修复乱码与残留的 Markdown 噪声、去掉答案明显错误或互相矛盾的条目；去重要先做归一化（去空白、统一标点）再哈希精确去重，跨来源的近重复样本可用 MinHash 一类方法聚类后抽样人工确认。一个常被忽视的顺序问题：切分训练集与验证集必须发生在清洗去重之前或与之原子完成，否则近似重复样本会泄漏进 held-out 集，评测分数虚高。

第三步是配比。只喂领域数据，模型容易过拟合到新格式而丢掉通用指令跟随能力，实践中普遍要在领域数据里掺一部分通用指令数据，示意比例可以从领域与通用 5:1 起步，再依据评测结果在 3:1 到 7:1 之间调整。

最后是隐私与合规。训练数据里的人名、手机号、订单号等个人信息要做脱敏或假名化；数据来源、授权链路和处理步骤应当留档，尤其是面向公众的生成式服务，需对照 2023-08-15 施行的《生成式人工智能服务管理暂行办法》检查语料合法性；无法证明来源与授权的数据，宁可不进训练集。

训练配置要点

学习率：全参微调通常取 1e-5 量级，LoRA 因为只训练小矩阵，可用到 1e-4 至 2e-4（以上为常见示意区间，务必先用小数据集做几次短训练标定）。配套用预热加余弦衰减的调度，避免一开始就大步长。

epoch 数：指令微调一般 2 到 4 轮即可，关键不是轮数而是按验证损失挑选检查点——验证损失开始回升后再训只会加深过拟合。

序列长度：先统计 token 长度的分布，按 P95 左右设定截断上限，超限样本要么截断要么剔除；注意力计算的开销随序列长度增长很快，长上下文对显存与速度都是非线性压力，不要盲目追高上限。

显存估算思路：粗略地，AdamW 优化器状态下全参训练每个参数约需 16 字节的权重、梯度与动量方差等动态开销，再加上随 batch 与序列长度增长的激活值。以 7B 模型为例，仅动态开销示意约 112 GB，所以全参微调天然要多卡分摊；LoRA 只给低秩旁路存梯度与优化器状态，QLoRA 又把 4 bit 量化后的基座权重压到约每参数 0.5 字节量级，单卡才变得可行。这些换算只用于判断“方案可不可行”，真实占用请用一张卡先跑一步看分配报表。

过拟合与灾难性遗忘的信号

过拟合最直观的信号是曲线背离：训练损失持续下降而验证损失在某个检查点后掉头向上，此时应当取拐点前的检查点。比曲线更早暴露的是输出形态——模型开始逐字复述训练样本、对没见过的问法生硬套用固定开头、换个领域的提问就答非所问，都是格式过拟合的表现。处理顺序建议是：先减少有效 epoch（提前停），再提高通用数据配比，然后考虑调小学习率或收缩 LoRA 的秩，而不是急着堆数据。

灾难性遗忘是另一类问题：领域任务分数上去了，通用能力却掉了。监测方法不是看训练损失，而是维护一个与业务无关的通用指令 held-out 集，每出一个检查点就跑一遍，与基座模型同集分数对比；一旦发现通用集明显劣化而领域集收益变小，就回退到更早的检查点，并提高下一轮训练的通用数据配比。相对而言，LoRA 这类参数高效方法因为冻结基座权重，遗忘程度通常比全参微调轻，这也是小团队从 LoRA 起步的原因之一。

评测

评测集要满足三个条件：与训练集严格隔离（切分先于清洗去重，见数据准备一节）、覆盖真实业务分布、规模上至少能支撑人工抽样。评估分三层做。

第一层是自动化指标。验证损失与困惑度只能反映训练过程健康与否，不能代替质量判断；任务层面要看格式合法率（输出能否被解析器按约定格式解析）、关键字段抽取的精确匹配、生成文本与参考译文的重叠度类指标（可作参考，不能单独作数）。

第二层是基线对比。同一批评测样本，至少跑三条线：基座模型加强提示词、RAG 方案（若适用）、微调模型。微调只有在明显且稳定地压过前两者时才值得上线，否则维护一个训练管线的成本会超过收益。

第三层是人工评估。制定简单的打分表（正确性、格式、有害性三个维度，各 1 到 3 分），从评测集随机抽样双盲对比微调前后输出，两名评审独立打分再合议。自动指标负责快速筛掉坏检查点，人工评估负责最终拍板，两者不可互相替代。

部署与合并权重

LoRA 产物有两种部署形态。一种是分离式：推理服务加载冻结基座，再按需挂载不同任务的适配器，同一份基座权重服务多个业务，切换与回滚只需换适配器文件，显存也只多一份小矩阵。另一种是合并式：训练结束后把低秩增量并进基座权重，导出一个普通模型直接部署，推理路径与原生模型完全一致，不需要服务侧支持适配器加载：

合并要注意三点：合并用的秩与缩放参数必须与训练一致，导出目录里记录基座模型名、适配器路径与合并时间，避免日后无法复现；合并后的权重同样继承基座的许可条款（Llama 2 的社区许可对商用有随规模而变的约束），发布前过一遍合规检查；一旦合并发布，就不能再靠热换适配器做 A/B，多版本要靠完整权重切换，回滚链路要提前演练。全参微调没有合并问题，但要留意检查点体积与分发耗时。

迭代节奏与成本记录

微调最容易失控的地方是节奏：一次全量训练动辄数小时到数十小时（示意值，取决于数据量与卡型），如果每次都从全量数据起跑，一周排不了几次实验。建议固定两级节奏：先用小规模快速验证——取几百到一两千条样本、1 个 epoch（示意值），只验证数据管线、模板与评测脚本是否正常，确认评测分数与人工观感一致后再放大；放大阶段才动全量数据与完整超参。每个阶段产出一个带版本号的候选，进入同一个评测集与同一份打分表。

小结

回到工程视角，微调的实践要点可以压缩成几句话：先用提示词与 RAG 兜住知识类问题，把微调留给格式、语气与任务行为；数据侧固定模板、先切分再清洗、领域与通用按比例混合；配置侧用小规模短训练标定学习率与显存预算，按验证损失选检查点，警惕过拟合与灾难性遗忘两类信号；评测坚持 held-out 集、基线对比与人工打分三层齐全；部署上优先用 LoRA 适配器保留回滚能力，合并权重时把可复现信息与许可约束写进发布记录。文中所有显存与耗时数字都是按公开换算规则给出的示意值，请在自己的卡与数据上复测后再做决策。对小团队而言，QLoRA 加 LoRA 的组合是当前投入产出比最高的一条起步路径，跑通一轮完整闭环，再谈全参微调也不迟。
