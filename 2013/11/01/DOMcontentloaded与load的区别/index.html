DOM contentloaded 与 load 的区别

刚学 DOM 事件的人，几乎都写过 window.onload = function () { ... }，然后把所有初始化代码都塞在里面。这个写法在图片很少的页面看不出问题，一旦页面挂了几张几兆的头图，就会发现按钮半天点不动。原因在于 load 等的是”所有资源下载完”，而不是”页面结构准备好”。本文把 DOMContentLoaded 与 load 的触发条件、document.readyState 的三态、jQuery .ready() 的实现思路，以及脚本位置对触发时机的干扰一次讲清，末尾给出实际项目里的选择建议。

两个事件到底在等什么

浏览器拿到 HTML 之后并不是”读完整份再渲染”，而是边下载边解析：读到一个开始标签就创建对应节点，读完 </html> 时 DOM 树基本成形。这个时刻触发的就是 DOMContentLoaded；而此时页面里的图片、样式表、iframe、甚至尚未执行完的外部脚本，都可能还在路上。

load 则是另一条时间线的终点：它要等 window 上所有资源——图片、样式表、子框架、脚本——全部加载完成才触发。两者最直观的差别可以用一张图说明：

flowchart TD
    A[开始下载 HTML] --> B[边下载边解析 构建 DOM 树]
    B --> C[DOM 树构建完成]
    C --> D[触发 DOMContentLoaded]
    D --> E[继续下载图片 样式表 iframe 等资源]
    E --> F[所有资源就绪]
    F --> G[触发 window.onload]

所以结论很直接：DOMContentLoaded 关心结构，load 关心资源。如果要做的是给按钮绑事件、读某个节点的文本、根据 DOM 结构初始化组件，那都应该挂在 DOMContentLoaded 上；只有当逻辑确实依赖图片尺寸（比如轮播图要按图片实际高度定位）时，才需要等 load。

一个常见的误解是”DOMContentLoaded 一定早于 load“。在正常文档里确实如此，但两者并非绑定关系：load 还可能因为某张永远加载不出来的图片而一直不触发，DOMContentLoaded 却早就执行过了。把关键初始化写在 onload 里，等于把可用性押在CDN 的心情上。

readyState 的三态与 readystatechange

事件是”通知”，document.readyState 则是”状态”。它有三个取值，分别对应文档生命周期的三个阶段：

  • loading：文档正在下载和解析，DOM 树还没建完。
  • interactive：DOM 树构建完成，可以操作 DOM，但子资源可能仍在加载。这个状态与 DOMContentLoaded 的触发点基本重合。
  • complete：文档及所有子资源加载完成，与 load 的触发点重合。

与它配套的是 readystatechange 事件，每次 readyState 变化时在 document 上触发。它的价值在于”补触发”：如果你的脚本是在文档解析过程中被动态插入并执行的，那么当它开始运行时，DOMContentLoaded 可能已经过去了，再注册监听永远不会回调。此时读一次 readyState 就能判断该自己动手还是继续等：

document.async 是 HTML5 给脚本元素加的一个属性（script.async = true），声明脚本为异步执行。异步脚本不保证按文档顺序执行，一旦下载完成就可能打断解析流程先跑起来。它的直接后果是：你无法预测异步脚本运行时 DOM 树建到哪一步。因此异步脚本内部不能假设任何 DOM 节点存在，要么自己判 readyState，要么把 DOM 操作全部交给事件回调。

实践中的取舍是：需要操作 DOM 的脚本放底部并保持同步；与首屏渲染无关的统计、日志类脚本才用 async，且这些脚本本来就不该碰 DOM。

性能意义：为什么要抢 DOMContentLoaded

把初始化从 load 挪到 DOMContentLoaded，收益主要体现在两件事上：提前绑定事件，提前发请求。

事件绑定提前意味着用户可能在资源还没下完时就点击按钮。在图片较多或网络较差的页面，两者间隔能有几百毫秒到数秒，这段时间里的点击全部无效，是很实在的体验损失。

更关键的是提前请求。很多页面的数据是靠 JS 拉的，如果等 load 再发请求，链路是”DOM 就绪 → 等图片下完 → 发请求 → 等响应”；挂在 DOMContentLoaded 上则变成”DOM 就绪 → 立刻发请求 → 边下图片边等响应”。两条链路并行之后，首屏可交互时间通常能缩短一截。

小结

DOMContentLoaded 与 load 的分界是”结构就绪”与”资源就绪”，绝大多数初始化逻辑应该挂在前者。document.readyState 用 loading/interactive/complete 三态描述了同一个过程，它的价值是让迟到的脚本也能判断当前进度，而不是死等一个已经过去的事件。jQuery .ready() 用 DOMContentLoaded、readystatechange、load 三重兜底，主要是在为 IE 8 及以下买单。脚本放在底部或设为异步，都会改变你对触发时机的预期，迟到场景必须自己读状态。最后，把初始化和数据请求提前到 DOMContentLoaded，是少数几处”改一行代码就能见效”的优化。
