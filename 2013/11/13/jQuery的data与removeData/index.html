jQuery 的 data 与 removeData

$(el).data('key') 大概是 jQuery 里最常用的 API 之一，写起来顺手，读起来也直观。但它背后并不是”往元素上挂了个属性”这么简单：jQuery 自己维护了一份全局数据缓存，.data() 在这份缓存和标签上的 data-* 属性之间来回倒腾。缓存能带来便利，也能带来”改了属性却读到旧值””删了节点数据还在内存里”这类问题。本文从这份缓存的实现结构讲起，把 .data() 的读写规则、.removeData() 的真实作用域，以及工程上怎么用才不出事讲清楚。

数据存在哪：$.cache 与 expando

先看结构。jQuery 给每个需要存数据的元素分配一个内部 id，写成一个属性挂在元素自身上，这个属性名叫 jQuery.expando，值形如 jQuery1900 加一串随机数字。真正的数据并不存在元素上，而是存在一个全局对象 jQuery.cache 里，用这个 id 作键。

这样做有一个历史原因：IE 6/7/8 的垃圾回收器无法处理 DOM 对象与 JS 对象之间的循环引用，如果把数据（尤其是函数）直接挂在元素属性上，节点一删就可能连带泄漏。数据集中放在 jQuery.cache 里，元素上只留一个字符串 id，环就被打破了。

从 jQuery 1.8 开始，这份缓存被拆成两半：data_priv 存放 jQuery 自己用的内部数据（事件处理函数、动画状态等），data_user 存放用户通过 .data() 写进去的数据。这个拆分直接决定了 .removeData() 的边界——它只清理用户那一半，事件那一半它碰不到。

flowchart TD
    A[jQuery 元素] -->|expando 属性| B[内部 id]
    B --> C[jQuery.cache]
    C --> D[data_priv 内部数据]
    C --> E[data_user 用户数据]
    F[".data() 读写"] --> E
    G[".on() 注册的事件"] --> D
    H[".removeData()"] --> E
    I[".off()"] --> D

.data() 的读取规则：先缓存，后属性

$(el).data(key) 读一个值时，jQuery 的顺序是：先看用户缓存里有没有这个键，有就直接返回；没有，才去标签上找 data-key 属性，找到就做一次类型转换并写入缓存。

类型转换的规则前面讲 data-* 时提过：能按 JSON 解析的就转，"1001" 变 1001，"true" 变 true，"null" 变 null，形如合法 JSON 对象的字符串会变成对象；转不成功就保留字符串。需要注意的是 "012" 会被当成八进制解析成 10，长数字串会丢精度。

写则完全不同：.data(key, value) 只写缓存，不碰标签。这与 .attr('data-key', value) 是两个世界。

不传参数调用 $(el).data()，返回的是该元素上当前全部数据组成的对象，调试时用它检查缓存很方便。传对象调用则是批量写入，但这里有个坑：jQuery 对象是一组元素，批量写入时同一个对象引用会被挂到这组元素的每一个上，它们共享一份数据，改一个就是改全部。

要每个元素独立，就得在循环里分别创建对象，或者借助回调逐个赋值。

.removeData() 到底删了什么

.removeData() 的语义比名字看起来窄。它做三件事：不带参数时删掉该元素的全部用户数据；带参数时只删指定键；返回值仍是 jQuery 对象，方便链式调用。

它不会做的事，比会做的更重要：

第三，它不释放元素在 jQuery.cache 里占的位置本身（内部 id 仍保留，只是内容被清掉）。真正让缓存条目整体消失的，是 jQuery 的 cleanData：用 .remove()、.empty()、.html() 这些 jQuery 方法删除元素时，jQuery 会顺手把元素及其后代的数据和事件一起清掉。反之，如果用原生 removeChild、innerHTML = '' 或者直接替换节点，jQuery 完全不知情，缓存条目就留在 jQuery.cache 里。

$.removeData(elem) 是等价的静态形式，传原生 DOM 节点即可，内部实现与实例方法共用一套。另外 jQuery 还提供了 $.hasData(elem) 判断某个节点上是否还有任何数据（含内部数据），写插件时可以用它避免重复初始化。

与 attr 的取舍：什么场景用哪个

把 .data() 与 .attr('data-*') 放在一起对比，选择就清晰了。

维度 .data() .attr('data-*')
存放位置 jQuery 内部缓存 标签属性
读标签同步 只在首次读取时同步一次 始终同步
写标签 不同步 同步
类型转换 自动（数字、布尔、JSON） 永远是字符串
删除方式 .removeData() .removeAttr()
事件数据 独立存放，互不干扰 无

判断法则可以归纳成三条。数据是纯前端状态、不需要反映到标签上，用 .data()，它不污染 DOM，也不会被 [data-x] 选择器误伤。数据可能被服务端渲染、被其他脚本通过原生 DOM 修改、或者需要被 CSS 选中，用 .attr('data-*')，保证读到的是最新值。数据是长数字串、编号、时间戳这类必须原样保留的字符串，也用 .attr()，绕开自动转换的精度陷阱。

小结

.data() 并不是给元素加属性，而是读写 jQuery.cache 里的一份用户数据，元素上只留一个 expando 属性作索引；数据集中存放是为了避开 IE 老版本 DOM 与 JS 循环引用的回收缺陷。读是”先缓存后属性”，写是”只进缓存”，这个不对称是绝大多数”改了 attr 却读到旧 data”的根源。.removeData() 只清用户数据，不删 data-* 属性、不解绑事件，也不负责释放 jQuery.cache 条目；清缓存条目要靠 .remove()、.empty() 这类走 cleanData 的 jQuery 接口。工程上的选型很简单：纯前端状态用 .data()，要与标签和外部脚本共享的数据用 .attr('data-*')。
