jQuery 操作 class 与样式的方法

$(".btn").addClass("active") 大概是 jQuery 里被写得最多的一行代码。也正因为太顺手，很多项目在 class 与 style 的管理上越走越乱：样式表里写一套，脚本里用内联样式覆盖一套，最后连”这个颜色到底由谁决定”都说不清。本文按一次真实重构的顺序复盘，把 jQuery 操作 class 与样式的常用方法、内部行为和坑点一次讲清。

class 四件套的基本盘

操作 class 的核心是四个方法：addClass、removeClass、toggleClass、hasClass。它们的参数都接受空格分隔的多个类名，调用后会返回原来的 jQuery 对象，因此可以继续链式下去。

这里有几个容易忽略的细节。第一，hasClass 从 jQuery 1.4 开始支持空格分隔的多个类名，语义是”这些类全部存在才返回 true”，不是”存在其中一个”。第二，toggleClass 的第二个参数是强制状态，jQuery 很早的版本就支持，但在实际项目里用得很少，它的价值恰恰在于把状态判断交给布尔值，避免自己去写 if else：

第三，addClass 传空字符串或纯空格时，jQuery 会安静地什么都不做，不报错。这种”静默失败”在拼接字符串出问题时很难排查，例如把 undefined 拼进了类名里。

css() 的两种形态

css() 既能读也能写。读取时返回的是浏览器解析后的计算值字符串，写入时则可以传单对键值，也可以传一个对象批量设置。

数字值会被 jQuery 自动补上 px，但只对”需要单位的属性”生效。像 zIndex、opacity、fontWeight、zoom 这类无单位属性，jQuery 内部维护了一份白名单，不会画蛇添足地加 px。

写法 实际设置的值 说明
.css("width", 100) width: 100px 需要单位的属性自动补 px
.css("zIndex", 100) z-index: 100 无单位属性保持原样
.css("opacity", 0.5) opacity: 0.5 jQuery 会为旧版 IE 补 filter

读取属性时有一个大坑：如果元素处于 display: none 状态，.css("width") 在部分浏览器下返回 "auto" 或 "0px"，而不是它理论上应有的宽度。需要拿真实尺寸时，请用 .width() 与 .height()，它们内部走的是 getComputedStyle 的降级方案，并处理了 box-sizing 的差异；需要相对定位父级的位置时用 .position()，需要相对文档的位置时用 .offset()。这四者是”取几何值”的正道，css() 是”取样式值”的正道，别混用。

另一个性能上的注意点：.css() 的每次读写都可能触发布局计算。jQuery 内部对同一批元素的连续写操作会做一些合并，但如果你在循环里交替读写，浏览器就会反复重排。正确做法是先集中读、再集中写：

一次真实的踩坑：class 与内联样式打架

项目里有个”高亮当前菜单项”的需求。第一版实现是直接写内联样式，后来产品要求主题可切换，内联样式改不动了，只能改成加 class。上线后却发现一部分菜单项变色、一部分不变色，回滚都来不及。

排查过程很典型：变色的都是没有内联样式的，不变色的都是之前被 .css("background-color", "#f90") 污染过的。原因是内联样式的优先级高于样式表里的类选择器，我加了 .menu .current { background-color: #369; }，但它被元素上的 style="background-color: rgb(255, 153, 0)" 死死压住。

方案三顺带说明了一个常见误区：很多人用 attr("class", "menu current") 整体覆盖类名，这会把页面其他地方动态加上的类一并抹掉。jQuery 从 1.0 起就支持给 attr 传函数，用它做追加才安全。

这次踩坑之后，团队定了一条规矩：颜色、间距、字号一律进样式表用类名表达，jQuery 只负责切换类名和少量与几何计算相关的位置值。内联样式只允许出现在两种场景——第三方组件注入的临时样式，以及动画中间态。规矩立住之后，同类 bug 再没出现过。

attr() 与 prop() 在类名上的边界

jQuery 1.6 引入了 prop()，用来区分”HTML 属性”与”DOM 属性”，1.9 之后这条界线非常清晰。对于 class，两者都能拿到值，但语义不同：attr("class") 读的是 HTML 标签上的 class 特性，prop("className") 读的是 DOM 节点的 className 属性，正常情况下两者字符串一致。

真正需要 prop() 的是布尔型属性，这也是迁移到 1.9 时最容易踩的坑：

在 1.9 里用 attr("checked", true) 设置后，elem.checked 并不一定为 true，反过来读取时也可能拿到 "checked" 或 undefined，行为取决于浏览器。表单类操作的规范写法是 prop 读状态、val 读写值、attr 读初始特性，三者的分工不要混。

用 data() 存状态，用 class 存表现

还有一类坑来自”把状态写进了 class 里”。比如用 hasClass("loaded") 判断是否加载过，看似省事，实则把行为状态和视觉状态绑死在了一起。一旦设计师要求 .loaded 也要有个过渡动画，或者某天要批量重置状态，就得去数 class。

更稳的分层是：data() 持有状态，class 只表达视觉。

需要留意的是，data() 会把首次读到的 data-* 值缓存到内部对象里，之后即使你改写了 HTML 上的 data-* 属性，再用 data() 读还是旧值。要拿实时值，得用 attr("data-loaded")。这个小细节在需要和外部脚本共享数据的页面里坑过人。

动画与 class 的协作

很多”展开收起”效果现在流行用 CSS transition 加 class 切换实现，jQuery 只当开关。这种写法的性能远好于 .animate()，但有一个前提：初始态和终止态都要在样式表里定义好，否则 transition 不会触发。

如果一定要用 .animate()，记得它同样会写内联样式，动画结束后元素上会留下一堆 style 残值。此时再想切回 class 控制，就要先 .stop(true, true) 并清理相关属性，否则内联值会继续压着样式表。这也是本文开头那条规矩的另一个理由：同一个属性，只留一个控制源。

小结

操作 class 的四个方法足够简单，难的是让”谁来决定样式”这件事始终保持唯一。本文的复盘结论可以归纳成几句：类名是给样式表看的，内联样式是给临时状态看的，两者不要互相覆盖；.css() 读写的是样式值，取几何尺寸请交给 .width()、.height()、.offset()、.position()；attr 管特性、prop 管属性、data 管状态，三者别越界；写样式要集中读、集中写，减少重排。jQuery 的这些方法十几年没大改，恰恰说明”简单 API 背后的工程纪律”才是真正需要花时间沉淀的部分。
