jQuery 的 getScript 与 getJSON

$.getScript 和 $.getJSON 是 jQuery 里两个最常被顺手套用、又最少被读文档的方法。它们本质上是 $.ajax 的语法糖，但因为签名短，很多人在应该用 $.ajax 的地方用了它们，然后在错误处理、缓存和跨域上接连踩坑。这篇把这两个方法的实现、和 $.ajax 的等价关系、缓存陷阱以及 JSONP 的安全问题讲清楚。

它们只是 $.ajax 的简写

jQuery 的简写方法族有一个共同点：内部都转到 $.ajax，只是预设了部分参数。三个方法对应三种数据类型：

方法 内部 dataType 典型用途
$.get(url, data, callback, type) 由参数决定，默认 HTML 文本 拉一段 HTML 或普通文本
$.post(url, data, callback, type) 同上 POST 提交表单
$.getScript(url, callback) script 动态加载并执行一段 JS
$.getJSON(url, data, callback) json 或 jsonp 拉 JSON 数据

getScript 与缓存陷阱

$.getScript 的实现是在文档里插入一个 <script> 标签，src 指向目标地址，onload 或 onreadystatechange 后触发回调。这个机制带来两个和 XHR 完全不同的特性。

第一个是它天然跨域。script 标签不受同源策略限制，所以 $.getScript 可以加载任何域上的脚本，这也是早期”跨域拉数据”套路的基础。

第二个是它天然受 HTTP 缓存影响。同一个 URL 的 script 标签，浏览器可能直接命中缓存不再发起请求，回调虽然还会执行（因为 jQuery 内部对已加载的脚本会直接调用回调），但你可能拿不到最新的代码。更麻烦的是 IE：它对 script 标签的缓存策略尤其激进，更新了服务器上的脚本文件，IE 上刷好几次还是旧代码。

jQuery 的应对是给 URL 加时间戳。$.getScript 内部默认 cache: false，jQuery 会自动在 URL 后面拼一个 _=时间戳 参数，让每次请求都不同，从而绕过缓存：

$.getScript 的第二个坑是错误处理。script 标签的加载失败不会触发 error 回调——浏览器层面 script 加载失败是静默的，jQuery 的 $.getScript 简写方法也不接受 error 回调参数。要拿到加载失败的通知，只能改回 $.ajax：

$.getJSON 的第二个坑也是错误处理。JSONP 失败时（比如服务端返回 404 或脚本语法错误），XHR 的 error 回调同样不会触发，因为整个流程没有 XHR。jQuery 1.9 里对 JSONP 的失败只有超时兜底：可以设 timeout，超时后 fail 会被调用，但拿不到具体的错误码。这是 JSONP 的结构性缺陷，不是 jQuery 的问题。

第三个坑是回调参数的类型。$.getJSON 的回调参数是解析后的 JS 值，不一定是对象。服务端返回的是一个 JSON 数组时，回调拿到的就是数组，直接 data.xxx 会得到 undefined：

缓存控制与批量治理

缓存问题值得单独说，因为它经常以”本地是好的”的形式出现。涉及三个层次。

第一，$.getJSON 走 XHR，IE 会缓存 GET 请求的响应，导致第二次请求不到新数据。jQuery 的默认行为是不自动加时间戳的，要么手动加，要么全局关缓存：

JSONP 的安全风险

JSONP 在 2013 年是跨域的主力方案，但它的安全模型很弱，值得在项目里明确约束。

最主要的风险是 XSSI（JSON 被当作脚本执行）。JSONP 的响应是一段 JS，浏览器会不假思索地执行。如果第三方接口被篡改、被运营商注入、或者服务端本身有缺陷，返回的内容就会以你页面的权限运行，能读到 cookie、操作 DOM。普通的 XHR 拿 JSON 则是当数据解析，不会执行。

几个实践约束：

  • 只对自己可控的域名用 JSONP，第三方接口评估后再决定。
  • 回调函数名固定且校验，不接受任意的 callback 参数值（防止被利用做反射型 XSS）。
  • 响应的 Content-Type 用 application/javascript，别用 text/html，减少被注入利用的面。
  • 重要的数据接口不要依赖 JSONP，走同域代理或者 CORS。CORS 在 2013 年的 Chrome、Firefox、IE 10+ 已经可用，是更干净的替代。

小结

$.getScript 和 $.getJSON 只是 $.ajax 预设了 dataType 的简写，遇到错误处理、缓存控制、超时这类需求，就该换回完整的 $.ajax 写法。$.getScript 通过注入 script 标签实现，天然跨域也天然受缓存影响，jQuery 默认加 _= 时间戳绕过缓存，要开缓存必须显式配置。$.getJSON 走 XHR，URL 带 callback=? 时切换为 JSONP，代价是失去错误回调、只支持 GET，并引入脚本执行的安全风险。回调参数的类型要先判断，多个动态脚本按依赖关系用 $.when 或队列控制顺序。
