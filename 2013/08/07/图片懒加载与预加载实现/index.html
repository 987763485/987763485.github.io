图片懒加载与预加载实现

长页面里塞着几十张图，首屏只看得见前几张，剩下的全在后台偷偷下载——这是懒加载要解决的浪费。反过来，灯箱里点开大图前的那一两秒白屏，又是预加载要填平的坑。一个拖后、一个提前，方向相反却常常出现在同一个页面里。这篇把这两件事的实现方式、常用插件和当年踩过的坑一次讲清。

先给结论：懒加载的核心是”把 src 的赋值推迟到接近视口时”，预加载的核心是”在用户需要之前就把资源塞进浏览器缓存”。两者都不需要新语法，用 jQuery 加几个事件就能写出来，麻烦全在细节。

懒加载的基本原理

浏览器只认 <img> 的 src。所以懒加载最简单的形态是：HTML 里先不放真实地址，只放一个占位符，真实地址放在自定义属性里；等图片快进入视口了，再用 JavaScript 把地址搬到 src 上。

关键点在于判断条件：offsetTop < 滚动位置 + 视口高度。为了在图片进入视口之前就开始下载，通常再预留一个阈值，比如提前 200 像素，这样滚到的时候图基本已经到位。

需要提醒的是它默认监听 window 的 scroll，如果你用了局部滚动容器，一定要传 container，否则永远不触发。这个坑当年不少人撞过。

占位图与低质量预览

懒加载不是”图片位置空着”。空着会导致图片载入瞬间把后面的内容往下推，布局跳动明显。所以一定要在 HTML 里写好 width 与 height，让浏览器提前算出占位空间。

更好的做法是给一个低质量预览：先用一张模糊的小图（几 KB）填上位置，高清图载入后再替换。视觉上是”先看到轮廓，再看清细节”，体验比空白好得多。

预加载的几种方式

预加载的目的是让资源提前进浏览器缓存，用户真点到的时候直接命中，无需等待。常见有四种做法，按侵入性从低到高排。

link rel=”prefetch” 与 rel=”prerender”

HTML5 的 link 标签提供了两个声明式预加载手段：

prefetch 在 Firefox 早期版本就已支持，Chrome 后续也跟进，语义是”以极低优先级下载，空闲时再传”。prerender 从 Chrome 13 起支持，它不只下载，还会在后台把整个页面渲染出来，用户点击时直接切换——代价是占用 CPU 与内存，且兼容性非常有限，2013 年基本只有 Chrome 能用，Firefox 与 IE 完全不认。

所以这两个属性的定位是渐进增强：写了不报错，支持的浏览器白拿收益，不支持的当它不存在。千万不要把关键路径上的资源押在它们身上。

Data URI 内联小图

极小的图片（几个字节到一两 KB 的纯色块、1 像素间隔线、迷你图标）可以直接转 Base64 写进 CSS 或 HTML，省掉整个请求。它既是”懒加载的占位图方案”，也是”预加载的极端形式”——根本不需要加载。

代价是体积增大约三分之一（Base64 编码的固有开销），且无法被单独缓存——CSS 一更新，内联图跟着变。所以只适合极小且长期不动的图，稍大一点就该回到懒加载或雪碧图路线。

懒加载与预加载的取舍

两条路线放在一起看，取舍标准就清楚了：

维度 懒加载 预加载
目标 省带宽、省首屏时间 省等待、让后续操作无感
适用对象 首屏外的图片、长列表图 即将用到的图、下一页资源
风险 判断失误导致该加载没加载 下载了用户根本没点的资源

最现实的组合是”当前屏用懒加载，翻页/下一页用预加载”。商品列表第一屏懒加载，用户往下滚再逐张加载；同时把第二页的数据与首图预取回来，翻页瞬间就有内容。

如果拿不准该不该给某张图做预加载，就问一句：用户点到它的概率是否高到值得为它花带宽？概率低就不要预加载，那是在拿大多数人的流量补贴少数人。

常见的坑

忘了写宽高。 图片载入后把内容顶下去，布局跳动，用户体验极差。HTML 里必须给 width 与 height，CSS 里也可以用 max-width: 100% 兜底响应式。

占位图撑出额外请求。 占位图本身如果是一张独立的小图，N 张懒加载图片就是 N 个占位图请求。用同一张并靠 HTTP 缓存，或者干脆用 Data URI。

JS 失效时整页没图。 懒加载依赖 JavaScript，脚本报错或用户禁用了 JS，页面就只剩占位图。稳妥做法是在 noscript 里补一个 <img> 的真实地址，或者首屏第一张图直接给真实 src，不做懒加载。

与缓存策略冲突。 懒加载把请求打散到滚动过程中，如果服务器对这些图片没有缓存，用户来回滚动会反复请求。确认这些图片有 Expires 或 Cache-Control 头，懒加载的收益才能落袋。

滚动容器判断错。 页面里有局部滚动区域时，用 window 的 scroll 事件永远等不到加载，如前面所说必须传 container。

小结

懒加载的本质是延迟赋值 src，判断准则是”元素距文档顶部的距离 < 滚动位置 + 视口高度 + 阈值”，配节流与缓存 offsetTop 保证滚动流畅。预加载的本质是提前把资源推进浏览器缓存，new Image() 最通用，rel="prefetch" 与 rel="prerender" 作为渐进增强，Data URI 只留给极小图片。两者方向相反，但在同一个页面里往往要同时使用。最后记住那条判断标准：懒加载省的是大多数人不看的图，预加载花的是大多数人都会点的带宽，想清楚概率再动手。
