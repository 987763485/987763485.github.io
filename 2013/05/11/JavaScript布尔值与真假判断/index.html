JavaScript 布尔值与真假判断

刚学 JavaScript 的时候，if (x) 这样的写法看起来理所当然，直到某天写了一个 if (config.title) 结果标题是 0 或者空字符串时逻辑没走进去，才意识到 JavaScript 里的真假不是”看起来”那么直观。后来做表单校验、接口数据处理，因为真假判断写错导致的 bug 越来越多，干脆把这块知识系统整理了一遍。本文从真值表、Boolean() 与 !!、document.all 这个特例，一直讲到 == 与 === 的区别，内容都是 ES5 范畴，可以直接对照《JavaScript 高级程序设计》第 3 版的相关章节阅读。

真值与假值的定义

JavaScript 是弱类型语言，任何值都可以放进条件判断里。规则很简单：在需要布尔值的地方，引擎会把值转换成 true 或 false。会转换成 false 的值一共只有六个，被称为”假值”：

  • false
  • 0（注意 -0 同样是假值）
  • ''（空字符串）
  • null
  • undefined
  • NaN

除了这六个，其他所有值都是真值，包括 '0'、'false'、[]、{}、function(){}，以及 Infinity。最后这几个是最容易搞错的：空数组和空对象都是对象，对象转布尔恒为真；字符串只要不为空就是真，哪怕内容是 'false'。

这个规则带来一个非常实用的写法：用 || 提供默认值。因为 || 返回的不是布尔值，而是参与运算的两个操作数之一，左边为假值时返回右边的值。

第一行那个坑我踩过。分页参数从 URL 传进来，用户主动传 page=0 表示第一页，结果被 || 覆盖成了 1，筛选条件怎么都不对。凡是 0、空字符串可能是合法值的场景，都不要用 || 做默认值。

真值表速查

把常见值按真假归类列成表，平时判断时对照一遍，比记规则更快。

值 布尔结果 说明
false、0、''、null、undefined、NaN false 仅有的六个假值
'0'、'false'、' ' true 非空字符串，空白字符也算内容
[]、{}、new Number(0) true 对象恒为真，即使包装的是 0
function(){} true 函数也是对象
Infinity、-Infinity true 非 NaN 的数字
-0 false 负零同样是假值
document.all false 规范承认的特例，见下一节

这张表值得单独强调 ' ' 这一行。用户输入一个空格，if (input.value) 判断结果依然是真，很多表单校验因此漏掉了纯空格的提交。稳妥的校验要先 trim 再判断长度，ES5 没有原生的 String.prototype.trim，jQuery 提供了 $.trim()。

另一个和空格有关的老问题是 parseInt。parseInt(' 12 ') 会自动忽略前后空白，但 parseInt('12px') 返回 12，parseInt('px12') 返回 NaN，而 parseInt('0x10') 在不同引擎下的历史行为不一致，ES5 之后规定不传 radix 时按十进制解析。取数值时统一传第二个参数，是更安全的习惯。

document.all 这个特例

假值列表在 ES5 规范里其实有第七个成员，一个非常特殊的存在：document.all。它是 IE 老版本遗留的宿主对象，按规范它应该被当作假值处理，尽管它是一个对象。

规范为此还专门定义了 [[IsHTMLDDA]] 内部槽位，typeof document.all 返回 'undefined'。ES5 的 Web 兼容性附录里明确记录了这个例外。实际开发中我们不会主动去用它，但了解这个特例的意义在于：判断一个值是不是对象时，不要想当然地认为”对象就一定为真”，真正严谨的写法是检查类型。

Boolean() 与 !!

有两个显式转换成布尔值的办法，效果完全相同。

Boolean(value) 是函数形式，语义清晰，可读性好。!!value 是先取反再取反，写法简短，压缩后的代码体积更小，2013 年的很多库里都偏爱它。性能上两者没有可感知的差异，选哪个纯粹是风格问题。

需要提醒的是，! 只做一次取反就够了，!!!value 没有意义，Boolean() 包一层再取反也是多余。另外，不要写 if (Boolean(value) === true)，既啰嗦又容易看错。

隐式转换的发生场景

真假判断的坑，一半来自对假值集合不熟，另一半来自不知道转换在什么时候发生。以下场景都会触发布尔转换：

  • if、while、for 的条件表达式
  • 三元运算符 ? : 的第一个操作数
  • ! 一元运算符
  • && 与 || 的第一个操作数

其中 && 和 || 最值得单独说，因为它们返回的是操作数本身，不是布尔值。

== 与 === 的区别

真假判断另一个高发 bug 区是相等比较。=== 严格相等，类型不同直接返回 false，不涉及转换。== 宽松相等，会先尝试把两边的类型转成一致再比较，规则相当复杂，ES5 规范第 11.9.3 节有完整定义。

最常见的几条规则：

  • null == undefined 为 true，但 null === undefined 为 false。
  • null 和 undefined 与任何其他值 == 比较都是 false，包括 0 和 ''。
  • 数字与字符串比较时，字符串转数字。1 == '1' 为 true。
  • 布尔值参与 == 时先转成数字。true == 1 为 true，false == 0 为 true。
  • 对象与原始值比较时，对象先调用 valueOf() 再调用 toString()。

最实用的结论就是：一律用 === 和 !==，不要用 ==。只有一种情况可以例外，就是同时想匹配 null 和 undefined 时，value == null 是更简短的写法，且不会误判其他值。jQuery、Zepto 的源码里都大量使用了这个小技巧。

小结

JavaScript 的真假判断规则只有一句话：六个假值，其余全真。但真正用好它，需要记住几个关键点：空数组、空对象、'0'、'false' 都是真值；document.all 是规范承认的假值特例；Boolean() 与 !! 等价，选一个保持团队统一即可。&& 和 || 返回操作数本身而非布尔值，做默认值或权限判断时要注意 0 和空字符串被误判。相等比较一律使用 ===，只有需要同时匹配 null 与 undefined 时才用 == null。把这些规则内化之后，写条件判断就不用再靠猜，读别人的代码也能很快判断出哪里有坑。
