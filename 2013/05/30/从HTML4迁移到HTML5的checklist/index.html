从 HTML4 迁移到 HTML5 的 checklist

本文属于《HTML 与 CSS》第 2/62 篇
上一篇系列目录下一篇

HTML5 规范在 2012 年已经成为 W3C 的候选推荐，WHATWG 那份” living standard”更是一直在滚动更新。到 2013 年，主流项目基本都具备了迁移条件，但真动手时会发现它不是一个”替换 doctype”的动作，而是一串彼此牵连的改动。本文把一次完整迁移拆成可勾选的条目，按”先改文档结构、再换语义标签、最后处理行为与兼容”的顺序推进，并给出验证工具。

第一步：文档头部的三个改动

迁移的第一站永远是文档头部，这三处改动风险最低、收益最直接。

第一处是 doctype。HTML4 的 doctype 有三种变体（strict、transitional、frameset），每一种都要引用一长串外部 DTD 地址，触发标准模式还需要写对：

<!DOCTYPE html> 在所有浏览器里都会触发标准模式，包括 IE 6。它不区分大小写，写 <!doctype html> 也合法，但团队统一成小写更利于 diff。

<meta charset> 必须放在文档的前 1024 字节内，否则浏览器可能已经按默认编码解析了部分内容。迁移时如果原来的 http-equiv 形式没有被删掉，两种写法并存不会报错，但属于冗余，建议一并清掉。

第二步：语义标签替换 div

HTML5 新增了一批结构性元素，用来替换层叠嵌套的 div。它们本身没有特殊行为，默认样式都是 display: block，价值在于语义与可访问性。

新标签 替换的场景
header 页面头、文章头，原来是 div class="header"
nav 导航区域，一组主要链接
article 可独立分发的内容单元，如一篇博文、一条评论
section 内容的分组，通常带标题
aside 与主内容弱相关的部分，如侧栏、广告位
footer 页面脚、文章脚
hgroup 一组标题与副标题，2013 年仍在规范中

替换的判据不是”看着像”，而是问一句：这块内容脱离上下文还能独立成立吗？能，就是 article；只是一个分组，就是 section；只是页脚，就是 footer。最常见的误用是把 section 当通用容器使，那不如继续用 div——规范明确说 section 应当带有标题，没有标题的分组应该用 div。

第三步：废弃元素与属性清理

HTML5 把一批纯表现型的元素标记为废弃，它们大多在浏览器里还能渲染，但属于应当清除的历史包袱。

废弃元素 替代做法
center text-align: center 或 margin: 0 auto
font CSS 控制字体、字号、颜色
big font-size
basefont 在 body 或具体元素上写 CSS
acronym 改用 abbr
frame / frameset 布局改用 CSS，嵌套内容用 iframe 或服务端包含
strike / s 区分语义：del 表示删除，s 在 HTML5 里被重新定义
tt、xmp、plaintext、listing、dir、isindex 均废弃

同时废弃的还有一批表现型属性：align、bgcolor、border（img 上的 0 以外取值）、cellpadding、cellspacing、hspace、vspace、link、marginheight、marginwidth、text、valign、width（部分元素）。这些在 HTML5 里都被移到了 CSS 一侧。

清理的策略建议是分两步，不要一次性替换完：

flowchart TD
    A[全站搜索废弃标签] --> B[替换为语义标签]
    B --> C[表现型属性改写为 CSS 类]
    C --> D[跑 W3C validator 确认无残留]
    D --> E[视觉回归测试]
    E --> F[提交]

先替换结构性的（center 换成 div 加类），再把属性搬进 CSS。如果一次性把 <font color="red"> 改成内联 style="color: red"，diff 会大到没法 review，而且与”表现归 CSS”的目标背道而驰。

第四步：渐进增强与 polyfill

IE 8 及以下不认识 HTML5 新增元素，这不仅意味着样式不生效——更麻烦的是这些元素无法通过 CSS 设置样式，因为它们不在 IE 的 DOM 里，getElementsByTagName('article') 返回空集合，事件绑定也无从谈起。解决办法是 html5shiv：用一小段 JavaScript 在文档解析时 createElement 出这些标签，IE 就会为它们建立 DOM 节点，之后 CSS 就能命中。

条件注释只在 IE 9 及以下生效，IE 10 起完全忽略了这种语法，所以现代浏览器不会下载这个脚本。这是 2013 年最常见的引入方式，本地部署时把路径换成项目内的副本即可。

第五步：行为属性与 ARIA 补充

HTML5 还带来了一批全局属性，它们不需要 polyfill，老浏览器会静默忽略，因此可以放心写：

属性 作用
contenteditable 让任意元素可编辑，IE 5.5 起就支持
spellcheck 控制拼写检查，Chrome 与 Firefox 支持
hidden 隐藏元素，等价于 display: none，IE 11 之前不支持，需配 CSS
draggable 声明元素可拖拽，配合拖放事件使用
tabindex 全局可用，控制 Tab 键焦点顺序

hidden 要特别注意：它作为属性在 IE 11 之前不被识别，只写 hidden 不会隐藏元素，必须在 CSS 里补一条 [hidden] { display: none; }。同理 draggable 在 IE 9 之前不支持，拖拽交互要退回鼠标事件模拟。

迁移顺序与验证工具

把上面五步串起来，一次完整迁移的实际推进顺序是这样的：

flowchart TD
    A[1 改 doctype 与 charset] --> B[2 替换语义标签]
    B --> C[3 清理废弃元素与属性]
    C --> D[4 引入 html5shiv 兜底 IE]
    D --> E[5 补 ARIA 与行为属性]
    E --> F[6 W3C validator 校验]
    F --> G[7 视觉回归测试]

第 1 步做完应立即提交，因为它独立且可回滚。第 2、3 步会大面积改动 HTML，建议按页面分批，每批都跑一次验证。第 4 步引入 html5shiv 必须在语义标签之前或同时上线，否则 IE 8 用户会看到样式错乱。第 5 步是增量，可以长期进行。

验证工具用 W3C 的 Markup Validator，把页面地址或源码贴进去，它会列出所有不符合 HTML5 规范的地方：

W3C validator 会报两类错误：一类是真正的语法问题，比如未闭合标签；另一类是”HTML5 里这个属性已废弃”的警告，正是迁移 checklist 要清理的目标。迁移完成后，一个干净的页面在 validator 上应当是零错误。

视觉回归测试不能省。语义标签虽然默认都是 display: block，但它们与原来的 div 在少数场景下表现不同：header 与 footer 在 IE 的旧版本里有内建样式，section 与 article 在部分版本里有默认 margin。这些差异要用显式 CSS 覆盖掉，不能依赖默认值。

小结

HTML4 到 HTML5 的迁移可以收敛成一份可勾选的清单：文档头部三处改动（<!DOCTYPE html>、<meta charset="utf-8">、省略 type 属性）、语义标签替换带 class 的 div、清理 center/font/frameset 等废弃元素与表现型属性、用 html5shiv 兜住 IE 8 及以下、最后补 ARIA 与 contenteditable 这类安全的行为属性。推进顺序上先做零风险的 doctype，再分批替换结构，html5shiv 必须与语义标签同时上线。验证靠 W3C validator 加视觉回归测试，两者都要过。整个过程没有技术难点，难在控制 diff 规模与保持可回滚。
