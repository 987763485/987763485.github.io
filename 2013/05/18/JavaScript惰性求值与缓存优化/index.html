JavaScript 惰性求值与缓存优化

做移动端页面优化时，我发现一个很常见的浪费：每次调用某个函数，都要重新判断一次运行环境，即使这个判断在页面生命周期内永远不会变。写法上就是几行 if，看起来无所谓，但在低端 Android 机上，一个被高频调用的函数里多几次分支判断，累积起来就能被感知到。顺着这个问题查下去，就有了惰性函数定义和缓存这两类优化手段，加上 || 与 && 的短路特性，构成了一套很轻量的性能工具箱。本文按从易到难的顺序把它们讲清楚，代码都是 ES5 语法，可以直接用。

短路求值：最基础的惰性

&& 和 || 本身就是惰性求值，右边表达式只在需要时才执行。这是 JavaScript 里最廉价的优化，也是最容易被忽视的。

短路的好处有两点。一是省掉了不必要的计算，二是在访问可能不存在的对象时起到了保护作用。但它也带来一个副作用：右边表达式里的赋值、函数调用都不会发生，如果代码里埋了副作用，行为就会变得难以预测。所以短路表达式里尽量只放纯粹的取值，不要放带副作用的调用。

惰性函数定义

同一个环境判断，没有必要每次调用都做一遍。惰性函数定义（lazy function definition）的思路是：第一次调用时完成判断，之后直接用覆盖后的版本。

memoize：缓存计算结果

惰性解决的是”重复判断”，memoize 解决的是”重复计算”。核心思想是把函数参数映射到返回值，同样的输入直接取缓存。

缓存最大的风险是失效策略。缓存了一个会随用户操作变化的数据，界面就会显示旧内容，而且很难复现。所以缓存只适合”输入相同、输出必然相同”的纯函数，或者有明确失效条件的数据。带副作用、依赖外部状态、依赖随机数的函数，一律不要缓存。

缓存的空间与清理

无限增长的缓存会带来内存压力，浏览器里表现为主频时间越长页面越卡。常见做法有三种。

小结

惰性求值与缓存优化的本质是把工作推到真正需要的时候，并让重复的工作不再发生。短路求值是免费的，|| 和 && 天生就只做必要的求值；惰性函数定义把一次性的环境判断从每次调用中拿掉，适合 API 探测这类稳定不变的分支；memoize 把纯函数的结果按参数缓存下来，斐波那契这类重复子问题收益最明显。使用缓存时最关键的不是性能提升，而是想清楚失效条件，缓存错一个数据造成的 bug 远比省下的几毫秒严重。最后，任何优化都要先测量，如果函数的调用频率低、开销小，加了缓存反而是纯粹的复杂度。
