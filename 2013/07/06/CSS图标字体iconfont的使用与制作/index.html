CSS 图标字体 iconfont 的使用与制作

本文属于《HTML 与 CSS》第 39/62 篇
上一篇系列目录下一篇

2013 年的项目里，图标方案基本是三选一：切好的 PNG 精灵图、内联的 data URI、还有正在兴起一小段时间的图标字体。前两者在 Retina 屏和换肤需求面前越来越吃力，图标字体则用”一个字体文件装下所有图标”的思路把问题一并解决了。这篇文章把图标字体的原理、用法、制作流程和当年绕不开的坑完整过一遍。

为什么图标字体值得一试

在图标字体流行之前，最主流的做法是把所有小图标拼成一张 PNG 雪碧图，然后用 background-position 定位到具体那一格。雪碧图解决的是请求数问题——几十个图标合成一张图，一次请求搞定，这在 HTTP/1.1 时代很关键。但它有几个天生的短板。

第一，位图放大就糊。2012 年之后 Retina 屏的移动设备越来越多，一套 16 像素的图标在高清屏上必须额外提供 32 像素甚至 64 像素版本，切图和维护成本直接翻倍。

第二，换肤困难。想做一个可切换的深色主题，图标颜色是写死在图片里的，只能再切一整套。hover 变色、选中变色这类交互更是无解。

第三，尺寸不够灵活。同一个图标要在 12 像素的按钮和 48 像素的推荐位上都清晰，位图要么准备多套，要么接受模糊。

图标字体恰好把这三件事一起解决了。字体是矢量轮廓，任意尺寸都不糊；颜色由 CSS 的 color 控制，和文字完全一样；尺寸用 font-size 控制，一套图标通吃所有场景。更实际的好处是体积——一个只含所需字形的子集字体，往往比一张雪碧图还小，而且矢量轮廓在复杂图形上比 PNG 压缩得更干净。

当然它也有代价：只能做单色图标，字体加载有闪烁问题，浏览器兼容要分情况处理。下面逐个说。

@font-face：让浏览器接受你的字体文件

图标字体的前提是 @font-face。这条规则在 CSS3 里被正式标准化，早在 2008 年前后主流浏览器就已支持，2013 年用它已经完全不需要犹豫。

这里的格式顺序是有讲究的。src 可以写多次，浏览器会按顺序取第一个自己能解析的格式。第一条单独写 .eot 不带 format()，是 IE9 以下的标准模式 bug：IE 遇到带 format() 的多格式 src 会整条跳过，所以要把纯 EOT 的 src 单独放在前面喂给它，第二条再用 ?#iefix 这种假查询串骗过 IE 的解析，把其他格式提供给现代浏览器。

格式选型上，WOFF 是当时最务实的选择：它本质是压缩过的字体容器，比 TTF 小三到五成，IE9、Firefox、Chrome、Safari 都支持。TTF 作为兜底，SVG 字体只用于旧版 iOS Safari（4 及其前后几个版本），2013 年新设备基本可以忽略，但为了兼容存量用户还是常写上。

字体本身可以放在自己域名下，也可以放公共 CDN。放自己域名时注意两点：一是服务器的 MIME 类型要正确，woff 对应 application/x-font-woff、ttf 对应 application/x-font-ttf，配错了部分浏览器会拒绝加载；二是图标字体不需要跨域头，因为它总是被当前页面的 CSS 引用，不像 Web Font 可能被第三方页面引用。

三种使用方式

字体声明好了，怎么把某个字形显示出来？当年有三种主流写法，本质都是”指定一个落在 Unicode 私用区的码位”。

方式一：content 伪元素

这是最干净的一种，HTML 里不放任何字符，全靠 CSS 注入。私用区（Private Use Area，PUA）的范围是 U+E000 到 U+F8FF，这个区间没有分配给任何文字，浏览器不会把它当成正常字符朗读，屏幕阅读器在大部分实现下也会跳过 content 生成的内容，可访问性反而更好。

这种方式的问题很明显：字符和码位的对应关系散落在模板各处，改一次映射要全文搜索替换，而且源码可读性差。它唯一的优势是不依赖 CSS 的 content，在没有 ::before 的老浏览器（IE7 不支持 ::before，只支持单冒号的 :before）里还能用——所以当年的兼容写法常常是 :before 单冒号，IE8 及以上两种都认。

方式三：class 名映射到具体字形

阿里妈妈 2011 年推出的 iconfont.cn 把流程做到了极致：上传 SVG、起个 class 名、下载一段 CSS，里面已经按你起的名生成好了 content 码位。Font Awesome（2012 年 3 月发布）和 Bootstrap 2 自带的 Glyphicons 走的是同一条路线，只是图标集是预制的。

实际项目里最推荐的是第一种加工具链：HTML 语义干净，映射关系集中在样式表里，改图标不用碰结构。

制作流程：从 SVG 到字体

自己造图标字体的完整链路是这样的。

flowchart TD
    A[设计工具中绘制 SVG 图标] --> B[统一画布尺寸与基线]
    B --> C[导入 FontForge 或 IcoMoon]
    C --> D[分配到私用区码位]
    D --> E[导出字体并做子集化]
    E --> F[生成 @font-face 与 class 映射 CSS]
    F --> G[页面引用并验收]

有几个环节容易翻车。

画布尺寸必须统一。SVG 的画布如果是 1024 单位，字体导出时会被缩放到字体的 em 方格（通常是 1000 或 2048 单位），缩放比例不一致会导致图标之间大小失衡。稳妥做法是固定一个画布，比如全部用 1024×1024，且图标四周留出一致的内边距。

基线对齐比想象中难。字体的字形是按基线（baseline）和升降部排布的，图标轮廓如果画得偏高，在实际文字旁边就会浮起来。修法有两种：一是在 SVG 里就把轮廓压到基线附近；二是导出后用 vertical-align 微调，比如 vertical-align: -1px 或 vertical-align: middle。这是图标字体最常见的视觉 bug，几乎每个第一次做的人都会遇到。

子集化直接决定体积。一个包含几千个汉字的中文字体动辄几 MB，绝不能直接拿来当图标容器。正确做法是只打包实际用到的十几个字形，导出的 WOFF 通常能压到 10 KB 到 30 KB。IcoMoon 这类工具默认就只导出你选中的字形，这也是它 2012 年之后迅速流行起来的原因。反过来，如果图集会持续增加，更好的策略是按业务拆成两个字体文件，把首屏图标和高频图标放进必加载的那个。

多色是当时的硬限制。字体天生只有一个前景色，想做双色图标只能拆成两个 ::before 和 ::after 分别上色，或者干脆退回 SVG。2013 年还没有彩色字体这回事，选型时如果设计稿里有彩色图标，要提前和设计师打招呼。

性能与调优：把图标字体的成本压到最低

从性能角度看，图标字体省掉的是请求数，付出的是字体加载的不可控。调优主要围绕三件事。

一、合并与缓存

图标字体应该全站共用一份，按主题或按业务拆分，而不是每个页面各引一份。字体文件的缓存时间要设长，因为它极少变动——每次改一个图标就换文件名或加版本号，用 Cache-Control 长缓存加文件名指纹，用户基本只会下载一次。CSS 里的 @font-face 声明同样建议抽成独立文件，让多个页面共享同一份缓存。

二、控制加载闪烁

浏览器在字体下载完成前不会用 font-family 渲染文本，这段时间的行为分两种：FOUT（Flash of Unstyled Text，先用后备字体显示，字体到了再替换）和 FOIT（Flash of Invisible Text，先不显示，字体到了才出现）。图标场景下两者都不舒服——FOUT 会让页面先冒出一堆”豆腐块”或乱码字符，FOIT 会让图标位置先空着再突然弹出。

当年的缓解手段有限但有效：把图标字体的 src 尽量提前（比如放在 CSS 文件靠前位置，避免被动态注入），配合 localStorage 缓存字体（把 WOFF 转成 base64 存起来，二次访问时同步注入样式）这种偏 hack 但很流行的方案。更简单的做法是接受首次访问的轻微闪烁，靠后续缓存兜住——图标字体体积小，这个成本通常可以接受。

三、别让图标字体拖慢首屏

如果首屏有十几个图标，而图标字体是异步加载的，用户会先看到空位。所以首屏用到的图标尽量不要走”字体后加载”的路线；非首屏图标可以延后。判断标准很简单：这个图标如果晚 200 毫秒出现，用户会注意到吗？会，就放进首屏字体。

四、和雪碧图做一次真正的对比

维度 PNG 雪碧图 图标字体
请求数 1 张图 1 个字体文件
高清屏 需 2 倍图 矢量无损
变色 需重新切图 CSS color 即可
多色图标 支持 不支持（当年硬限制）
加载问题 几乎无 FOIT/FOUT
兼容 IE6 起全通 IE6-7 需 EOT，需注意格式
体积 与复杂度相关 子集化后可很小

从这张表能看出选型逻辑：单色、需要变色、需要多尺寸，就用图标字体；彩色、形状复杂、数量少，位图反而更直接。实际项目里两者长期共存，并不存在谁彻底取代谁。

小结

图标字体的核心价值在于把图标变成文本：一次请求、矢量缩放、CSS 控色控尺寸，这三条正好命中雪碧图的所有软肋。使用时推荐 class 名加 content 伪元素的写法，码位落在私用区，兼顾可访问性与结构干净。制作时盯紧三件事：统一画布与基线、只做字形子集化、接受单色限制。调优时把字体抽成全站共享的一份并设长缓存，接受首次访问的轻微闪烁。它不是银弹，但在 2013 年，它是单色图标最划算的方案。
