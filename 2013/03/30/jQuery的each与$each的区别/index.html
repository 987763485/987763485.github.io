jQuery 的 each 与 $.each 的区别

$(".box").each() 和 $.each() 都能”遍历”，初学者常常随手抓一个用，反正看起来效果差不多。实际上一个挂在 jQuery 实例上、一个挂在 jQuery 静态对象上，调用形式、返回值、适用场景和性能取向都有差别。本文把两者的定位、实现差异和坑点一次讲清，便于在实际项目里做选型。

each 与 $.each 分别是什么

jQuery.fn.each 是实例方法，只服务于当前 jQuery 对象里已经匹配到的这一批 DOM 元素。它在 jQuery 1.0 就已经存在，1.0 到 1.7 期间内部是一个自带的循环，1.8.3 与 1.9 时期改为由 jQuery.each 驱动，语义没变。

jQuery.each（即 $.each）是 jQuery 命名空间上的静态方法，用来遍历一个普通对象或一个类数组结构。它的参数就是纯粹的集合，与选择器、与 DOM 都毫无关系。

一句话概括：$().each() 遍历的是”选择器筛出来的 DOM”，$.each() 遍历的是”任意数据”。

从归属上看，jQuery.fn 是 jQuery 原型对象的别名，1.9 里 jQuery.fn === jQuery.prototype 为真，所以 $("div").each 与 jQuery.prototype.each 是同一个函数；而 $.each 挂在 jQuery 这个构造函数本身，与原型链无关。这决定了两者的身份：实例方法必须先有”匹配到的元素”才能调用，静态方法则根本不需要 jQuery 实例参与。也正因为如此，在没有匹配元素时 $().each(fn) 里的 fn 一次都不会执行，回调不会报错，只是静默跳过——这既是特性也是陷阱，后面还会提到。

第一，$().each() 本质上就是 $.each(this, callback, args) 的一次转发，两者并不是两套独立机制。this 是一个类数组的 jQuery 对象，因此走的是 isArraylike 为真的那条分支。

第二，jQuery.each 内部用 isArraylike 判断传入值是不是数组或类数组：有 length 属性、length 是非负整数、jQuery.type(obj) !== "function" 且 window 不在其原型链上。jQuery 对象、arguments、NodeList 都满足这个条件，所以可以一路用 for 循环走完；普通对象则退化到 for...in，只遍历可枚举属性。

第三，回调的返回值只有 false 是有意义的：返回 false 相当于 break，提前结束遍历。返回 undefined、null、true 都表示继续。这个约定对两者完全一致。

性能与写法上的坑

第一，不要用 $().each() 去遍历非 DOM 的集合。如果你写 $().each(arr, fn)，arr 会被忽略，jQuery 只会遍历当前匹配到的元素，函数不报错但结果完全不对。

第二，遍历纯数组时优先用原生 for 或 Array.prototype.forEach（jQuery 1.9 内部也有 for (; i < length; i++) 的写法）。$.each 每次都多一次 callback.call 和一次 isArraylike 判断，在成千上万条数据上会有一点开销。jQuery 的遍历胜在与 DOM 操作的衔接，而不是数据处理性能。

第三，$.each 遍历对象用的是 for...in，原型链上可枚举的属性也会被带出来。遍历用户自定义对象一般没问题，但如果对象是通过构造函数创建并且原型上挂过方法，那些方法会被遍历到：

第四，在 each 回调里写异步操作要格外小心。回调里发一个 $.ajax，循环本身不会等待请求返回，闭包捕获的 index 是按闭包捕获规则来的，如果用到循环外变量，很容易出现”所有回调都打印最后一次的值”这类问题。

第六，$.each 遇到 null 或 undefined 会直接跳过而不报错，因为 length 取到 undefined 时两个分支都不进入；但它遇到没有 length 的对象时走 for...in，遇到 window 会抛错，因为 isArraylike 明确排除了 window。

与原生写法和其他遍历工具的对比

jQuery 的遍历并不是孤立存在的，把它放回整个工具箱里看，选型会更清楚。

对比原生 for 循环。遍历纯数组时，for (var i = 0; i < arr.length; i++) 永远是最快的，没有任何函数调用开销。jQuery 1.9 的 $.each 在数组分支里也正是这么写的，只是外面套了一层 callback.call，所以它一定比裸循环慢。差别在日常几百条数据上可以忽略，在几万条数据或者每帧都要执行的动画回调里就能测出来。

对比 Array.prototype.forEach。ES5 引入的 forEach 语义与 $.each 接近，但它没有”返回 false 提前退出”的约定，只能用 throw 强行打断，而且它无法遍历普通对象——$.each 的 for...in 分支是它做不到的。IE8 不支持 forEach，这也是 2013 年 jQuery 遍历仍有存在价值的原因之一。

对比 $.fn.map() 和 $.fn.filter()。它们与 each 同属”遍历后处理”家族，区别在于返回值：each 返回原集合，map 返回处理结果组成的集合，filter 返回筛中的子集。所以”既要遍历又要拿结果”时应该用 map，而不是在 each 里手动往数组里 push：

$.map() 是 $.fn.map() 的静态版本，第一个参数直接是数组或对象，与 $.each() 的用法完全对齐。需要注意的是 $.map() 会把回调返回的 null 和 undefined 从结果里剔除，这点与 each 不同。

小结

$().each() 是 jQuery 实例上的遍历器，服务于选择器匹配到的 DOM 集合，回调第二参与 this 都是原生元素；$.each() 是静态方法，第一个参数就是要遍历的任意数组或对象，回调第二参是当前值。前者实现上就是调用后者并转发 this，所以提前退出都用 return false。选型时记住一条：操作 DOM 集合用 $().each()，处理数据用 $.each()，处理纯数组还能考虑原生循环。真正容易踩的坑是参数含义错位、$().each() 误传集合、以及 for...in 带上原型方法这三点。
