CSS3 圆角、阴影与边框新特性

本文属于《HTML 与 CSS》第 35/62 篇
上一篇系列目录下一篇

2013 年的前端圈有个明显的分水岭：一边还在给 IE7 打补丁，一边已经兴冲冲地把圆角和阴影用上了产品页。CSS3 的背景与边框模块（CSS Backgrounds and Borders Level 3）在这一年基本成型，Chrome、Firefox、Safari 的支持度已经能支撑生产环境，IE 也终于从 IE9 开始跟进了 border-radius。这篇以工程视角把当年真正用得上的几件事梳理清楚：圆角怎么分角指定、阴影怎么叠加、border-image 为什么迟迟没推广开、以及写成什么样才能在 2013 年的浏览器里安全落地。

从一张”切图”说起

在 CSS3 之前，要做圆角只有两条路：切九宫格图片，或者让设计师把方块直角当风格。前者意味着每个按钮、每个卡片都要出图，改一个圆角半径就要重新切一次，遇到可伸缩的按钮更是灾难。本文刚入行时维护过一个论坛页面，光是按钮的圆角切图就有 idle、hover、active 三种状态共十几张，设计师离职后没人敢改数值。

border-radius 结束的正是这种局面。它把”圆角半径”变成一个可计算、可继承主题、可动态修改的数值，配合颜色和渐变，一个纯 CSS 的按钮就此成立。当年 :hover 时用 transition 把 border-radius 从 2 像素过渡到 6 像素，是再常见不过的交互细节。

真正容易被忽略的是椭圆圆角：用斜杠分隔两组值，斜杠前是水平半径，斜杠后是垂直半径。两组值都可以写 1 到 4 个，缺省时复制补齐。

椭圆圆角的经典用途是仿造叶子、水滴或者带弧度的标签底板。它的另一个妙处是做”上圆下方”的卡片头部：给容器顶部两个角一个较大的垂直半径，视觉上就得到向下弯的弧线。

圆角与内边距的配合

圆角生效后，内容区仍然是矩形，子元素或者文字如果顶到角落，会”探出”圆角之外，这是当年很常见的一个 bug。解决办法不是加大圆角，而是让内容自己也有圆角，或者用 overflow: hidden 把溢出裁掉。后者在放图片时尤其管用：

box-shadow：inset、多阴影与扩散半径

box-shadow 的完整形式是 offset-x offset-y blur spread color，四个长度值都可以为 0，inset 关键字把阴影从外侧翻到内侧。

水平偏移为正往右、为负往左；垂直偏移为正往下、为负往上。模糊半径决定边缘过渡的柔和程度，0 就是硬边阴影。扩散半径最直观：正值让阴影整体放大（比元素本身还大），负值让阴影收缩，只留出紧贴边缘的一圈。

这个技巧当年非常流行，用来做聚焦高亮、校验不通过的红色描边，比改 border 安全——它不占据布局空间，不会引起重排。

多阴影叠加

box-shadow 可以写多组，用逗号分隔，先写的画在上层。这让”一层柔和的漫射光加一层清晰的接触阴影”这种真实光照效果成为可能，也是当年扁平化设计里拟物残留的标准做法：

多阴影的一个注意点是层叠顺序与 inset 混用。内侧阴影画在所有外侧阴影之上，没有例外。如果想让内部高光和外部投影同时出现，把它们写在同一组里即可，引擎会自己处理。

阴影不占布局，但会重绘

box-shadow 不影响盒模型尺寸，加了阴影元素 position 也不会变，这点比 border 友好。但它属于绘制层面的开销：元素每次重绘（改颜色、改内容、跑 transition）都要重新绘制阴影，面积大、模糊半径大时成本更高。当年的实践教训有两条：

  • 不要给长列表的每一项都加半径很大的扩散阴影，尤其是列表还会滚动。宁可给容器加一层，或者干脆用更廉价的 1 像素边框。
  • 用 transform: translateZ(0) 之类的技巧在动画前提升图层，能让阴影只在合成阶段重绘，不过这招是后来的经验，2013 年更多是老老实实减小模糊半径。

border-image：被寄予厚望却难落地

border-image 想解决的是”渐变边框、异形边框、随尺寸拉伸的装饰边框”。它把一张图切成九块，四个角按原样放，四条边按 repeat 或 round 方式排布，中间区域默认被丢弃（也可用 fill 保留）。属性拆开是五个：

理想很丰满：改边框样式只需换一张图，边框厚度跟着 border-width 走，还能随元素尺寸自由伸缩。现实是它在 2013 年有几处硬伤。

  • 不支持百分比宽度。slice 是无单位数值，图被切成块之后，边的尺寸由 border-image-width 决定，而 width 需要 border-style 非 none 才有意义，浏览器实现一度不一致。
  • 与 border-radius 不共存。圆角边框想同时用 border-image，各浏览器的处理方式是把图片按直角绘制，圆角处出现明显接缝。想圆角就放弃 border-image，反之亦然，这个限制到今天还没变。
  • 作者容易切错图。内部分割线、羽化边缘、Nine-Patch 的取图规则都需要设计师配合，成本比直接加 border 高。

结论就是：2013 年的兼容梯队里，Chrome 与 Firefox 支持，IE 全系不支持。工程上的降级方案是先写一条传统 border，再用 border-image 覆盖：

边框样式新值与 outline-offset

CSS 2.1 的边框样式那套值——dotted、dashed、double、groove、ridge、inset、outset——在 CSS3 里被明确保留，但它们的渲染差异值得说清，因为它们常被误用。

dotted 在部分浏览器里画的是方点而不是圆点（Square 点阵系统下尤其明显），dashed 的线段长度没有标准规定，各浏览器不一。double 需要边框宽度至少 3 像素才看得出双线，且线宽分配比例由 UA 决定。groove 与 ridge 是一对：前者看起来刻入背景，后者浮出背景，依赖两种明暗色调的模拟，颜色不可控，观感受主题影响大。inset 与 outset 更古老，只在 border-style: inset 用于 fieldset 之类的控件时有存在感，日常基本不用。

比这些更实用的是 outline-offset。轮廓（outline）不占布局、不影响盒模型，画在边框外沿，当年的一个标准需求就是”聚焦时在输入框外留出空隙画一圈高亮”，outline 恰好合适，而 outline-offset 控制这段空隙：

轮廓一贯的争议是 Firefox 早期会把它画在元素圆角之内，圆角与直角轮廓同时出现时观感撕裂。稳妥做法是配合圆角，把轮廓也写成同色描边，或者只在关键交互元素上用。还有一个容易忘的点：outline 是键盘可访问性的兜底，清掉它的样式表基本等于把键盘用户拒之门外，这条红线不要碰。

background-clip：让背景跟着边框盒走

背景默认绘制到边框盒的外沿，于是设置 border 之后，半透明边框会把背景”透”出来——这在做半透明描边时完全不是想要的效果。background-clip 就是用来指定背景裁剪到哪个盒子的。

三个取值的差别：

取值 背景绘制范围 典型场景
border-box 一直到边框外沿（默认） 实色边框，看不出区别
padding-box 边框内侧，不进入边框区域 半透明描边、圆角图裁切
content-box 只覆盖内容区 内嵌背景、装饰性图案

它与圆角的配合堪称绝配：给一个圆角容器设 background-clip: padding-box 再加深色边框，能得到一圈干净的”内衬”效果，不需要任何图片。做带头图的卡片时，还可以让背景只铺内容区、内边距区露出底色，形成图文的天然分隔。

工程实践：一套可复用的圆角阴影方案

把上面这些零散能力组合成团队规范，是这篇最想留下的东西。2013 年的项目里，笔者通常按下面的分层组织。

第一层，变量化半径与阴影。 圆角半径全站只用三档，阴影只允许三套深度，禁止在业务代码里随手写 border-radius: 7px。这既是设计一致性的要求，也方便后续替换。

第二层，把兼容性写进混入而不是散落在业务里。 双写前缀的规则是固定的，交给预处理器的混入处理，业务只管调用：

第三层，降级预案写清楚。 IE8 及以下不支持 border-radius 与 box-shadow，直接放弃圆角阴影即可，布局不能因此错乱。绝对不能让圆角承担”这是可点击按钮”的唯一视觉线索，那样在 IE 下按钮就没了辨识度。弥补办法是同时保留背景色差异与文本颜色的对比，形状只是增强而非依赖。

第四层，性能预算写进规范。 大面积阴影不许超过两层，模糊半径不建议超过元素的一半，长列表项默认不加扩散阴影。这些约束看起来琐碎，但它们是当年”加了阴影页面滚动变卡”这类工单的根治办法。

小结

border-radius 把圆角从切图解放成数值，分角指定与椭圆圆角覆盖了绝大多数异形需求，配合 overflow: hidden 和 background-clip 能处理内容溢出和半透明描边。box-shadow 的价值在多阴影与 inset，用负扩散做高亮描边是不占用布局的经典技巧，但要注意重绘成本。border-image 虽然设计优雅，受限于不支持圆角、IE 全线缺席和切图成本，在 2013 年并未成为主流，降级到纯色边框往往是更划算的选择。工程上的稳妥姿势是：半径和阴影令牌化，前缀交给混入，降级兜底交给颜色与边框，性能预算写进规范。CSS3 这些特性的共同启示是——新能力解决的是视觉表达的效率，而能不能落地，取决于你是否为它的兼容性与成本留好了位置。
