Object.keys、values 与 entries 的使用

ES5 给 Object 加了一批静态方法，其中 Object.keys() 是日常最常用的一个：它把一个对象的所有可枚举自有属性名收集成数组。网上常有文章把 Object.keys、Object.values、Object.entries 并列介绍，但后两者要到 2017 年才进入标准，在本文写作时它们还只是提案，浏览器一概没有实现。本文以 Object.keys 为核心讲透，顺带说清另外两个方法在当时该怎么自己实现。

Object.keys 是什么

Object.keys(obj) 接收一个对象，返回一个由该对象自身可枚举属性的键名组成的数组，顺序与 for...in 遍历到的顺序一致。它是 ES5（ECMA-262 第 5 版，2009 年 12 月）新增的静态方法，IE9 起支持，IE8 及以下没有。

这里的”自身”很关键：原型链上继承来的属性不会被算进来；”可枚举”同样关键，通过 Object.defineProperty 设成 enumerable: false 的属性也会被跳过。这两条边界让它比 for...in 干净得多。

它的返回值是一个真正的数组，于是 Array.prototype 上的所有方法立刻都能用，这是它最大的价值所在。

在 IE9 成为底线的那两年，Object.keys 是替代 for...in 加 hasOwnProperty 判断的首选方案。

与 for…in 的差别

在 Object.keys 出现之前，枚举对象属性几乎只有 for...in 一条路：

for...in 会沿着原型链往上走，把所有可枚举属性一个不漏地列出来。多数时候这正是 bug 的来源：遍历一个用户对象，结果把原型上的方法也当成数据处理了。Object.keys 直接切断了原型链，只返回自有属性，语义精确。

第二个差别是产物类型。for...in 只能在循环体内逐个处理，拿不到一个可复用的集合；Object.keys 返回数组，可以先缓存、可以先求长度、可以先排序，再交给 forEach 或 map：

第三个差别是对非对象的处理。Object.keys 在 ES5 里遇到非对象参数会抛 TypeError（ES2015 起改为把原始值装箱、返回空数组），而 for...in 对原始值会静默跳过。写公共函数时这个差异决定了错误是当场暴露还是被吞掉。

values 与 entries：当时的真实状况

为什么当年要等这么久

ES5 在 2009 年定稿时，Object.keys 被放进标准，而 values 和 entries 没有。原因之一是当时还在争论”对象属性的枚举顺序是否可依赖”：如果顺序不确定，那么以数组形式返回 values 和 entries 就会带来跨浏览器不一致。这个争论一直持续到 ES2015 才通过规范明确排序规则，ES2017 顺理成章地把 values 和 entries 补上。所以 values 与 entries 迟到，不是没人想到，而是前置问题没解决。

理解这段背景对写当年的代码有实际帮助：既然顺序尚未标准化，就不要把 Object.keys 的结果顺序当作业务逻辑依赖。要做”按固定顺序输出字段”这类需求，应该显式维护一份键名数组。

兼容性与垫片

Object.keys 在主流浏览器里的落地时间是：IE9、Firefox 4、Chrome 5、Safari 5、Opera 12。到 2013 年，只有 IE8 及以下需要兜底。

还有一点要提醒：这个垫片只处理了自有可枚举属性，没有处理 Object.keys 在 ES5 里对非对象抛 TypeError 的行为，也没有处理字符串参数（ES5 会把字符串按下标拆成 "0"、"1"）。如果要完全对齐标准行为，垫片要写得更长；大多数项目选择只覆盖常用路径。

坑点与边界

第一，键的顺序。Object.keys 返回的顺序对纯数字键是升序的，对其他字符串键是插入序。如果对象混用数字键和字符串键，数字键会被排到最前面，且按数值大小而非插入顺序。遍历时如果依赖顺序做处理，最好先 sort()。

第二，length 不保证等于 for...in 的数量。原型链上的可枚举属性在 for...in 里出现、在 Object.keys 里不出现，两者的结果集本来就不是一个东西，不要互相换算。

第三，Object.keys 不会递归。嵌套对象里的属性不会出现在结果里，需要深层枚举只能自己写递归：

第四，用它做”对象有没有某属性”的判断时，注意区分自有属性和原型属性。Object.keys(obj).indexOf(key) !== -1 只查自有属性，这与 key in obj 的语义不同。如果你要的是”包括原型链在内的属性查找”，应该用 in；如果只要自有属性，Object.prototype.hasOwnProperty.call(obj, key) 比先建数组再 indexOf 更快，因为它不需要遍历。

小结

Object.keys 是 ES5 带来的实用工具，它把对象自身可枚举属性名收成一个数组，既切断了 for...in 的原型链污染，又让数组方法可以接力，在 IE9 成为底线的年代几乎是必然选择。Object.values 和 Object.entries 在本文写作时还只是提案，2017 年才进标准，当时要用只能基于 Object.keys().map() 自己实现，键值配对、筛选重组都能靠这几行代码解决。真正需要留神的边界是：只看自有可枚举、不递归、数字键会按升序排到前面，以及与 in 运算符在语义上的差别。
