CSS3 渐变 linear-gradient 与 radial-gradient 实战

本文属于《HTML 与 CSS》第 36/62 篇
上一篇系列目录下一篇

渐变是 CSS3 里最直观的特性之一，一个 linear-gradient 就能省掉一张背景图。但 2013 年的浏览器前缀现状让它的写法相当混乱，稍不注意就出现”Chrome 里正常、IE 里纯色”的尴尬。本文从入门角度讲清两种渐变的语法、色标位置、尺寸关键字，以及当年的前缀与降级方案，最后给几个能直接抄走的实战图案。目标是把”看起来差不多”的几个写法彻底分清。

两种写法描述的是同一个视觉结果，但语义完全颠倒。-webkit-linear-gradient(bottom, red, blue) 与 linear-gradient(to bottom, red, blue) 效果相同，而 linear-gradient(bottom, red, blue) 是无效的。2013 年写新代码一律用带 to 的新语法，只为兼容旧版 WebKit 才写无 to 的前缀版本。

角度语法则更直观：0deg 是从下往上，90deg 是从左往右，180deg 是从上往下。

关键字与角度的换算关系是：关键字 to top 等于 0deg，to right 等于 90deg，to bottom 等于 180deg，to left 等于 270deg。这个对应关系常被搞混，记住”角度描述的是渐变前进的方向，0deg 指向上方”即可。

色标与位置百分比

色标可以带位置，位置决定该颜色在渐变线上的确切落点，单位可以是百分比或长度：

多个色标时，若某个色标没写位置，浏览器会在前后已声明的位置之间均匀分配。位置必须递增，乱序的声明会被规范视为无效并忽略。

色标位置最实用的价值是做出硬边。两个相邻色标给同一个位置，中间就没有过渡带，直接切换。这是做条纹、分隔线的基础。

background-size 配合渐变是当年的常用技巧：渐变本身铺满整个元素，但用 background-size 限制它只占一小块，再靠 repeat 平铺成图案。2013 年的浏览器对渐变加 background-size 的组合支持已经比较可靠。

radial-gradient 的形状与尺寸

径向渐变的语法比线性复杂，因为它多出形状、尺寸、圆心位置三个维度。

形状只有两个取值：circle（正圆，半径单一）和 ellipse（椭圆，默认值，有两个半径）。选 circle 时不能指定椭圆式的双半径，选 ellipse 时可以分别指定水平和垂直半径。

尺寸关键字有四个，它们决定渐变结束边缘的位置：

关键字 含义
farthest-corner 默认值，从圆心到最远角
farthest-side 从圆心到最远边
closest-corner 从圆心到最近角
closest-side 从圆心到最近边

对 circle 而言，farthest-corner 与 farthest-side 的表现差异最明显：前者渐变延伸得更远，颜色过渡区域更大；后者更紧凑。选择哪个取决于你想要的效果是”光从中心照亮整个盒子”还是”光晕收紧在一角”。

repeating 渐变

repeating-linear-gradient() 与 repeating-radial-gradient() 是普通渐变的重复版本，只要渐变的长度小于容器，就自动平铺。它做规则图案比手动拼接图片高效得多。

repeating 版本与普通渐变加 background-size 的区别是：前者由色标位置决定周期，后者由 background-size 决定周期。前者写起来更紧凑，后者可以与其他背景属性配合。做图案时选哪种都行，但要注意 repeating 渐变的色标位置必须是绝对长度，用百分比会让周期计算变得反直觉。

2013 年的前缀现状与降级

这是当年最麻烦的部分。渐变语法在 2012 年改过一次，导致浏览器厂商分两批实现，前缀写法各不相同：

要点有三：

  1. 标准写法放在最后一条。同一声明里后写的生效，浏览器不认识的前缀版本会被忽略，认识标准语法的就用标准版。
  2. -webkit- 旧版无 to，且方向语义相反，写错就是上下颠倒。
  3. -ms-linear-gradient 是 IE10 预览版语法，最终版 IE10 支持标准语法。为它单独写一条意义不大，反而增加维护成本，当年更常见的做法是直接放弃 IE10 预览版。

IE9 及以下不支持 linear-gradient，但支持 filter 渐变。这是唯一能在 IE 上做出渐变效果的办法：

filter 渐变有诸多限制：只支持垂直和水平方向（没有角度）、色标最多两个、rgba 透明度需要转成 #AARRGGBB 形式。所以它是纯降级，不能指望表现力。

当年的另一个选择是直接放弃 IE 的渐变，让它显示纯色。判断标准是业务上能否接受，多数项目选择接受。

性能注意

大面积渐变并非零成本。渐变是绘制时实时计算的，元素尺寸大、渐变复杂、且频繁触发重绘时，开销会体现出来。几条实践建议：

  • 动画只改 transform 和 opacity，不要动画 background-image 本身（渐变无法被平滑插值，只会跳变）。
  • 大面积背景渐变如果静态不变，考虑导出为图片，尤其在小屏低端机上。
  • 不要把渐变用在会被反复重排重绘的元素上，比如滚动容器里每一项的背景。
  • 渐变可以作为纯色的降级兜底，但反过来不成立——先写 background-color，再写 background-image，这样渐变不被支持时至少有个颜色。

小结

linear-gradient 与 radial-gradient 在 2013 年已经具备实用价值，语法上要牢记三点：现代 linear-gradient 的方向关键字带 to 且描述的是渐变前进方向，0deg 朝上；色标位置可以精确控制，两个色标同位即得硬边；radial-gradient 的形状、尺寸关键字和圆心位置三者共同决定光晕形态。前缀现状是标准写法放最后、-webkit- 旧版无 to 语义相反、-ms-linear-gradient 基本可弃，IE9 及以下用 filter 做双色垂直渐变降级或直接给纯色。实战中光泽按钮、条纹和斜纹底纹都是几行 CSS 就能搞定的图案，但渐变是实时计算的，大面积静态背景在低端机上值得换成位图。
