HTML5 语义化标签的兼容性处理

本文属于《HTML 与 CSS》第 3/62 篇
上一篇系列目录下一篇

HTML5 语义化标签写起来很爽，但 2013 年的现实是：IE8 及以下完全不认识 header、article 这些元素，页面样式一塌糊涂。本文从兼容性处理的角度，把 html5shiv、条件注释、兜底样式这套组合拳讲清楚，并说明语义化在 SEO 与无障碍上的真实收益。核心结论是：语义化标签的兼容成本极低，真正的成本在于你必须放弃 main 这类当时还不安全的标签。

问题出在哪：IE 不认识未知元素

IE8 及以下的 DOM 实现里，没有在已知元素表中登记过的标签名会被当作”未知元素”处理。未知元素有三个后果：无法作为子节点插入（早期版本甚至会直接丢弃）、无法被 CSS 选择器选中、内部结构被错误地解析。

这段代码在现代浏览器里是一个块级容器，在 IE8 里却可能连节点都建不起来，里面的 h1 也会跟着消失。更麻烦的是，即使节点勉强存在，header { background: #333; } 这样的规则也不会生效，因为 IE 无法为它构建样式。

Remy Sharp 在 2009 年找到了一个非常取巧的解法，也就是后来广为人知的 html5shiv（早期也叫 html5shim）：在文档头部用 document.createElement 先把这些标签名”注册”一遍。

原理在于 IE 的未知元素表是动态的：一旦某个标签名被 createElement 创建过，后续 HTML 解析遇到同名标签就会按已知元素处理，CSS 也能选上它。这就是”shiv”——垫片的意思。

条件注释与兜底样式

条件注释是 IE 独有的注释语法，只有 IE 会解析里面的内容，其他浏览器当成普通注释跳过。它让我们可以把 hack 精确限制在指定版本上，不必让现代浏览器也加载一份多余的脚本。

SEO 与屏幕阅读器的真实收益

语义化对 SEO 的价值常被夸大。搜索引擎在 2013 年已经不那么依赖标题层级和标签语义来判断内容权重，真正影响排名的仍然是内容质量、外链、页面性能。但语义化确实带来两个实际收益：爬虫对结构化内容的抽取更准（article 里的正文比一堆 div 里的正文更容易被识别），以及富媒体摘要（figure 配 figcaption）有机会被更好地呈现。

屏幕阅读器这边的收益是实打实的。一个读屏软件的用户浏览页面的方式，很大程度上依赖地标（landmark）：跳到导航、跳到主内容、逐条读文章。nav、main、article 配上对应 role，就是给读屏软件铺路。没有它们，用户只能从头听到尾。

迁移时的几个实践建议

第一，不要在项目里混用两套容器命名。既然上了语义标签，就不要再写 <div id="header">。混用的结果是后来者根本分不清该用哪个。

第二，类名与标签名解耦。标签管语义，类名管样式，.sidebar 挂在 aside 上，而不是给 aside 本身写一堆样式。这样以后想把 aside 换成 div，只动 HTML 不动 CSS。

第三，section 不是 div 的替代品。规范里 section 是”主题性分组”，应该有标题。如果一段内容只是想包起来加样式，用 div；如果是一个有意义的主题块，用 section。滥用 section 会让文档大纲变得稀碎。

第四，保留一份降级检测清单。每次改动结构，在 IE8 里过一遍。条件注释的样式文件要单独维护，别让它和主流样式混在一个文件里，否则一次重构就可能把 IE 的修正规则连带删掉。

小结

HTML5 语义化标签的兼容处理在 2013 年已经很成熟：html5shiv 用 document.createElement 骗过 IE 的未知元素表，条件注释把它限制在 IE8 及以下，再加一份 display: block 兜底样式，三步就能让老浏览器正确渲染。语义化的收益主要在无障碍和内容结构化，对 SEO 是温和的正向作用而非决定性因素。main 标签当时尚不安全，配合 role="main" 的 div 是更稳的选择。整个方案的代码成本不超过二十行，真正需要投入的是团队约定——标签管语义、类名管样式，以及每次都记得在 IE8 里验证一次。
