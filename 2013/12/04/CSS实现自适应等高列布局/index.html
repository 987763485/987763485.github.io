CSS 实现自适应等高列布局

本文属于《HTML 与 CSS》第 26/62 篇
上一篇系列目录下一篇

多栏布局里最磨人的需求，莫过于”几栏内容不一样多，但高度要一样”。内容少的栏背景色总在中间就断掉，露出一道刺眼的白边。这个问题困扰了 CSS 布局很多年，2013 年的我们手里已经有好几套解法，但每一套都有代价。本文按”负 margin 补偿法、伪元素背景法、table 布局法、Flexbox 法”的顺序逐个拆解，最后给出兼容性表和选型建议。

为什么等高是个难题

要理解这个问题，先得接受一个事实：CSS 的盒模型里，每个块级元素的高度由它自己的内容决定。父元素不会因为某个子元素更高而自动把其他子元素拉高，这与表格单元格的行为正好相反。表格里 td 天生等高，是因为表格的行高由行内最高的单元格决定。

flowchart TD
    A[父容器] --> B[栏一 内容多 高]
    A --> C[栏二 内容少 矮]
    B --> D[栏一背景铺满自身高度]
    C --> E[栏二背景在中途结束]
    E --> F[视觉上出现断层]

于是”等高”这个需求本质上是在问：能不能让一栏的背景延伸到与最高栏齐平的位置。注意是”背景齐平”，而不是把内容撑开——后者通常不是想要的。接下来所有方案，思路都是”给矮栏的背景造假”，只是造假的手法不同。

方案一：负 margin 补偿法

这是最经典也最取巧的一套。核心思路是：父容器给一个远大于实际内容高度的 padding-bottom，同时用 overflow: hidden 把溢出的部分裁掉；每个栏再配一个等大的负 margin-bottom，把自己的实际占位高度抵消掉。这样父容器的高度由最高的栏决定，而每栏的背景因为被拉伸到了 padding 区域，视觉上就等高了。

方案二：伪元素背景法

这是 2013 年的主流做法，也是笔者当年最常用的一套。思路是把”假的等高栏”从真实的栏里拆出来，交给绝对定位的伪元素去铺：容器的 ::before 和 ::after 分别铺满左右两栏的区域，高度设为 100%，因为它们是绝对定位且容器是定位上下文，100% 会撑到容器实际高度——而容器高度已经由最高的栏决定了。

实际写法上有一个细节：真实栏的背景通常是透明的，颜色交给伪元素画；或者真实栏保留背景，伪元素只负责补差额。两种都可以，但真实栏不能盖住伪元素，必要时给栏加 position: relative; z-index: 1。

它的优点是零魔法数字、兼容 IE 8 及以上（IE 8 支持 ::before 但要用单冒号语法 :before），且不影响文档流。缺点是：伪元素只有两个，做三栏以上就要嵌套或者借用真实元素配合；绝对定位的伪元素不能响应点击，如果栏上有可点击背景就要注意层级；此外 bottom: 0 依赖容器高度确定，容器若被内容撑开的过程是异步的（比如等图片加载），会出现先错位再校正的闪烁。

方案三：display: table 与 table-cell

这套方案返璞归真：既然表格天生等高，那就把元素”变成”表格。

table-layout: fixed 在这里几乎必写：它让列宽只由第一行或显式宽度决定，不参与内容计算，这样”自适应等宽”和”内容不等高”才能同时成立。vertical-align 也要显式写 top，否则默认的 baseline 会在文字行高不一致时让各栏内容参差不齐。

优点是代码最少、语义最直接，等高是渲染引擎白送的，不需要任何造假；对 IE 8 及以上都支持。缺点是：table-cell 之间不能有空白字符，否则会出现空格间隙；单元格不能设置 margin，间距只能用 padding 或者 border-spacing（后者会作用到整个表格外圈，需要负 margin 抵消）；它对响应式不友好，改成单列堆叠时必须把 display 换回 block；此外它无法直接实现”某一栏固定宽、其余自适应”之外更复杂的弹性分配。

方案四：Flexbox 的 align-items: stretch

Flexbox 把等高做成了默认行为：容器的 align-items 初始值就是 stretch，意味着所有 flex 项目在交叉轴上被拉伸到与容器一致。也就是说，只要不显式改 align-items，Flexbox 天然等高，什么都不用写。

2013 年用 Flexbox 的真实处境是：语法还没统一，-webkit-box、-ms-flexbox、flex 三套并存，且子属性名各不相同；IE 10 实现的是 2011 年的中间语法，IE 9 及以下完全不支持。所以它只能作为渐进增强：先保证 table-cell 或伪元素法在所有浏览器里等高，再在支持 Flexbox 的浏览器上换用更灵活的写法。

分隔线怎么画：linear-gradient 的小技巧

等高列布局几乎总要配一条竖向分隔线。早年做法是给栏加 border-left，但这会让加了边框的栏总宽多出 1 像素，在百分比宽度下必然错位，得配合 box-sizing: border-box 或者把宽度手动减 1 像素。

2012 年 linear-gradient 普及之后，出现了一个更干净的办法：把分隔线画在容器的背景上。用两条硬过渡的渐变，在 50% 和 50.01% 处各放一个颜色断点，就能画出 1 像素的纯色线，且完全不占用布局宽度。

这个写法的关键是两个颜色断点挨得极近（49.99% 到 50%、50.01% 到 50.02%），浏览器渲染出的就是一条 1 像素的线。三栏就写两组断点。它的优点是零布局影响、宽度自适应；缺点是百分比断点在非整数像素宽下可能被抗锯齿成一条模糊的浅线，需要实测微调；另外老浏览器要加 -webkit-、-moz-、-o-、-ms- 前缀，且要准备一张 1 像素的背景图作为降级。

笔者的选型建议分三档：

基线用 display: table-cell。两栏、三栏等宽的常见需求，它是代码最少、行为最稳的方案，从 IE 8 起全覆盖，等高由引擎保证，不需要任何数字。栏间距用 padding 解决，分隔线用背景渐变解决，二者叠加刚好绕开它的两个短板。

伪元素背景法作为补充。当栏数超过三个、或者栏的结构复杂到不适合改成 table-cell（比如栏内还要嵌套浮动），用伪元素把背景补齐。它比负 margin 法干净得多，没有魔法数字，也不会裁掉溢出内容。

负 margin 法留给必须支持 IE 6/7 的项目。它是唯一能在 IE 6 下跑起来的方案，代价是要认真处理那个魔法数字和溢出裁切。如果项目已经放弃 IE 7 以下，这个方案基本可以退出工具箱。

Flexbox 只做渐进增强。用特性检测加 class 的方式，在支持的浏览器里换用 flex: 1 分配宽度，获得 margin 间距和更自由的对齐能力；不支持的浏览器继续走 table-cell。切记不要把它当基线——2013 年的 IE 9 用户还相当多，而它对 Flexbox 一无所知。

最后提醒一个四套方案共同的问题：等高的前提是容器高度由内容决定。如果容器自身被设置了固定高度，或者栏内图片在页面加载完成后才撑开高度，都会出现”先等高后错位”的闪烁。图片场景务必提前指定宽高，让布局在第一轮就稳定下来。

小结

等高的难点在于块级元素高度各自独立，而视觉上要求背景齐平，所以所有方案的本质都是”给矮栏的背景造假”。负 margin 补偿法用大 padding 加负 margin 抵消，兼容最好但满是魔法数字和裁切副作用；伪元素背景法借绝对定位铺满容器高度，是 2013 年的主流；display: table 加 table-layout: fixed 让引擎白送等高，代码最少；Flexbox 的 align-items: stretch 本是默认行为，却受困于三套并存的语法和老 IE，只能渐进增强。选型上，2013 年的稳妥答案是 table-cell 打底、伪元素法补复杂场景、Flexbox 做增强。分隔线优先用 linear-gradient 画在容器背景上，避免 border 带来的 1 像素错位。
