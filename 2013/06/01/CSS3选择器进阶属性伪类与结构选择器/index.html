CSS3 选择器进阶：属性、伪类与结构选择器

本文属于《HTML 与 CSS》第 22/62 篇
上一篇系列目录下一篇

属性选择器、结构伪类和状态伪类是 CSS3 里最实用的一批新能力，它们让很多过去必须靠 JavaScript 判断或者靠后端加 class 的需求，变成了纯 CSS 一行搞定。这篇文章把常用的几类梳理一遍，重点放在它们的匹配语义、兼容边界和写起来够快的用法上。

属性选择器

属性选择器在 CSS 2.1 里就有雏形，CSS3 把通配形式补齐了。七种写法分别对应不同的匹配语义。

最容易混淆的是 ~= 和 |=。前者要求属性值是空格分隔的列表，后者只匹配「值本身」或「值以指定字符串加连字符开头」。语言类属性用 |=，其余列表型属性用 ~=。

需要注意的是，属性选择器匹配的是属性的字面值，不看大小写（HTML 里属性值通常区分大小写，属性名不区分）。要强制忽略大小写，规范层面还没有统一方案，只能靠 JavaScript 预处理。

伪类：状态与结构

CSS3 把伪类分成几类，用途差别很大。

状态类伪类描述用户交互，从 CSS 2.1 就存在：:hover、:focus、:active、:visited、:link。:link 表示未访问的链接，:visited 表示已访问，两者只对带 href 的 <a> 有效。出于隐私考虑，:visited 能改的属性很有限，基本只剩颜色相关的几个，不能再用它读取链接地址。

表单状态伪类是 HTML5 之后新增的实用能力：:enabled 与 :disabled 对应可编辑与禁用的表单控件，:checked 对应被选中的单选按钮和复选框。它们让「选中项高亮」这类需求不再需要 JavaScript。

想要斑马纹表格时，两种写法的结果也常常不同：表格里如果混了 <thead> 或表头之外的元素，nth-child(odd) 的计数就会偏移，nth-of-type(odd) 更稳。

伪元素

伪元素用于创建或选取不存在于文档树中的抽象元素，CSS3 统一用双冒号书写，以区别于单冒号的伪类。常用的是 ::before、::after、::first-line、::first-letter，加上浏览器私有的 ::selection。

选择器性能

写选择器不只是对不对的问题，还有快不快的问题。浏览器的匹配机制是从右往左的：拿到一个复合选择器，它先找最右边那个「关键选择器」匹配的所有元素，再逐层往左验证祖先是否满足条件。

由此得出几条当年的经验规则。

第一，最右边的选择器决定成本。把关键选择器写得越具体越好，.list a 会先抓出页面上所有链接再逐个验证，代价远高于 .list > li > a。能用子选择器就不用后代选择器，能加标签限定就不要裸写。

第二，通配符最贵。* 会匹配所有元素，* > * 这类写法要彻底避免。通配符只适合放在重置样式里针对已知的少量元素使用。

第三，嵌套别太深。.a .b .c .d .e .f 这种写法，每一层都要往上游走一遍。超过三层的后代选择器，通常意味着 HTML 结构该调整了，或者该用一个 class 直接标记目标。

第四，ID 最快，类次之，标签和属性更慢。这不是绝对结论，但在同等级别下成立。把频繁匹配的元素挂上 ID 或专用 class，比堆一串结构选择器更快。

第五，结构伪类本身有成本。:nth-child() 需要对每个候选元素计算它在兄弟节点中的位置，比普通类选择器贵。在长列表上大量使用 :nth-child 时，可以用类选择器兜底，或者只在列表长度可控的场景使用。

第六，别为「好看」复用选择器。同一个选择器在样式表里出现多次，浏览器不会因此多花时间，但维护时会漏改。真正影响性能的是选择器的数量级：一个页面几千条规则和几百条规则，重算时的差距是实打实的。

还有一个当年容易忽略的点：:hover 在触屏设备上的行为。移动端浏览器为了兼容桌面站点，会在首次触摸时模拟 :hover，导致样式闪一下就消失。处理办法是给触屏单独写一份样式，或者在探测到触摸事件后禁用 :hover 规则。这不算性能问题，但和选择器写法直接相关，放在一起提。

兼容边界与兜底

这些选择器在 2013 年的支持情况并不统一。IE8 是分水岭：属性选择器、:first-child、:last-child、:nth-child()、:nth-of-type()、:not()、::before、::after 在 IE8 里可用，但 IE7 及以下全部不支持，::before、::after 在 IE8 也只认单冒号写法。

稳妥的做法是：样式基线用类选择器写死，结构伪类作为增强层叠加。这样老浏览器丢掉的是锦上添花的部分，布局不会塌。

这种写法也叫渐进增强：先保证所有浏览器可用，再让新浏览器更简洁。判断某个选择器当前是否可用，可以用 document.querySelector 做一次探测，不支持的浏览器会抛异常：

小结

属性选择器按字面值匹配，七种写法各有语义，~= 用于空格分隔的列表、|= 用于语言前缀，别混用。结构伪类里 nth-child 按所有子节点计数、nth-of-type 只数同类型标签，混有其他标签时两者的结果会分叉。伪元素用双冒号书写，但 IE8 要额外保留单冒号版本。写选择器时记住引擎从右往左匹配，关键选择器越具体越快，通配符与过深嵌套是主要浪费，ID 与类远快于结构与属性选择器。兼容上以类选择器为基线、结构伪类做增强，再用 querySelector 探测兜底，就能在 IE7 到现代浏览器之间都得到可用的结果。
