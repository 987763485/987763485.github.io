CSS 居中的十种写法与适用场景

本文属于《HTML 与 CSS》第 25/62 篇
上一篇系列目录下一篇

居中大概是 CSS 里被问得最多的问题，也是新手最容易栽跟头的地方。同一个「把盒子放中间」的需求，能写出十几种写法，而每一种都有自己的前提条件和浏览器边界。本文把这十种做法按「水平、垂直、双向」分类讲透，每种都给出适用场景、优缺点和当时的浏览器兼容情况。需要提前说明的是，本文写于 2013 年，Flexbox 刚有现代语法、calc() 刚刚铺开，文中所有结论都以那个年代的环境为准。

为什么居中这么麻烦

CSS 的盒模型决定了：默认情况下，块级元素撑满父容器的宽度，行内元素跟随内容流动。所谓居中，本质上是在打破这种默认的流动方向，让元素在某个轴上回到中点。

水平居中相对简单，因为块级元素有确定的宽度基准（父容器的 content box），margin: auto 就是为这个设计的。垂直居中麻烦得多，因为 CSS 2.1 的垂直布局是基于行盒与 vertical-align 的，而 vertical-align 只在表格单元格和行内上下文里有效，对普通块级元素无能为力。这个设计上的不对称，是垂直居中方案特别多的根本原因。

另一个背景是浏览器碎片化。2013 年的现实是 IE6 到 IE10 并存，Firefox 与 Chrome 迭代迅速，一套代码要在四五种内核里都对，很多理论上优雅的方案就被兼容性卡死了。所以本文的每一种写法都会附上兼容表，选型时先看表，再看优劣。

还有一个容易被忽略的前提：居中对象的类型。同样是「把一个 div 放中间」，这个 div 可能是定宽的、可能是自适应的、可能是脱离文档流的浮层、也可能只是一个行内元素，前提不同，可选方案立即少掉一半。本文的组织方式就是先按「水平、垂直、双向」把问题域切开，再在每个子域里按「是否要求定宽」细分，读者遇到具体需求时可以直接跳到对应小节。

一、text-align: center（水平居中）

最古老的方案，只对行内内容有效。给父容器设置 text-align: center，其中的文本、行内元素、inline-block 元素就会水平居中。

适用场景：段落文本居中、按钮组（多个 inline-block 的按钮并排且整体居中）、图标与文字混排的居中。

优点是零成本、全兼容、不影响布局流。缺点是会继承，父容器里所有的行内内容都被居中，如果内部还有左对齐的模块需要逐个 text-align: left 覆盖；另外它无法让块级子元素自身居中。

二、margin: 0 auto（水平居中）

这是块级元素水平居中的标准做法。给元素自身设置左右外边距为 auto，浏览器会自动平分剩余空间。

适用场景：定宽的内容区块，如文章正文、固定宽度的侧边栏、居中的表单。

关键前提是元素必须有明确宽度。如果 width: auto，块级元素本来就会撑满父容器，剩余空间为 0，auto 无意义。另一个前提是父容器的宽度要大于子元素，否则 auto 同样算不出正值。

优点是完全标准、全兼容、性能好。缺点是只能做水平，且需要预先知道宽度。对于需要响应式的内容，宽度不能用固定值，此时要配合 max-width 使用。

三、position + 负 margin（双向居中）

在 Flexbox 之前，这是双向居中兼容性最好的方案。子元素绝对定位，top: 50%; left: 50%，再用负的 margin-top 与 margin-left 把元素往回拉自身宽高的一半。

适用场景：需要支持 IE6 的弹窗、居中浮层、图片灯箱的居中容器。

优点是全兼容，IE6 也能正常工作，且不依赖父元素的内容高度。缺点是必须知道元素的宽高，一旦内容是动态的，负 margin 就得用 JS 量；另外绝对定位会使元素脱离文档流，父容器如果没有其他内容，高度会塌陷，需要额外撑高。

四、position + margin: auto（top/right/bottom/left: 0 + margin: auto）

这是上一个方案的改良版，也是很多人不知道的技巧。CSS 2.1 规定：当一个绝对定位元素四个方向偏移量都为 0 且宽高确定、margin 为 auto 时，浏览器会把剩余空间平分给四个方向的 margin，元素自然落在正中间。

适用场景：与负 margin 方案相同，但元素宽高动态时更优——不需要写死一半的数值，用 JS 改 width/height 即可，margin 保持 auto 不用动。

优点是代码更简洁、宽高变化时无需同步修改 margin。缺点是 IE6 与 IE7 不支持这种平分行为，它们会把 margin: auto 计算为 0，元素贴在左上角。所以 2013 年如果客户要求兼容 IE6，这个方案只能作为增强。

五、display: table-cell + vertical-align: middle（垂直居中）

利用表格单元格的垂直对齐能力。把父容器设为 display: table-cell，vertical-align: middle 就能让其中的行内内容和 inline-block 子元素垂直居中。

适用场景：不定高的文字块垂直居中、导航项、需要同时支持 IE6 的垂直居中。

优点是兼容性极好，IE6 到 IE8 都支持 display: table-cell，且不需要知道子元素高度。缺点是父容器变成表格单元格后会丢失一些块级特性：不能同时使用 margin: auto 做水平居中（要用 text-align: center 替代），宽度行为变得像表格一样收缩，且 table-cell 元素不能设置 position: relative 之外的某些属性。另外，如果不加 display: table 的外层包裹，单元格宽度会依赖上下文。

表格方案还有一个少有人用的衍生技巧：把 display: table-cell 换成 display: table-row，或者利用表格的 caption-side，可以做出一些特殊的对齐效果。但这些都属于表格模型的边角，实际项目里不如直接记 table-cell 一个值。

六、line-height 等于容器高度（单行文本垂直居中）

如果只是单行文字垂直居中，最简单的办法是让 line-height 等于父容器高度。行盒的高度由 line-height 决定，文字基线落在行盒中部，视觉上就是垂直居中。

适用场景：按钮文字、单行的标题栏、导航项、表格里的单行单元格文字。

优点是极其简单、全兼容、性能最好。缺点是只适用于单行文本，一旦文字换行就会溢出；另外这个方案让行盒和容器等高，如果后续要加 padding，需要同步调整 line-height，维护起来略别扭。对中文还有一点要注意：不同字体的基线与 ascent/descent 比例不同，同样 line-height 下文字的视觉中心可能有 1px 到 2px 的偏差，要求像素级精确时建议用Flexbox 或表格方案兜底。

这里补充一个变体：如果容器高度不确定但希望单行文字垂直居中，可以把 height 换成 padding，用上下内边距撑开容器，此时 line-height 保持一个固定值（比如 20px）即可。这种做法在表单控件和按钮里极其常见，因为它不依赖任何 magic number 之外的高度。

七、inline-block + ::after 撑高（垂直居中）

这是一个非常巧妙的技巧，在 2013 年的实际项目里用得很多。思路是：给父容器加一个 ::after 伪元素，设为 display: inline-block; height: 100%; vertical-align: middle，它会在行内排布中占据整行高度并把基线拉到中间，前面的子元素只要也是 inline-block 且 vertical-align: middle，就会跟着居中对齐。

适用场景：不定高内容的垂直居中，同时需要水平居中，且要兼容 IE8。商品卡片、图文混排的媒体对象都常用这个写法。

优点是不需要知道子元素高度、能同时处理水平与垂直、IE8 支持 ::after（IE6/7 不行）。缺点是依赖行内排布，子元素之间的空白节点（HTML 里的换行与空格）会产生间隙，需要处理；另外 ::after 的内容不能为空字符串之外的形式，且父容器不能有 overflow: hidden 干扰。

空白间隙的处理办法是给父容器设置 font-size: 0，子元素再单独设置字号，这是当时的标准做法。

八、Flexbox（justify-content + align-items）

Flexbox 是 CSS3 里为这类问题准备的正解。2013 年的情况是：现代语法在 2012 年定稿，Chrome 与 Firefox 需要 -webkit- 前缀，IE10 支持现代语法但仍有少量 bug，IE9 及以下完全不支持。

适用场景：现代浏览器项目、移动端页面、后台管理系统的组件居中、需要同时处理多个子元素间距的场景。

优点是代码最简洁，且语义清晰；不需要知道子元素尺寸；多个子元素时自动分配空间，配合 flex-wrap 能处理换行。缺点是兼容性在当时受限，且 Flexbox 规范本身经历过 2009 草案、2011 年重构、2012 年现代语法三个阶段，网上大量教程的语法互相冲突，需要特别注意自己抄的是哪一代。

当时的三代语法大致是这样：2009 年的草案是 display: box，2011 年的中间版是 display: flexbox，2012 年的现代版才是 display: flex。IE10 只认现代语法，所以不需要为它写 -ms- 前缀。

Flexbox 居中还有两个高频变体。第一个是只做垂直、不做水平，此时省略 justify-content 即可，但 align-items 的默认值 stretch 会把子元素沿交叉轴拉满，必须显式改成 center。第二个是子元素需要保持自身宽高，此时要给子元素明确尺寸，否则会被 stretch 拉伸。

多个子元素之间的间距分布交给 justify-content 的其他取值：space-between 把空隙分到元素之间，space-around 让每个元素两侧都有空隙。这几个值在 2013 年的 Flexbox 里都可用，也是它相对传统方案最大的增量价值。

九、transform: translate(-50%, -50%)（双向居中）

CSS3 的 transform 在 2012 年后现代语法稳定，这个方案的核心是利用 translate 的百分比是相对元素自身尺寸这一特性，把绝对定位到 50% 的元素往回拉自身的一半。

适用场景：内容宽高不固定的居中浮层、tooltip、模态框、图片在容器里的居中。

最大的优点是不需要知道元素宽高，百分比基于自身计算，内容变化时自动居中。这也让它成为 2013 年内容动态场景下的首选方案。

缺点是 IE8 及以下不支持 transform（IE9 开始支持，但早期版本对 translate 百分比的支持有争议，实际项目建议在 IE9 上验证）。另外 transform 会影响元素的渲染层级与模糊处理，某些场景下需要配合 z-index 调整。还有一点：transform 会让元素创建一个包含块，影响内部 position: fixed 子元素的定位基准，嵌套浮层时要留意。

十、绝对定位 + calc()

calc() 在 IE9 与 Chrome 19 之后开始支持，2013 年已经可以用于生产环境，但需要评估兼容成本。思路与负 margin 类似，只是用 calc() 把「一半宽度」算出来，从而不需要写死具体数值。

适用场景：宽高已知、但希望减少硬编码的固定宽度场景；在需要与其他 calc() 计算（比如宽度减去固定 padding）组合时尤其方便。

优点是语法直观，能与响应式布局的百分比宽度配合计算。缺点是兼容性比前几种方案窄，IE8 及以下、Firefox 4 之前的版本不支持；另外老版本浏览器对 calc() 内部空格有严格解析要求，calc(50%-30px) 不写空格会直接解析失败，这是当时很常见的一个坑。

如果元素宽高不定，还可以用负 margin 与 calc() 之外的另一种思路——margin 百分比：垂直方向的 margin 百分比是相对父容器高度计算的，因此也可以用 margin-top: 25% 之类的百分比，但要求父容器有确定高度，且百分比必须是相对值的一半，实际使用受限，这里只作为补充提及。

最后补充一种老派但至今仍在用的思路：padding 撑挤法。如果不需要元素相对父容器居中，而只是希望「左右留白相等」，可以直接用百分比或 auto 的左右 padding 把内容挤到中间，语义上比绝对定位干净得多。

这种写法的关键是 max-width 与 margin: 0 auto 必须同时出现：只有百分比 padding 而没有宽度上限，超宽屏下内容会被拉到屏幕边缘；有了 max-width，margin: auto 才重新接管剩余空间的分摊。它是 2013 年做「内容区限宽居中」事实上的标准答案，也是十种方案之外最常用的一种。

几条经验性的结论：

如果项目 2013 年还需兼容 IE7，垂直居中的主力只能是 table-cell 方案与 line-height 方案，双向居中用负 margin。Flexbox 再好也只能作为渐进增强。

如果只面向 Chrome 与 Firefox，无脑用 Flexbox，代码量与可维护性都最优。

如果元素内容高度不固定且需要支持 IE9，transform: translate(-50%, -50%) 是综合最优解，它不需要 JS 介入，也不需要维护一份宽高的副本。

如果同时需要水平和垂直，且父容器高度也是动态的，建议优先考虑 Flexbox，其次是 inline-block + ::after，因为负 margin 与 calc() 都要求父容器高度确定。

坑与调试

坑一：margin: auto 失效。绝大多数情况是因为没有给元素设宽度，或者父容器没有形成格式化上下文。用开发者工具看计算后的 margin-left 是否真的是 auto，如果显示为具体像素值，说明宽度没约束住。

坑二：vertical-align: middle 不生效。这个属性只对表格单元格与行内级别元素有效，给一个普通块级 div 设置它毫无作用。误用的根源是把 HTML 里默认的行内行为当成了块级行为。

坑三：百分比 top 与 margin 的基准不同。top: 50% 相对父容器高度，而 margin-top: 50% 同样相对父容器高度，但 translateY(-50%) 相对元素自身。混用时容易算错，写之前先确认基准。

坑四：Flexbox 的 align-items 与 align-content 混淆。单行居中用 align-items，多行且换行时才需要 align-content。2013 年不少教程把两者混着讲，抄错属性名会导致静默失效。

坑五：calc() 的空格。calc(50% - 30px) 的加减号两侧必须有空格，乘除可以不留。早期浏览器对这一点解析不一致，属于纯粹的手写规范问题。

坑六：负 margin 方案在元素高度超过父容器一半时的反向溢出。当子元素高度大于父容器高度的一半，top: 50% 加负 margin 会把元素中心推到父容器中心，元素两端都会溢出，视觉上「偏了」。这种情况下要么给父容器加 overflow: auto，要么改用 Flexbox 的 align-items: center，后者在内容超高时会向上溢出但中心仍然正确。

坑七：inline-block 的基线间隙。第七种方案里子元素是 inline-block，而行内块的基线对齐规则会让它和伪元素之间产生额外的行盒高度，导致父容器实际内容高度大于 height: 100% 的预期。解决办法除了 font-size: 0，还可以给子元素加 vertical-align: top 并调整伪元素的 vertical-align，具体取值需要按实际结构试。

坑八：Flexbox 里的 margin: auto 与 justify-content 混用。在 Flex 容器里给子元素设 margin: auto 会自动吸收剩余空间，效果等价于居中，但此时再设置 justify-content 就不会再生效，两者混用容易产生「改了没反应」的困惑。建议在一个组件里只用一种机制。

调试这些问题的通用办法：先用浏览器的开发者工具（Chrome DevTools 的 Elements 面板或 Firebug）查看元素的计算样式与盒模型，确认每个属性的实际生效值；再用 Timeline 面板排除掉重排导致的居中抖动；最后在真实的目标浏览器里验证，不要只在 Chrome 里看效果。

调试时还有两个小技巧值得记住。第一，临时给居中的元素加一个鲜艳的 outline（IE8+ 支持，不影响布局），可以直接看出元素盒子与视口的相对位置，比反复猜要快得多。第二，把父容器的高度临时改成一个极端值（比如 10px 或 2000px），观察元素是否仍然居中，可以快速区分「方案本身错了」和「父容器高度没有传递下去」。

小结

居中的十种写法本质上是三代思路的叠加：CSS 2.1 时代靠 margin 与 text-align 处理水平，靠 line-height 与表格单元格处理垂直，双向居中只能靠绝对定位加负 margin 手工回拉；CSS3 时代 transform 与 calc() 让「相对自身回拉」成为可能，Flexbox 则把居中变成容器属性。2013 年的选型不是「哪个最好」，而是「兼容底线在哪里」：底线 IE7 时主力是表格与负 margin，底线 IE9 时可以引入 transform，底线 IE10 才能放心用 Flexbox。理解每一种方案的前提条件（是否定宽、父容器是否有高度、是否脱离文档流）比记住代码更重要，因为这些前提正是它们失效的原因。
