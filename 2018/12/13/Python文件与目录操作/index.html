Python 文件与目录操作

本文属于《Python 学习路线》第 7/29 篇
上一篇系列目录下一篇

写脚本的人迟早会遇到这样的需求：把一批日志按月归档、把上传目录里的临时文件清掉、给配置生成一份备份。这些事情看起来只是几句 open 和 os 调用，真正放到生产机上却会冒出编码错误、权限拒绝、文件被占用、路径穿越等一连串问题。

本文从路径拼接讲起，依次覆盖文件读写、目录遍历、复制删除、临时文件与原子写，最后落到权限与安全边界。读者只需要会基本的 Python 3 语法；读完应当能写出在 Linux 与 Windows 上都不容易出事的文件操作代码，并知道哪些写法是明令禁止的。

路径的两套 API：os.path 与 pathlib

Python 里处理路径有两套并存的接口。一套是 os.path 的函数集合，从 Python 2 时代沿用至今；另一套是 3.4 引入、在 3.6 之后逐渐成熟的 pathlib。两套都能用，但混着用会让代码风格割裂，先各自看清楚。

os.path：函数式接口

os.path 把路径当成普通字符串，所有操作都是函数调用。最常用的是 join、dirname、basename、splitext 和 abspath。

这里有两个容易误解的地方。第一，join 只负责拼接，不会检查目录是否存在，也不会把 .. 规范化；传入绝对路径时会直接丢弃前面的部分，os.path.join("/tmp/example", "/etc/passwd") 的结果就是 /etc/passwd。第二，splitext 按最后一个点切分，对 .bashrc 这类以点开头的文件会返回空扩展名，这与 shell 通配符的直觉并不一致。

os.path.exists、isfile、isdir 返回布尔值，看起来很好用，但它们是“某一瞬间”的快照。判断通过之后、真正打开之前，文件完全可能被别的进程删掉或替换，后文会专门讨论这种竞态。

pathlib：把路径当成对象

pathlib.Path 把路径封装成对象，用 / 运算符拼接，属性和方法都挂在对象上，读起来更接近自然语言。

几个方法值得记住。resolve() 返回绝对路径，同时把 .. 和符号链接展开成真实位置；3.6 之后 strict 默认是 False，路径不存在也不会抛异常，适合“先算路径、稍后创建”的场景。expanduser() 把 ~ 展开成主目录，is_absolute() 判断绝对路径，parts 把路径拆成元组，便于做前缀检查。

为什么新项目优先 pathlib

第一，类型清晰，Path 不会被误当成文件内容，拼接也不会漏分隔符。第二，跨平台，/ 在 Windows 上自动产生反斜杠，不需要 os.sep。第三，方法齐全，判断与遍历可以链式表达。

代价是一部分老库只认字符串，用 str(p) 转换即可；Path 的比较遵循平台的文件名规则，判断两个路径是否指向同一位置时，最好先 resolve() 再比。从 3.6 起 open 与 os 的多数函数都接受路径对象（PEP 519），日常代码可以全程用 Path，只在调用外部命令时转字符串。

文件读写：模式、编码与上下文管理

路径解决“在哪里”，接下来是“怎么读写”。open 的参数不多，但每一个都对应一类事故。

模式字符的含义

open 的第一个参数是路径，第二个是模式字符串。基础模式有四个：r 只读，文件必须存在；w 只写，文件不存在则创建，存在则清空；a 追加，写入位置永远在末尾；x 独占创建，文件已存在就抛 FileExistsError。这四个都可以加 + 变成可读可写，加 b 变成二进制模式。

需要特别记住的是 w 的破坏性：打开瞬间就把文件截断为零字节，哪怕一行都没写。要原地修改应当用 r+，它要求文件已存在且不截断，但读写共用一个位置指针，写完必须 seek(0) 才能从头读。x 模式则适合“生成新文件”，文件已存在就抛异常，比先 exists 再 open 可靠。

encoding 必须显式写出

Python 3 的文本模式要在字节和字符串之间解码，编码由 locale.getpreferredencoding(False) 决定。Linux 与 macOS 通常是 UTF-8，Windows 简体中文环境往往是 GBK，同一份代码换台机器就读出乱码。

所以在文本模式下 encoding="utf-8" 应当视为必填。读取来源不明的文件可以先用 errors="replace" 兜底，确认后再改严格模式；写入不要用 errors="ignore"，那会静默丢字符。

with 与逐行读取

文件对象持有系统句柄，数量有上限，忘记关闭会逐渐耗尽，写操作还可能在缓冲区里丢数据。with 保证退出时调用 close()，即使中途抛异常也一样；手工 open/close 一旦中间有 return，关闭就被跳过。

读取大文件时不要用 read() 或 readlines()。readlines() 返回一个列表，每个元素是一行字符串，文件有多大，内存里就至少有一份多大的副本，外加每个字符串对象几十字节的开销。一个两 GB 的日志用 readlines() 读，进程很可能直接被系统的内存限制杀掉。

目录操作：创建、遍历与删除

目录操作的核心矛盾是“幂等”。部署脚本、定时任务往往重复执行，创建目录的代码必须能在目录已存在时安然通过，而不是第二次运行就报错退出。

创建目录

os.mkdir 只能建一级，父目录不存在就失败；os.makedirs 逐级创建，配合 exist_ok=True 可以重复执行。mode 参数受 umask 影响，最终权限是 mode & ~umask，传入 0o777 并不等于得到 777。

exist_ok=True 只忽略“目录已存在”。若同名路径是普通文件，仍会抛 FileExistsError，所以它不是万无一失的保险。

遍历目录

os.walk 返回三元组 (dirpath, dirnames, filenames)，默认自顶向下。它最大的特点是可以在循环里修改 dirnames 来剪枝，跳过不需要进入的目录，这对扫描大目录树非常实用。

这里必须用切片赋值，直接写 dirs = [...] 只是重新绑定局部变量，os.walk 看不到修改。os.walk 默认不跟随符号链接，打开 followlinks=True 后遇到指向上级的链接可能无限递归，需要自己记录已访问的真实路径。pathlib 的 iterdir()、glob()、rglob() 更紧凑，返回生成器，顺序不做保证。

删除目录

os.rmdir 与 Path.rmdir() 只能删空目录，目录非空会抛 OSError。删除非空目录要用 shutil.rmtree，它会递归删掉整棵树，没有回收站，也没有二次确认。

风险不在函数本身，而在参数。变量写成空字符串、None 或上一层的父目录，后果都不可逆。稳妥做法是先用 resolve() 得到绝对路径，断言它位于预期根目录之下，并把待删清单写进日志。

复制、移动与删除

shutil 是标准库里的高层文件操作模块，屏蔽了底层的读写循环，但它的几个函数在元数据和符号链接上的行为并不一致，选错会留下难以察觉的差异。

copy 与 copy2

shutil.copy(src, dst) 复制文件内容，并把权限位一并复制过去；shutil.copy2 在此基础上再复制时间戳等元信息。两者都不复制属主，因为修改属主需要 root 权限，普通用户本来也做不到。

下游若依赖修改时间做增量判断，就必须用 copy2：copy 复制出的文件修改时间是“现在”，备份工具会误判它刚被改动。只求内容一致时，copy 够用。

copytree 与 move

shutil.copytree 递归复制整棵树，但要求目标目录不存在，3.7 没有“合并到已有目录”的参数，需要合并只能自己遍历后逐个 copy2。symlinks 默认 False，会把链接指向的内容复制成普通文件；设为 True 才复制链接本身，备份场景通常选后者。

shutil.move 先尝试 os.rename，同一文件系统内是原子操作；跨设备时退化为“复制加删除”，中途失败可能留下半份文件。它覆盖已有文件的行为在两个平台上不同，跨平台脚本应先判断目标。

删除文件

os.remove 与 os.unlink 是同一个函数，只能删文件；Path.unlink() 等价。rmtree 遇到符号链接删除的是链接本身，不会跟进目标目录，但它对传入路径没有任何保护，作用域写错就是灾难。

这段检查只是最低限度的护栏，真实系统里还应结合配置项做白名单，避免路径来自用户输入。

临时文件与原子写入

直接往目标文件写有隐患：写到一半崩溃或磁盘写满，目标就变成残缺内容，而读者无法分辨。解决办法是先写临时文件，成功后再替换。

tempfile.NamedTemporaryFile 在系统临时目录生成唯一文件名，避免手工拼 xxx.tmp 带来的冲突与符号链接攻击。它在 Windows 上默认独占打开，通常要配 delete=False，关闭后自行清理。TemporaryDirectory 更省事，进入 with 得到目录，退出时整棵删除，适合解压、转码的中间产物。

临时文件必须与目标在同一目录，否则 os.replace 会因跨文件系统直接失败。先 fsync 再替换，可以避免断电后“名字换了、内容还在页缓存”的情况。

编码、换行与二进制

UTF-8 是最稳妥的默认选择，但要注意 BOM。Windows 记事本保存的 UTF-8 常带 BOM，用 utf-8 读取会在首行多出一个不可见字符，导致配置键名匹配失败；读这类文件用 utf-8-sig，写文件时则不要用。

换行由 newline 控制。文本模式默认启用通用换行，读取时把 \r\n 与 \r 转成 \n，写入时把 \n 转成平台换行符，同一份文件在 Windows 上是 CRLF、Linux 上是 LF，校验和自然对不上。需要字节稳定时写入指定 newline="\n"；处理 CSV 时按文档传 newline=""，把控制权交给 csv 模块。

二进制模式不涉及编码与换行转换，读到的是 bytes。两种模式不能混用：把 str 写进 wb 文件会抛 TypeError，反之亦然。图片、压缩包一律用 rb 与 wb。

文件元信息与权限

os.stat 和 Path.stat() 返回 st_size、st_mtime、st_mode 等字段。注意 st_size 是逻辑大小，稀疏文件或压缩文件系统上的实际占用要看 st_blocks；st_mtime 是浮点秒数，精度取决于文件系统，不能当作严格递增的版本号。目录的 st_size 在各平台含义不同，不要拿它统计目录内容。

权限用 os.chmod(path, 0o644) 设置，八进制写法最直观：属主读写、同组与其他用户只读。chmod 不改变属主，修改属主要 os.chown，且需要 root 权限；普通用户的脚本不应假设自己能做这件事。部署时更常见的做法是让服务以专用账户运行，目录属主设为该账户，权限收紧到 0o750，而不是到处 777。

安全与健壮性

最典型的漏洞是路径穿越。用户传入 ../../etc/passwd，代码直接 os.path.join(base, name)，拼出来的路径就跑到了预期目录之外。仅靠字符串替换 ../ 并不安全，编码变形、绝对路径、Windows 的反斜杠都能绕过。

可靠的做法是取文件名部分，拒绝任何分隔符，再用 resolve() 后的公共前缀做二次校验。os.path.commonpath 比字符串 startswith 更不容易被 /tmp/example-evil 这种同前缀目录骗过。

符号链接是另一类风险。若攻击者能在上传目录里预先放一个指向 /etc/shadow 的链接，后续以高权限运行的写入就可能落到目标上。上面的示例会因 resolve() 越界而拒绝这类链接；代码若绕开了校验，则至少应用 x 模式创建、用 tempfile.mkstemp 拿唯一名字，并在打开后检查 os.path.islink 与 stat 的 st_uid。

异常处理要区分场景。PermissionError 说明权限不足，通常应记录后跳过；FileNotFoundError 可能是父目录没建；Windows 上文件被其他进程占用也会抛 PermissionError，底层 winerror 为 32，重试若干次往往能成功，而在 Linux 上已删除但仍被打开的文件不会阻止删除。OSError 的 errno 比异常文本更适合做分支判断。

常见坑

忘记关闭文件是最普遍的。CPython 的引用计数会在对象销毁时关闭文件，但那是实现细节，PyPy 上回收时间不确定，长驻进程里句柄会越积越多。一律用 with。

用 os.path.exists 先判断再操作，属于典型的检查与使用分离，两个瞬间之间文件可能已被删除或替换，正确姿势是直接操作并捕获异常。

rmtree 的作用域写错，多半源于变量复用或配置缺失，删除前务必打印绝对路径并做前缀断言。

Windows 的路径分隔符与保留名也常被忽略：CON、PRN、AUX 等名字无法作为文件名，路径总长还有约 260 字符的限制，跨平台脚本要预留余量。

小结

文件与目录操作不难，难在边界。路径统一用 pathlib，文本读写显式指定 encoding 与 newline，大文件坚持逐行迭代，目录创建带上 exist_ok=True，删除前先断言作用域。复制用 copy2 保留时间戳，需要合并目录时自己遍历，临时文件与目标放在同一目录再用 os.replace 完成原子替换。最后，凡是路径来自外部输入，都要做规范化与越界校验，并假设检查与使用之间文件已经改变。

把这些习惯固定下来，脚本从开发机搬到服务器时，就不会因为一个编码参数或一个斜杠而返工。
