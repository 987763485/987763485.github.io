Vue 2 全家桶入门实践

刚接手一个 Vue 项目时，最容易迷路的不是模板语法，而是“这个功能该写在哪”：请求放在组件里还是 action 里，页面参数从 URL 取还是从 store 取，打包后的白屏又是谁的责任。本文以 2018 年初的主流工具链为背景，把 vue-cli 2 的脚手架、单文件组件、路由、状态、请求封装和上线部署串成一条完整的线。适合已经会写 Vue 基础语法、但还没独立搭过一个完整项目的读者。

全家桶指什么

“全家桶”是社区叫法，不是官方术语。它指的是围绕 Vue 核心库的一组配套：vue-router 负责路由，Vuex 负责共享状态，axios 负责 HTTP 请求，vue-cli 与它背后的构建工具负责工程化。这几样东西各管一段，边界清楚，组合起来才称得上“桶”。

需要注意 axios 并不是 Vue 官方项目，只是它的 Promise 风格与拦截器设计恰好契合当时的开发习惯，逐渐成了事实标准。把它们的分工摊开看，大致是这样：

  • Vue 只负责视图层，把数据渲染成 DOM，并把用户操作变成事件；
  • vue-router 把 URL 映射成组件树，让“页面”这个概念落在地址栏上；
  • Vuex 存放需要跨组件共享的状态，典型是登录用户、权限和全局配置；
  • axios 与后端通信，把响应交回组件或 action；
  • vue-cli 提供目录约定、开发服务器、热更新与生产构建。

一个最小的入口文件就能看出这种分层。main.js 只做三件事：装配根组件、挂上路由、挂上 store。

反过来也要说清楚：不是所有项目都需要全家桶。一个活动页、一个只有两三个视图的展示站，引入路由和状态库只会增加心智负担，组件内维护几个字段反而更直接。判断标准很简单：当出现“多个页面共享同一份数据”和“需要直接访问某个地址”这两个需求时，才值得把它们请进来。

用 vue-cli 2 搭起骨架

当时的脚手架还是 2.x 版本，安装后通过 vue init 拉取模板。2017 年的 webpack 3 已经足够稳定，模板也提供 webpack、webpack-simple、browserify 三种选择，做正式项目一般选第一种，因为它自带热更新、ESLint、单元测试和生产构建配置。

组件是 Vue 的基本单位，.vue 文件把视图、逻辑和样式收在一处，避免在三个文件之间来回跳。下面是一个带交互的卡片组件：

三块内容的分工很清楚：<template> 描述结构，编译后变成 render 函数，且只能有一个根元素；<script> 导出组件选项，data 写成函数是为了让复用同一组件的多个实例互不干扰；<style scoped> 由构建工具给元素加上 data-v- 属性，使选择器只命中本组件。这里的边界并不绝对，子组件的根节点仍会受父组件 scoped 样式影响，需要穿透时用 >>> 或 /deep/。

lang 属性用来切换预处理器。开发后台项目时常见 <style lang="scss" scoped>，脚手架里已经预留了 scss、less、stylus 的处理规则，装上对应的 loader 与编译器就能用；模板换成 <template lang="pug"> 也是同样的道理。至于 <script lang="ts">，涉及类型声明与装饰器，属于另一套工程改造，本文不铺开。

组件之间的数据流只有一条主线：props 向下，事件向上。父组件通过 :user="currentUser" 传值，子组件用 this.$emit('follow', id) 通知，父组件再写 @follow="onFollow" 接收。子组件不应该直接修改 props，否则数据流向就乱了，调试时很难判断是谁改的。需要“看起来双向”的场景，比如弹窗开关，可以用 .sync 修饰符省掉一个事件名：父组件写 :visible.sync="show"，子组件触发 this.$emit('update:visible', false)。

把页面交给 vue-router

路由做的事情是把 URL 映射成组件树。项目里的路由表通常集中在一个文件，新增页面就是加一条记录：

mode 有两个取值。默认的 hash 模式地址里带 #，刷新不会打到服务端，部署最省心；history 模式地址干净，但要求服务端把未匹配的路径回退到 index.html，否则刷新子路由就是 404。<router-view> 是渲染出口，通常放在 App.vue 或布局组件里；<router-link to="/user/1"> 会生成 <a> 标签，并在激活时带上 router-link-active 类名，比手写点击跳转更利于无障碍和右键新开。

参数分两种，别混用。params 是路径的一部分，比如 /user/:id 里的 id，刷新后依然存在；query 是问号后面的键值对，适合分页、筛选这类可选条件。组件内用 this.$route.params.id 读取，跳转用 this.$router.push({ name: 'userDetail', params: { id } })。记住 $route 是当前路由信息对象，$router 是路由实例，前者读、后者跳。

用 Vuex 收拢共享状态

当登录信息、菜单权限、未读数量这些数据被多个页面读写时，靠父子传参已经不现实。Vuex 的思路是建一个全局仓库，所有组件都从同一个地方取，也往同一个地方写。核心概念只有五个：

state 是单一数据源；getters 相当于仓库里的计算属性，依赖不变就不会重算；mutations 是修改状态的唯一入口；actions 负责异步流程，拿到结果后提交 mutation；modules 让每个业务模块拥有自己的 state 与 mutation，避免一个文件膨胀到上千行。加上 namespaced: true 之后，调用要带前缀，比如 this.$store.dispatch('user/login', form) 和 ...mapState('user', ['profile'])。

很多人问为什么 mutation 必须同步。原因在调试：开发者工具会记录每一次 mutation 的提交，并保存提交前后的状态快照，时间旅行就是靠重放这些快照实现的。如果 mutation 里夹着 setTimeout 或请求回调，快照之间的因果关系就断了，工具显示的顺序与实际修改顺序对不上，排查问题时反而更乱。所以约定很明确：同步赋值写在 mutation，异步逻辑写在 action。

开发阶段的跨域由代理解决。浏览器的同源策略只认协议、域名、端口三元组，本地页面跑在 8080，接口在 8000，请求就会被拦。config/index.js 里的 proxyTable 让开发服务器代转发，浏览器看到的一直是同源地址：

构建产物、部署与按需加载

执行 npm run build 之后，2017 年的 webpack 3 配置 build/webpack.prod.conf.js 会做三件事：压缩 JS 与 CSS、把样式抽成独立文件、给文件名加内容哈希。产物全部落在 dist/ 下：

index.html 里的资源引用由 config/index.js 的 assetsPublicPath 决定。默认是 /，适合部署在域名根目录；如果项目要放到 https://example.com/admin/ 这样的子路径下，就必须改成 /admin/，否则浏览器会去根目录找 js，控制台一片 404，页面白屏。带哈希的文件名可以配合 Cache-Control 做长期缓存，而 index.html 本身不要缓存，否则用户拿到的还是旧入口。

发布流程也值得固定下来：把 dist/ 整个目录传到服务器的对应路径，先覆盖 static/，最后替换 index.html。顺序反过来的话，用户在切换的几秒内可能拿到新入口、却引用到还没上传的旧 chunk，表现为随机白屏。回滚同理，保留上一版目录即可。

几个反复踩到的坑

第一个是 this 指向。Vue 会把 methods 和生命周期钩子绑定到组件实例，但回调函数里的 this 不受保护：

第二个是响应式限制。Vue 2 通过 Object.defineProperty 在初始化时递归转换数据，所以新增的属性不会被追踪，数组按下标赋值也检测不到：

数组的 push、pop、splice、sort 等方法被 Vue 重写过，可以放心用；对象整体替换 this.obj = { ...this.obj, newKey: 'value' } 同样能触发更新。

第三个是环境变量被写死。process.env.NODE_ENV 和 config/*.env.js 里定义的字段，在构建时会被替换成字面量，打进 js 文件里。这意味着“打完包再改配置文件切换接口地址”是行不通的，同一份产物无法在测试和正式环境复用。需要运行期配置时，只能在 index.html 里注入一段全局变量，由部署脚本替换。

第四个是 history 模式的 404。开发服务器自带回退，所以本地一切正常；上线后忘记配 try_files，用户刷新子路由就白屏。这类问题排查顺序很固定：先看 Network 里失败的请求路径，再看服务端有没有把非静态资源交回 index.html。

还有一个与列表有关的细节：v-for 的 key 不要用数组下标。删除中间一项时，后续元素的下标会整体前移，Vue 依据 key 判断节点是否可以复用，结果把输入框里已填的内容错配到别的行上。改用数据自身的唯一 id，复用关系才稳定，排序和插入也不会出怪问题。

小结

全家桶的价值不在“全”，而在边界：视图归组件，地址归路由，共享状态归 Vuex，通信归 axios，构建归脚手架。先用 vue-cli 2 把骨架搭起来，再从单文件组件和 props/事件入手，等共享状态真的出现时再引入 Vuex。请求层尽早封装实例与拦截器，能省掉后面大量的重复代码。上线前确认三件事：assetsPublicPath 与部署路径一致、history 模式有回退规则、环境变量在构建时就已确定。
