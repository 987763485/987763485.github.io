Element UI 与 iView 组件库实践

2018 年上半年，Vue 2 技术栈在中后台项目里已经相当普遍，组件库的选择往往在项目启动前就要定下来。本文从实际项目出发，比较 Element UI 与 iView 的定位和选型维度，再走一遍接入、按需引入与主题定制，最后落到表单、表格、弹窗和国际化这些高频场景。读完本文，你应该能为新项目做出有依据的选型，并把组件库用得更稳。

两个库的定位与生态

Element UI 由饿了么前端团队维护，定位是桌面端中后台组件库。它的设计语言克制、留白充足，组件 API 以配置项和事件为主，表格、表单、弹窗的文档示例比较完整，主题用 SCSS 编写，适合已经有 SCSS 体系的团队。

iView 由 TalkingData 团队维护，作者是梁灏。它同样面向中后台，视觉风格更圆润，信息密度略高，组件种类更细，文档以中文为主，主题用 Less 编写，配套的后台模板让需要快速搭架子的项目省事不少。

两者都不是移动优先的方案。真正影响日常开发的是设计语言是否合团队口味、复杂表格与动态表单能否覆盖、主题变量是否好改，而不是组件数量的绝对值。本文只谈选型与使用，组件库如何设计 API、做样式隔离与发布，不在讨论范围。

选型要看哪些维度

选型时先把需求拆成清单：必须用到的组件、必须支持的复杂交互、团队现有的样式方案与构建链。下面这张表只做定性比较，不引用统计数据，结论仍要结合项目验证。

表格只能排除明显不合适的选择。更稳妥的做法是列出十个必用组件和三个复杂场景，例如可编辑表格、动态增删表单、大文件上传，用两个库各做一页 Demo，再看谁的默认行为更接近业务预期。团队用 SCSS 还是 Less，也会直接影响主题定制的工作量。

表格实践：插槽、排序与分页

el-table 用 data 传入数据，列用 el-table-column 声明，自定义单元格用作用域插槽，slot-scope 能拿到当前行、列和索引：

排序分本地与后端两种。本地给列加 sortable，但默认比较规则对中文和数字字符串不一定符合预期，复杂场景用 sort-method。后端排序把列设为 sortable="custom"，监听 sort-change 拿到 prop 与 order，order 的取值是 ascending、descending 或 null，翻译成接口参数再请求。筛选本地用 filters 配 filter-method，后端筛选监听 filter-change，并给列设置 column-key 以便识别。

固定列用 fixed="left" 或 fixed="right"，实现上会额外渲染一份表格，固定列越多、行数越大，开销越明显。固定列还要求行高一致，单元格内容换行会导致左右错位，必要时给内容加省略与悬浮提示。

分页要与请求参数保持同步，切换每页条数时把当前页重置为 1，否则可能停在一个不存在的页码上。大数据量下 el-table 会渲染全部行，几千行就会出现明显卡顿。第一选择是分页，实现简单且状态可分享；虚拟滚动只渲染可视区域，体验更好，但当年没有通用方案，和固定列、展开行组合时问题较多。必须一次展示很多行时，至少简化单元格里的插槽和格式化逻辑，并保持固定行高。

确认框 $confirm 返回 Promise，确认走 then，取消与关闭走 catch。只在 then 里写业务，取消时控制台会出现未捕获的 rejection 警告，补一个空的 catch 即可：

消息类 API 还有 $message、$notify、$alert、$prompt，按交互轻重选择。Dialog 用 :visible.sync 控制显示，表单弹窗建议加 :close-on-click-modal="false"，避免误点遮罩丢失输入。destroy-on-close 让关闭后销毁内容，下次打开是全新的组件实例，适合同一个弹窗反复编辑不同数据；项目所用小版本如果没有这个属性，用 v-if 包住内容效果相同。重置表单要放在 closed 事件里而不是 close，后者在动画开始前就触发，此时 DOM 还在。

层级冲突是弹窗最常见的问题。Element 的弹层由内部层级管理统一分配，初始值在 2000 附近，嵌套弹窗、下拉、日期面板会依次递增。祖先元素一旦设置了 transform、filter 或 perspective，就会创建新的层叠上下文，弹窗的 z-index 再大也压不过外面的元素。给弹窗加 append-to-body 挂到 body 上，或者去掉祖先的 transform，比手写 9999 有效。

按需引入时没有 Vue.use(ElementUI) 这一步，语言包要通过 element-ui/lib/locale 的 use 方法设置。iView 的方式类似，在 Vue.use 的第二个参数里传 locale，语言包从 iview/dist/locale 下引入。语言切换后，已经渲染的组件文案不一定全部更新，后台项目通常刷新页面最稳妥。

日期组件有两个容易混淆的属性：format 控制输入框里的显示格式，value-format 控制绑定值的格式。接口要字符串时直接指定 value-format，绑定值就是字符串而不是 Date 对象：

注意 Element 的日期标记是 yyyy、MM、dd，不是 Moment 的 YYYY、MM、DD，混用会得到错误结果。时区问题来自 Date 对象：默认绑定 Date 时，序列化成 JSON 会转成 UTC 字符串，跨时区或跨零点可能差一天；用 value-format 返回字符串可以避开转换，但字符串本身不带时区，前后端要约定按本地日期处理。用 new Date('2018-05-29') 解析纯日期字符串也要小心，规范里按 UTC 解析，东八区拿到的是当天早上八点，换算到西半球时区就会退回前一天。

常见坑清单

最后整理一份上线前常查的清单，每条都对应前面的机制。

样式被全局覆盖

全局样式、重置样式、第三方 CSS 都可能命中组件类名。优先用 scoped 样式配 /deep/ 改组件内部，全局覆盖集中在一个文件里并放在组件库之后，不要改 node_modules，也不要靠 !important 堆叠。

按需引入后组件未注册

页面写了标签却提示未知组件，通常是只导入没注册，或者只注册了一部分。函数式 API 还要单独挂到原型上。排查时先看控制台警告里的组件名，再全局搜索该组件的注册语句。

表单校验不触发

先查 el-form-item 是否写了 prop，再查 rules 是否绑到 el-form 上，最后看 trigger 与交互方式是否匹配。自定义组件要确保 v-model 正确派发 input 事件，否则规则拿不到新值。

表格高度自适应

固定表头需要给表格明确高度，常见做法是用 flex 布局撑满剩余空间，再监听窗口 resize 重新计算。2018 年浏览器原生的尺寸监听还不能当通用能力，侧边栏折叠、标签页切换都要手动触发重算，记得加防抖。

打包体积仍然很大

按需配置生效后体积没降，多半是还有整库导入、主题 CSS 与自定义主题同时引入，或者依赖里出现了两份不同版本的组件库。用构建报告定位具体模块，再逐一清理。

小结

Element UI 与 iView 都是 Vue 2 时代成熟的中后台组件库，选型先看设计语言与团队样式体系，再用真实页面验证，不必纠结组件数量。接入阶段全局引入方便开发，上线前切到按需引入并用构建报告确认体积。主题定制要记住 Element 先定义变量再编译、iView 依赖 Less 的延迟求值。表单与表格的多数问题来自初始化时机和数据流，而不是组件本身。把上面的坑清单当作上线前检查表，可以省下不少排查时间。
