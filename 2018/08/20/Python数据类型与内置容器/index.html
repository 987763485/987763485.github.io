Python 数据类型与内置容器

本文属于《Python 学习路线》第 2/29 篇
上一篇系列目录下一篇

Python 的很多“诡异”行为，追根溯源都是对象模型与可变性的问题：为什么改了一个列表，另一个变量也跟着变；为什么循环里拼字符串越来越慢；为什么字典的键不能是列表。本文围绕 Python 3.7 的内置类型，从对象与引用讲起，依次梳理数值、字符串、列表、元组、字典与集合的语义和常见操作，最后落到容器选择、拷贝与高频误区。适合已经能写脚本、但希望把基础打牢的读者，读完后应能对“该用哪种容器、这段代码为什么会这样”给出确定的答案。

一切皆对象：变量只是引用

在 C 语言里，变量是一块内存，赋值就是把值抄进去；Python 里变量只是一个名字，通过引用指向堆上的对象。每个对象都有身份、类型和值：id 在生命周期内不变，type 决定它能做什么，值则可能改变。a = b 从不复制对象，只是让两个名字指向同一个对象；is 比较身份，== 比较值。

可变对象通过任何别名做的就地修改，其他别名都看得到；不可变对象所谓“修改”，其实是新建对象再把名字绑过去。函数传参同理，传的是对象引用：在函数里 append 列表，调用方看得见；给整数重新赋值，调用方看不见。

常见的可变类型有 list、dict、set、bytearray；不可变类型有 int、float、str、tuple、frozenset、bytes。判断可变与否有一个简单办法：看它是否支持就地修改且 id 不变。list.append 之后 id 不变，而 str 的方法不会改动原字符串，只会返回结果。这个划分决定了它们能否作为字典的键、能否被安全共享。

数值类型：精度与取舍

Python 3 的 int 不再区分普通整数和长整数，天然支持任意精度，只受内存限制。整数除法 / 总是返回 float，要整数商用 //，注意 // 对负数是向下取整，-7 // 2 得 -4；divmod 一次拿到商和余数，分页时很方便。

float 是 IEEE 754 双精度，约 15 到 17 位有效数字，二进制无法精确表示 0.1，所以 0.1 + 0.2 得到 0.30000000000000004。这不是 Python 的缺陷，其他主流语言一样。比较浮点数用 math.isclose，不要用 ==；金额、税率、对账用 decimal.Decimal，并且必须用字符串构造，Decimal(0.1) 会把误差带进来。需要保留分数精确值时用 fractions.Fraction，代价是分子分母增长后运算变慢。

bool 是 int 的子类，True 等于 1，sum([True, False, True]) 得 2；但把布尔值混进数值容器时要清楚语义，isinstance(True, int) 为真。

字符串：文本与字节

字符串是不可变的 Unicode 码点序列，所有“修改”方法都返回新字符串，这也是循环里反复拼接会不断产生新对象的原因。索引从 0 开始，负数从末尾数；切片含头不含尾，越界不报错，步长为负可以反转，切片结果是拷贝。

Python 3 把文本和字节分开：str 是文本，bytes 是字节序列，用 encode 和 decode 转换。解释器内部默认使用 UTF-8，但文件读写的编码取决于平台，读文件时仍建议写明 encoding="utf-8"，在 Windows 上尤其容易踩到 GBK 的坑。bytes 里的每个元素是 0 到 255 的整数，不是字符。

常用方法记几个就够：strip 去两端空白，split 切分（不传参数时按任意空白切分并丢弃空串），join 连接，replace 替换，startswith 判断前缀，find 找不到返回 -1，而 index 直接抛异常。

格式化首选 3.6 引入的 f-string：花括号里写表达式，冒号后跟格式说明符，.2f 保留两位小数，>6 右对齐，, 做千分位。它比 % 和 format 更短也更快，但表达式别写得太复杂，可读性优先。

列表：最常用的可变序列

列表是可变有序序列，底层是动态数组：尾部追加和弹出均摊 O(1)，头部插入删除要搬移元素，是 O(n)。append 追加单个，extend 拼接可迭代对象，insert 按位置插入，remove 按值删第一个匹配项，pop 按位置弹出，del 按位置或切片删除。

切片也能赋值，并且可以改变长度：nums[1:3] = [7, 8, 9] 把两个元素换成三个，赋空列表相当于删除这一段。批量替换时这比循环 pop 干净得多。

排序有两个入口：list.sort 就地排序、返回 None，sorted 接受任意可迭代对象、返回新列表，两者都支持 key 和 reverse。写成 nums = nums.sort() 会把列表弄丢，这是新手常犯的错误。

列表最常见的坑是“拷贝”其实只是别名：b = a 不是拷贝，b = a[:]、list(a)、a.copy() 才是拷贝，而且都是浅拷贝，嵌套的子列表仍然共享。

元组：不可变的记录

元组是不可变有序序列，创建后不能增删改，但这种不可变是浅层的：元组里放列表，列表照样能改。语法上起决定作用的是逗号而不是括号，(1) 是整数，(1,) 才是单元素元组。

元组最大的价值是解包。a, b = b, a 一行完成交换；函数返回多值，本质就是返回元组；first, *rest = items 把剩余部分收集成列表。两边数量必须匹配（带星号的一项除外），否则抛 ValueError。

需要给字段命名时，collections.namedtuple 生成 tuple 子类，既能按属性访问，也能按索引访问、解包和比较，同样不可变、可哈希，适合坐标、数据库行、配置项这类小结构。字段多、需要默认值或方法时，再考虑普通类。

元组能否当字典键，取决于是否可哈希：所有元素都可哈希才行。("CN", 1) 可以，("CN", [1]) 不行；含列表的元组放进 set 同样会抛 TypeError。

注意 namedtuple 生成的是类，字段名不能与关键字冲突；_replace 不会修改原对象，而是返回新实例。它的字段访问比下标可读，又比普通类省内存，在需要轻量记录的场合很实用。

字典：哈希表与键的约束

字典是哈希表实现的键值映射，平均查找、插入、删除都是 O(1)，代价是额外内存和哈希计算。键必须可哈希，即不可变且哈希值稳定，所以 int、str、tuple、frozenset 可以，list、dict、set 不行。判断键相同用 == 加哈希，因此 1、1.0 和 True 会落到同一个键上，值被后来的覆盖。

读取有三条路：d[key] 最快但缺键抛 KeyError；d.get(key) 返回 None，get(key, default) 返回默认值；key in d 只判断存在。写入用 d[key] = value；需要“不存在才初始化”时用 setdefault，做分组和计数很顺手；update 批量合并，pop 删除并返回。

3.6 的实现让字典记住插入顺序，3.7 起写进语言规范，可以放心依赖：遍历 items、keys、values 的顺序就是插入顺序，删了再插的键排到末尾。但“有序”不等于“排序”，要按 key 排序仍得用 sorted(d.items())。

字典推导式 {k: v for k, v in pairs} 让构造一步到位；计数场景可以用 collections.Counter，它是 dict 的子类，专为计数而生。

字典的键对象本身也不能再修改。如果一个自定义对象先作为键，之后又改了参与哈希的字段，再按原值查找就会失效。正确的做法是让参与哈希的字段不可变，或者改用 id 之类的稳定值做键。

集合：去重与成员判断

集合表达“一组互不相同的元素”，底层也是哈希表，元素必须可哈希，查找插入平均 O(1)。最常见的用途是去重：set(seq) 一行搞定，但它不保留顺序，既要去重又要保序时，可以配合 dict.fromkeys 或手动遍历。

集合支持交并差：& 交集、| 并集、- 差集、^ 对称差，对应 intersection、union、difference 等方法，还有就地更新的版本。判断两个列表有没有共同元素，用集合比双重循环清晰，复杂度也从平方级降到线性级。

set 可变，能增删元素，所以不可哈希，不能嵌套也不能当键；frozenset 是不可变版本，可以嵌套、可以做键。把“一组标签”当字典键时，frozenset 是标准答案。

集合也有成本：每个元素都要算哈希、存哈希，内存占用高于列表，迭代顺序不保证。元素少、只遍历一次时，列表更合适。自定义对象放进集合，必须实现 __hash__ 和 __eq__，并保证相等对象哈希相同，否则会出现放进去了却查不到的怪事。

容器选择：按语义再按性能

把前面几类放在一起比较，选择容器先看语义，再看性能。列表保序、可重复、按位置访问；字典表达映射，按键快速查找；集合表达归属与去重；元组表达固定记录；deque 是双端队列，两端进出都是 O(1)。

判断可以简化成几问：需要键值对应就用 dict；只关心在不在、有没有重复就用 set；频繁在两端进出、当队列用就用 collections.deque，不要用 list.pop(0)；需要保序、下标、频繁中间增删用 list；数据固定、要当键或要解包用 tuple。

也要提醒一句：不要为想象中的性能把简单结构换成复杂结构。几百个元素的列表做线性查找，通常远不是瓶颈，先让代码清楚，再用 profile 找热点。

浅拷贝与深拷贝

拷贝分两层：浅拷贝只复制容器本身，元素仍是原来的引用；深拷贝递归复制容器里的所有对象，得到一棵独立的树。切片 a[:]、list(a)、dict(a)、a.copy() 都是浅拷贝，copy.copy 是通用入口。

浅拷贝对“容器里放不可变对象”完全够用，因为元素本来不会变；一旦容器嵌套容器就会出问题：外层是新的，内层还是同一批对象，改内层两边都变。

深拷贝用 copy.deepcopy，它用一个 memo 字典记录已复制的对象，因此能处理循环引用：A 引用 B、B 又引用 A 时，复制结果里 A’ 仍引用 B’，闭环保留，不会无限递归。浅拷贝只是把引用原样抄一遍，做不到这一点。

深拷贝的代价是时间和内存，对象图很大时明显变慢；文件句柄、数据库连接、线程锁这类资源型对象也不该复制，通常需要自定义 __deepcopy__ 或干脆避免复制。更推荐让数据保持不可变，需要修改时构造新对象，从根上绕开拷贝。

判断该用哪一种，可以看“修改会不会穿透”：只在外层增删元素，浅拷贝即可；会改到嵌套结构，或者要把数据交给不信任的代码，就用深拷贝。还有一点容易忽略：不可变对象的 copy 往往直接返回自身，因为复制没有意义，这不算 bug。

常见误区

最后盘点几个高频误区，它们几乎都能从前面的对象模型推出来。

可变默认参数。默认值在定义时求值一次，之后每次调用共享同一个对象，def add(item, bucket=[]) 里的列表只创建一次，多次调用会越积越多。正确写法是用 None 作哨兵，在函数体内判断并新建。

is 与 ==。is 比较身份，== 比较值。小整数（-5 到 256）和部分字符串会被缓存或驻留，导致 is 偶尔返回 True，这是实现细节，不是语言保证；两个内容相同的长字符串用 is 比较可能为 False，在交互式环境里又可能为 True。判断 None 用 is None 是可靠惯用法，其余比较一律用 ==。

遍历时修改列表。for 循环靠内部下标推进，删除元素会让后面的元素前移，于是有元素被跳过；遍历副本、用列表推导生成新列表、或倒序删除都可以。字典和集合更不能在遍历时增删，会直接抛 RuntimeError。

字符串拼接。循环里 text += piece 在 CPython 上碰巧有就地扩容的优化，但依赖它并不稳妥，换个实现或结构稍复杂就可能退化成平方级。标准做法是先 append 到列表，最后用 "".join(parts)；次数少时 f-string 或 + 都无所谓。

再补充一个与键有关的细节：不要把可变对象当作字典键或集合元素，也不要为了省事用 id(obj) 当键，因为对象销毁后 id 会被复用，旧键可能指向新对象。需要按对象身份索引时，直接把对象本身当键，前提是它的哈希基于不可变字段。

小结

Python 的内置类型不多，但语义细节决定了代码是否正确。变量是对象的引用，可变对象通过别名共享修改，不可变对象每次“修改”都产生新对象，这是理解后面一切的前提。选择容器时先问语义：映射用 dict，去重与成员判断用 set，保序与下标用 list，固定记录用 tuple，两端进出用 deque。拷贝要分清浅与深，嵌套结构优先考虑不可变数据；默认参数、is 比较、遍历中修改、字符串拼接这四个坑，值得在代码评审时逐条对照。
