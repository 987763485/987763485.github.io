安全加固：Windows 基线配置

一台刚装好的 Windows Server 2016，默认配置是“可用优先”而非“安全优先”：Guest 账户还在、SMBv1 还开着、RDP 只靠口令。本文面向需要给 Windows 服务器做安全加固的开发与运维人员，按账户、权限、远程访问、SMB、补丁、审核、防火墙、服务八块给出可落地的基线项，并说明如何用本地安全策略、secedit 与 PowerShell 核查整改。读完你能得到一份适用于 Windows Server 2012 R2 与 2016 的检查清单。本文只讲 Windows 主机，不涉及 Linux 加固与堡垒机等 4A 平台。

一、基线是什么

基线是一组明确的、可验证的配置项，回答“这台机器应该长什么样”。它追求三点：最小攻击面，关掉与业务无关的账户、服务、端口与协议；可重复，同角色同配置，换台机器结果一致；可审计，每项都能说清依据，也能被脚本查出偏差。

基线不是越严越好。把不用的服务全关、出站全禁，确实能减少暴露面，但补丁分发、域认证、监控采集会一起失效，运维最后只能临时开口子。合理做法是分层：先做共用的基础基线，再叠加 Web、数据库等角色基线。

国内项目常把基线挂在等级保护上。等保 1.0（GB/T 22239-2008）在主机安全层面提出身份鉴别、访问控制、安全审计、入侵防范、恶意代码防范、资源控制六项要求，本文的账户、权限、审核、服务几节基本对应。等保 2.0 在 2018 年仍是报批稿，尚未发布实施，其安全计算环境把这些要求重新收进身份鉴别、访问控制、安全审计、入侵防范、恶意代码防范、可信验证等控制点。落地时按 1.0 做、按 2.0 报批稿补齐即可。

基线工作是个闭环：

flowchart TD
  A[确定角色与合规依据] --> B[编写基线项与判定方法]
  B --> C[测试环境验证]
  C --> D[组策略或脚本下发]
  D --> E[脚本核查与抽样复核]
  E --> F{是否存在偏差}
  F -- 是 --> G[登记整改并修复]
  G --> E
  F -- 否 --> H[归档报告 进入下一周期]

闭环里最容易被忽略的是判定方法。写成“应关闭不必要的服务”，核查时人人都能说合规；写成“Remote Registry 启动类型为 Disabled 且服务处于 Stopped”，才能被脚本判定。

二、账户与口令

账户是攻击者的第一入口。装完系统先用 net user 看清全部本地账户，确认没有多余的测试账户与离职人员账户，并确认 Guest 已禁用。

重命名 Administrator 要权衡。内置管理员 SID 以 500 结尾，改名不改变 SID，枚举工具仍能按 RID 找到它，收益只是提高一点猜测成本；代价是依赖固定账户名的脚本与监控会失败。改名就记进资产文档，并检查计划任务与服务里有没有硬编码的账户名。更有效的是设足够长的口令，或禁用内置账户、改用另一个管理员账户，并在“拒绝通过终端服务登录”里排除不需要远程登录的账户。

口令与锁定策略：最短 12 位（等保检查项通常要求 8 位以上，12 位是留余量）、启用复杂度、最长使用期 90 天、记住 24 个历史口令；锁定阈值 5 次、锁定时长 30 分钟、观察窗口 30 分钟。

锁定策略是双刃剑，它挡住在线爆破，也能被人用来锁死运维账户，面向互联网的入口要配合来源限制。

本地与域账户要分清。域成员机的口令与锁定策略由域组策略下发，本地安全策略的同名项对域账户无效；但本地 SAM 账户依然存在，.\Administrator 在域环境里仍能登录，这类口令要么统一管理，要么用 LAPS 定期轮换。Windows Server 2016 自带 PowerShell 5.1，可直接用 Get-LocalUser、Get-LocalGroupMember；2012 R2 没有该模块，退回 net user 与 ADSI。

三、权限与组

先清理本地管理员组。Administrators 的成员应该能一一点名，检查用 net localgroup administrators 或 2016 的 Get-LocalGroupMember -Group Administrators。常见问题有三类：装软件时临时加的账户没删、把域管理员组整个加进本地管理员、应用服务用管理员账户在跑。第二类最危险，等于一处失守、全域失守。

最小权限要落到目录上。应用账户只给它需要的目录与注册表项，用 icacls 精确授予，不要给 Everyone 写权限。

UAC 在服务器上常被关掉，理由通常是远程操作弹窗太烦。建议保持 EnableLUA=1，ConsentPromptBehaviorAdmin 设为 2（在安全桌面上请求同意），PromptOnSecureDesktop 设为 1，并打开 FilterAdministratorToken，让内置管理员也走批准模式。这些值在 HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System 下，图形入口是“本地安全策略 → 本地策略 → 安全选项”。

服务账户要按需选。LocalSystem 在本机权限最大，访问网络时以计算机账户出现；NetworkService 本机权限低一些，网络身份相同；LocalService 的网络访问是匿名的。自定义域账户能访问域内资源，但口令写在服务配置里，要定期更换，还要授予“作为服务登录”并拒绝交互式登录。能用虚拟账户或组托管服务账户（gMSA，2012 起支持）时，就不要用带口令的域账户。

四、远程访问

RDP 是最常见的暴露面，先启用网络级别身份验证（NLA）。它在建立完整会话前先完成身份认证，把未认证连接挡在登录界面之外。图形入口在系统属性的远程页，对应注册表是 HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp 下的 UserAuthentication=1，同时把 SecurityLayer 设为 2，强制 TLS。

端口与来源要一起看。把 3389 改成别的端口只减少扫描噪音，不构成防线，扫描很容易找回来。有效的是用防火墙限制来源，只允许管理网段访问 3389。

会话超时也要配，路径在“计算机配置 → 管理模板 → Windows 组件 → 远程桌面服务 → 远程桌面会话主机 → 会话时间限制”，分别限制活动会话与断开连接会话，避免挂着的会话被他人接管。

WinRM 按需启用。5985 与 5986 是横向移动的常用通道，不做批量管理就停服务并删对应防火墙规则；需要时限制来源并关闭 Basic 认证。

五、SMB 与共享

SMBv1 要关。它陈旧、缺少现代防护，2017 年那轮勒索软件传播让“关闭 SMBv1”成了普遍检查项。2012 R2 用 Uninstall-WindowsFeature FS-SMB1 卸载；2016 以可选功能管理，也可直接改服务端配置。

关闭前先确认老设备。一些扫描仪、老式 NAS、备份一体机只会说 SMBv1，贸然关闭会造成业务中断，可先在测试环境验证。签名有一点性能开销，通常可接受，大量小文件读写的文件服务器要实测。

匿名访问也要收口。确认“网络访问：不允许 SAM 账户和共享的匿名枚举”已启用，即 RestrictAnonymous 与 RestrictAnonymousSAM 为 1；再看 everyoneincludesanonymous 是否为 0，并清空 NullSessionShares 与 NullSessionPipes 中多余的项。

共享权限与 NTFS 权限叠加时取更严格的一方。共享权限只对网络访问生效，NTFS 权限对本地与网络都生效。推荐共享权限给 Authenticated Users 完全控制，精细控制全部放在 NTFS 上，排查时只有一处要看。

六、补丁与更新

补丁基线包含两件事：补什么，什么时候重启。

补什么以厂商月度更新为主，重要漏洞的带外补丁走紧急流程。评估不要只看公告标题，要看受影响组件与本机角色是否匹配：只跑 IIS 的机器，数据库补丁可以缓，.NET 与 IIS 的更新必须优先。装完不等于生效，要确认组件版本。

内网一般用 WSUS 集中分发：组策略指定 Intranet 更新服务位置，客户端按计算机组自动审批。WSUS 的价值不只是省出口流量，更重要的是分组与审批，可以一组先发、观察几天再全量。策略路径在“计算机配置 → 管理模板 → Windows 组件 → Windows 更新 → 指定 Intranet Microsoft 更新服务位置”。

重启窗口必须写进变更单，避开业务高峰。关键系统先打一台，观察业务指标与事件日志，再滚动推进；打之前留快照或备份。评估记录至少留五项：补丁标识、影响组件、计划窗口、验证方式、回滚方案。很多事故不是补丁引起的，而是“没预约重启、凌晨自动重启”引起的。

七、审核策略

审核策略决定“出了事能不能查”。

必开三类：登录与注销，成功与失败都开，用于发现爆破与异常时段登录；账户管理，成功与失败都开，用于发现账户被创建或提权；策略更改，开成功，用于发现审核策略被动过。对象访问按需开，而且要先在目标文件或注册表项上设 SACL，否则开了也记不到东西；进程跟踪日志量极大，只在排障时短时开。

子类别名称随系统语言变化，中文系统显示“登录”而不是“Logon”，脚本里先 auditpol /get /category:* 看清本机名称。不想折腾语言差异，就在组策略里配，“计算机配置 → Windows 设置 → 安全设置 → 本地策略 → 审核策略”是语言无关的入口。

日志容量也算基线。默认安全日志往往只有 20 MB，演练时几小时就滚没了，建议安全日志不小于 1 GB，应用与系统日志不小于 256 MB：

单机日志总会丢，内网应部署 Windows 事件转发，把关键事件集中到收集器。《网络安全法》要求网络日志留存不少于 6 个月，等保 2.0 报批稿的审计条款也向这个口径看齐，集中存储比单机磁盘可靠。

八、防火墙

Windows 防火墙按域、专用、公用三个配置文件分别生效，三个都要管，只配域配置文件是常见疏漏。

出站规则的取舍要现实。出站默认拒绝能挡住反弹 shell 与下载器，但会同时挡住补丁下载、域认证、时间同步、监控上报，逐条放行成本高且容易漏。务实路径是：先保持出站允许，把出站连接记进日志观察一段时间，梳理出真实的外联清单，再对高风险网段收紧。

规则要能回退。组策略下发的规则优先于本地规则，排查“规则不生效”时用 Get-NetFirewallRule -PolicyStore ActiveStore 看合并结果。

九、服务与启动项

服务是持久化最喜欢待的地方，也是最需要按角色裁剪的部分。

禁用不必要的服务。典型候选有 Remote Registry、Telnet、Fax、路由与远程访问，以及没有监控依赖的 SNMP。判断依据是角色而不是习惯：数据库服务器上的 IIS、Web 服务器上的打印服务，都可以直接关。

sc.exe 的 start= 后面必须留一个空格，写成 start=disabled 会报参数错误，这是常见笔误。改启动类型前先看依赖，sc.exe qc RemoteRegistry 能看到可执行路径与依赖，避免停一个服务带倒一片。

启动项要清。服务器上的启动项多来自运维留下的脚本与监控代理。用 Get-CimInstance Win32_StartupCommand 列登录启动项，msconfig 只用于查看。

计划任务要审计。重点看三类：以 SYSTEM 运行、程序路径不在 C:\Windows 下、触发器是登录时或每小时。Get-ScheduledTask 配 Get-ScheduledTaskInfo 能列作者、路径与上次结果，2012 R2 上用 schtasks /query /fo LIST /v 更顺手。不认识的任务先禁用再确认，不要直接删。

十、落地方式与检查清单

同一套基线有四种落地手段，按机器数量与环境选。

secedit /configure 会覆盖 /areas 范围内的设置，应用前备份原策略并在测试机验证；它只管安全策略，防火墙与服务要另外用 PowerShell 补。域内应统一用组策略：按角色建 GPO、链接到对应 OU，用 gpresult /h 验证。本地策略会被域 GPO 覆盖，加域后再改 secpol.msc 往往白改。

小结

Windows 基线没有神秘技巧，核心是把“默认可用”改成“按需开放”，并让每条改动都能被复述、被检查、被回滚。账户、权限、远程访问、SMB、补丁、审核、防火墙、服务八块覆盖了主机层面的大部分检查项，配置时优先用组策略与脚本，少做单机手工修改。落地先小范围验证、留好回滚，再滚动推开。基线不是一次性任务，按月核查、随变更更新，它才真正起作用。
