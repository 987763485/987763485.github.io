Python 3 基础语法快速上手

本文属于《Python 学习路线》第 1/29 篇
上一篇系列目录下一篇

如果你写过 C、Java 或 JavaScript，第一次读 Python 代码多半会觉得它像伪代码：没有分号，没有大括号，类型也不写在变量前面。但真正动手时，缩进、动态类型、可变默认参数以及 == 与 is 的区别，又会接连带来困惑。本文面向有其他语言基础、第一次系统写 Python 的读者，以 Python 3.7 为准，从运行方式讲到语法骨架、控制流、函数、类、异常、推导式与模块，目标是读完后能写出结构清晰、可直接运行的脚本。容器层面的可变性、哈希与切片细节已在《Python 数据类型与内置容器》中展开，本文只在必要处举例。

先弄清楚代码是怎么跑起来的

Python 常被称为解释型语言，但 CPython 并不是逐字符翻译源码：它先把源文件编译成字节码，再交给虚拟机执行，.pyc 缓存只影响启动速度，不改变语义。日常开发只需记住：解释器命令是 python3，源文件以 .py 结尾，标准库随解释器一起安装。

2018 年的现实是 Python 2 与 Python 3 并存。Python 2.7 已进入维护尾期，官方计划在 2020 年初停止支持，新项目没有理由再从 2 开始。很多系统里的 python 仍指向 2.7，所以本文一律写 python3，动手前先确认版本：

flowchart LR
    A[源文件 .py] --> B[编译为字节码]
    B --> C[Python 虚拟机执行]
    C --> D[调用标准库或 C 扩展]

运行代码有四种常见方式：在终端输入 python3 进入 REPL，逐行输入表达式并立刻看到结果；把代码存成脚本，执行 python3 hello.py；用 -c 传入一行代码，适合写进 shell 管道；用 -m 以模块方式运行，例如 python3 -m json.tool data.json，它会按模块查找规则定位代码。REPL 里可以用 exit() 或 Ctrl-D 退出，下划线 _ 保存上一次的运算结果，临时算个数很方便。

脚本用 sys.argv 读取命令行参数，下标 0 是脚本名，真正的参数从 1 开始。f"..." 是 3.6 起提供的格式化字符串，花括号内可以直接写变量或表达式，比 % 和 str.format 都直观。

实际项目还要隔离依赖。系统 Python 常被其他工具共用，直接 pip install 会污染全局环境，不同项目对同一个库的版本要求很快就会打架。标准库的 venv 可以为每个项目建独立环境：

激活后 python3 与 pip 都指向该环境。venv 只隔离第三方包，不隔离解释器版本；.venv 不应提交到版本库，队友按 requirements.txt 重建即可。

缩进、注释与命名

Python 用缩进表示代码块，这是语法而非排版。行尾冒号表示“下面开始一个块”，紧随其后的行必须缩进，通常用四个空格；同一块内缩进必须一致，混用 Tab 与空格会抛出 TabError。空行和注释不影响块结构，缩进一旦回退，当前块就结束了。

暂时不写内容的块要放 pass 占位。过长的表达式优先在圆括号、方括号或花括号内断行；反斜杠续行容易因行尾多一个空格出错，不推荐。

注释以 # 开始直到行尾，应解释“为什么”而不是复述代码。函数、类或模块开头的第一句三引号字符串是文档字符串，会保存到 __doc__，help() 与许多文档工具都依赖它：

命名遵循官方风格指南：变量与函数用小写下划线形式，类名用首字母大写的驼峰形式，常量全大写，下划线开头表示内部使用，均属约定而非强制。双下划线包围的名字由解释器保留，不要自行发明；也不要拿 list、dict、type 这类内置名做变量名，否则会遮住内置对象。风格指南还建议每行不超过 79 个字符、缩进统一用空格，这些约定可由编辑器与 flake8 之类工具检查，团队应尽早统一。

变量、动态类型与运算符

Python 没有变量声明，赋值同时完成名字创建与对象绑定。名字本身没有类型，类型属于它指向的对象：

这就是动态类型，但它不等于弱类型："1" + 1 会抛出 TypeError，不会悄悄把字符串转成数字。代价是类型错误到运行时才暴露，因此公共函数建议补类型注解，并配合 mypy 做静态检查；注解不参与运行。

多重赋值右侧先组成元组再解包，所以交换变量不需要临时变量：a, b = b, a。星号可收集多余元素，如 first, *rest = [1, 2, 3]，细节属于容器语义，此处不展开。

算术运算符有三处与 C 系语言不同。/ 永远返回浮点数，6 / 3 得 2.0，整数商用 //；// 对负数向负无穷取整，-7 // 2 得 -4，% 的符号跟随除数，-7 % 2 得 1；** 右结合且优先级高于乘除，-2 ** 2 是 -4，负数平方要写 (-2) ** 2。

浮点数无法精确表示多数小数，0.1 + 0.2 == 0.3 为假，比较结果应留容差，金额改用 decimal.Decimal。round 采用银行家舍入，round(2.5) 得 2，与直觉的四舍五入不同，涉及金额时必须写清舍入规则。

比较运算符支持链式书写，0 < x < 10 等价于两个比较的组合，中间操作数只求值一次。== 比较值，is 比较是否为同一对象：

判断 None 一律写 x is None。不要用 is 比较数字或字符串，小整数与短字符串的复用是 CPython 的实现细节。需要观察对象身份时可以打印 id(a)，同一对象在生命周期内编号不变，但对象销毁后编号可能被复用，不能当作持久标识。in 对列表逐个比较，是线性复杂度；对字典和集合走哈希，接近常数时间。

但 or 会把 0、空字符串当成假值，若 0 是合法输入，就应显式判断 is None。and 可做前置校验，如 user and user.is_active。条件表达式 x if cond else y 适合简单二选一，嵌套超过一层就该改回 if 语句。

控制流：条件、循环与 else 子句

条件语句的条件外不需要括号，行尾必须有冒号，分支靠缩进划分。elif 自上而下匹配，第一个为真的分支执行后整体结束。任何对象都能按真假解释：None、False、零、空字符串、空容器为假，因此 if items: 是判断非空的惯用写法。

Python 3.7 没有 switch，多分支可用 if/elif 链，或用字典分派，后者在分支较多时更清晰：

for 遍历可迭代对象，而不是下标递增。列表、字符串、字典、文件都能直接遍历；字典默认遍历键，要键值对用 items()。需要下标时用 enumerate：

range(start, stop, step) 含起点不含终点，步长为负可倒序；它返回惰性对象，不会建出整张表，成员判断仍是线性扫描。

while 适合次数未知的循环，每轮开始前检查条件，循环体内必须让条件趋向结束。while True 配合 break 把退出条件放在中间，通常比在循环头堆叠条件更易读。

break 跳出当前层，continue 跳过本轮。循环还可以带 else：没有因 break 退出时执行，正好表达“没找到”：

内层 for 的 else 只在没有整除时执行，因此打印质数。该写法省掉标志变量，但可读性有争议。要跳出多层循环，Python 没有带标签的 break，可把内层抽成函数用 return 退出，或设置标志位后在外层判断。

函数：参数比想象中灵活

函数用 def 定义，形参写在括号里。调用时可按位置传参，也可写 参数名=值；位置参数必须排在关键字参数之前。参数可带默认值；参数列表里放一个单独的 *，其后的参数只能按关键字传递，适合参数多、容易传错顺序的接口。

默认值的坑在求值时机：默认值在函数定义时只计算一次，所有调用共享同一个对象。用列表做默认值，上一次的结果会被带进下一次：

正确做法是用 None 占位，在函数体内新建容器。任何可变对象都不该直接做默认值。

*args 把多余位置参数收成元组，**kwargs 把多余关键字参数收成字典；调用处的 *nums、**options 则把序列与字典拆开传入。它们多用于装饰器与转发函数，业务接口不宜滥用，参数含义明确比“什么都能收”更重要。

没有 return 时函数返回 None，返回多个值实际是元组，调用方可以直接解包。函数内第一次赋值的名字是局部变量，要改全局得写 global，但这通常说明设计有问题。注解 def area(width: float) -> float: 只是提示，运行时不检查。闭包与装饰器留到专门文章。

类与对象：从数据到行为

类用 class 定义，实例通过调用类创建。__init__ 是初始化方法，不是构造函数：对象已经存在，它负责挂属性。self 代表实例，必须显式写出。实例属性在 __init__ 中赋值，各实例独立；类体里的属性属于类属性，所有实例共享：

类属性适合放常量或所有实例一致的配置，不要放可变容器：items = [] 写在类体里，所有实例会共享同一个列表。继承写在括号里，子类用 super() 调用父类方法，既完成父类初始化，也为多重继承下的方法解析顺序留出余地。判断类型优先用 isinstance，它会把子类也算进去。

双下划线方法接入内置行为：__str__ 决定 print 输出，__repr__ 面向调试，__eq__ 定义相等，__len__ 支持 len()，__add__ 支持 +。按需实现即可，不必一次写全。3.7 新增的 dataclasses 能减少样板代码，适合纯数据载体，但读懂手写版本仍是前提。

异常：让错误停在能处理的地方

Python 用异常报告错误，每一层都可以选择处理或继续上抛。try 放可能出错的语句，except 按类型捕获，else 在无异常时执行，finally 无论成败都执行，常用于释放资源。捕获顺序自上而下，子类异常要写在父类前面。

只捕获能处理的异常，并写明类型。裸 except: 会连 KeyboardInterrupt 与 SystemExit 一起吞掉，让程序无法正常退出。常见异常有 ValueError、TypeError、KeyError、IndexError、AttributeError、ZeroDivisionError 与 FileNotFoundError。把可能出错的语句压缩在 try 里、其余逻辑放进 else，还能避免误捕获无关异常。

自定义异常通常继承 Exception，类名以 Error 结尾，必要时携带上下文字段。raise 原样抛出可保留栈，raise 新异常 from 原异常 能形成异常链，排查时不会丢失根因。不要捕获后什么都不做，至少记录日志或转换成调用方理解的错误。

推导式与常用内置函数

推导式把建容器的循环压成一行。列表推导式写作 [表达式 for 变量 in 可迭代对象 if 条件]，字典推导式用 {键: 值 for ...}，集合推导式把方括号换成花括号。换成圆括号得到生成器表达式，不会立刻建出整个列表，适合只遍历一次的大数据量场景。

推导式不适合塞副作用或三层以上嵌套，遇到这种情况老老实实写循环。enumerate 遍历时同时给出下标，zip 并排打包、长度不一致时以最短的为准；sorted 返回新列表且排序稳定，key 对每个元素只调用一次。sum、min、max、any、all 配合生成器表达式能少写不少循环。

模块与包：把代码组织起来

一个 .py 文件就是模块，目录下有 __init__.py 就构成包。import json 后使用 json.dumps，命名空间清晰；from json import dumps 直接引入名字，适合高频调用；import numpy as np 用别名缩短长模块名。应避免 from module import *，它会污染命名空间，让名字来源难以追踪。导入顺序通常按标准库、第三方库、本地模块分三组，组间空一行，便于一眼看出依赖来源。

模块被导入时顶层语句执行一次。既要做脚本运行、又要被其他模块导入时，把主逻辑放进函数并保护入口：

直接执行 python3 app/cli.py 时，__name__ 是 "__main__"，入口执行；被导入时是模块名，入口不执行，从而避免导入即产生副作用。包内相对导入要求以模块方式运行，也就是 python3 -m app.cli。导入路径、循环导入与命名空间包涉及 sys.path 与导入器，已在《Python 模块与包管理》中讨论。

小结

Python 3 的语法骨架不复杂：缩进划分代码块，名字绑定对象，控制流与函数组织逻辑，类与异常提供抽象和容错。真正需要刻意养成的习惯，是分清 == 与 is、避开可变默认参数、在合适的层级捕获异常，以及用虚拟环境隔离依赖。建议把本文示例逐个敲一遍，再故意改坏几处观察报错，最后尝试把一个小脚本拆成模块与函数。等这些写法成为本能，再去看容器语义、迭代器与装饰器，难度会低很多。
