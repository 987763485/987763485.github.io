Flutter 路由与页面导航

Flutter 的导航可以从一个 Navigator.push 就开始写业务，但只要有登录页、底部导航、深链和 Web 地址，“栈”很快就不够表达。本文按 2024 年上半年的实际选择，把命令式与声明式两条线的能力边界讲清楚，再落到 go_router 的用法、深链配置与登录守卫。适合正准备给项目定路由规范的同学。

先分清两套心智

命令式的 Navigator：栈是唯一真相，代码用 push、pop 决定去哪里，调用点即跳转点。好处是直观、转场与返回值自然；缺点是“该在哪个页面”没有集中表达，路径、深链、浏览器地址都得自己翻译。

声明式的 Router：用配置与路径描述“当前应该显示什么”，外部给一段路由信息（一个 URL、一个 location），框架把它翻译成页面栈并重建界面，跳转成了改地址之后的结果。社区习惯叫它 Navigator 2.0，到 2024 年它已是既有能力，本文不当新特性讲。

2024 年上半年的实际选择：存量项目多是 Navigator 1.0 加 onGenerateRoute；新建项目要么用 MaterialApp.router 手写 delegate，要么直接用 go_router，后者把 delegate 与 parser 封在库里。分工要认清：声明式负责“地址到栈”的映射，转场、临时弹层、结果回传仍然靠 Navigator 的栈操作，两者是分工。

Navigator 1.0：直接操作路由栈

五个方法覆盖大部分栈需求，区别只在“压入之后怎么处理原来的栈”。

  • push 压入一个新路由，返回一个 Future，页面被 pop 时完成。
  • pushReplacement 压入并替换栈顶，用户按返回键不会回到来源页。
  • pushAndRemoveUntil 压入并持续移除栈里的路由，直到谓词返回 true。
  • popUntil 一路回退到谓词首次为真的位置，常用来“回到根”。
  • pop 出栈，可以带一个返回值。

栈的元素是 Route，MaterialPageRoute 是最常用的实现，负责把页面包装成带平台转场、可被手势中断的路由。onGenerateRoute 是兜底工厂：routes 里查不到名字时，由它按 RouteSettings 现场造一个 Route，路径参数、鉴权这类静态表写不了的逻辑就放这里。

冲突来自手势竞技场：全屏横向轮播、可左右拖的图表会注册自己的水平识别器，与边缘返回手势抢同一个拖动。思路是收窄竞争范围而不是关掉返回手势——在屏幕左缘叠一条只接收水平拖动的窄拦截层，让边缘位移归返回手势、其余区域归页面内容；或把横向滚动的起点限制在离左缘若干像素以外。这类效果要真机验证。

MaterialApp.router 与两个 delegate

声明式把职责切成两半，各一个抽象类。

RouteInformationParser 负责翻译：把系统给的 RouteInformation（主要是一个 uri）解析成应用内部配置，反向的 restoreRouteInformation 再把配置写回地址。它做的是字符串到类型的活，不碰栈。

RouterDelegate 负责栈：拿到配置后决定 Navigator 里应该有哪些页面，并在 build 里把它们声明出来；它同时承接“按了返回键”（popRoute）与“来了新地址”（setNewRoutePath）两类事件。

关键是 build 出的 Navigator 用 pages 列表而不是命令式压栈：delegate 只描述“当前这一摞页面”，框架对比前后两次列表，自己算出谁进栈、谁出栈。

这个骨架能跑，但把嵌套、Tab 多栈、路径参数全丢了，真实 delegate 复杂得多。MaterialApp.router 是接入点，把 delegate 与 parser 交给它（或直接给同时实现两者的 routerConfig），其余与 MaterialApp 一致。

还有个容易漏的：地址被应用内部改掉时（重定向、程序化换栈），系统并不知道当前在哪，要用 SystemNavigator.routeInformationUpdated(location: '/detail/123') 把地址回写给宿主——Web 上它决定地址栏与历史记录。

深链与 Web 地址

initialLocation 决定没有外部地址时的落点；有链接进来时，它被当作路由信息交给 parser，最终由 delegate 落成栈。若外部形态与内部路径不一致（推送里是自定义 scheme 的短链），用 deepLinkBuilder 在解析前改写一次：它收到链接的 URI，返回真正用来跳转的 location，签名细节以锁定的库版本为准。

平台侧配置是另一半工作，也往往是失败的那一半。Android 要在清单里给对应 Activity 声明可过滤的 intent-filter（scheme、host、路径前缀逐个对上，想免确认弹窗还要 autoVerify 并让站点托管校验文件）；iOS 的 Universal Links 要登记关联域名，站点根目录的 .well-known 下也要放描述文件，任缺其一都拉不起应用。

Web 上对应关系更直接：一个地址对应一摞页面，浏览器前进后退会驱动路由变化；二级页刷新能否拿到同一个页面，取决于服务器有没有把未命中的路径重写回入口，这是部署配置而不是路由代码。

排查顺序要固定：第一步看平台侧（intent-filter、关联域名、校验文件齐不齐、是否生效），第二步看应用内地址表能否解析这个路径（有没有被 redirect 拦走、未知路径有没有兜底页），第三步才看 Flutter 代码。深链打不开大多停在第一步。

登录守卫收拢到一处

守卫的位置是 GoRouter 的根 redirect：每次地址求值都会跑它，返回一个新地址而不是执行跳转，天然覆盖深链与浏览器前进后退。登录态用一个 ChangeNotifier 承载并交给 refreshListenable，状态一变整张路由表重新求值。

isPublic(loc) 是自己维护的白名单（登录、协议、公开活动页），漏掉会出现登录后弹回登录页的死循环。单页有额外条件时可以在那条 GoRoute 上再挂 redirect，但全局判断不要散落到各页面。

反面写法是每个受保护页面在 build 里判断未登录就跳走：它会先渲染出半帧越权界面，pop 回来时可能重复触发，深链与 Web 后退更绕开这层判断。分工也要划清：路由级守卫回答“这个地址能不能进”，组件级权限渲染回答“进来后哪些按钮该出现”，后者不能靠前者代替。手写 delegate 时没有 refreshListenable，得自己在 setNewRoutePath 里重算并通知重建。

页面状态与生命周期

栈里每一页都保有自己的 State，这是导航行为也是内存事实：栈越深，被留住的页面越多，它们的数据与控制器就都在内存里（量级看自己的包，本地观察即可，别拿示意数字当结论）。

两类工具各有场合。AutomaticKeepAliveClientMixin 用在页面于 Tab 或容器间切换时要留住状态的场合——保住滚动位置、省掉重复请求，代价是这一页常驻。RouteAware 配合 RouteObserver 用在需要知道页面被看到或被遮住的场合——曝光上报、离开时暂停播放，因为 initState 与 dispose 不等于可见与不可见。

要避开把整页数据塞进页面对象：栈会把数据一起留下，返回后仍占着。稳妥做法是页面只持有标识（一个 id、一个查询串），数据由仓库层按需提供、离开时释放。划一句界：路由负责“在哪一摞页面”，状态管理负责“这一页要哪些数据”，不要用状态里的标志位去模拟跳转，那等于绕开栈、转场与地址三件事。

五个常见坑与修法

  • Navigator.of(context) 取错 context。项目里嵌了第二个 Navigator（比如底部栏分支）时，就近查找拿到内层那个，push 出来的页面只盖住局部区域。修法是把跳转与作用层级绑定：用对应分支的 GlobalKey<NavigatorState>，或在 go_router 里给路由指定父级 Navigator。
  • 在 build 里 push。构建中触发栈变化会引起重建，重建里又跳转，表现为循环或断言报错。修法是把跳转排到当前帧之后（addPostFrameCallback），或者把条件写进 redirect，让路由表决定去哪。
  • await 之后继续用 context。页面已出栈或被销毁，BuildContext 不再有效，取 ScaffoldMessenger、Navigator 就崩。修法是先用 context.mounted 判断，或在跳转前把需要的对象取出来。
  • 路径与参数类型不一致，深链打不开。路由表写 /orders/:id，推送里却发 /order?id=；或 id 一处按 int 解析一处按 String 拼。修法是把路径常量集中定义、参数只做一次显式转换，日志要把进来的地址与解析结果成对打出。
  • 同一张路由表在 Web 与移动端行为不同。Web 上栈由浏览器历史驱动，pop 未必等价于用户后退，深链还依赖服务器重写。修法是把差异关进配置层：地址表只有一份，初始地址、重写、后退策略按平台单独处理，别在页面里到处写 kIsWeb。

需求到 API 的对照

导航需求 该用的 API 或配置 需要注意

从深层回到根页 popUntil 配 route.isFirst 谓词要命中栈里真实路由

未登录拦截 根 redirect 配 refreshListenable 白名单漏项会死循环
深链拉起指定页 initialLocation 与 deepLinkBuilder 先查平台侧链接配置

小结

两条线的分工值得再说一遍：Navigator 负责栈里的动作，Router 那一套负责地址与栈的对应。2024 年的实践里，新项目把路由表交给 go_router，登录判断收进根 redirect，Tab 多栈交给 StatefulShellRoute，而转场与结果回传仍然落在 Route 上。定规范时建议讲清四件事：地址怎么拼、参数放哪里、守卫在哪一层、栈允许留多少页。深链问题多数要去平台侧配置里找答案，而不是在 Dart 代码里加判断。
