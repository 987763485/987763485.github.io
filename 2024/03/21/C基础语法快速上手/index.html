C# 基础语法快速上手

本文面向刚接触 C# 或从别的语言转过来的开发者，把核心语法串一遍：类型系统、变量与常量、字符串、可空引用类型、属性与记录、模式匹配、集合与 LINQ、异常与工程约定。全篇以 .NET 8 SDK 为运行环境，示例都能用 dotnet run 跑起来。读完应能看懂一份现代 C# 项目的骨架，并分清推荐写法与新手高频坑。

类型、变量与常量

C# 的类型分为两大类：值类型（数值、bool、struct、enum、Nullable<T>）与引用类型（class、interface、delegate、数组、字符串）。区别在于变量持有的是数据本身，还是指向堆上对象的引用。

值类型存放在栈上或内联在宿主对象里，赋值即复制；引用类型在托管堆上分配，赋值只复制引用，两个变量指向同一个对象。

装箱（boxing）是把值类型放进引用类型容器的过程，拆箱反过来。int 赋给 object 时，运行时分配一个”盒子”、把值复制进去，取用时再复制回来，垃圾回收跟着承压。泛型让这件事基本消失：List<int> 按 int 特化，元素连续存放，不再装箱；约束类型参数用 where 子句。这就是”能用泛型就别退化成 object“的原因。

struct 与 class 的取舍看语义而不是看性能传闻。表示一个不可变的小数值，比如坐标、金额、日期，拷贝成本可接受，”字段都一样就等于相等”正是想要的语义，用 struct；对象有身份、字段多或需要继承，用 class。把字段多又频繁传递的类型硬改成结构体，会因为反复整体拷贝而变慢。

两个限定符用来划定边界：readonly struct 表示成员不修改自身状态，编译器可以省掉一些防御性拷贝；ref struct 只能存在于栈上，不能作为字段、不能装箱、不能出现在异步方法里，典型用途是包装一段受限资源的轻量视图，比如 Span<T>。它们服务于高性能场景，日常业务模型不需要。

const 与 readonly 都表达”不该被改”，机制不同。const 是编译期常量，值在编译时直接嵌进调用方代码，只能用于基元类型、string 或 null，改了它必须重编译所有引用方。readonly 是运行时只读字段，只能在声明处或构造函数里赋值，类型不限，也可以来自配置文件：

字符串：几种写法与一个正确态度

string 是引用类型，但语义上更像值类型：内容不可变，== 比较的是内容而不是引用地址。常用写法有四种：

内插适合少量变量嵌入，表达式部分可以带格式说明符；逐字字符串（@ 前缀）用来写 Windows 路径、正则这类充满反斜杠的内容；原始字符串字面量用三重引号包裹，在 .NET 8 上可直接使用，好处是嵌入 JSON 或多行模板时不用转义引号。

不可变意味着每次拼接都产生新对象。正确的态度是：不要在循环里用 + 反复累加长文本，改用 System.Text.StringBuilder；单次少量拼接交给编译器处理即可。需要在字符串上取片段又不想分配新对象时，用 Span<char> 做窗口视图。至于快多少，应当在项目里实测，而不是记住某个”几倍”的结论。

可空引用类型：让编译器抓住一类真实 bug

值类型早就有 Nullable<T>（写作 int?）表达”可能没有值”，这是运行时能力。可空引用类型不同：它不改变运行时表示，string? 在运行时就是 string，只是给编译器补充”这里允许为 null“的信息。项目文件里 <Nullable>enable</Nullable> 全局打开，也可以按文件用 #nullable enable 局部控制，老项目渐进迁移时有用。

把它当错误看，就能在编译期抓住一类真实 bug：方法在边界分支返回了 null，调用方直接解引用，测试数据恰好没覆盖那条分支，线上才抛 NullReferenceException。

三种写法配合使用：?? 提供回退值，?. 做空条件访问，! 是”我保证这里不为 null”的静默符（null-forgiving operator）。

! 只让编译器闭嘴，不产生任何运行时检查，当万能钥匙用等于把 bug 重新藏回去。合适的场合只有两种：外部库没标注可空性但契约明确，或者上面已经判过空而编译器没顺着推断。

集合与 LINQ

三者关系：List<T> 和 Dictionary<TKey, TValue> 是具体数据结构，负责存储与增删查；IEnumerable<T> 只是”可以被依次枚举”的契约，不关心东西存在哪。前者实现后者，而 LINQ 的扩展方法全部挂在 IEnumerable<T> 上，所以同一段写法既能跑在内存列表上，也能跑在别的数据源上。

flowchart TD
    A[具体集合 List / Dictionary] -->|实现| B[IEnumerable 契约]
    C[迭代器方法 yield return] -->|产出| B
    B -->|扩展方法| D[LINQ 查询 Where / Select / GroupBy]
    D -->|立即执行| E[foreach / ToList / Count / First]

延迟执行是 LINQ 最容易被误解的地方。查询在构造时只建立一条”待执行的计划”，每次枚举都完整重跑一遍，由此带来两个陷阱。一是多次枚举：同一个 adults 被遍历两次，背后就是两次真实的工作。二是副作用被推迟或重复：在 Select 里写文件、累加外部变量，执行时机与次数都不由你控制。

ToList、ToArray 的时机有明确准则：确实需要把结果固化成快照，比如要多次遍历或索引访问，就在查询构造完立刻 ToList() 一次；不要为了”看着安全”到处加。读单值优先 FirstOrDefault，要求”必须恰好一个”就用 Single。

自定义迭代器用 yield return，编译器把方法变成状态机，消费一条产一条，适合按行读大文件；yield break 提前结束。代价同样是延迟执行，所以参数校验要拆两段：外层普通方法先检查，再交给 yield 版本。

异常处理与资源清理

try/catch/finally 的形状与其他语言相似，值得说的是三点。第一，异常是异常，不是控制流：用它表达”用户不存在”这种可预期结果，会让调用方难以处理，也要付出栈展开的成本。

第二，when 子句是异常过滤器：条件不满足时异常继续向外冒泡，栈信息保持原样，比在 catch 里再 if 判断更贴近”我只处理这一类”的本意。重新抛出时 throw; 保留原始调用栈，throw ex; 会把它截断，这是最常见的写法错误。

第三，自定义异常层次要有边界：一个继承 Exception 的基类加上按原因细分的派生类，配好消息与内部异常两个构造函数，让调用方可以只捕获基类。业务模型不要继承异常，异常也不要用来返回值。

资源的确定性释放走 using 与 IDisposable：using 声明在作用域结束时调用 Dispose，即便中途抛异常也一样，等价于 try/finally 加一次判空。

异步流程里的异常传播与聚合方式不同，另有一篇专讲，这里不展开。

工程视角：命名、组织与项目开关

命名约定不是审美问题：类型、属性、方法、命名空间用 PascalCase，局部变量与参数用 camelCase，私有字段常加下划线前缀，接口以 I 开头，泛型参数写成 T 或 TItem，异常类型以 Exception 结尾。

命名空间是源码层面的分组，程序集（编译出的 dll 或 exe）才是部署与引用层面的一组类型，两者不必一一对应。global using 写在一个文件里等于每个文件都隐式引入，配合 <ImplicitUsings>enable</ImplicitUsings> 能省掉大量样板；但别把几十个命名空间全塞进全局，隐式引入越多，同名冲突也越多。

两个开关建议新项目一开始就定下来：<Nullable>enable</Nullable> 让新代码都带上可空信息，历史文件用 #nullable disable 局部关掉；<TreatWarningsAsErrors>true</TreatWarningsAsErrors> 把警告当错误，判等、多次枚举、匹配不到的分支都不会悄悄留下。

从 Java 或 Kotlin 转过来，最常调整的是三个习惯。第一，不要为每个字段手写 getter 和 setter，属性是语言级构造，{ get; set; } 就够。第二，判等要成对考虑：record 最省事，在 class 里重写 Equals 就必须同时重写 GetHashCode。第三，资源释放用 using 而不是把 Close 塞进 finally，IDisposable 是确定性释放的约定，不是垃圾回收的替身。

小结

C# 的语法点几乎都指向同一个目标：把约定变成编译器能检查的东西。类型系统决定拷贝还是共享，可空标注决定谁能为 null，模式匹配的穷尽性决定分支有没有漏，延迟执行决定代码什么时候真的跑。先按下面表格的推荐写法执行，把编译警告当真实缺陷去读，性能判断留给实测。

语法点 推荐用法 新手常犯的错
值类型与引用类型 小不可变值用 struct，其余用 class 把大对象改成 struct，赋值时反复整体拷贝
泛型与装箱 用 List<T> 等泛型集合，不退化成 object 为”通用”到处传 object
var 类型显而易见时推断，签名处写全类型 在字段和方法签名上用 var
const 与 readonly 编译期定死的基元值用 const，其余 readonly 用 const 放跨程序集会变的值
字符串 内插与原始字符串按场景选，循环里用 StringBuilder 在循环里用 + 反复累加长文本
可空引用类型 全局开启，用 ?? 与 ?. 显式处理 到处写 !，把警告当噪音压制
属性与 record 对外用属性，值语义模型用 record 只重写 Equals，忘了 GetHashCode
模式匹配 switch 表达式加穷尽分支 _ 放前面，后续分支永不命中
LINQ 延迟执行 明确消费点，必要时一次 ToList() 同一查询反复枚举，在 Select 里写副作用
