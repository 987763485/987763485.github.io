Dart 语言核心特性

Dart 是一门同时服务于脚本与客户端应用的现代语言，2023 年发布的 Dart 3.0 一次性带来了记录类型、模式匹配和类修饰符，语言面貌变化相当明显。本文只讨论 Dart 语言本身，Flutter 框架层面的工程实践不在范围内。如果你写过 Java、Kotlin 或 C#，读完这篇可以建立一张 Dart 特性地图：每个特性解决什么问题、标准写法是什么、坑埋在哪里。

bin/main.dart 里就是熟悉的 void main()。单个文件也能直接 dart run bin/main.dart，不必先建工程，这一点让它很适合写脚本和小工具。

真正需要留意的是两种运行模式。dart run 走 Dart VM 的 JIT（即时编译）路径：代码先跑起来，运行期持续优化，冷启动开销小、反馈循环短，开发阶段基本都用它。交付时通常换成 AOT（提前编译），用 dart compile exe 把源码编译成平台相关的本机可执行文件，启动不再需要预热，代价是改一行就要重新编译。

两者的差别不只是快慢，还会影响语言行为。JIT 下运行期类型信息更完整，反射类能力可用；AOT 产物会裁剪不可达代码，依赖反射的库在两种模式下表现可能不一致。写公共库时如果用到 dart:mirrors，必须清楚它在 AOT 场景不可用。

类型系统与空安全

var、final 与 const

Dart 是静态类型语言，但类型可以写、也可以交给编译器推断。

var 不等于可变，它只是省略标注；推断完成后类型就固定了，后面写 count = 'x' 会编译失败。final 约束的是引用不能被重新赋值，对象内部仍然可变，上面的 names 照样能 add。const 要求初始值在编译期就能确定，并且在同一个编译单元里字面量相同的常量会规范化为同一个实例，const [1, 2] 两次出现指向同一对象。这种深度不可变的值在传参和缓存比较时很省事。

dynamic 与 Object?

Object? 继续参与静态分析：访问任何具体成员之前，必须先证明它非空或先做类型收窄。dynamic 则把成员查找整个推迟到运行期，方法名写错、参数类型不匹配，编译器一声不响，错误留到线上爆；热路径上的 dynamic 调用也难以内联优化。这一点与 C# 的 dynamic 语义接近，都是主动绕过静态派发。合理用法是只在 JSON 反序列化这类真正动态的边界处出现，进入代码内部后立刻转成强类型。

类、构造与类修饰符

命名参数、初始化列表与工厂构造

命名参数让调用处自带文档，六个布尔参数的接口在 Dart 里几乎不会出现；required 把”必填”从注释升级为编译期约束，漏传直接报错。初始化列表是给 final 字段赋值的唯一场所，并且在构造体执行之前完成，所以列表里不能引用 this 的其他字段状态。命名构造函数解决”同一个类型多种语义构造”，比传一个带魔法默认值的构造器清楚得多。工厂构造函数则用于对象池、单例、返回子类型这类”构造结果不由当前类决定”的场景，作用与 Java 的静态工厂方法相近，区别是它写在类型上、仍用 new 之外的普通调用形式。

Dart 3 的四个类修饰符

Dart 3 在类声明上加了一组修饰符，用来精确控制”谁能继承、谁能实现、能不能枚举子类型”。

sealed 是模式匹配的地基：编译器知道全部子类型，switch 少写一个分支就编译失败。final 用来冻结不想被扩展的实现类，避免”继承我的实现细节”。abstract interface class 让一个类只提供接口，实现方拿不到默认实现，比传统”抽象类当接口用”更克制。mixin class 则修正了旧 mixin 不能实例化、不能声明构造函数的限制，使同一份代码既能混入又能独立使用。按需选择即可，不要给所有类都加修饰符，否则扩展点会变成团队负担。

扩展能力与 on 类型

extension 允许给无法修改源码的类型添加成员，标准库的很多便利写法本身就靠它。

on 后面的类型就是扩展的作用目标，也是它的关键限制：扩展是静态解析的，编译器按变量的声明类型挑选扩展，而不是运行期对象实际类型。

由此引出几条实用规则：想批量启用扩展要显式导入甚至 show；两个扩展给同一类型加了同名成员时，用 extension 名字 on 加 名字.方法() 的显式形式消歧；扩展不能被实现、不能覆盖已有成员、也不能给 dynamic 声明的值生效。它只是补一层语法，运行期对象类型不变。

另一个容易混淆的是扩展类型（extension type）。它同样写在 on 之后，但定位完全不同：普通扩展是给现成类型加方法，扩展类型则是给一个已有的表示类型套上新的编译期身份，让”同一个 int 到底是毫秒还是字节”在类型层面被区分开。就本篇写作时的口径，该能力仍在演进，落到公共库前先确认锁定的 SDK 版本与官方文档说明，不要简单当成 extension 的加强版来用。

集合与迭代

集合字面量的类型由元素推断，推断不出来时要手动标注。

展开运算符 ... 把可迭代对象摊平进新字面量，...? 则允许源为 null，这两者让”以常量列表为基再叠加”的写法非常干净；花括号字面量到底是 Set 还是 Map 取决于元素形式，容易看走眼时统一写出类型参数最稳妥。

需要只读语义时，const 集合是深度不可变的（前提是整个表达式处在常量上下文，且元素本身也是常量）；运行期生成的列表想对外只读，用 List.unmodifiable 或 UnmodifiableListView 包一层视图。视图不是拷贝：源列表被改动，读到的内容会跟着变，跨模块传数据时要想清楚要哪种。

异步与并发

Dart 是单线程事件循环模型：一个 isolate 内没有抢占式并发，await 之后的代码作为回调排进队列。

flowchart TD
  A[事件循环] --> B[微任务队列]
  A --> C[事件队列]
  B --> D[先清空全部微任务]
  C --> E[每次取一个事件执行]
  D --> A
  E --> A

Future 表示一次未完成的计算，Stream 表示一串按序到达的值。

on 类型 catch 变量 的写法让你按异常类型分流，不必全部兜住；没有 catch 的 on 分支会重新抛出。异步方法的错误不会掉进调用方的同步 try，只有 await 它才会转成异常，忘记 await 的 Future 会被静默丢弃，用 unawaited() 明确表示”故意不等”。监听流则要显式给 onError，否则错误会异步抛出、难以定位。

包管理与工程化

包的清单文件是 pubspec.yaml，依赖与约束都写在里面。

^1.0.0 是范围约束的简写，等价于 >=1.0.0 <2.0.0，主版本升级被视为破坏性变更；要写跨主版本或收紧到具体区间，就直接用 >=x.y.z <a.b.c，锁定单一版本写精确值。any 看着省事，实际会让解析器随时挑到不兼容的新版本，禁止出现在提交里。dart pub get 按约束解析并写 pubspec.lock，库包不该把 lock 文件提交、可执行包则要提交；升级前用 dart pub outdated 看兼容性，dependency_overrides 只用于本地临时打通，绝不能进发布产物。

静态分析靠 analysis_options.yaml，团队项目建议从一开始就挂规则集：

规则集解决的是协作口径，新增规则最好一次性修完再合入，不要长期挂文件级忽略注释。站在库作者的角度，还有三条稳定性纪律：破坏性变更只随主版本走；公共 API 的返回类型不要泄露第三方依赖的类型，否则上游一个主版本升级就会传导到你的用户；废弃成员用 @Deprecated 标注并写清替代方案与移除窗口，配合 /// 文档注释与 dart doc 生成的站点，让调用方在 IDE 里就能看到警告。

特性与坑对照

特性 解决什么问题 易踩的坑
JIT 与 AOT 双模式 开发反馈快与交付启动快 依赖反射的代码在 AOT 产物里不可用
var 类型推断 少写重复类型标注 误以为 var 是动态类型，推断后仍固定
final 与 const 表达不可变与常量共享 把 final 当深不可变，实际只锁引用
dynamic 承接 JSON 等真动态数据 绕过编译期检查，错误推迟到运行期
空安全与 late 把空指针从运行期提到编译期 滥用 ! 与 late，等于关掉安全网
命名参数与 required 调用处可读、必填可校验 位置参数过多后改签名容易错位
工厂构造函数 缓存实例、返回子类型 误以为一定新建对象，忽略返回来源
sealed、final 等修饰符 封闭继承面、只给接口 全量加修饰符，扩展点变成团队负担
记录与模式匹配 轻量返回多值与穷尽分支 字段改名让对象模式静默失效
extension 给现成类型补成员 按声明类型静态派发，父类声明时不可见
展开运算符 组合已有集合 常量上下文的展开只能用于常量字面量
Future、Stream 单线程内的异步编排 漏掉 await 或未处理流错误
Isolate 长计算不拖慢事件循环 为 IO 并发而开，反付复制消息成本
版本约束与 lint 依赖可复现、风格有口径 库包提交 lock、any 与临时 override 外泄

小结

Dart 3.0 把这条语言线拉到了”现代静态语言”的位置：空安全是默认而非选项，记录与模式匹配让判别式联合有了干净的写法，类修饰符把继承与实现的边界交还给类型声明。写的时候值得记住三条判断：不确定要不要 dynamic 时先试 Object?；能用 sealed 加 switch 穷尽的分支，就不要写带 default 的兜底；扩展是静态派发，声明类型决定可见性。异步上，先假设自己只有一个线程，把长计算当成必须隔离的例外，而不是随手并发的常规手段。语言特性和工程口径是配套的，规则集与约束写法越早定下来越省事。
