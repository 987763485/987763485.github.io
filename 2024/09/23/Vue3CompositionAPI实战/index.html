Vue 3 Composition API 实战

本文要回答的不是 Composition API 有哪些函数，而是在真实的 Vue 3 项目里这段代码应该怎么写：什么时候用 ref、什么时候就写普通变量、一段逻辑该不该抽成组合函数、钩子为什么在 await 之后悄悄失效。适合写过 Options API、正把页面往 <script setup> 迁移的读者，读完希望建立三层口径：写法边界、时机语义、类型契约。

setup 与 script setup：先建立编译产物的心智

为什么不用手写 return

关键在于最后一步：编译器扫描顶层语句，把顶层绑定收集成对象再返回，模板从中取值。于是几条规定都成了自然结果——只有顶层绑定进模板，分支里临时声明的常量拿不到；绑定名与模板引用在编译期静态对齐，靠动态字符串取值就没有保障。

define 前缀的是宏，不是函数

defineProps、defineEmits、defineExpose、defineOptions、defineSlots 与 3.5 起稳定的 defineModel 都是编译器宏：只存在于 <script setup> 上下文，编译阶段就被替换，因此不能导入、不能解构、也不能在普通 setup() 里调用；用 setup() 的组件，对应关系仍是 props、emits 选项与 context.expose。宏还意味着参数要在编译期被静态分析：defineProps 的类型字面量必须能被看懂，类型放在别的文件里可以（3.3 起支持导入类型），同文件里堆过深的类型体操往往直接卡在编译阶段。

响应式的边界：ref、reactive 与普通 const

本文只讨论怎么写，Proxy 拦截与依赖收集那套机制在《Vue 3 响应式原理：Proxy 与依赖收集》里已经讲透，不再重复。写法上的第一判据很简单：这个值要不要参与视图更新、要不要被别的响应式逻辑追踪，要才包上响应式。

三者怎么选

ref 是默认选择：原始类型与对象都适用，能解构、能整体替换、能放进数组，代价只是多写一个 .value。reactive 适合“一组一定一起变化、又不会被整体替换”的字段，典型是表单草稿：

把它整个传下去，接收方拿到的是同一个代理，随手一改就污染上游。普通 const 也不必有负罪感：一次性配置、取出来就不再变的路由参数、useRouter() 解构出的方法引用都算；两个分支的开关写成 ref 再满屏 .value，纯属噪音。

解包规则要记牢

模板里顶层 ref 自动解包，脚本里不会；reactive 内部的 ref 属性读写时是解包的，普通对象与数组内部的 ref 必须手写 .value：

watch 的源同理：监听 reactive 对象默认按深层处理，不需要也不能写 .value。Vue 3.5 优化了响应式内存占用，接口没变；shallowRef 仍适合整体替换的大列表，替换后 triggerRef 通知一次。渲染开销与包体优化不在本文范围，另文展开。

组合函数：抽取判据、命名与返回值形态

什么时候值得抽

满足任意一条就值得抽：逻辑出现在两个以上组件里；自带需要在卸载时清理的副作用；状态与改它的动作成对出现；单独测比挂在组件里测便宜。这几类别抽：把模板里的一个条件搬进脚本、只服务一个页面的三行代码、把一堆 ref 原样搬进函数再搬出来——抽完只剩一层转发，读的人多跳一次却得不到好处。

  A[这段逻辑要不要抽] --> B{两个以上组件复用}
  B -->|是| E[抽成 use 函数]
  B -->|否| C{自带副作用需要清理}
  C -->|是| E
  C -->|否| D{状态与动作成对出现}
  D -->|是| E
  D -->|否| F[就地写在组件里]
  E --> G{外部需要改它吗}
  G -->|只读| H[返回 computed 或 readonly]
  G -->|可写| I[返回 ref 加显式动作]

命名、入参与返回值

文件名用 use 前缀加能力名，放进 src/composables/，一个文件一个主函数。入参优先接收可变的引用，而不是一次性的值：

MaybeRefOrGetter 与 toValue 自 Vue 3.3 提供，调用方传 ref、传 getter、传普通字符串都能工作。签名写成 title: string 时，父组件改了 props 组合函数感知不到，只能让调用方额外加 watch，这是最常见的接口缺陷。

返回值形态最值得盯：默认返回 ref 组成的扁平对象，别返回 reactive，调用方一解构就丢响应性，而且这类问题只在运行时暴露；只读的用 computed 或 readonly 暴露，把可改的入口收窄到几个动作上。

状态用名词、动作用动词。跨模块的组合函数要导出参数接口、必要时标注返回类型；目录内部的小函数不必为“看起来规范”堆导出。至于把逻辑做成全局共享的响应式单例，已经不是组合函数的职责，store 的设计与测试口径在《Vue 3 生态：Pinia 状态管理》一文里，本文不展开。

时机：生命周期钩子与异步的关系

钩子只有一个语义

onMounted 只表示组件对应的 DOM 已插入文档，不是“开始干活的地方”：请求、订阅、初始化计算放在 setup 顶层执行没问题，还能更早拿到数据，确实要碰 DOM 才留到 onMounted。挂载顺序是子组件先于父组件，父组件的 mounted 里不要假设子孙都完成了异步初始化。

watch 由数据变化驱动，onMounted 由挂载驱动。immediate: true 的 watch 在 setup 阶段就执行首次回调，此时 DOM 还不存在，取模板引用必然拿到 null；要等 DOM 也更新完，靠 flush 解决。

await 之后注册钩子为什么失效

setup 同步执行期间，Vue 把当前实例放在一个内部上下文里，onMounted、onUnmounted、provide、inject 都靠它确认自己属于哪个组件。await 一让出执行权，恢复时上下文已不在当前实例上，注册就成了静默失败——既不报错，也不生效。正确做法是把注册全部压到第一个 await 之前：

组合函数同理：它在 setup 里被同步调用时才搭上这趟车，函数自己 async 时注册同样要在第一个 await 之前。跨异步边界保留实例上下文的手段确实存在，业务代码极少用得上，名称与限制以官方文档为准。

另一类不会自动回收的是原生副作用：addEventListener、ResizeObserver、setInterval、第三方图表实例。Vue 只清理 watch、computed 与钩子，这些要在 onBeforeUnmount 里关掉，或用 watch 回调第三个参数 onCleanup 登记清理函数。

computed、watch、watchEffect 的选型与 flush 语义

computed 用在派生值上：要同步读出来放进模板或传给别的计算，且结果可按依赖缓存。两类禁忌：函数体里产生副作用——求值时机由读取方决定，副作用就不可预测；每次求值都返回新建的响应式对象，让下游追踪链反复重建。

watch 用在“值变化后要执行的动作”上，尤其是需要旧值、需要惰性、需要精确指定源的时候：

多个源用数组形式。deep: true 会做深度遍历与比较，对上百字段或含大数组的对象默认开启它属于自伤，能精确到 getter 就别“先 deep 一下”。

watchEffect 只在“不关心旧值、只想跟着依赖跑”时用，它默认立即执行一次。麻烦在于依赖全藏在函数体里：后来多读了一个 ref，就多一条触发路径，重构时容易引入意外循环，所以建议把它限制在同步 URL、同步标题这类短副作用上，其余写显式 watch。

flush 管的是相对组件更新的时机

flush 管回调相对于组件更新的时机，不是相对于浏览器绘制。pre 是默认，依赖变化后、组件重新渲染前执行，同一轮多次变化会合并成一次回调；post 在组件更新之后执行，此时 DOM 已是新值，读写 DOM 的副作用用它；sync 一变就同步执行，代价是可能读到半更新状态、可能递归触发。post 仍在同一个更新周期的微任务里，与 requestAnimationFrame 无关；想再往后一步，await nextTick() 更直白。immediate 只决定首不首次执行，与 flush 正交。

跨层依赖与模板引用

provide/inject 用在哪里

合适的场景有三类：插槽内容需要回连父级上下文（标签页、折叠面板、表单项）、跨多层传配置类信息（主题、只读态、精度格式）、避免把五六个 props 一路穿透。不合适的是拿它当全局业务状态，那既没有 devtools 的时间旅行，也没有可测试的边界。key 的类型化靠 InjectionKey：

带类型的常量 key 让 inject 的返回值自动推断，字符串 key 做不到。Symbol 换来唯一性，代价是 devtools 里只剩描述文本，所以给它传一个可读的名字值得坚持；模块内部私有的注入用字符串常量问题不大，会随包发布的 key 一定要走 InjectionKey。下发可变值的口径是给 ref（读写都显式 .value），或给只读 computed 配一组受控动作，最糟的是把 reactive 整个交出去。inject 和钩子一样，只能在 setup 同步阶段调用。

模板引用：3.5 起的 useTemplateRef

useTemplateRef 自 Vue 3.5 可用，参数就是模板里那个 ref 名字：它把“变量名与模板名必须相同”的隐式约定变成显式调用，改名不再依赖巧合，也更容易被静态工具检查。在此之前用 ref<HTMLCanvasElement | null>(null) 加同名模板 ref 的写法依然有效，存量代码没必要为此改造。取子组件实例时类型写成 InstanceType<typeof Child>，且子组件必须 defineExpose 开放成员，否则拿到的是一个几乎没有内容的代理。

v-for 里的模板引用是另一处分水岭：3.5 起同名 ref 收集成数组且顺序与源数组一致，更早版本不保证顺序，要严格对应就用函数式绑定自己收：

函数式 ref 每次更新都会被调用，别在里头做重活；边界行为以官方文档为准。

组件契约：props、emits 与 defineModel

类型形式的声明在编译期只生成运行时的 required（不带 ? 即必填）和有限信息，它不做深度校验：数组元素是否合法、字符串是不是合法邮箱，都得回到运行时声明或自己写断言。Vue 3.3 起支持直接引用导入的类型，defineEmits 也接受元组写法 (select: [id: string, shift: boolean])；withDefaults 仍是存量代码里最稳的口径，3.5 起在解构里写默认值才成为可用写法。解构的年代差别要记住：3.5 起 const { limit = 20 } = defineProps<...>() 保持响应性，更早版本里解构会断掉追踪。

defineModel 自 Vue 3.5 稳定：

它等价于声明一个 modelValue 或具名 prop 加对应的 update: 事件，把两行样板折成一行，适合搜索框、分页器、开关这类受控输入。不适合的是“看着该双向、其实该单向”的数据流：父组件需要在子组件改动时拦截或校验，就显式写 props 加 emit，把决策留在父级。defineExpose 是契约的另一半——默认封闭是好事，要开放 focus()、reset() 就显式列出，接收端用 InstanceType<typeof Child> 标注，别把内部状态整包暴露出去。

组合函数如果只用 ref、computed、watch，连组件都不需要，直接调用就能断言。一旦用到 onMounted 或 inject，就得补一个上下文：

global.provide 与 global.stubs 顶掉真实的注入与子组件；等一轮更新用 flushPromises() 或 await nextTick()；jsdom 缺的 ResizeObserver 要在测试初始化文件里补上，否则报错会把人带偏。还有一条：<script setup> 的内部绑定只在开发构建里对 wrapper.vm 可见，所以断言要落在 DOM 与 emitted() 上。

混用的现实约束

Options API 各选项自身的语法在早前的 Vue 2 系列文章里已经写过，本文只谈混用与迁移的边界。

<script setup> 与 mixins、extends、data、methods 无法在同一个组件里共存：name、inheritAttrs 能用 defineOptions 搬进来，生命周期与状态选项搬不进来，只能改写。迁移按组件为单位推进，别按页面为单位——一个组件里同时留着 data() 与 setup() 时，两套状态在模板里都取得到，但改动来源追不清。this 在 setup 里不存在，旧代码的 this.$refs、this.$emit 要换成模板引用与 defineEmits。只有 Options API 形态的历史组件，包一层适配比硬翻划算。

需求、写法与不要写成

需求 推荐写法 不要写成
组件内部状态 ref 一律 reactive 再到处解构
一起变化的草稿字段 reactive 配 toRefs 几个独立 ref 手工同步
派生值 computed 在 watch 里手动拼缓存
变化后发请求 watch 配 onCleanup watchEffect 里读无关依赖
等 DOM 更新完 flush: 'post' 或 nextTick setTimeout 赌时序
深层透传配置 InjectionKey 配 provide 层层转发五六个 props
全局共享业务状态 交给 store 组合函数里的模块级单例
取模板里的元素 useTemplateRef（3.5 起） 依赖同名变量的隐式约定
受控输入组件 defineModel 手写 prop 与事件再拼双向
逻辑两处复用 use 前缀组合函数 复制粘贴再加注释
异步后注册钩子 注册放首个 await 前 在 await 之后调 onMounted

小结

Composition API 的难点不在记 API，而在三条边界：值要不要响应式、逻辑要不要抽出去、副作用注册在哪个时机。默认用 ref，把 reactive 留给整体变化的字段，把普通 const 还给不会变的东西；组合函数按“复用、副作用、成对的状态与动作”判断，返回值给扁平的 ref 加显式动作；钩子注册一律压在第一个 await 之前，需要 DOM 就用 flush: 'post'。类型声明只保证必填与推断，真正的校验还得自己写；defineModel 与 useTemplateRef 自 3.5 起可以放心使用，存量写法不必为它们改造。
