Electron 桌面应用开发实战

Electron 让前端团队用同一套 Web 技术栈交付 Windows、macOS 与 Linux 产物，代价是要重新理解进程边界、安全默认值与打包分发这些浏览器里不存在的环节。本文面向第一次从零搭 Electron 工程、有 React 或 Vue 经验的读者，走通进程模型、窗口能力、安全基线、preload 桥接、系统集成、数据落盘、打包更新与调试排坑这条主线；进程通信细节与性能优化各只用一句指向后续专文。

进程模型与工程骨架

Electron 的运行时由三类角色组成。主进程有且只有一个，跑在 Node 环境里，负责生命周期、创建窗口与原生能力，是应用的权限中心。每个窗口对应一个渲染进程，里面是 Chromium，只负责把页面变成界面，默认拿不到 Node 能力。preload 在页面脚本之前执行，运行在 isolated world 里，通过 contextBridge 把白名单方法挂到 window 上，页面只能看见你显式暴露的那些名字。

这样拆分有三层原因。第一是权限隔离，特权操作留在主进程，渲染进程即使被注入恶意脚本也碰不到 child_process 与文件路径。第二是故障隔离，渲染进程崩溃只影响它的窗口，主进程重建窗口即可。第三是演进独立，渲染层可自由升级 React 18 或 Vue 3.4 的组件与构建链。代价是每个渲染进程都是独立的 Chromium 实例，成本随窗口数量增长，内存与启动优化另有专文。

工程骨架从 package.json 开始，Electron 只认 main 字段指向的文件，因此 TypeScript 项目要先编译出 CommonJS 产物再启动，别把源码路径写进去。

主进程与 preload 属于 Node 侧，单独用一份 tsconfig.node.json：目标 ES2022、输出 CommonJS、strict 打开、types 带上 node 与 electron；渲染层按 ESM 交给前端构建工具。开启 sandbox 后 preload 必须打成单文件 CommonJS，多文件产物会直接报错。

渲染层仍是普通的 React 18 或 Vue 3.4 应用，只是不再假设自己能碰网络与磁盘：需要特权的事情都经 preload 转交主进程。

BrowserWindow 与窗口能力

BrowserWindow 的构造参数决定窗口形态，webPreferences 决定页面能力边界。width 与 height 只是初始值，minWidth 与 minHeight 更该认真设置：没有最小尺寸时，用户能把窗口拖到内容彻底变形。show: false 配 ready-to-show 近乎标配，直接显示会在加载完成前露白底；backgroundColor 取首屏同色可掩盖剩下的空档。

标题栏是跨平台分歧最大的地方。frame: false 去掉系统边框，标题栏与按钮全自己画，代价是要处理拖动区域与缩放边缘；更稳的做法是保留原生边框，macOS 用 titleBarStyle: 'hiddenInset'，Windows 与 Linux 用 titleBarOverlay 让系统按钮浮在自定义条上。

parent 与 modal 组合出父子窗口：模态子窗阻塞父窗交互，运行时可用 setModal 切换。要不要用独立窗口承载二级界面取决于隔离需求——新窗口就是新渲染进程，要付内存与启动成本，换来崩溃被限制在自己范围内；设置页与向导适合拆开，普通弹窗用页面路由即可。

webPreferences 里除安全章节详谈的四项，还应关注 zoomFactor、devTools（生产环境关掉）与 partition（隔离会话）。默认值随大版本调整，用到的项全部显式写出来。

安全基线

桌面应用与网站的安全模型不同：页面里一旦出现可执行任意代码的路径，攻击者拿到的是整台机器的用户权限。下面几条是防御基线，不是可选优化。

第一，nodeIntegration: false 与 contextIsolation: true 是底线组合：前者让页面脚本无法直接 require Node 模块，后者让 preload 与页面处于不同 JavaScript 世界，页面改不了 preload 里的对象。第二，sandbox: true 的现状是渲染进程默认进入 Chromium 沙箱，系统调用因此受限，代价是 preload 环境被削弱、必须预先打成单文件。第三，新工程不要引入 remote：它早被官方标记为不推荐并拆成独立包，等于把主进程对象图暴露给页面，任何 XSS 都会升级为任意代码执行。

暴露接口要遵循最小化——只给动作，不给通道。

第四，导航与新窗口必须拦截：will-navigate 阻止页面被带到外部地址，setWindowOpenHandler 决定 window.open 的结果；确需打开外链时先校验协议与域名白名单，再交给 shell.openExternal，否则 file:// 或本地协议就能被用来探测磁盘结构。

第五，webSecurity 不要关：关掉等于同时废掉同源策略与本地文件限制，跨域的正解是由主进程发请求或用 session.webRequest 调整响应头。第六，渲染层 index.html 配好 CSP 并禁止 unsafe-eval，用户可控内容一律走模板转义，React 与 Vue 的默认插值正好是帮手。第七，凭据不要在渲染层与日志里出现明文；哪些信息必须保护由安全与合规口径界定，工程上按最严格的一档处理。

preload 与 IPC 的最小可用姿势

进程之间只能靠消息，日常需求分两类：要返回值的请求响应用 ipcRenderer.invoke 配 ipcMain.handle，不要返回值的单向通知用 ipcRenderer.send 配 ipcMain.on。别混着用——send 做查询得自己造关联 ID 与超时，handle 做高频事件则每条都要等一个无意义的 Promise。

类型上把桥接接口声明抽成一份 shared/bridge.d.ts 供两侧引用，window.bridge 的签名就不会漂移。调用时把 invoke 的 reject 当正常分支处理：跨进程堆栈不可读，错误信息要带可辨识的 code。

至于序列化代价、transferList 与 MessagePort、多窗口广播与背压控制，属于 IPC 语义细节，另有专文，本文只保证示例能跑通。

生命周期与单实例

app 是主进程的状态机。就绪用 app.whenReady() 这个 Promise 等待；结束侧事件要分清：window-all-closed 是最后一个窗口关掉，before-quit 在退出流程开始前触发（可弹确认框并 preventDefault），will-quit 释放 globalShortcut 这类系统资源，quit 是最后一步。

macOS 的约定与另两个平台相反：窗口全关后应用仍留在 Dock 与菜单栏，点图标应当重建窗口，所以 window-all-closed 里要按 process.platform !== 'darwin' 判断再退出；Windows 与 Linux 上关窗即退出才是用户预期，这条差异最好封装成一个函数。

单实例锁的语义是”抢到锁的进程存活，后来的进程退出并把参数交给它”，必须在 app.whenReady() 之前同步调用，否则会有两个窗口短暂共存的竞态。主窗处于最小化时，second-instance 里要连着还原、显示并聚焦，不然观感就是”双击没反应”。

菜单、托盘与系统集成

应用菜单在主进程用 Menu.buildFromTemplate 构造，再 Menu.setApplicationMenu 挂到窗口上。模板里尽量用 role：reload、toggleDevTools、close、minimize 这些角色由系统提供本地化文案与快捷键，比自己抄一遍省事。macOS 约定第一条菜单显示应用名，about、services、hide、quit 由系统排在那里，不要挪进”文件”菜单；Windows 与 Linux 的菜单挂在窗口顶部，可用 autoHideMenuBar 隐藏并用 Alt 唤出。

上下文菜单与全局快捷键解决两类需求。前者在 webContents 的 context-menu 事件里针对命中元素弹出，带 selectionText 等信息，适合”复制引用”这类语义动作；后者用 globalShortcut.register 配 Accelerator 字符串，CommandOrControl+Shift+Space 里的 CommandOrControl 会自动落到平台对应修饰键。能用页面内快捷键就别注册全局快捷键：全局键位卸载不干净会长期影响用户，务必在 will-quit 里 unregisterAll。

托盘与通知是跨平台成本最高的两块。macOS 要求模板图（单色、Template 命名、由系统按明暗反色），Windows 的图标尺寸与右键行为自成一套，Linux 依赖桌面环境的 StatusNotifier，有的环境根本没有托盘——产品口径上要允许这类能力缺失。Windows 发通知前要先 app.setAppUserModelId，且这个 ID 发布后不能改。app.setLoginItemSettings 控制开机自启，macOS 与 Windows 参数形态不同，Linux 得写桌面入口文件。

持久化与文件

app.getPath('userData') 是当前应用的用户数据目录，配置、缓存与日志都写在这里；别往 appData 根目录或安装目录写文件——安装目录在 Windows 上受权限限制，有自动更新时还会被覆盖。documents、downloads、temp 等路径同样应在主进程解析后使用，渲染层只看到方法名。

配置文件最大的风险不是格式而是写坏：写入中途被杀、磁盘满或强退都会留下半截 JSON，下次启动解析失败等于丢配置。正确做法是原子写——先写同目录临时文件，fsync 后 rename 覆盖目标，并保留上一版备份；主文件损坏就回退到备份并记一条告警。

文件选择交给原生对话框：showOpenDialog 与 showSaveDialog 用 properties 决定多选与目录，filters 是描述加扩展名数组，两者都要处理 canceled 而不能假定一定拿到路径。凭据不进配置文件：macOS 钥匙串与 Windows 凭据管理器可用 safeStorage 封装，主进程加密后落盘，解密结果只在内存里用；isEncryptionAvailable() 为假时要显式降级并提示，不能静默写明文，敏感字段的范围按团队的安全与合规口径界定。

自动更新与打包签名

自动更新可以拆成四问。更新源是什么：对象存储、私有服务器或第三方仓库，本质都是带版本清单的静态文件。清单里有什么：版本号、文件名、大小与哈希，客户端据此比对版本决定是否下载。什么时候装：静默下载、下完提示、点击后重启三种策略，工作类应用要提前告知即将重启并允许推迟，因为更新会打断未保存的操作。如何验收：更新包必须验签与验哈希，校验失败当作网络故障处理并保留旧版本。发布流水线（构建机、证书托管、产物归档与灰度）另有专文。

打包侧用 electron-builder 这类工具，产物按平台分工：Windows 常见 nsis 安装包与免安装的 portable，macOS 是 dmg 加内部的 zip，Linux 有 AppImage 与 deb。配置写进 package.json 的 build 字段：

appId 是安装与更新识别应用的标识，发布后绝不能改：改了就是另一个应用，旧版本收不到更新。图标按平台准备，macOS 用 icns、Windows 用 ico、Linux 用多尺寸 png，缺图标时产物会退回默认图标。签名决定分发能否成功：macOS 要代码签名并完成公证，否则下载后被系统直接拦下；Windows 没有签名证书时 SmartScreen 会给出吓人警告，企业环境甚至装不上。按平台分发的成本要算进预算：账号与证书年费、公证排队、至少三套构建环境、更新服务器带宽，这类流程问题最容易在排期里被漏掉。

调试、常见坑与发布前检查清单

发布版没有终端，主进程日志要自己落盘：以 userData 下的 logs 目录为目标，注册 process.on('uncaughtException') 与 unhandledRejection 记录堆栈，并给 webContents 挂上 did-fail-load、render-process-gone、unresponsive 三个事件，这样渲染进程崩溃时可以选择重建窗口。主进程断点用 node --inspect 启动再附加调试器；渲染层开发期 openDevTools({ mode: 'detach' })，生产包把 devTools 设为假，临时诊断改用远程调试端口。

白屏按三条顺序排查。第一看资源路径：打包后页面走 file:// 协议，构建工具里的资源基准必须是相对路径，绝对路径 /assets/... 会指向磁盘根目录。第二看 CSP 与导航拦截是否把自己的脚本或 dev server 地址挡在外面。第三看 did-fail-load 的错误码，它通常直接指出哪个文件没找到。

发布前逐项确认：

  • 安全基线四项全部显式写出，未引入 remote
  • 外链与导航拦截生效，webSecurity 开启，CSP 已配置
  • 凭据走系统安全存储，配置写入为原子流程，日志无明文
  • 单实例锁生效，最小化后再次启动能唤起主窗
  • 三平台产物各安装一次，覆盖安装与卸载残留通过
  • 签名与公证通过，appId 与更新清单版本号一致
  • 更新失败不破坏现有安装

内存与启动优化的剖析流程另有专文，本文只解决”能跑、跑得安全”这一段。

小结

能力需求 落在哪个进程 用什么 API 安全注意点
窗口增删 主进程 BrowserWindow 安全项显式声明，别靠默认值
界面渲染 渲染进程 React 18 / Vue 3.4 组件 页面代码不接触 Node
本地配置读写 主进程 app.getPath('userData') 渲染层只拿白名单方法
远端接口请求 主进程 net、session 不关 webSecurity 绕跨域
菜单与快捷键 主进程 Menu、globalShortcut 全局键位可关，退出时释放
托盘与通知 主进程 Tray、Notification 文案不泄露敏感内容
选择本地文件 主进程 dialog.showOpenDialog 由用户动作触发
打开外部链接 主进程 shell.openExternal 校验协议与域名白名单
保存凭据 主进程 safeStorage 不可用时提示降级
自动更新 主进程 更新清单与安装包 验签验哈希，失败留旧版本

Electron 的开发体验可以概括为一次职责划分：主进程管权限与原生能力，渲染进程管界面，preload 是两者之间唯一被审查过的窄门。守住这条边界，安全基线、生命周期、系统集成与打包签名都只是围绕它的具体配置。建议新项目从本文骨架起步，先写死安全默认值，再按平台逐项验证产物。
