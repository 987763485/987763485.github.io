Kotlin 基础语法入门

如果你已经写过 Java、C# 或其他静态语言，Kotlin 并不需要从零学起：它跑在 JVM 上、与既有生态兼容，绝大多数概念都能找到对应物。本文按语言全景的顺序，把环境、变量与类型、控制流、函数、类与继承、集合操作串成一条线，每节配可运行的最小示例。读完你应该能独立写一个几百行的 Kotlin 程序，并看懂官方文档里的常见惯用法；空安全深挖、与 Java 的互操作、协程另有专文。

变量、常量与基本类型

val 与 var

Kotlin 用 val 声明只读引用，用 var 声明可变变量。经验法则是默认写 val，只有确实需要重新赋值时才改成 var：

类型推断覆盖声明、赋值与返回值三个位置，显式类型只在需要宽化（例如把 Int 当 Long 用）或提升可读性时补上。命名遵循 lowerCamelCase；真正的常量，也就是顶层或对象里的 const val，使用 UPPER_SNAKE_CASE。测试方法名允许空格，需要用反引号包裹。

const 的边界

const val 不是 val 的加强版，而是编译期常量：只能修饰顶层属性、object 或伴生对象里的属性，类型限于 String 和数字等原生类型，右值必须是编译期可求的表达式。

不满足这些条件时，直接写 val 即可，不要为了”看起来像常量”硬套 const。

没有裸原始类型

Kotlin 的 Int、Long、Double、Boolean 都是类型，但编译器会按上下文还原成 JVM 原生类型，所以既享受对象语法又没有装箱开销。代价是没有隐式加宽转换，任何转换都要显式调用：

字面量的类型由后缀决定：1L 是 Long，0.5f 是 Float，10_000 的下划线只影响可读性。整数除法会截断，7 / 2 得 3，想要小数就写 7.0 / 2；% 的符号跟随被除数，处理负数下标时要留意。

三个入门级注意事项

第一，List<String?> 与 List<String>? 是两回事，一个是元素可为 null，一个是列表本身可为 null，先确认自己面对的是哪一种。第二，参数常用可空表达”没传”，例如 fun find(city: String? = null)。第三，!! 会把编译期保证换成运行时异常，业务代码里不推荐；分支中如何收窄可空判定、如何用契约声明非空，属于进阶话题，另有专文。

控制流与表达式

if 是表达式

if 有值，可以直接参与赋值和返回，三元运算符因此被取消：

两个分支的类型会被推断成一个公共类型；差异过大时显式标注变量类型。

when 的多形态

when 是 Kotlin 的分支中枢，能力远超 switch：匹配常量、匹配区间、匹配类型、甚至不带主语当作紧凑的 if-else 链。

带主语的写法是 when (n) { 1, 2 -> "小"; in 3..9 -> "中"; else -> "大" }，一个分支可以并列多个值。用于枚举或密封层级且穷尽时 else 可以省略，新增分支时编译器会提醒补齐，这是它比 switch 可靠的地方。

引用函数与操作符

:: 是引用符号：String::length 引用成员函数，::parseInt 引用顶层函数，Foo::bar 引用属性，省掉再包一层的无意义 Lambda。运算符都能自定义，声明 operator fun plus(other: T) 后 a + b 即可编译，in 对应 contains，索引访问对应 get/set。infix fun 定义的中缀函数让 a to b 这类读法成为可能。

类与对象

主构造函数与 init

类默认 final、成员默认 public，属性直接写进主构造函数就不必再写字段加赋值的重复代码：

init 块与属性初始化按声明顺序执行。需要额外构造路径时用次构造函数 constructor(...) 委托给主构造函数。访问器也能针对单个属性改写，在 get()/set(value) 里做校验或派生，而不必额外暴露方法。

可见性修饰符

四档可见性是 public、private、protected、internal。private 限本类或本文件（顶层声明的 private 只在本文件可见），protected 限子类且对模块内其他类不可见——这点比 Java 更严，别指望子包能访问。internal 是 Kotlin 独有，含义是”同一模块内可见”，编译单元层面把实现细节挡在库外。扩展函数只能访问 public 成员，因为它拿不到私有字段。

数据类与解构

data 关键字自动生成 equals、hashCode、toString、copy 和解构函数，主构造函数里的每个属性都要参与相等性比较。它只适合承载不可变数据，字段频繁变动或有生命周期语义的类不适合写成数据类。

object 与伴生对象

object 用于无状态的单例、无参比较器或事件定义；伴生对象则替代静态工厂与类级常量，名字可省略。Kotlin 没有静态成员这一概念，”看起来像静态”的能力都应落到对象或伴生对象上，这一点在设计与阅读代码时要先建立预期。

语法糖、思维调整与常见坑

扩展函数与作用域函数

扩展函数让你在不修改原类、不参与继承的前提下给已有类型追加一个方法，调用写法与成员方法完全一致：

作用域函数有 let、run、with、apply、also 五个，都是把一小段代码包在某个对象周围并返回其中一个值，区别只在接收者写法与返回值，本文只点名。IDEA 的意图动作能把重复的字段声明一键转成数据类、把显式类型换成推断、把 forEach 改成 map。类型推断越充分，重命名与提取方法的改动面越小；对外暴露的 API 建议保留显式类型，当作契约。

从 Java 过来的三个思维调整

第一，少写样板：属性、构造、equals、单例都不再需要手工模板，代码量下降后阅读重心回到逻辑本身。第二，把可空写进类型：判空从”文档里的一句提醒”变成签名的一部分，调用方在编译期就被迫处理。第三，优先表达式：if、when、对象创建都返回值，先算后赋值的中间变量能省掉大半，函数也更短。

新手最常踩的三个坑

!! 只用在”为 null 就是程序 bug”的地方；lateinit 适合依赖注入与测试 setup，但只允许用于非空、非原生类型的 var，读之前要确认已赋值；第三个坑的修法是对外暴露 items.toList()，内部可变、外部只读。共同点是：编译器管不到的地方，需要人来守规矩。

小结

Kotlin 的语法收益集中在三处：类型系统更精确、样板更少、表达式代替语句。入门阶段把 val 与可空类型当作纪律，把 when 与集合链式操作当作默认写法，风格就基本到位。下表按本文顺序整理，便于速查。
