开源模型部署：Qwen 与 Llama

本文以已进入稳定期的 Qwen2.5 与 Llama 3.x 为讲解对象，把从拿到权重到跑成可用服务之间要做决定的环节串一遍：开放了什么、先核验什么、精度与容量怎么判断、走哪条路线、怎么升级回滚。适合第一次自行部署开源权重模型的读者，读完能得到一套登记字段、一组估算公式和一份排查清单。

先分清“开源”到底开了什么

结论：本文说的“开源模型”只指权重可下载、能在自己机器上推理，不承诺训练数据可见，也不自动承诺可自由商用。

这三层常被压成一句话：开放权重只意味着拿得到参数文件，开放训练数据意味着查得到语料构成（本文两个系列都不满足），能否自由商用则只由许可证决定，与权重是否公开无关。

获取渠道三类：系列官方发布条目、第三方平台镜像条目、社区二次打包的分发件。三类风险不同：第一类最接近原始版本；第二类说明由平台撰写，未必与作者口径一致；第三类常已改名、重新分片或换过精度，落地名字和原始名字对不上是常态。本文只把第一类当基准。

许可证条款盯四件事：能否商用、能否再分发、衍生条目是否要沿用同样条款、有没有对使用场景或规模附加限制。同系列不同尺寸、不同精度的条目条款未必一致，带变体后缀的常有额外限制。本文把要点抄进登记表，而不是写一句“它是开源的”。

同期还有以推理见长的开放权重模型与闭源商用模型，本文不拿它们当基准，只在中文与工具调用上提一句对照。

落盘之后的第一件事：核验与登记

结论：先证明“这就是官方那一份”，再谈运行配置；顺序反过来，后面的排查会失去参照物。

核验分三步。查来源：条目全名、发布方标识与下载页是否指向同一条记录，平台镜像要记下条目全名，只记系列名等于没记。查清单：对照发布方给的文件名与大小列表核对个数、命名与后缀，缺件、多件、后缀被改都算异常，先停手而不是先跑起来。查校验和：有官方哈希就逐文件核对，没有就把清单、大小与落地时间固化成基线。校验和的价值不在算法，而在把“来源可信”变成可复述的证据。

三个维度是后续判断的坐标系。系列指模型家族，本文讲 Qwen2.5 与 Llama 3.x；变体指同族里用途不同的条目，指令型、基座型与不同尺寸都算；精度指权重按什么位宽存储或落在哪一档量化上。三个维度塞进一个条目名，是事故最常见的来源：同系列下指令型与基座型模板不同，档位不同表现也差得明显。

精度与量化档位：只讲方向和判断方法

结论：档位不是越省越好，而是要和瓶颈对齐；判断错了，压得越狠返工越多。

方向三条。第一，原生精度是效果基线，位宽往下走权重占用大致线性下降，但格式敏感的任务先出问题：工具调用参数格式、长指令跟随度、数字与代码稳定性，这些比“读起来顺不顺”更早暴露。第二，量化档位主要解决装不进去，对跑不快与长上下文撑不住帮助有限，那部分开销在缓存与余量里。第三，两个系列的档位命名体系不互通，同一标记在两边的开销与损失不能互推。

量化文件的内部结构与格式细节归《模型量化与 GGUF 格式》，本文只把“档位”当外部标签。

判断三步。先定瓶颈：加载就失败是权重占用问题，方向是降档位或分片；加载成功但并发上来就退化是缓存与调度问题，方向是控长度、限并发或换路线。再用同一份评测集在同等条件下对比，否则差异不可解释。最后把损失写成可见的退化形式：记哪一类输出开始不合规，别记笼统分数。

容量估算：用符号表达，不背数字

结论：本文只给公式与判断，具体显存数字一律按当期硬件当场核对，写进文章就会过期。

设参数量为 P、每参数字节数为 b，权重占用 W ≈ P × b。分 S 片做张量并行时，单卡约 W / S，再加对齐与冗余。设每 token 的键值缓存字节数为 k，它由注意力头维度、层数与缓存位宽决定；设并发请求数为 N、平均占用长度为 T，则缓存占用 C ≈ N × T × k。两个含义：C 随并发与长度同时线性增长，“多开几路”和“允许更长”不能同时放大；C 逐 token 累计，长文多轮里常先于 W 成为瓶颈，降档位救不了它。再设运行时余量 R，含激活缓冲、采样临时结构与框架自身占用。总需求 M ≈ W + C + R，乘安全系数得 M_safe ≈ α × M。符号形式如下，系数与单位按当期硬件自取：

两条接入路线的适用边界

结论：本地运行时与推理服务是两条路，选哪条看“谁来调用、要几路并发”，不看“哪个更快”。

本地运行时这一条（llama.cpp、Ollama 一类）适合单机、并发极少、以验证和内部工具为主的场景，目标是用最短路径把权重跑起来。推理服务这一条（vLLM 一类）适合要提供稳定接口、多副本部署、靠连续批处理与请求调度换吞吐的场景。

怎么装、怎么调参、源码做了哪些优化，归《ollama 本地大模型部署》《llama.cpp 源码与推理优化》《vLLM 推理加速实践》，本文不重复。

两系列差别记三条，验证后才进台账。接入广度：Llama 3.x 出现得早、跟进实现多；Qwen2.5 的中文与工具调用行为更贴近本文场景，但能否直接用取决于模板与格式支持。失败方式：模板不匹配时，一个系列偏向输出混乱，另一个偏向原样复读提示词，都是配置问题而非能力问题。档位命名不互通，两条路线各测一遍。

部署形态与升级回滚

结论：形态由要不要对外承担流量决定，升级由能不能整体退回上一版决定，都要在设计阶段定下来。

三档形态。单机试验：一份权重、一个进程，做完登记与核验即可，不做容量规划，只验证行为与格式，别把试验机上的观察当成生产结论。多副本服务：多个副本加调度与配额，重点是把配置条目与权重条目绑成整体发布，副本之间条目不一致最难排查。混合与外部分担：主体留在本地，超出容量或不便本地化的请求交给外部商用服务；路线决策与合规面归《大模型私有化部署方案》，分层与服务侧架构归《大模型应用架构分层》与《推理服务架构设计》。

升级与回滚按下面动作走。

flowchart TD
    A[登记候选条目并核验] --> B[单机跑固定评测集]
    B --> C{自建指标是否达标}
    C -->|达标| D[灰度接少量真实请求]
    C -->|不达标| E[路由指回旧条目]
    D --> F{是否触发回退条件}
    F -->|是| E
    F -->|否| G[按配额逐步放大]
    E --> H[记录失败原因并归档]

三个要点。权重版本化：条目全名加校验和进台账，换文件就开新记录，禁止原地覆盖，否则回滚时说不清线上是哪份。灰度评测：先跑固定评测集再接真实请求，看合规率与截断率的变化。失败回退：条件要能机械判定，例如不合规率越过自建阈值、加载失败、超时集中；动作是把流量指回台账旧条目并重启，不是热改参数。

中文场景与上下文适配的自建评测

结论：评测集不必大，但必须来自你自己的输入分布；记录时把“跑不起来”与“效果不好”分两栏，否则下一步会选错。

搭法四步。取样：把实际要交给模型的事按类别抽条目，至少覆盖中文摘要、长文改写、结构化输出、带工具调用的多步任务四类，条数够区分就行。定指标：只用五个可判定的量，即可用率、格式合规率（能否被下游解析）、截断率、拒绝率、返工成本（改写处数或人次）。做对照：同题集、同模板、同长度上限，跑不同条目与档位，另留一组外部模型输出当参照，用来判断是不是自己配错了。记账：两栏分开。

条目与变体 跑不起来（阶段） 效果不好（类别） 判定动作
系列甲 指令型 某档位 加载成功无异常 结构化输出解析失败 修模板与终止标记
系列乙 基座型 某档位 加载即失败 不评价 降档位或做分片
系列乙 指令型 某档位 无 长文改写后半段跑题 收紧长度上限复测

“跑不起来”记阶段：下载、加载、首次推理、并发上来之后。“效果不好”记类别：哪一类任务、失败长什么样。两份记录分开归档，配置问题与能力问题就不会混谈。表内均为示意值，不代表实测。

常见问题清单

结论：下面几项里多数属于配置与格式不匹配，不是能力不足；先走完清单，再考虑换条目。

  1. 对话模板不匹配。两个系列的指令段写法、角色标记、终止标记都不同，提示词不能直接搬；基座型没有指令模板，硬套不如裸提示。表现是复读提示词、连续输出多个角色、不认终止标记。
  2. 工具调用格式差异。参数内联还是分步给出、说明放系统段还是单独槽位、结果怎么回填，两个系列做法不同，解析器要各写一份。
  3. 长度超限的截断行为不同。有的从输入侧裁剪（可能丢掉最早轮次或系统段），有的从输出侧硬截（留下半句话），有的直接报错。三种表现对下游完全不同，必须实测，不能互推。
  4. 分词与计数差异。同一句中文在两个系列下的单元数不同，限流或计费的阈值不能互套；按字符数估会低估，按另一系列的规则估会误判。计数用条目自带分词器，口径写进台账。
  5. 许可证里的商用与再分发限制。只抄要点：能否商用、条款是否传递给衍生条目、能否对外再分发、有无场景或规模附加条件。同系列不同条目条款可能不一致，条目变了就重看一次。

路线对照与本文结论的边界

结论：把前面的判断合成一张表，按“适用阶段”倒着查，不要从“吞吐取向”正着选。

部署路线 上手成本 吞吐取向 定制能力 适用阶段
本地运行时、单机单进程 低 单路为主，不追求吞吐 只能换条目与档位 验证行为、内部工具
单机推理服务 中 受本机容量限制 可调长度与采样策略 小范围正式使用
多副本推理服务 高 追求吞吐与延迟分布 可按条目分档路由 承担正式流量
混合与外部分担 中高 本地瓶颈由外部补 需维护两套接口 峰值或边界外请求

表里的定制能力指原版权重之上可配置的程度，不含模型改造。

最后划两条边界。其一，本文结论只在 Qwen2.5 与 Llama 3.x 这两个稳定系列上成立；Llama 4 刚刚发布，本文未做验证，上文的档位、模板与截断行为不能推给它。其二，本周有厂商更新商用模型，属外部服务侧变化，本文不做能力比较，只承认外部侧接口与条款要另做登记。

小结

本文流程可以压成一句话：先分清开放了什么，再核验并登记，然后按瓶颈选档位、按并发选路线、按能不能回退设计升级。系列、变体、精度三个维度是判断的坐标系，台账要能十秒答出“跑的是哪份、谁批准的”。容量部分只给公式不给数字，是为了让结论不随硬件过期。两个系列的差异集中在对话模板、工具调用格式、截断行为与档位命名上，都属配置层面，实测后固化进台账。工具操作、量化格式细节与架构设计各有专文，本文只负责选型判断与登记流程。
