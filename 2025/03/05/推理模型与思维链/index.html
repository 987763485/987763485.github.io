推理模型与思维链

推理模型与思维链经常被写进同一句话，但它们是两件事：一个是输出形态，一个是模型类别。本文画清这条界线，再讨论可见性、预算交换、工程影响与验证方法。文中所有数字都是示意值，只用于描述趋势形状。

两个概念先分开

结论：思维链是“提示出来的中间步骤”，推理模型是“把推理过程纳入训练与采样预算的一类模型”。前者是套在任何模型上的输出结构，后者需要厂商同时改动训练目标与采样预算，二者不在同一层。

思维链（Chain of Thought）落在提示层：你要求模型先列条件、再分步推导、最后给结论，它便把中间步骤原样写进响应。它改变的是你看见什么，不改变模型能算对几道题；任何模型都能被提示出步骤。推理模型落在模型层：训练时把推导过程当作被优化的对象，推理时在正式答案之外额外分配一段生成预算，让模型有地方去试、去检查、去推翻自己。DeepSeek-R1（2025-01-20）、o1 系列（2024-09 之后）、o3-mini（2025-01-31）都属于这一类。

误判通常长这样：给提示加上“请一步步思考”，正确率上去了，就对外宣称换成了推理模型；实际上权重、预算、延迟都没变。反过来也常见：接了推理模型，因为看不到步骤，就认定它没有推理。

过程可见与不可见

结论：中间步骤是否暴露给用户，是产品与商业决策，不是技术必然；一旦折叠，工程上最直接后果是无法审计中间步骤。

推理模型普遍把过程藏起来：接口只给最终答案，或者给一段可展开的摘要，甚至明确不返回过程字段。原因有三层。其一是阅读价值：过程文本大量是自我怀疑与回退，直接铺开噪声多于信息。其二是合规：过程里可能复述提示词或敏感中间结论。其三是竞争：过程文本是能力的外在表征，厂商不愿它被大规模采集。

代价落在调试上。只看结果，错误就无法定位到步：过去如果步骤显示第 3 步把条件读漏了，你可以去修提示或修输入解析，现在只知道错了。补这个缺口只能在结果层重建可观测性，做法见后文。另外要区分不返回过程与没有过程：前者是接口策略，后者才是能力问题。

用预算换准确率

结论：更多生成 token 确实能换来更难题目上的正确率，但曲线不是直线，它先陡后平，在简单题上甚至倒挂。

把思考预算当横轴、正确率当纵轴，按三档题目描述示意形状，数字仅示意趋势而非实测：

题目难度 不给预算 低预算 中预算 高预算
简单题 92% 93% 93% 91%
中等题 58% 71% 79% 81%
超出能力 12% 14% 15% 15%

三档的原因各不相同。简单题那行几乎平、到高档还略降：任务已在饱和区，多出的预算逼着模型去想更多，把本来一步到位的判断反复改写，反而引入偏离。中等题是收益区，曲线最陡处就在这里，模型的检查与回退真正用得上。超出能力那行也平，原因不同：所需的信息或能力模型根本不具备，再多自我对话也只是在同一个错误附近打转。

代价是明确的：思考 token 要付费、要等、要占并发，延迟随预算大致线性上升，正确率却不是。所以预算档位应按任务类型设定而不是全局拉满，分类打分类走最低档，多步推导类才值得开中高档。

三种不如别的方案的情况

结论：有三类情形，推理模型不是合理选择——需要最新事实时检索更合适，需要稳定格式时微调更合适，简单任务上推理模型反而更慢更贵。

第一类，需要最新事实。推理预算不能生成不存在于参数里的事实；给它更多思考时间，只会让它在过期知识上推导得更完整，错得更成体系。这一类为什么选检索，属于《RAG 与微调的取舍》的范围，本文不重讲。

第二类，需要稳定格式。当要求是输出必须能被下游解析时，冗长的思考段是干扰而不是收益；格式遵循不会因预算变多而更稳，反而可能因模型在长输出里忘了最初的约束而变差。训练细节《大模型微调 Fine-tuning 实践》已有交代。

第三类，简单任务。抽取字段、判断情感、按规则分类，正确率本来就在高位，加预算的期望收益接近零，延迟与成本却是实打实的正数。此时应当用最小的可用模型，并用前置分类器决定哪些请求值得走带思考的路径。

工程上的连锁影响

结论：接入推理模型会同时改动五处工程假设——超时预算、流式展示、成本口径、缓存命中与评测集构成。

第一，超时预算。首包时间不再代表完成时间，思考段可能占整次请求的大部分时长。应把超时拆成连接建立、首包到达、整体完成三档，对最后一档单独设上限与告警；盲目重试会把思考成本翻倍支付。

第二，流式展示。思考段与答案段性质不同，混在同一个气泡里刷出来全是自我否定与回退。处理办法是分区渲染：过程区折叠或只显示进度，答案区正常流式；服务不返回过程字段时，要在等待期给出心跳与占位。实现细节归《大模型流式输出实践》。

第三，成本按思考 token 计。计费口径必须包含推理段的生成 token，否则预算一提高，账单变化看起来像涨价而不是用量上涨。归因上要按任务类型统计思考长度，才有收敛档位的信号；核算方法交给《大模型推理成本核算》。

第四，缓存命中率下降。前缀相同的请求一旦进入各自不同的思考展开，键值缓存与语义缓存的可复用部分都会缩水，重试与追问也命中得更差。

第五，评测集偏置。集子偏数学与逻辑会高估收益，偏短答案与格式抽取会低估延迟代价。正确做法是按线上流量分层抽样并标注难度档，避免把三档平均成一个数。部署与服务架构不属于本文，《大模型私有化部署方案》与《推理服务架构设计》各自负责。

还要不要写“一步步想”

结论：本文不给结论，给判断方法——边际变化取决于模型形态与任务档位，而不是提示文字本身。

方法分三步。第一步，别看单次输出：同一问题分别用带步骤指令与不带步骤指令两组提示各跑若干次，比较答案分布而不是某一次的答案，温度不为零时单次差异几乎不构成证据。第二步，看步骤文本落在哪一侧：加指令后步骤明显变长而答案分布不动，说明显式步骤只是展示层；答案分布移动了，说明显式展开挤占了原本留给内部检查的预算，此时提示可能有害。第三步，看总生成 token 与延迟的配对变化：加提示后总 token 下降而正确率不变，往往意味着模型把一部分内部展开搬到了可见位置，净收益接近零但可读性变好。

两个坑要避开。一是把提示效果与模型升级混记：换了模型又改了提示，收益归因不了，两件事要分批上线。二是把可读性当正确性：步骤工整不代表步骤为真，也不代表结论由步骤推出。提示的写法与管理，《Prompt 工程实践指南》《大模型提示词管理》《提示词版本化管理》已有分工。

怎么验证它对不对

结论：过程不可见时，正确性只能靠结果层的四件事重建——抽样复评、可核对来源、双模型交叉检查、失败样本回收。

第一件，抽样复评。按线上流量分层抽样，复核答案本身而不是只看格式。分层至少包括任务类型与难度档，否则结论会被简单题淹没。复评要落进指标：错误率、错误类型分布，以及答案对但推导说不通这类样本的比例。

第二件，让检索提供可核对来源。事实性断言尽量带上可点开的出处，让复核变成对照原文而不是重新判断；没有出处的断言显式标记为不可验证。这一条只解决可核对性，检索与微调怎么选不是本文范围。

第三件，双模型交叉检查。用第二个模型充当判据，检查结论与前提是否自洽、有没有算错或读错题。坑有两个：同族模型有同源偏差，会一起错；判据模型自身上限决定检出率，所以它只适合当筛子，不适合当终审。

第四件，失败样本回收。线上确认错的样本要落库并归因，粗分四类就够用：事实错、计算错、读错题、步骤中断。前三类各有去处——检索覆盖、任务拆分、输入描述；步骤中断说明预算档位不够或过程被截断。回收样本进入回归集。

任务类型对照表

结论：把前几节收敛成一张按任务类型选路径的对照表。“思维链提示”指不换模型只改提示，“推理模型”指走带思考预算的路径。

多步数学与逻辑题 有效但受模型上限约束 收益最明显 无关 推理模型，按难度设档
强时效事实问答 无收益 无收益，更自信地错 检索直接解决 走检索，不加预算
固定格式抽取 小幅改善 过程冗长是干扰 微调可稳定达标 走微调
长文改写与摘要 用处有限 更慢更贵 按需检索 用普通对话模型
代码修复与调试 有助定位 有助跨文件推理 微调补风格 二者结合，先做可复现
简单分类与打分 收益小 延迟不划算 微调更省成本 用最小可用模型

三点提醒。一是表中的建议是路径选择而非结论承诺：同一任务类型在不同难度档上的最优路径会翻转。二是检索或微调那一列只回答该不该走这条路。三是当业务要向监管或客户解释结论怎么得出时，可见的显式步骤可能比不可见的更高正确率更有价值。

小结

本文的核心区分是层次：思维链在提示层改变你看见什么，推理模型在训练与采样层改变模型能做什么，把“输出了步骤”当成“具备推理能力”是最常见的选型误判。第二是可见性：过程折叠后无法审计中间步骤，正确性只能靠抽样复评、可核对来源、双模型交叉与失败样本回收在结果层重建。第三是预算与正确率的曲线：简单题平甚至倒挂，中等题最陡，超出能力的部分不动，所以档位要按任务类型设定。第四是工程假设要一起改：总时长超时档、过程与答案分区展示、按思考 token 计费、缓存命中率下降与评测集分层。

实践建议给三条。一是上线前先做同题双路径对比，用统一口径记录首包、总耗时与思考长度，不要只看答案。二是给请求加前置分流，让简单任务留在低成本路径，把预算留给真正难的一小撮。三是把过程是否可见当作接口能力单独建档，因为它决定你能用哪种验证手段。
